Exponentiation by squaring (an)

 Home Mathematics Area of mathematics Number theory
OurBigBook.com Words: 1k Articles: 5
Exponentiation by squaring computes an integer power by reading the exponent's binary expansion. Appending a binary digit b to a prefix of value p replaces p by 2p+b, so the corresponding power changes by
a2p+b=(ap)2ab,b∈{0,1}.
(22)
Each new digit requires one squaring and, only for digit one, one further multiplication. The number of digits grows with the logarithm of the exponent, making this useful for modular exponentiation, primality testing, and powers of matrices using matrix multiplication.[ref]
For a concrete calculation, 13=(1101)2​=8+4+1, so 313=38⋅34⋅3. The optimized left-to-right algorithm used here instead keeps one accumulated power: initialize r=3 from the leading digit one, then process only the remaining digits 1,0,1:
1111101101​:r=3,:r=32⋅3=27,:r=272=729,:r=7292⋅3=531441⋅3=1594323.​
(23)
Thus 313=1594323, using three squarings and two further multiplications, instead of twelve successive multiplications starting at 3.
For a general positive integer n=(bℓ−1​⋯b0​)2​ with leading digit bℓ−1​=1, set r=a and, for i=ℓ−2,…,0, first replace r by r2, then multiply it by a if bi​=1. Return r. This explicitly skips the leading digit's otherwise unnecessary operations on one. A Computational Introduction to Number Theory and Algebra by Victor Shoup (Section 3.4, pp. 65–66) presents the version initialized at one and processing every digit; the optimization here makes the counting convention unambiguous.
The loop invariant is r=ap, where p is the value of the digits already read. Initially p=1 and r=a. If the next digit is b, then squaring and optionally multiplying give r′=a2p+b, exactly the next prefix. At termination p=n. This proof uses associativity of multiplication; it works in any monoid, including matrices with the identity matrix as identity element, and needs no commutativity between different bases.
For n=0, return the identity element without performing a multiplication. This is the empty-product convention a0=1; if a=0, the algorithm therefore returns one for 00 by convention, rather than resolving its meaning in every mathematical setting. Negative integer exponents require an inverse element: compute (a−1)−n, counting the inversion separately. Over the integers, such an inverse generally leaves the integers, and a zero base has no inverse.
