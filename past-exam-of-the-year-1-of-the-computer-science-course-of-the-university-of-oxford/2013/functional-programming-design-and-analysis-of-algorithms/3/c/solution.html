Compare frequencies in decreasing order and use lexicographic order on words to break ties. Implement merge sort explicitly, so no imported sorting routine is needed:
-- Entry, TextWord and Frequency are as in part (b).
before :: Entry -> Entry -> Bool
before (w, p) (v, q) = p > q || (p == q && w <= v)

sort :: [Entry] -> [Entry]
sort []  = []
sort [x] = [x]
sort xs  = merge (sort left) (sort right)
  where
    (left, right) = splitAt (length xs `div` 2) xs

merge :: [Entry] -> [Entry] -> [Entry]
merge [] ys = ys
merge xs [] = xs
merge xa@(x:xs) ya@(y:ys)
  | before x y = x : merge xs ya
  | otherwise  = y : merge xa ys
The merge algorithm step always emits the smaller key under the ordering (−frequency,word). The unchosen heads cannot precede that emitted entry because each input is already sorted. It preserves all entries, and each call removes one head, so it terminates with exactly the sorted union of the inputs. Mathematical induction over the recursive splits establishes correctness of merge sort.
For n entries, splitting and merging cost Θ(n) per level, and there are Θ(logn) levels:
T(n)=T(⌊n/2⌋)+T(⌈n/2⌉)+Θ(n)=Θ(nlogn)(n≥2).​
(12)
The base cases take constant time. This counts word comparisons as primitive operations, as in the question. If the maximum compared word length is L, the character-operation bound becomes O(Lnlogn), in addition to frequency comparison costs.
For the supplied input, sort . count yields
[("baa",2),("sir",2),("yes",2),("any",1),("bags",1),("black",1),
 ("full",1),("have",1),("sheep",1),("three",1),("wool",1),("you",1)]
In particular, the secondary ordering places sir before yes, even though yes appears earlier in the original text. The Θ(nlogn) requirement concerns sort; the simpler association list implementation of count has its own cost.
