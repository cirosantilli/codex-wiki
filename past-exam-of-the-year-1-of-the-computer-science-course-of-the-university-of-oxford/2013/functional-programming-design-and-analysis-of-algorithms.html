The map function changes each element of a list while preserving its order and length. List concatenation removes one level of nesting. Currying changes a function on a pair into a function taking its two arguments separately; uncurrying reverses this conversion:
map :: (a -> b) -> [a] -> [b]
map f []     = []
map f (x:xs) = f x : map f xs

concat :: [[a]] -> [a]
concat []       = []
concat (xs:xss) = xs ++ concat xss

curry :: ((a, b) -> c) -> a -> b -> c
curry f x y = f (x, y)

uncurry :: (a -> b -> c) -> (a, b) -> c
uncurry f (x, y) = f x y
These polymorphic type signatures impose no numerical, equality or ordering constraints: the definitions only inspect list or pair structure and apply a supplied function. In particular,
curry(f)xy=f(x,y),uncurry(g)(x,y)=gxy.​
(1)
The recursive equations describe the two possible list constructors, so they also explain how the empty case terminates each finite computation.

In the type signature map :: (u -> v) -> [u] -> [v], the supplied function is concat :: [[a]] -> [a]. Type inference therefore identifies u with [[a]] and v with [a]. Consequently,
map concat :: [[[a]]] -> [[a]]
Thus [[[α]]]→[[α]]​ is the principal type. For example, map concat [[[1],[2,3]],[[4],[]]] gives [[1,2,3],[4]]: it concatenates each inner group, preserving the outermost grouping.

Both uses of x in this definition have the same monomorphic type within the body. Write x :: u -> v. The inner application x z forces z :: u and has type v; the outer application x (x z) forces v = u. Thus x :: u -> u. Finally, x (x z) is applied to y, so u must itself be a function type, say a -> b. This gives
f :: ((a -> b) -> a -> b) -> a -> (a -> b) -> b
f x y z = x (x z) y
The principal type is therefore
((α→β)→(α→β))→α→(α→β)→β.​
(2)
The argument x transforms a function into another function of the same type. The body transforms z twice, then applies the resulting function to y; no recursive type equation is required.

Represent Pascal's triangle by an infinite outer lazy list, each of whose elements is one finite row. Pad the preceding row with zero on its left and on its right, then add corresponding entries:
pascal :: [[Integer]]
pascal = iterate next [1]
  where
    -- Padding supplies the two boundary entries as well as the interior sums.
    next :: [Integer] -> [Integer]
    next row = zipWith (+) (0 : row) (row ++ [0])
Here iterate next [1] begins [[1],[1,1],[1,2,1],[1,3,3,1],...]. Every call to next receives a finite row, so its final zero is reachable. Lazy evaluation produces any requested finite prefix without trying to finish the infinite outer list.
Indexing rows and columns from zero, Pascal's rule says
pascaln​=[(0n​),(1n​),…,(nn​)],(jn+1​)=(j−1n​)+(jn​).​
(3)
Take out-of-range binomial coefficients to be zero. The seed is the zeroth row, and the padded addition implements this identity at every position, including the two boundaries. Mathematical induction therefore proves every generated row correct. Using unbounded integers prevents overflow. Generating rows zero through r takes Θ(r2) arithmetic operations, with additional bit costs as the binomial coefficients grow.

Use structural induction on the finite list xs, strengthening the induction hypothesis to hold for every accumulator value y. For the empty list, the defining equation of the left fold gives
x⊕foldl(⊗)y[]=x⊕y=foldl(⊗)(x⊕y)[].
(4)
For the inductive step, suppose the identity holds for the tail zs and every accumulator. Expand the first left fold, apply the induction hypothesis at accumulator y⊗z, and then use the supplied compatibility law:
x⊕foldl(⊗)y(z:zs)​=x⊕foldl(⊗)(y⊗z)zs=foldl(⊗)(x⊕(y⊗z))zs=foldl(⊗)((x⊕y)⊗z)zs=foldl(⊗)(x⊕y)(z:zs).​
(5)
Hence
x⊕foldl(⊗)yxs=foldl(⊗)(x⊕y)xs.​
(6)
Only equation (1) is needed for this part; the seed condition in equation (2) enters the next proof. Quantifying over the accumulator is essential because the recursive call changes it.

Set both ⊕ and ⊗ equal to list concatenation, with a=[]. Associativity gives xs ++ (ys ++ zs) = (xs ++ ys) ++ zs, which is equation (1). The two identity laws give xs ++ [] = [] ++ xs, which is equation (2). Part (b) therefore yields
concat :: [[a]] -> [a]

Thus concat=foldl(++)[]​ on finite lists. The argument order is unchanged: the accumulator is the already concatenated prefix, and the next inner list is appended to its right. This preserves the order but repeatedly copies that prefix.

Let there be k inner lists, of lengths ℓ1​,…,ℓk​, and let N=∑j​ℓj​. Evaluate the whole output list spine, taking each input element as an already available value. The defining equation (x:xs) ++ ys = x : (xs ++ ys) shows that list concatenation traverses its left operand, sharing its right operand.
The right fold puts each original inner list on the left of exactly one concatenation. Thus its total element traversal is proportional to N, and visiting the outer list costs k:
Tright​=Θ(k+N).​
(9)
The k term matters when many inner lists are empty. With k rows each of length r, the bound is Θ(k+kr). In particular, with uniformly bounded positive row length it is linear in k.

Write Sj​=ℓ1​+⋯+ℓj​, with S0​=0. At the jth step of the left fold, the left operand of list concatenation is the accumulated prefix of length Sj−1​. Fully forcing these concatenations repeatedly copies earlier elements. Including the traversal of the outer list and the whole output spine gives
Tleft​=Θ(k+N+j=1∑k−1​Sj​)=Θ(k+N+t=1∑k−1​(k−t)ℓt​).​
(10)
For singleton inner lists, this becomes Θ(1+2+⋯+(k−1))=Θ(k2), whereas the right fold takes Θ(k). More generally, for equal positive length r, the left fold takes Θ(rk2+k).
An O(kN+k) bound is tight in the worst case over length distributions, but is not a tight formula for every distribution: if all N elements occur only in the final inner list, all earlier accumulators are empty and the cost is Θ(k+N). Lazy evaluation changes when the work happens; it does not remove repeated prefix traversal when the whole result is demanded.

A word can be a string, and the input text a list of those strings. Use names that avoid clashing with the Standard Prelude machine-word type Word:
type TextWord = String
type Text = [TextWord]
Thus TextWord=String,Text=[TextWord]​. These are type synonyms, so ordinary string and list operations remain available without wrapping or unwrapping constructors. They describe input that has already been tokenized; punctuation and word boundaries do not need a separate treatment here.

Normalize each word once by applying toLower to its characters. Maintain an association list whose keys are distinct normalized words and whose values are their frequencies:
import Data.Char (toLower)

type TextWord = String
type Text = [TextWord]
type Frequency = Integer
type Entry = (TextWord, Frequency)

count :: Text -> [Entry]
count = foldl addWord [] . map (map toLower)
  where
    -- Increment the unique matching key, or append a new key with count one.
    addWord :: [Entry] -> TextWord -> [Entry]
    addWord [] w = [(w, 1)]
    addWord ((v, n):rest) w
      | w == v    = (v, n + 1) : rest
      | otherwise = (v, n) : addWord rest w
After any input prefix, each normalized word seen so far occurs exactly once as a key, with its number of occurrences as value. This loop invariant holds initially for the empty association list. A step either increments the unique existing entry or introduces exactly one new entry, so mathematical induction proves
lookup w (count input)=Just(number of normalized occurrences of w)​
(11)
for every word that occurs. In particular, Baa and baa contribute to the same key baa; the three frequency-two keys in the source example are baa, yes and sir.
The association list preserves first-occurrence order, although the specification allows any order here. For t input words and d distinct normalized words, it performs O(td) key comparisons in the worst case. Character normalization costs the total input character count, and a string comparison can inspect multiple characters. Characterwise toLower supplies the intended case-insensitive comparison convention for the example; full Unicode case folding can require a different normalization policy.

Compare frequencies in decreasing order and use lexicographic order on words to break ties. Implement merge sort explicitly, so no imported sorting routine is needed:
-- Entry, TextWord and Frequency are as in part (b).
before :: Entry -> Entry -> Bool
before (w, p) (v, q) = p > q || (p == q && w <= v)

sort :: [Entry] -> [Entry]
sort []  = []
sort [x] = [x]
sort xs  = merge (sort left) (sort right)
  where
    (left, right) = splitAt (length xs `div` 2) xs

merge :: [Entry] -> [Entry] -> [Entry]
merge [] ys = ys
merge xs [] = xs
merge xa@(x:xs) ya@(y:ys)
  | before x y = x : merge xs ya
  | otherwise  = y : merge xa ys
The merge algorithm step always emits the smaller key under the ordering (−frequency,word). The unchosen heads cannot precede that emitted entry because each input is already sorted. It preserves all entries, and each call removes one head, so it terminates with exactly the sorted union of the inputs. Mathematical induction over the recursive splits establishes correctness of merge sort.
For n entries, splitting and merging cost Θ(n) per level, and there are Θ(logn) levels:
T(n)=T(⌊n/2⌋)+T(⌈n/2⌉)+Θ(n)=Θ(nlogn)(n≥2).​
(12)
The base cases take constant time. This counts word comparisons as primitive operations, as in the question. If the maximum compared word length is L, the character-operation bound becomes O(Lnlogn), in addition to frequency comparison costs.
For the supplied input, sort . count yields
[("baa",2),("sir",2),("yes",2),("any",1),("bags",1),("black",1),
 ("full",1),("have",1),("sheep",1),("three",1),("wool",1),("you",1)]
In particular, the secondary ordering places sir before yes, even though yes appears earlier in the original text. The Θ(nlogn) requirement concerns sort; the simpler association list implementation of count has its own cost.

An empty constructor and a constructor containing a label and two subtrees give a polymorphic algebraic data type:
data STree a = Empty | Node (STree a) a (STree a)
  deriving (Eq, Show)
The binary search tree invariant is every left label<x<every right label​ at each Node left x right, together with the same invariant recursively in both subtrees. Labels are distinct because the representation is of a set. The declaration itself needs no ordering constraint; operations that compare labels require Ord a in their type signatures.

Follow the unique branch in which the new key could belong. At an equal key, keep the existing node so that duplicate insertion does not change the represented set:
insert :: Ord a => a -> STree a -> STree a
insert y Empty = Node Empty y Empty
insert y (Node left x right) =
  case compare y x of
    LT -> Node (insert y left) x right
    EQ -> Node left x right
    GT -> Node left x (insert y right)
The Haskell Ord class supplies the three-way comparison. Each visited nonempty node costs one such comparison; rebuilding a node preserves all untouched subtrees. The inserted key satisfies every comparison along its search path, so it obeys both the local and ancestor binary search tree inequalities.
For height of a binary tree h, the worst search costs Θ(h) comparisons​ when it reaches the bottom. With n existing nodes, a chain can require n comparisons, giving a worst case of Θ(n). Under the standard random-insertion model, distinct keys arrive in a uniformly random order and the expected path length is Θ(log(n+1)). Thus the usual average-case answer is Θ(logn)​ for growing n, but this expectation needs the stated distribution: an arbitrary unbalanced binary search tree has no logarithmic guarantee.

A tree fold replaces Empty by a seed and Node by a combining function. The combining function receives the already folded left subtree, the node's label and the already folded right subtree:
foldSTree :: (b -> a -> b -> b) -> b -> STree a -> b
foldSTree combine empty Empty = empty
foldSTree combine empty (Node left x right) =
  combine (foldSTree combine empty left)
          x
          (foldSTree combine empty right)
Its polymorphic type signature is
(β→α→β→β)→β→STree α→β.​
(13)
The result type need not be the label type: it may be a list, a number or another structure. No ordering constraint is needed because this tree fold follows constructors without comparing labels.

Use the empty list for an empty subtree, and join the left result, the current label and the right result:
flatten :: STree a -> [a]
flatten = foldSTree (\left x right -> left ++ (x : right)) []
Thus flatten(Node l x r)=flatten(l)++[x]++flatten(r)​. This is an inorder traversal. By structural induction, each subtree produces its labels in order; the binary search tree invariant places every left label below x and every right label above x, proving that the whole result is increasing. The definition works for any binary-tree shape, although its result is sorted only when the ordering invariant holds. Repeated list concatenation can give quadratic cost on a left chain; the question asks for a tree fold definition, rather than an optimal traversal implementation.

g OurBigBook.com
Search as for insertion. Removing a node with at most one nonempty child leaves that child in its place. With two children, use the smallest key in the right subtree as the replacement and remove that occurrence from the right subtree:
delete :: Ord a => a -> STree a -> STree a
delete _ Empty = Empty
delete y (Node left x right) =
  case compare y x of
    LT -> Node (delete y left) x right
    GT -> Node left x (delete y right)
    EQ -> join left right
  where
    -- Join two search trees with every left key below every right key.
    join :: STree a -> STree a -> STree a
    join Empty r = r
    join l Empty = l
    join l r = let (smallest, rest) = takeMin r
               in Node l smallest rest

-- Precondition: the input tree is nonempty.
takeMin :: STree a -> (a, STree a)
takeMin Empty = error "takeMin: empty tree"
takeMin (Node Empty x right) = (x, right)
takeMin (Node left x right) =
  let (smallest, rest) = takeMin left
  in (smallest, Node rest x right)
The call to takeMin occurs only after both empty cases have been excluded. Its structural recursion follows left children until it reaches the minimum label and rebuilds the path with that occurrence removed.
For a matching label x and successor s, all left labels are below x<s, while every label remaining on the right is strictly above s. Thus replacing x by s preserves the binary search tree invariant. Every other branch preserves the invariant by structural induction. The resulting set is exactly
keys(delete y t)=keys(t)∖{y}.​
(14)
Whether the key is absent or present, untouched subtrees can be shared. The search path followed by the successor path uses O(h) time and fresh nodes for original height of a binary tree h, so the worst case is O(n) without balancing. This is persistent binary search tree deletion: the original value remains available.

A length-zero graph path starts and ends at the same vertex. Therefore P0​ is the Boolean identity matrix. A graph path of length at most one is either such a stationary graph path or one original directed edge:
P0​[i,j]=(i=j),P1​[i,j]=(i=j)∨E[i,j],P1​=I∨E.​
(15)
The logical disjunction is entrywise. Diagonal entries of E may be false if there are no self-loops, but every diagonal entry of P1​ is true because the zero-length graph path is allowed.

A graph path of length at most k+1 either already has length at most k, or consists of a prefix of length at most k followed by one edge. Therefore
Pk+1​[i,j]=Pk​[i,j]∨t=0⋁n−1​(Pk​[i,t]∧E[t,j]).​
(16)
The forward implication follows by removing the final edge of a nonempty graph path. Conversely, concatenating the indicated prefix and edge gives a walk of length at most k+1, and removing repetitions if necessary gives a graph path no longer than that walk.
Writing ⊙ for Boolean matrix multiplication, the formula is Pk+1​=Pk​∨(Pk​⊙E). Because P1​ includes the identity matrix, an equivalent formula is
Pk+1​=Pk​⊙P1​.​
(17)
Compute each new matrix from an unchanged copy of the preceding matrix, so the subscript continues to specify exactly the length bound.

Start with P1​=I∨E and repeatedly apply part (b), keeping a fresh output matrix. A simple implementation is
P := I OR E
repeat:
    Q := P OR boolean_product(P, E)
    if Q = P: return P
    P := Q
At the start of each iteration, P=Pk​ for the current length bound k. The update produces Pk+1​, proving the loop invariant by mathematical induction. If Q=P, every edge extension of a known graph path is already known. Repeating the same update then makes no further change, so every longer graph path is represented as well.
Every reachable pair of distinct vertices has a simple path of at most n−1 edges: a repeated vertex allows the intervening part to be deleted. Thus the process stabilizes after finitely many updates and returns
R[i,j]=true precisely when j is reachable from i, including i=j.​
(18)
This is the reflexive transitive closure. An alternative stopping rule is to stop once the length bound is at least n−1, avoiding a final equality-detection iteration. For n=0 or 1, P1​ already suffices.

Interpret the source's m as the maximum finite shortest-path distance among reachable pairs, taking m=0 when only length-zero graph paths are needed. This is the length bound required for reflexive transitive closure. A directed graph cycle permits arbitrarily long walks, so the maximum length of all possible walks would not be a finite termination parameter.[ref]
For the elementary dense implementation, each Boolean matrix multiplication evaluates all n3 triples (i,t,j), with no early exit. Each equality test costs O(n2). Starting from P1​, the algorithm reaches Pm​ after m−1 updates when m≥1, then performs one further update to detect stability. Consequently, for n≥2,
Textend​=Θ(n3max{1,m}),auxiliary space=Θ(n2).​
(19)
For the usual nontrivial case m≥1, this is Θ(mn3). Since m≤n−1, the overall worst case is Θ(n4). This bound is tight for this implementation: the directed chain 0→1→⋯→n−1 has m=n−1 and gains previously unknown pairs at every length until then, while every update scans all triples. This tightness does not claim an inherent lower bound for the reflexive transitive closure problem; it concerns the specified repeated-extension algorithm.

Split a graph path of length at most 2k into two consecutive parts of length at most k, allowing a zero-length part. Conversely, concatenating two such parts gives a walk of length at most 2k and hence the same reachability. Therefore
P2k​=Pk​⊙Pk​.​
(20)
Start at P1​=I∨E, then square to obtain P2​,P4​,P8​,…. Stop at equality of successive matrices, or after the length bound reaches n−1. The invariant is now P=P2r​ after r squarings. Equality implies closure under composition, and the included identity matrix ensures reflexivity.
For the same elementary dense Boolean matrix multiplication and equality stopping test, the cost is
Tsquare​=Θ(n3(1+log(m+1))),space=Θ(n2).​
(21)
The additive constant covers the final stability check and the cases m=0,1. Thus, with m≥2, the number of cubic passes falls from Θ(m) to Θ(logm). In terms of n alone the worst-case bound improves from Θ(n4) to Θ(n3logn) for these implementations. A directed chain also requires logarithmically many squarings. This comparison uses ordinary triple-loop multiplication, rather than a faster matrix multiplication method.

Divide-and-conquer algorithms split a problem into smaller instances of the same kind, solve them recursively, and combine the solutions. A base case handles instances too small to split. For merge sort, divide the input into two halves, recursively sort both halves, and merge them by repeatedly taking the smaller current head. Empty and singleton inputs are already sorted.
The merge algorithm step preserves sortedness because its chosen head is no larger than either remaining head; it also preserves every input occurrence. These facts and mathematical induction on input length prove correctness. Splitting and merging take Θ(n) time, so
T(n)=T(⌊n/2⌋)+T(⌈n/2⌉)+Θ(n)=Θ(nlogn).​
(22)
At each level the subproblem sizes sum to n, and there are Θ(logn) levels. Part 3(c) supplies an explicit Haskell implementation of this construction with a more specialized comparison rule. Standard array implementations use O(n) auxiliary storage.

Restrict attention to distinct keys; any comparison sort must handle these inputs. A deterministic comparison sort can be represented by a binary decision tree: an internal node records a comparison and its two possible outcomes, and a leaf records the final ordering of the input positions.
There are n! possible relative orders. Two different orders cannot finish at the same leaf, since the algorithm would then output the same ordering of positions for both, making at least one result incorrect. A binary decision tree of height h has at most 2h leaves. Hence
2h≥n!,h≥⌈log2​(n!)⌉.
(23)
Using the given bound, or just the last ⌊n/2⌋ factors of n!, gives
h∈Ω(nlogn).​
(24)
This is a worst-case comparison sorting lower bound, and merge sort achieves the same order. The result concerns comparison sorting; a procedure that uses numerical digits or bounded integer values has a different computational model.

Store the array as a binary heap with min-heap order. Build it bottom-up by sifting down internal nodes in reverse order, rather than inserting all n values one at a time. The sum of subtree heights is O(n), so construction costs Θ(n). Then perform i minimum extractions: output the root, move the last remaining entry to the root, and sift it down to restore the heap order.
Each extraction returns the smallest remaining key, so the outputs are the i smallest keys in increasing order. For a heap of current size s, an extraction takes O(log(s+1)) time. Hence
T2​(n,i)=O(n+∑j=0i−1​log(n−j+1))=O(n+ilogn).
(26)
The tight worst-case bound for this ordinary binary heap implementation is
T2​(n,i)=Θ(n+ilogn).​
(27)
When the extraction term is substantial, worst-case extractions follow root-to-leaf paths of logarithmic length; when i is small, the linear construction already dominates. The bound stays valid at i=n, since log(n!)=Θ(nlogn). Building by n separate insertions would lose the linear construction bound and is unnecessary.

Use deterministic median of medians to select the element of rank i in worst-case Θ(n) time. Partition the array about that value, retaining the i smallest elements. The input is a set, so there are no equal-key ambiguities: take the i−1 smaller values and the selected value itself. Sort these i elements with merge sort, then output them.
For completeness, median of medians groups values in fives, finds each small group's median, recursively selects a median of those medians as a pivot, and recurses only into the partition containing the requested rank. At least 3n/10−O(1) entries lie on each side of the pivot. Its worst-case recurrence is
S(n)≤S(⌈n/5⌉)+S(7n/10+O(1))+O(n)=O(n).
(28)

T3​(n,i)=Θ(n+ilog(i+1)).​
(29)
Scanning the input is necessary even to identify its minimum. Ordering the selected i distinct values also has the comparison sorting lower bound Ω(ilogi), so this is asymptotically optimal for the task. A usual randomized Quickselect gives linear expected selection time, but its quadratic worst case would not establish the requested worst-case guarantee.

Dynamic programming specifies a collection of overlapping subproblems, expresses each answer using smaller subproblem answers, and stores answers so each subproblem is solved once. One may fill a table in dependency order or use memoization to compute only requested entries. The key design choice is a state that retains every feature needed by later decisions.
The principle of optimality says that, after a decision in an optimal solution, the remaining decisions must solve the corresponding residual subproblem optimally. Otherwise, replacing that residual solution by a better one would improve the entire solution. This replacement argument requires the state to describe the residual constraints completely. Its useful form here is
optimal value of a state=feasible first decisionsmax​{immediate value+optimal residual value}.​
(30)
The maximization applies to these value-maximization problems; minimization uses the analogous minimum recurrence.

In the 0-1 knapsack problem, item j has weight wj​ and value vj​. Choose a subset of the n items, using each at most once, whose total weight is at most W and whose total value is as large as possible. For the capacity-indexed dynamic program, take W and the weights to be nonnegative integers. The empty choice is allowed.
Let K[j,c] be the greatest value attainable using only items 1,…,j with capacity c. The base case is K[0,c]=0. With item j unavailable when it is too heavy, the recurrence is
K[j,c]={K[j−1,c],max{K[j−1,c], vj​+K[j−1,c−wj​]},​wj​>c,wj​≤c.​​
(31)
Every feasible optimum either excludes item j, giving the first candidate, or includes it exactly once, leaving capacity c−wj​ for earlier items. The principle of optimality proves that the remaining earlier items must attain the indicated residual optimum. Conversely, either candidate constructs a feasible solution, so taking the larger is both necessary and sufficient. Mathematical induction on j proves the table's meaning and the final answer K[n,W]​.
Store item weights and values in arrays and the values in a two-dimensional array with (n+1)(W+1) entries. Fill rows in increasing j; each entry uses at most two values from the previous row. There are n(W+1) constant-work updates, giving
time=Θ(n(W+1)),table space=Θ((n+1)(W+1)).​
(32)
For positive growing capacities this is the familiar Θ(nW) bound. The +1 terms also cover capacity zero and zero-weight items: one must not initialize every K[j,0] to zero if zero-weight, positive-value items are allowed.
To recover an actual subset, store the chosen alternative at each entry or compare the two candidates while tracing backward from (n,W). A selected item changes (j,c) to (j−1,c−wj​); an excluded item changes it to (j−1,c). This takes O(n) extra time.
If only the optimal value is needed, keep two rows, using Θ(W+1) space. With strictly positive weights, a single capacity row updated in decreasing capacity also prevents item reuse. The two-row version handles zero weights without special in-place reasoning. The running time is pseudopolynomial, since the binary input length of W is only logarithmic in its numerical value.

For the two-bag 0-1 knapsack problem, let D[j,a,b] be the maximum total value using the first j items, with remaining capacity limits a in the first bag and b in the second. Initialize D[0,a,b]=0. Item j has exactly three possible decisions: omit it, place it in bag one if it fits, or place it in bag two if it fits. Hence
D[j,a,b]=max({D[j−1,a,b]}∪{vj​+D[j−1,a−wj​,b]:wj​≤a}∪{vj​+D[j−1,a,b−wj​]:wj​≤b}).​
(33)
A braced candidate with a false condition is omitted. All candidates refer to layer j−1, which prevents the same item from entering both bags. Combining two independently optimized single-bag knapsacks would not enforce that restriction.
The principle of optimality proves correctness exactly as in part (b): condition on the location of the final item and replace the earlier items by the optimal feasible residual assignment. Every candidate is realizable, and every feasible assignment belongs to one of the three cases. The final answer is D[n,W1​,W2​]​.
Fill the three-dimensional array in increasing item index. Each of its n(W1​+1)(W2​+1) updates inspects at most three candidates:
time=Θ(n(W1​+1)(W2​+1)),full space=Θ((n+1)(W1​+1)(W2​+1)).​
(34)
For positive capacities the customary expression is Θ(nW1​W2​). Keeping only two item layers reduces space to Θ((W1​+1)(W2​+1)) for the optimal value. Full decision storage also permits backward reconstruction of each item's bag assignment. Nonnegative integer weights and capacities are the assumptions behind this capacity-indexed dynamic programming table.

Use Kahn's algorithm for topological sorting. With an adjacency list representation, count every vertex's indegree by scanning the edges. Put all zero-indegree vertices in a queue. Repeatedly remove one such vertex u, append it to the output, and delete its outgoing edges by decrementing the stored indegree of each neighbour; enqueue a neighbour exactly when its count becomes zero.
The loop invariant is that stored counts are the indegrees in the unreported subgraph and the queue contains exactly its unreported zero-indegree vertices. A nonempty finite Directed acyclic graph always has such a vertex: otherwise following incoming edges would eventually repeat a vertex, creating a directed graph cycle. Thus the queue cannot become empty while any vertex remains.
For every original edge u→v, v cannot enter the output until that edge has been removed by outputting u. Therefore
u→v⟹position(u)<position(v).​
(35)
Each vertex enters and leaves the queue once, and every edge is scanned a constant number of times, giving Θ(∣V∣+∣E∣)​ time and O(∣V∣) auxiliary space beyond the adjacency lists. If given only an adjacency matrix, scanning neighbours instead takes Θ(∣V∣2) time.

Take two directed triangles meeting only at a central vertex a. Make a→b→c→a entirely black and a→d→e→a entirely white. All five vertices lie in one strongly connected component, since every vertex can reach a and can be reached from a. It contains internal edges of both colours.
A closed walk can traverse the black triangle and then the white triangle. But a simple cycle using edges from both triangles would have to pass through a to change triangles and pass through a again to return. It would repeat a other than the single start/end identification, contradicting simplicity. Removing a separates the two triangles, so no other transition between them is possible. Therefore
one SCC can have both edge colours while every simple cycle is monochromatic.​

Use the two-pass strongly connected component algorithm. First run a complete depth-first search of G, starting a new search at each unvisited vertex as necessary. Append each vertex to a list when its recursive call finishes. Next construct the graph transpose GT by reversing every edge. Reset all visited flags. Process the vertices in decreasing first-pass finishing order, running depth-first search in GT from each still-unvisited vertex. The newly reached vertices in each such search form one strongly connected component.
To prove this, contract each strongly connected component to one vertex. The resulting condensation graph is a Directed acyclic graph, because a directed graph cycle of distinct components would make them mutually reachable and hence a single component. For a component C, write F(C) for its largest first-pass finishing time. If there is an edge C→D between distinct components, then F(C)>F(D). Indeed, if the first search reaches C before D, it can reach D, which must finish before the search in C finishes. If it reaches D first, D cannot reach C or they would be the same component, so D finishes before C is discovered.
Among unreported components, the one with greatest F therefore has no incoming edge from another unreported component in G. In the graph transpose it has no outgoing edge to any other unreported component. A second-pass search cannot escape it, while strong connectivity lets that search reach all its vertices. Earlier reported components are ignored by the visited flags. Repeating this argument proves
each second-pass search returns exactly one SCC, and all SCCs are returned.​
(40)
Both depth-first searches visit every vertex and scan every edge once, and transposition costs Θ(∣V∣+∣E∣). Therefore the total time complexity is Θ(∣V∣+∣E∣)​ with adjacency lists. Storage for the transpose is O(∣V∣+∣E∣), while visited flags, finishing order and the search stack use O(∣V∣) additional space. No sorting is needed: reverse the list recorded at finishing time.
