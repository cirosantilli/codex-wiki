Use two array indices, advancing only the smaller current entry. Here and in Questions 1–4, code is structured Oberon-style pseudocode: RETURN exits a procedure, Some(x) and None distinguish success and absence, and AND short-circuits from left to right. Arithmetic is exact where the source asks us to ignore integer overflow.
PROCEDURE common(a, N, b, M): INTEGER;
VAR i, j: INTEGER;
BEGIN
  i := 0; j := 0;
  WHILE a[i] # b[j] DO
    IF a[i] < b[j] THEN i := i + 1
    ELSE j := j + 1
    END
  END;
  RETURN a[i]
END common;
Let z be the smallest common value, and let a[p]=b[q]=z. Existence implies N,M>0. A useful loop invariant is 0≤i≤p<N, 0≤j≤q<M, with no common value among the discarded prefixes a[0..i) and b[0..j). Initially the prefixes are empty. If a[i]<b[j], then a[i] cannot equal any entry of b[j..M) because that sorted array is increasing; it cannot be a common value in the discarded prefix either. Moreover i=p would imply z=a[i]<b[j]≤z, a contradiction. Thus i<p and incrementing i is safe. The other branch is symmetric.
Every guard and return therefore uses valid array indices, even without explicit bounds tests. The loop variant (p−i)+(q−j) decreases on each iteration. At exit the equal entries form a common value no larger than z, hence equal z. There are at most N+M−2 increments and constant work per increment. The procedure returns the smallest common value in O(N+M) time and O(1) auxiliary space.

Replace the existence-dependent bounds proof with explicit bounds tests. Neither input array is changed or copied.
PROCEDURE commonOrNone(a, N, b, M);
VAR i, j: INTEGER;
BEGIN
  i := 0; j := 0;
  WHILE (i < N) AND (j < M) DO
    IF a[i] = b[j] THEN RETURN Some(a[i])
    ELSIF a[i] < b[j] THEN i := i + 1
    ELSE j := j + 1
    END
  END;
  RETURN None
END commonOrNone;
The loop invariant is 0≤i≤N, 0≤j≤M, and every common value of the original arrays lies in both remaining suffixes a[i..N) and b[j..M). Equivalently neither discarded prefix contains a common value. Advancing the smaller current value preserves this for the same ordering reason as in part (a).
Both array bounds are checked before any element is read. If the remaining heads are equal, all later entries are larger, so the returned value is the smallest. If either suffix becomes empty, the loop invariant proves there is no common value. The loop variant (N−i)+(M−j) decreases on each unsuccessful comparison. The result is Some(smallest common value) or None, with O(N+M) time and O(1) auxiliary space, including empty-input cases. A language without short-circuit operators can use nested tests; the guard here itself contains no array reads.

The cyclic strict comparisons in the hint identify a head that cannot be the answer:
PROCEDURE common3(a, N, b, M, c, L): INTEGER;
VAR i, j, k: INTEGER;
BEGIN
  i := 0; j := 0; k := 0;
  WHILE (a[i] # b[j]) OR (b[j] # c[k]) DO
    IF a[i] < b[j] THEN i := i + 1
    ELSIF b[j] < c[k] THEN j := j + 1
    ELSE k := k + 1
    END
  END;
  RETURN a[i]
END common3;
Let z=a[p]=b[q]=c[r] be the smallest common value. The loop invariant is 0≤i≤p<N, 0≤j≤q<M, 0≤k≤r<L, and every discarded entry is not common to all three arrays. If a[i]<b[j], the entry a[i] cannot occur in the unprocessed part of b, so discard it. The branch b[j]<c[k] has the analogous justification. If neither comparison holds but the heads are not all equal, the hint guarantees c[k]<a[i], so discard c[k].
A pointer at its target position cannot be advanced: for example i=p and a[i]<b[j] would imply z<b[j]≤z. Thus all reads stay within array bounds. The loop variant (p−i)+(q−j)+(r−k) decreases. At exit all heads equal z. The cost is O(N+M+L) time and O(1) auxiliary space.

Maintain one array index per input and a candidate value. Cycle through the arrays, counting consecutive agreements with that candidate; when a larger head is encountered, start counting agreements again. p is an auxiliary array of m indices, not a copy of any input.
PROCEDURE commonMany(as, n, m);
VAR p: ARRAY m OF INTEGER;
    j, candidate, agree, x: INTEGER;
BEGIN
  FOR j := 0 TO m-1 DO
    p[j] := 0;
    IF n[j] = 0 THEN RETURN None END
  END;
  candidate := as[0][0];
  j := 0; agree := 0;
  WHILE agree < m DO
    IF p[j] = n[j] THEN RETURN None END;
    x := as[j][p[j]];
    IF x < candidate THEN
      p[j] := p[j] + 1
    ELSIF x = candidate THEN
      agree := agree + 1;
      j := (j + 1) MOD m
    ELSE
      candidate := x;
      agree := 1;
      j := (j + 1) MOD m
    END
  END;
  RETURN Some(candidate)
END commonMany;
The loop invariant has three parts. All indices satisfy 0≤p[t]≤n[t]; no discarded entry is common to every input; and every original common value is at least candidate. Additionally, the agree cyclically consecutive arrays immediately preceding index j have heads equal to candidate. These facts are true initially, with an empty agreement run.
A head below candidate is not globally common, by the lower-bound clause, so advancing its pointer is safe. A head above candidate gives a new lower bound: every globally common value lies in this array's unprocessed suffix and so is at least its head. Only this array is yet certified to agree with the new candidate. An equal head extends the run by one. An exhausted suffix proves absence; a run of m agreements covers every array exactly once and proves that candidate is common, and the lower-bound clause proves minimality. The exhaustion test precedes each dereference, including after the last entry of a suffix is discarded.
For algorithm termination and time complexity, charge comparisons to the pair (j,p[j]). A fixed entry is discarded at most once, can raise the candidate at most once, and can be counted as an agreement at most once: before the same array is revisited, either the algorithm has finished or the candidate has strictly increased. Thus there are at most three comparisons per input entry, besides the O(m) initialization. The result is the smallest common value or None in O(m+∑t​n[t]) time and O(m) auxiliary space. For m=1, the first head immediately gives the answer.

Evaluate the supplied function once at each positive integer, retaining its largest value so far. In particular do not initialize the maximum to zero: f might be negative everywhere.
PROCEDURE record(f, emit);
VAR n, best, y: INTEGER;
BEGIN
  best := f(1);
  emit(1);
  n := 2;
  WHILE TRUE DO
    y := f(n);
    IF y > best THEN
      emit(n);
      best := y
    END;
    n := n + 1
  END
END record;
At the loop head the loop invariant is n≥2, best =max{f(i):1≤i<n}, and precisely the record values with argument less than n have been emitted, in increasing argument order. The first argument is a record because its comparison set is empty. The strict test correctly excludes ties. Updating best only on a strict increase preserves the loop invariant.
Exactly one call of f is made per processed argument. For an arbitrary supplied function, an unexamined argument can have a value larger than all previous values, so skipping its evaluation cannot be correct in general. This assumes f is a total, deterministic function; the requested infinite computation ignores integer overflow.

Test each possible positive divisor directly:
PROCEDURE divisors(n: INTEGER): INTEGER;
VAR i, count: INTEGER;
BEGIN
  i := 1; count := 0;
  WHILE i <= n DO
    IF n MOD i = 0 THEN count := count + 1 END;
    i := i + 1
  END;
  RETURN count
END divisors;
For n≥1, the loop invariant is 1≤i≤n+1 and count =∣{d:1≤d<i, d∣n}∣. Testing i adds exactly the next possible divisor. The loop variant n+1−i decreases, and the divisor in MOD is always positive. At exit the interval 1≤d≤n contains every positive divisor. This computes the divisor function τ(n) using n remainder operations, Θ(n) time, and O(1) auxiliary space.

Use trial division on a shrinking residual. Once the trial divisor exceeds its square root, any residual larger than one is itself prime.
PROCEDURE divisors(n: INTEGER): INTEGER;
VAR residual, trial, exponent, answer: INTEGER;
BEGIN
  residual := n; trial := 2; answer := 1;
  WHILE trial * trial <= residual DO
    exponent := 0;
    WHILE residual MOD trial = 0 DO
      residual := residual DIV trial;
      exponent := exponent + 1
    END;
    answer := answer * (exponent + 1);
    trial := trial + 1
  END;
  IF residual > 1 THEN answer := 2 * answer END;
  RETURN answer
END divisors;
For the outer loop invariant, let P be the set of primes below trial and ep​ their exponents in the original n. Then
n=residual∏p∈P​pep​,answer=∏p∈P​(ep​+1),
(3)
and residual has no prime factor below trial. If trial divides the residual it must therefore be prime: a composite trial value would have a smaller prime factor, contradicting this clause. If it does not divide, the zero exponent contributes the factor 1.
For the inner loop invariant, let r0​ be the residual on entry. Then r0​=trialexponentresidual. Each exact division reduces the positive residual by at least a factor of two, so this loop terminates. At exit the exponent is the full multiplicity of trial; multiplying by exponent+1 preserves the outer loop invariant. The outer loop terminates because trial increases and residual never increases. When it exits, a composite residual would have a prime factor at most its square root, yet every smaller trial factor has already been excluded. Hence the residual is 1 or a single remaining prime of exponent 1.
The procedure computes τ(n) in O(n​) unit-cost time and O(1) auxiliary space, with the separate successful divisions bounded by ⌊log2​n⌋. No array or table of primes is needed, and n=1 correctly returns 1.

The second procedure should reach large outputs faster, because the first makes exactly n expensive MOD operations when processing argument n, whereas the second tries only up to the square root of a shrinking residual, with at most ⌊log2​n⌋ successful DIV operations. Each successful division also requires a successful MOD test; each outer iteration adds one final unsuccessful MOD test. Thus its expensive-operation count is O(n​+logn) per argument, and at most O(n3/2) cumulatively through argument n, compared with Θ(n2) for direct counting.
The speedup is not an assertion that every single call uses fewer divisions: for n=4, the second code makes three MOD tests and two DIV operations, while the first makes four MOD tests. Small constant costs can go either way. The many small prime factors in highly composite numbers also shrink the residual early, which often helps further; the cumulative comparison includes every preceding argument, not only the printed records.

Print a prefix while following the linked list, counting how many closing parentheses remain. The final reciprocal can be printed without parentheses.
PROCEDURE printCF(f: fraction);
VAR p: fraction; opened: INTEGER;
BEGIN
  p := f; opened := 0;
  Out.Int(p.head, 0);
  p := p.tail;
  WHILE p # NIL DO
    IF p.tail = NIL THEN
      Out.String("+1/"); Out.Int(p.head, 0)
    ELSE
      Out.String("+1/("); Out.Int(p.head, 0);
      opened := opened + 1
    END;
    p := p.tail
  END;
  WHILE opened > 0 DO
    Out.String(")"); opened := opened - 1
  END
END printCF;
The first loop invariant says that p is the next unprinted linked list node, the printed text is the correct expression prefix, and opened counts its unmatched opening parentheses. The final node contributes no opening parenthesis; the second loop invariant says that precisely opened closing parentheses remain. Thus [1,2,3,4,5] produces 1+1/(2+1/(3+1/(4+1/5))). A singleton prints just its head. If the first head is negative, its leading minus remains a valid prefix; subsequent heads are positive.
The precondition is a finite nonempty continued fraction list. Every dereference is made only for a nonnull pointer. The procedure uses O(1) auxiliary space and time linear in the number of nodes, apart from printing their digits. The source's claimed strict upper bound x0​+1 has an exception under its stated definition: [x0,1] represents x0​+1. None of these algorithms relies on that incorrect strict bound.

Use the Euclidean algorithm with floor quotient and nonnegative remainder, including for a negative numerator:
PROCEDURE rat2cf(n, d: INTEGER): fraction;
VAR q, r: INTEGER; p: fraction;
BEGIN
  q := n DIV d; r := n MOD d;
  NEW(p); p.head := q; p.tail := NIL;
  IF r # 0 THEN p.tail := rat2cf(d, r) END;
  RETURN p
END rat2cf;
For d>0, Euclidean division gives n=qd+r with 0≤r<d. If r=0, the singleton [q] is exact. Otherwise
dn​=q+dr​=q+d/r1​,
(4)
so the recursive tail represents d/r. Its numerator is positive and greater than its denominator, so every tail head is a positive integer. The new denominator r is strictly smaller than d, proving algorithm termination by descent through the positive integers.
The returned list represents exactly n/d. For example −7/3=−3+1/(1+1/2) gives [-3,1,2]; truncating negative division toward zero would violate the required positivity of the tail. There are O(logd) Euclidean algorithm steps, with output allocation and recursive stack depth linear in the number of generated nodes.

Append each quotient directly to the output linked list, retaining a pointer to its last node. The nodes are required output; auxiliary variables remain simple integers and pointers.
PROCEDURE rat2cf(n, d: INTEGER): fraction;
VAR first, last, p: fraction; q, r: INTEGER;
BEGIN
  first := NIL; last := NIL;
  REPEAT
    q := n DIV d; r := n MOD d;
    NEW(p); p.head := q; p.tail := NIL;
    IF first = NIL THEN first := p
    ELSE last.tail := p
    END;
    last := p;
    n := d; d := r
  UNTIL d = 0;
  RETURN first
END rat2cf;
At the start of each iteration, d is positive, and the output prefix consists exactly of the quotients already obtained by the Euclidean algorithm. last points to its final node, or both first and last are null when the prefix is empty. The current ratio n/d is the unexpanded tail of the original continued fraction. The quotient/remainder step extends that prefix by the same value as the recursive version, then replaces the unexpanded ratio by its reciprocal residual tail. If the remainder is zero, no tail remains and the loop stops before another division.
The loop variant is the positive current denominator, which strictly decreases after each nonfinal iteration. The input denominator is positive, so at least one node is allocated, including for zero or an integral ratio. This is the same exact conversion with O(1) auxiliary space, excluding the returned list, and no input mutation.

Convert the tail first and apply the reciprocal identity. Two output parameters hold the rational number's numerator and denominator.
PROCEDURE cf2rat(f: fraction; VAR n, d: INTEGER);
VAR u, v: INTEGER;
BEGIN
  IF f.tail = NIL THEN
    n := f.head; d := 1
  ELSE
    cf2rat(f.tail, u, v);
    n := f.head * u + v;
    d := u
  END
END cf2rat;
The singleton case is immediate. If the recursive call returns the tail as u/v, then u,v>0 because every tail head is positive. The full value is
f.head+u/v1​=uf.headu+v​.
(5)
Structural induction on the finite nonempty linked list proves correctness, and the denominator is always positive even if the first head is negative. If the tail pair is coprime, then gcd(xu+v,u)=gcd(v,u)=1; the base pair (x,1) is coprime, so the result is in lowest terms. Return (head*u+v,u) after converting the tail, using linear node-processing time and linear recursive stack space.

Accumulate the product of the 2×2 matrices from left to right, which matches forward linked list traversal.
PROCEDURE cf2rat(f: fraction; VAR n, d: INTEGER);
VAR p: fraction; a, b, c, e, x: INTEGER;
BEGIN
  a := 1; b := 0; c := 0; e := 1;
  p := f;
  WHILE p # NIL DO
    x := p.head;
    a, b, c, e := a*x+b, a, c*x+e, c;
    p := p.tail
  END;
  n := a; d := c
END cf2rat;
The four-value assignment is simultaneous, as permitted by the source. With M(x)=(x1​10​), the loop invariant after reading the prefix x0​,…,xt−1​ is
(ac​be​)=M(x0​)⋯M(xt−1​),
(6)
with the empty product initialized to the identity matrix. Multiplication on the right by M(x) produces exactly the four assignments above. The associativity of matrix multiplication allows this left-to-right accumulation even though the recursive conversion groups operations from the right.
At completion, the first column is the numerator/denominator pair for the whole continued fraction: the last factor sends (1,0)T to (xn​,1)T, and each earlier factor applies the recurrence from part (d). The vector (1,0)T is an algebraic device, not a finite input ratio requiring division by zero. For a nonempty list the resulting c is positive; for a singleton it is 1. The product has determinant (−1)n+1, so its first-column entries are coprime. Return (a,c) in linear node-processing time and O(1) auxiliary space, without changing the list.

Assume every indicated segment lies within array bounds, and lengths are nonnegative. Use a temporary value of element type T:
PROCEDURE swap(i, j: INTEGER);
VAR x: T;
BEGIN
  x := m[i]; m[i] := m[j]; m[j] := x
END swap;

PROCEDURE blockswap(i, j, n: INTEGER);
VAR t: INTEGER;
BEGIN
  t := 0;
  WHILE t < n DO
    swap(i+t, j+t);
    t := t + 1
  END
END blockswap;
The first procedure even works for i=j. For the second, disjointness ensures that each swap exchanges the two original entries at offset t without disturbing any other pair. Its loop invariant says that offsets below t have been exchanged, offsets from t through n−1 retain their original values, and everything outside the two segments is unchanged. The loop variant n−t proves algorithm termination. A block exchange uses n swaps and O(1) auxiliary space. The stray wp printed after this source subpart is not an additional requirement.

Exchange symmetric pairs, stopping before the middle:
PROCEDURE reverse(i, n: INTEGER);
VAR t: INTEGER;
BEGIN
  t := 0;
  WHILE t < n DIV 2 DO
    swap(i+t, i+n-1-t);
    t := t + 1
  END
END reverse;
Writing m0​ for the pre-call array, the loop invariant says that the first and last t positions of the segment already satisfy m[i+s]=m0​[i+n−1−s], all positions between them retain their original values, and positions outside the segment are unchanged. Each swap fixes the next symmetric pair. The loop variant ⌊n/2⌋−t decreases; the two indices are distinct and in bounds whenever the body executes. Exactly ⌊n/2⌋ swaps reverse the segment, with the odd-length middle element left in place and no accesses for n≤1.

Write the segment as AB, where ∣A∣=n−k and ∣B∣=k. The desired array rotation is BA. Reverse each block, then the whole segment:
PROCEDURE rotate(i, n, k: INTEGER);
BEGIN
  IF (k = 0) OR (k = n) THEN RETURN END;
  reverse(i, n-k);
  reverse(i+n-k, k);
  reverse(i, n)
END rotate;
The state changes are AB→ARB→ARBR→BA, using the list reversal identity supplied in the paper and reversal being an involution. Three reversals implement the right rotation in O(n) time and O(1) auxiliary space. The initial return covers empty and identity rotations.

Let a=n−k and b=k be the lengths of the left and right blocks. Exchange the smaller block with the equally long block at the opposite end.
PROCEDURE rotate(i, n, k: INTEGER);
VAR a, b: INTEGER;
BEGIN
  IF (k = 0) OR (k = n) THEN RETURN END;
  a := n-k; b := k;
  IF a = b THEN
    blockswap(i, i+a, a)
  ELSIF a < b THEN
    blockswap(i, i+b, a);
    rotate(i, b, b-a)
  ELSE
    blockswap(i, i+a, b);
    rotate(i+b, a, b)
  END
END rotate;
If a<b, split B=B1​B2​ with ∣B2​∣=a. The first block swap sends AB1​B2​ to B2​B1​A; A is now in its final suffix. Rotate the remaining prefix of length b right by b−a to send B2​B1​ to B1​B2​. If a>b, split A=A1​A2​ with ∣A1​∣=b. The swap sends A1​A2​B to BA2​A1​; the fixed prefix is B, and rotating the remaining length-a suffix right by b restores A1​A2​. In both cases the exchanged segments are disjoint.
The remaining length strictly decreases, so induction on n proves algorithm termination and correctness. This implements the block-exchange rotation. It uses only simple explicit variables, but its recursive call stack can have Θ(n) depth when one block has length 1; the iterative version removes that extra storage.

PROCEDURE rotate(i, n, k: INTEGER);
VAR a, b: INTEGER;
BEGIN
  WHILE (k > 0) AND (k < n) DO
    a := n-k; b := k;

    ELSIF a < b THEN

The loop invariant is that every position outside the current unresolved segment already has its final value, while rotating the current segment by the current k completes the original array rotation. The block decompositions in part (ii) prove preservation. The positive unresolved length decreases in each continuing branch; the equal-block branch finishes immediately. The same rotation now uses O(1) auxiliary space, including control storage, and leaves the rest of the array untouched.

Save the last entry, shift the others right in descending index order, and put the saved value at the left. Descending order prevents overwriting an unread entry.
PROCEDURE rotate(i, n, k: INTEGER);
VAR x: T; step, t: INTEGER;
BEGIN
  IF (k = 0) OR (k = n) THEN RETURN END;
  step := 0;
  WHILE step < k DO
    x := m[i+n-1];
    t := n-1;
    WHILE t > 0 DO
      m[i+t] := m[i+t-1];
      t := t-1
    END;
    m[i] := x;
    step := step+1
  END
END rotate;
For one pass, after the shifts at offsets greater than t, those positions contain the original preceding entries; offsets through t are still available, and x retains the original last entry. The loop variant t decreases to zero. The outer loop invariant is that the segment has been rotated right by step places relative to its initial state. Repeating a one-step cyclic permutation k times therefore gives the required array rotation. The method uses one extra T variable and O(kn) time, with O(1) auxiliary space. The early return avoids all accesses for an identity rotation.

Count element reads and writes, ignoring simple-variable operations. A swap of distinct entries makes two reads and two writes, hence four expensive accesses. For 0<k<n, the three-reversal method therefore costs
4R,R=⌊2n−k​⌋+⌊2k​⌋+⌊2n​⌋.
(7)
Here R=n if n and k are both even, and R=n−1 otherwise.
For either block-exchange version, let a=n−k, b=k, and let S(a,b) count element swaps. The recurrence is S(a,a)=a and, when the lengths differ,
S(a,b)=min(a,b)+S(min(a,b),∣a−b∣).

S(a,b)=a+b−gcd(a,b)=n−gcd(n,k).
(9)
Thus both block-exchange methods cost 4(n−gcd(n,k)) accesses, no more than the three-reversal method. Their element-access counts are identical; the iterative one avoids the recursive stack. For example a half-length rotation uses n/2 swaps instead of approximately n reversal swaps.
Each single-place pass in part (iv) reads every entry once and writes every entry once, costing 2nk accesses. For k=1, its 2n accesses beat the block method's 4(n−1) for n>2 and tie for n=2. For k≥2 the block method costs strictly less than 2nk. All three methods as written return without accesses for k=0 or k=n. Repeated shifting can take quadratic time; the reversal and block methods take linear time. An abstract data type specifies a set of abstract values and the operations on them, including their observable behavior, independently of their concrete representation. Its operation signatures say what can be requested; its laws or preconditions and postconditions say what those requests mean.
For example a stack can be specified by an empty value, push, pop, and isEmpty, with pop(push(x,s)) returning x and leaving s. A linked list and an array can implement the same abstract data type if clients observe the same specified behavior. Encapsulation hides the representation, while a representation invariant describes which internal states are valid and an abstraction function explains which abstract value each valid internal state represents. An abstract class is a language mechanism; it is not by itself a full abstract data type specification.

Read prop3​(u,v) as the existence of a directed successor path from u to v. Then the property says every reachable ordered pair of even-valued nodes admits a connecting route through an odd-valued node. More exactly, for all even-valued u,v with u reaching v, there is an odd-valued w such that u reaches w and w reaches v.
The two reachability witnesses concatenate to a directed walk through w. In an acyclic graph this yields an intervening node on a path. In a graph with directed cycles, the concatenation may revisit vertices. The existential witness does not say that every connecting path contains an odd-valued node, or even that an even-to-even edge is forbidden. For example edges u→v, u→w, w→v, with even endpoints and odd w, satisfy the property for this pair despite the direct even-to-even edge.
There are two source-notation qualifications. The displayed outer universal quantifier binds both symbols appearing as formal arguments to prop, so the whole formula is a global property of T, rather than a genuinely free two-node predicate. Also the indexed ellipsis defining prop3 does not formalize path length zero. With positive-length reachability, even nodes on a cycle impose additional requirements; with reflexive reachability, choosing u=v also imposes a requirement, and an isolated even-valued node would fail. The usual intended reading here is positive-length successor reachability. No uniqueness, acyclicity or specific path-length convention is proved by the displayed formula alone.

Programming language polymorphism permits one interface or piece of code to work with values of several types, while providing the behavior appropriate to those values. For example a routine that calls play through a Player reference can use a Regular, Optimistic, or House object without knowing its concrete software class.
Use programming language polymorphism when clients should depend on a common contract while concrete behavior varies, or when an algorithm is independent of the element type. It avoids duplicating client logic or repeatedly inspecting concrete runtime types, and supports extensions behind the same interface. A shared interface must still have meaningful behavioral guarantees: merely giving unrelated operations the same name does not establish that implementations can safely replace one another.

Two mechanisms are subtype polymorphism and parametric polymorphism.
With subtype polymorphism, a trait or abstract class declares an operation and concrete subclasses implement or override it. A Player reference holding a House object invokes House.play through dynamic dispatch. The client is written against the common contract.
With parametric polymorphism, a software class or generic method has a type parameter, such as List[T] or def identity[T](x: T): T = x. The same definition works for many supplied type arguments, with static relationships between input and output types. Method overloading is another mechanism, usually called ad hoc polymorphism: alternatives share a name but are selected from their parameter signatures at compile time.

Creational patterns organize object creation; behavioral patterns organize interactions and responsibility for behavior. A creational pattern controls how concrete software objects are selected, instantiated, or shared, so clients need not hard-code the entire construction policy. Examples include the factory method pattern and the singleton pattern.
A behavioral pattern describes how objects collaborate, receive requests, or distribute an algorithm's behavior. For example the observer pattern lets a subject notify dependants after its state changes, and the strategy pattern supplies interchangeable implementations of an operation. This distinction concerns the pattern's principal responsibility; a system can use both kinds together.

object GymStandings {
  private var scores = Map.empty[GymEquipment, Int]

  def record(e: GymEquipment, calories: Int): Unit = {
    scores = scores.updated(e, calories)
  }

  def remove(e: GymEquipment): Unit = {
    scores = scores - e
  }

  def leaders: List[(GymEquipment, Int)] = {
    if (scores.isEmpty) Nil
    else {
      val best = scores.values.max
      scores.toList.filter { case (_, score) => score == best }
        .sortBy { case (equipment, _) => equipment.name }
    }
  }
}

class Performance(e: GymEquipment) extends Functionality {
  private def calories: Int =
    ((e.age - e.weight + e.heartRate) * e.time) / 10

  e.addFunctionality(this)
  GymStandings.record(e, calories)

  def update(): Unit = {
    val current = calories
    GymStandings.record(e, current)
    println("Your current performance is: " + current + " calories burned.")
  }
}
For example, new Performance(treadmill) and new Performance(bike) attach two observers; later GymStandings.leaders returns the leading equipment/score pairs. Initial registration records the equipment's present score, even before its first subsequent update. Recording replaces the same equipment's previous score, so repeated notifications do not multiply its contribution. The explicit remove supports taking an equipment object out of the comparison; detaching its observer when its session ends also prevents later re-registration through another notification. In the original single-threaded event model no extra synchronization is needed.
All equipment observers report to the same standings software object, and leaders returns every maximum or Nil if empty. Use the iterator pattern when clients need sequential access to a collection's elements without depending on its internal representation.
