(1)
Here i is a nonnegative integer; n=1 gives i=0.

b OurBigBook.com
Keep both the exponent and its power. This Oberon procedure uses only the permitted arithmetic:
PROCEDURE IntLog(b, n: INTEGER): INTEGER;
VAR i, p: INTEGER;
BEGIN
  i := 0; p := 1;
  WHILE p*b <= n DO
    p := p*b; i := i+1
  END;
  RETURN i
END IntLog;
The loop invariant is i≥0 and p=bi≤n. It holds initially because n>0. A successful guard permits the next power, and the two assignments preserve the relation between p and i. At exit, p≤n<pb, which is exactly part (a). Each iteration increases i, and only finitely many powers of b≥2 are at most n, proving algorithm termination. The returned value is ⌊logb​n⌋. Its running time is Θ(1+logb​n) arithmetic operations; integer overflow is deferred to part (e).

Use repeated squaring, including index zero:
b2[0] := b; top := 0;
WHILE b2[top]*b2[top] <= n DO
  b2[top+1] := b2[top]*b2[top];
  top := top+1
END;
The loop invariant is b2​[j]=b2j for 0≤j≤top, with b2​[j]≤n for every stored entry except possibly the initial entry when b>n. Squaring b2j gives b2j+1, proving preservation. The first failed guard identifies the first larger power outside the range. If b>n, no power with k≥1 needs storing.
Index zero is deliberately included. The original paper asks for indices k≥1 but then claims that their products represent every allowable power. Taken without b2​[0]=b, that claim fails for odd exponents, since every available exponent would be even. The extra initialized entry makes the intended binary expansion argument valid without changing the requested entries.
Let M be the largest representable positive integer. The worst case is b=2, requiring indices through ⌊log2​⌊log2​M⌋⌋. Thus enough = 5 for signed 32-bit integers, or 6 for signed 64-bit integers, suffices for stored powers that fit; a larger convenient constant is harmless. This counts slots starting at zero and does not reserve a slot for an out-of-range sentinel. The multiplication in the guard can still suffer integer overflow, independently of this array capacity bound.

Store a second array weight with weight[k] = 2^k. Descending through the binary digits of the answer gives this greedy algorithm:
PROCEDURE FastLog(b, n: INTEGER): INTEGER;
VAR b2, weight: ARRAY enough OF INTEGER;
    top, k, i, p: INTEGER;
BEGIN
  b2[0] := b; weight[0] := 1; top := 0;
  WHILE b2[top]*b2[top] <= n DO
    b2[top+1] := b2[top]*b2[top];
    weight[top+1] := weight[top]+weight[top];
    top := top+1
  END;
  i := 0; p := 1; k := top;
  WHILE k >= 0 DO
    IF p*b2[k] <= n THEN
      p := p*b2[k]; i := i+weight[k]
    END;
    k := k-1
  END;
  RETURN i
END FastLog;
For the second loop, write L=⌊logb​n⌋. Immediately before processing k, its loop invariant is
p=bi≤n,i≤L<i+2k+1.
(2)
Initially the failed squaring guard gives L<2top+1; this also holds when b>n, since then L=0. The test succeeds exactly when i+2k≤L. If successful, adding 2k selects that binary digit; otherwise the upper bound tightens to L<i+2k. Either way the invariant holds for the next smaller k. At k=−1, i≤L<i+1, so i = L.
There are O(1+log(1+logb​n)) squarings and descending tests. For fixed b, this is O(1+loglogn) arithmetic operations, hence logarithmic in the bit length of n, and also within the weaker O(logn) bound. This counts arithmetic operations on integers as unit cost; bit complexity would also charge for the growing operands. No division is used.

Let M be the maximum positive machine integer. A positive product xy suffers integer overflow when x>MDIVy. The vulnerable expressions are p*b in part (b), b2[top]*b2[top] in the table guard, and p*b2[k] in the descending search. Even a rejected candidate must be evaluated before its comparison with n.
The table guard becomes dangerous as soon as its current entry exceeds M​: approximately 46340 for signed 32-bit integers, or 3.04×109 for signed 64-bit integers. These are thresholds for the intermediate power, not for n alone. For example, with 32-bit arithmetic, b=2 and n=65536 reach the stored power 65536 and then try its overflowing square 232. If b>46340, even the initial square may overflow for a tiny n. In part (b), the final test can overflow when the next power above n exceeds M; at b=2, this already happens for n≥230.
For positive operands, integer division gives the exact equivalence xy≤n⟺x≤nDIVy. Therefore replace the three guards respectively by
p <= n DIV b
b2[top] <= n DIV b2[top]
p <= n DIV b2[k]
and perform each multiplication only after its guard succeeds. Every accepted product is then at most n≤M. With these guarded products and sufficient table capacity, the algorithms work throughout 2≤b≤M, 1≤n≤M. The stored exponents and weights also fit in those machine ranges. Checking for overflow after multiplying would be too late.

Separate integer partitions according to whether they contain a part equal to i. Removing one such part is a bijection to partitions of n−i whose parts are at most i. The alternatives are disjoint, giving
p(i,n)=p(i−1,n)+p(i,n−i)(i≥1, n≥1).​
(3)
Use p(i,0)=1, because the empty integer partition is counted once, and p(0,n)=0 for n>0, with p(i,n)=0 for n<0. This Oberon implementation avoids negative recursive arguments:
PROCEDURE P(i, n: INTEGER): INTEGER;
VAR answer: INTEGER;
BEGIN
  IF n = 0 THEN answer := 1
  ELSIF i = 0 THEN answer := 0
  ELSIF i > n THEN answer := P(i-1, n)
  ELSE answer := P(i-1, n) + P(i, n-i)
  END;
  RETURN answer
END P;

PROCEDURE Partitions(n: INTEGER): INTEGER;
BEGIN
  RETURN P(n, n)
END Partitions;
The precondition is i,n≥0. Each recursive call reduces i+n, proving algorithm termination. Every positive part of a partition of n is at most n, so the required one-argument count is P(n,n). Counts require a sufficiently wide integer representation.

For partitions into distinct parts, using a part i prevents using it again. Hence
d(i,n)=d(i−1,n)+d(i−1,n−i)​
(4)
when 1≤i≤n, with d(i,0)=1, d(0,n)=0 for n>0, and d(i,n)=0 for n<0. When i>n, use d(i,n)=d(i−1,n). Thus change the second call in the final branch of P to D(i-1, n-i) and rename all calls to D. The same split into two disjoint classes proves correctness; its second class removes its unique largest allowed part. The answer is D(n,n), giving D(4,4)=2, from 4 and 3+1.

Write parts in nonincreasing order. The array part stores the current prefix, and Emit(i,r,len) completes it using parts at most i with remaining sum r. With Out as the Oberon output module:
VAR part: ARRAY MaxParts OF INTEGER;

PROCEDURE Emit(i, r, len: INTEGER);
VAR j: INTEGER;
BEGIN
  IF r = 0 THEN
    j := 0;
    WHILE j < len DO
      IF j > 0 THEN Out.Char("+") END;
      Out.Int(part[j], 0); j := j+1
    END;
    Out.Ln
  ELSIF i > 0 THEN
    IF i <= r THEN
      part[len] := i;
      Emit(i, r-i, len+1)
    END;
    Emit(i-1, r, len)
  END
END Emit;

PROCEDURE PrintPartitions(n: INTEGER);
BEGIN
  Emit(n, n, 0)
END PrintPartitions;
The recursion invariant is that part[0..len) is nonincreasing, has sum n−r, and every further part must be at most i and at most the last existing part. The first branch includes the next part i; the second excludes it. These alternatives partition all completions, so each integer partition is printed exactly once. A recursive call reduces i+r; the printing loop's loop invariant is that the first j entries have been printed with exactly the necessary separators.
For n>0, no partition has more than n parts, and the all-ones partition has exactly n. Thus the fixed array requires 0≤n≤MaxParts to handle every partition. When a write occurs, r>0 and therefore len < n, so this bound prevents an out-of-range write. Zero prints one empty line, representing the empty integer partition. Available call stack space imposes a further practical limit.

Use dynamic programming in increasing order of the maximum permitted part and then of the remaining sum. Let Count be a sufficiently wide integer type and let table have dimensions (MaxN+1) by (MaxN+1):
PROCEDURE CountPartitions(n: INTEGER): Count;
VAR i, j: INTEGER;
    table: ARRAY MaxN+1, MaxN+1 OF Count;
BEGIN
  table[0,0] := 1; j := 1;
  WHILE j <= n DO table[0,j] := 0; j := j+1 END;
  i := 1;
  WHILE i <= n DO
    table[i,0] := 1; j := 1;
    WHILE j <= n DO
      table[i,j] := table[i-1,j];
      IF j >= i THEN
        table[i,j] := table[i,j] + table[i,j-i]
      END;
      j := j+1
    END;
    i := i+1
  END;
  RETURN table[n,n]
END CountPartitions;
Require 0≤n≤MaxN. The outer loop invariant says all rows below i equal p(⋅,⋅). The inner loop invariant additionally says entries before column j in the current row are correct. Its dependencies are the previous row and the earlier column j−i, so no future entry is read. Each state is evaluated once, giving Θ(n2) arithmetic operations and Θ(n2) stored counts. A memoization table around part (a)'s recursion is another valid way to share states; its entries need a separate “computed” flag because zero is a legitimate answer. Growing count sizes affect bit complexity and can cause integer overflow in a fixed-width Count.

a OurBigBook.com
A trie node needs a terminal flag as well as its children: a stored word can also be the prefix of a longer stored word.
TYPE Trie = POINTER TO Node;
     Node = RECORD
       terminal: BOOLEAN;
       child: ARRAY 26 OF Trie
     END;
Index zero denotes a, index 25 denotes z; null pointers denote absent branches. The set represented by a nonnull node consists of the empty string if terminal is true, together with every child's words prefixed by that child's letter. Represent the empty set by NIL. The singleton containing the empty string instead has a terminal root and no children.
The declarations alone do not force a unique representation. A nonterminal leaf, or a whole branch without terminal descendants, contributes no word. To obtain uniqueness up to pointer addresses, impose a representation invariant: the structure is a finite rooted tree, and each allocated node lies on a path to a terminal node. Then precisely the prefixes of stored words exist, all flags are determined, and the empty set has only the NIL representation. The insertion procedures below preserve this invariant when starting with such a trie.

For the paper's 26-letter alphabet, use the Oberon CAP operation and contiguous character codes:
PROCEDURE Index(c: CHAR): INTEGER;
BEGIN
  RETURN ORD(CAP(c)) - ORD("A")
END Index;
Both cases of a letter map to the same uppercase letter before subtraction, so the result lies in 0..25. This relies on the ordinary Latin A–Z and a–z character encoding used by Oberon; it is not a Unicode case-folding algorithm. The stipulated letter-only precondition avoids any need to reject punctuation.

Perform a depth-first traversal, retaining the path's letters in a buffer. A terminal node must be printed before its children, so a word precedes its proper extensions in lexicographic order.
VAR word: ARRAY N OF CHAR;

PROCEDURE Visit(t: Trie; depth: INTEGER);
VAR j, c: INTEGER;
BEGIN
  IF t # NIL THEN
    IF t.terminal THEN
      j := 0;
      WHILE j < depth DO
        Out.Char(word[j]); j := j+1
      END;
      Out.Ln
    END;
    c := 0;
    WHILE c < 26 DO
      IF t.child[c] # NIL THEN
        word[depth] := CHR(ORD("a")+c);
        Visit(t.child[c], depth+1)
      END;
      c := c+1
    END
  END
END Visit;

PROCEDURE PrintTrie(t: Trie);
BEGIN
  Visit(t, 0)
END PrintTrie;
The recursion invariant is that word[0..depth) spells the path to t. The child loop's loop invariant says children with indices below c have been completely printed. Each edge appends its lowercase label; each terminal flag prints exactly one represented string. All words therefore appear once, in lowercase. The output loop prints precisely the prefix of length depth; no terminating zero needs storing in this buffer.
An N-character buffer suffices for words of length at most N. At depth N there can be no child, so word[N] is never accessed. A terminal root prints an empty line; a NIL root prints nothing. The running time is linear in allocated nodes plus the number of printed characters, since the alphabet size is fixed at 26.

Allocate nodes only as required, explicitly initializing every field:
PROCEDURE Make(VAR t: Trie);
VAR c: INTEGER;
BEGIN
  NEW(t); t.terminal := FALSE; c := 0;
  WHILE c < 26 DO t.child[c] := NIL; c := c+1 END
END Make;

PROCEDURE AddTail(VAR t: Trie; s: ARRAY OF CHAR; i: INTEGER);
BEGIN
  IF t = NIL THEN Make(t) END;
  IF s[i] = 0X THEN
    t.terminal := TRUE
  ELSE
    AddTail(t.child[Index(s[i])], s, i+1)
  END
END AddTail;

PROCEDURE Add(VAR t: Trie; s: ARRAY OF CHAR);
BEGIN
  AddTail(t, s, 0)
END Add;
Here 0X is the zero character, and s must contain its terminator within its array bounds. Make establishes that the first c child fields are NIL as its loop invariant. Passing t by reference lets the base allocation replace a missing root or child pointer.
For correctness, use induction on the number of characters before the terminator. At length zero, setting terminal adds exactly the empty suffix. Otherwise the chosen child stores exactly words with the required next letter, and the induction hypothesis adds the remaining suffix while preserving all other words. Thus the resulting set is the old set union the supplied word, ignoring case. Repeated insertion changes no word membership. A newly allocated path reaches the newly terminal node, preserving the canonical representation invariant after the procedure finishes. The running time is O(1+ℓ) for a word of length ℓ, using O(1+ℓ) call stack space without optimization.

A directly self-recursive procedure can be replaced by a simple loop when every recursive call is a tail call. This is tail recursion: no operation, including an update or cleanup action, remains to be performed after the call returns. The loop tests the same cases, performs the same nonrecursive work, and replaces the current parameters by the next call's arguments. Argument values must be computed before assignments if their expressions depend on old parameter values; by-reference bindings also need preserving.
A traversal that must return to explore another child is not in this form. It can still be implemented iteratively with an explicit stack, but that is a different transformation and generally retains the deferred work.

AddTail in part (d) is already tail-recursive: the recursive call is the final action of its branch. The following loop follows a separate cursor so that the caller's root pointer is preserved:
PROCEDURE AddIter(VAR t: Trie; s: ARRAY OF CHAR);
VAR u: Trie; i, c: INTEGER;
BEGIN
  IF t = NIL THEN Make(t) END;
  u := t; i := 0;
  WHILE s[i] # 0X DO
    c := Index(s[i]);
    IF u.child[c] = NIL THEN Make(u.child[c]) END;
    u := u.child[c]; i := i+1
  END;
  u.terminal := TRUE
END AddIter;
The loop invariant is that u points to the node reached by the first i letters, all necessary nodes along that path exist, and no previously terminal node has lost its flag. Each iteration advances one character. At the terminator, marking u inserts exactly the desired string. Using t := t.child[c] as the cursor update would instead overwrite the caller's root through the VAR parameter. This version has O(1+ℓ) running time and constant auxiliary space, apart from newly allocated nodes in the result.

For a proposed loop invariant I, initial condition P, guard B, body S, and postcondition Q, establish these Hoare logic obligations:
P⇒I,{I∧B} S {I},I∧¬B⇒Q.
(5)
The first establishes I before the loop; the second preserves it after each iteration; the third derives the desired result when the guard is false. Together they prove partial correctness. For total correctness, also prove algorithm termination, for example by a nonnegative integer loop variant that strictly decreases whenever the body executes. The loop invariant need not be the postcondition: it generally describes completed and unfinished work together.

Let A denote the original array, used only in the proof. Save its first entry before overwriting it:
PROCEDURE LeftOne;
VAR saved: T; i: INTEGER;
BEGIN
  saved := a[0]; i := 0;
  WHILE i < N-1 DO
    a[i] := a[i+1]; i := i+1
  END;
  a[N-1] := saved
END LeftOne;
The loop invariant is saved = A[0], a[j]=A[j+1] for 0≤j<i, and a[j]=A[j] for i≤j<N. Thus the next source is untouched, and the assignment extends the completed prefix. At exit, the saved entry supplies the last position. The loop variant is N−1−i. The result is a[j]=A[(j+1)modN]. This also handles N=1, and uses exactly N element reads and N element writes, counting the saved read and final write, with one extra value of type T.

PROCEDURE RightOne;
VAR saved: T; i: INTEGER;

The loop invariant is saved = A[N-1], a[j]=A[j] for 0≤j≤i, and a[j]=A[j−1] for i<j<N. The decreasing loop variant is i. At exit the untouched saved value fills index zero. The result is a[j]=A[(j−1)modN], again with N reads, N writes, and one extra value of type T. Applying this after part (b) restores every original entry.

Normalize the amount to r=kmodN, with 0≤r<N; negative k then naturally denotes a right rotation. When r=0, return without touching the elements. Otherwise the map j↦(j+r)modN has g=gcd(N,r) disjoint permutation cycles, each of length N/g. Use representatives 0,…,g−1:
PROCEDURE RotateLeft(k: INTEGER);
VAR r, g, x, y, h, s, j, next: INTEGER; saved: T;
BEGIN
  r := k MOD N;
  IF r # 0 THEN
    x := N; y := r;
    WHILE y # 0 DO h := x MOD y; x := y; y := h END;
    g := x; s := 0;
    WHILE s < g DO
      saved := a[s]; j := s;
      IF j >= N-r THEN next := j-(N-r) ELSE next := j+r END;
      WHILE next # s DO
        a[j] := a[next]; j := next;
        IF j >= N-r THEN next := j-(N-r) ELSE next := j+r END
      END;
      a[j] := saved; s := s+1
    END
  END
END RotateLeft;
The conditional calculation of next implements addition modulo N without first forming a possibly overflowing j+r. Oberon's MOD with positive divisor supplies the nonnegative remainder. The first loop is the Euclidean algorithm, with loop invariant gcd(x,y)=gcd(N,r) and decreasing nonzero remainder.
For the outer loop, cycles with representatives below s are complete and every other cycle retains its original values. In one cycle, write ct​=(s+tr)modN. The inner loop invariant is saved = A[s], j=ct​, and a[cu​]=A[cu+1​] for 0≤u<t, with the remaining sources still untouched. When the next index returns to s, the saved value closes the cycle. The cycle length is N/g: writing N=gN′ and r=gr′ with gcd(N′,r′)=1, the least positive t with tr≡0(modN) is N′. Each residue class modulo g is one cycle, justifying the chosen representatives.
Every element is read once and written once: 2N element accesses, compared with 2Nk for k>1 repetitions of part (b). The zero rotation uses none. The running time is O(N) and auxiliary space is constant; the original array A is proof notation, not a copy made by the program.

Use the convention anew​[j]=A[p[j]], as required by the paper's rotation example. Follow each permutation cycle once. Temporarily encode a visited value v∈[0,N) as −v−1, and restore the whole permutation before returning:
PROCEDURE Permute(VAR p: ARRAY OF INTEGER);
VAR s, j, next: INTEGER; saved: T;
BEGIN
  s := 0;
  WHILE s < N DO
    IF p[s] >= 0 THEN
      IF p[s] = s THEN
        p[s] := -p[s]-1
      ELSE
        saved := a[s]; j := s;
        next := p[j]; p[j] := -next-1;
        WHILE next # s DO
          a[j] := a[next]; j := next;
          next := p[j]; p[j] := -next-1
        END;
        a[j] := saved
      END
    END;
    s := s+1
  END;
  s := 0;
  WHILE s < N DO p[s] := -p[s]-1; s := s+1 END
END Permute;
Require LEN(p) >= N and that p[0..N) is the stipulated permutation. Its cells must be writable and distinct from the data array. The marking map is reversible and fits whenever the original valid indices and N fit in the signed integer type.
At each outer test, all marked indices belong to fully completed cycles; all unmarked cycles still contain their original data and permutation entries. Within a cycle the same shifting loop invariant as part (d) applies, with successor given by the original p: all previously filled positions have their final values, and saved preserves the overwritten first source. A permutation has no path into a different cycle, so every new successor is unmarked until it returns to s; no encoded negative value is used as a source index. At outer-loop exit every index is marked and correct. The restoration loop has decoded precisely the indices below s.
The procedure uses one extra value of type T, O(N) time, and at most N data reads plus N data writes, with no data access for fixed points. It returns p unchanged, though it marks it temporarily. If p must remain read-only even during execution, test whether each index is its cycle's smallest member by traversing p before moving that cycle. Class inheritance defines a software class by extending another software class, inheriting its available operations and optionally adding members or providing method overriding. In languages supporting it, traits and mixins can contribute reusable behavior as well.
Use inheritance for a sound specialization whose instances can satisfy the superclass's contract wherever its instances are expected. For example, every specific gate in part (d) is usable through the common gate object interface. Subtyping supports this substitution and dynamic dispatch selects the specialized calculation. Merely noticing shared code does not establish the required behavioral relationship; object composition is often better for a replaceable component or policy that an object contains. A subclass must preserve the superclass's promised behavior, rather than just sharing its field names.

abstract class Gate {

The Prototype pattern is a creational pattern that creates new software objects by copying an existing configured object through a common cloning object interface. A client keeps or selects a prototype and requests a copy, without naming the concrete software class or repeating its construction recipe.
It is useful when the concrete type is selected at runtime, when many objects share a configuration, or when reconstructing an initialized object is expensive. For example, a drawing application can duplicate a configured graphical object through the same interface for many shape classes. The contract must specify what is copied: nested mutable state may require a deep copy, whereas a shallow copy would retain reference aliasing. A copy should preserve the intended configuration while allowing independent changes where promised.

The Strategy pattern is a behavioral pattern that encapsulates alternative algorithms behind a shared object interface. A context holds a strategy and delegates the relevant operation to it, letting the chosen algorithm vary independently of its caller.
Use it when the same task has interchangeable policies, such as alternative pricing or route-selection algorithms. Object composition makes the selected strategy replaceable; clients rely on its contract rather than on one concrete implementation.

The UML class diagram shows the subject's collection of observers and the added concrete observer. Each concrete company also retains the SomeService reference shown in its attributes; notifications call meth() through Company.
Use an unscaled value both initially and in every callback:
class NonProfit(service: SomeService) extends Company {
  private var v: Double = service.value
  service.addCompany(this)

  override def meth(): Unit = {
    v = service.value
    printf("New service value: %f\n", v)
  }
}
Initializing v before registration prevents a callback from observing an uninitialized field if registration is later extended to notify immediately. For a service initially valued at 100.0, this initializes v to 100.0; after updateValue(125.0), the callback sets v to 125.0 and prints New service value: 125.000000 under a decimal-point locale. The NonProfit update uses factor one.
The word “always” requires a qualification in the supplied design. In the intended single-threaded notification protocol, v=service.value holds after construction and after a completed SomeService.updateValue. However, the printed public value_= setter changes the subject without calling sendMessage(). Calling service.value = ... can therefore leave every cached observer value stale. No implementation that merely caches v in meth() can guarantee literal equality after that unannounced change. If equality on every query is required, replace the field by private def v: Double = service.value, retaining registration and the same printing callback; alternatively every mutation route must notify observers.
