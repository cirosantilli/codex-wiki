A MIPS R-type instruction has the 32-bit instruction encoding
6op​​ 5rs​​ 5rt​​ 5rd​​ 5shamt​​ 6funct​​.
(1)
For add $x,$y,$z, the processor register indices are rs=y, rt=z and rd=x, while shamt=0. The main opcode selects the R-type family and the function field selects addition. The register file reads its two operands from instruction bits 25:21 and 20:16. In the original datapath, RegDst=1 selects bits 15:11 as the destination, ALUSrc=0 selects the second register file output, and ALUFunc=ADD makes the arithmetic logic unit add its inputs. The result returns to wdata; RegWrite=1 writes it to x at the active clock edge. The zero output is irrelevant here.[ref]
A MIPS I-type instruction instead has the instruction encoding
6op​​ 5rs​​ 5rt​​ 16immediate​​.
(2)
For addi $x,$y,n, rs=y, rt=x, and the low sixteen bits contain the immediate operand. The register file supplies y to the first arithmetic logic unit input. Set RegDst=0 to select bits 20:16 for the destination, and ALUSrc=1 to select the extended immediate operand for the second input. The opcode directly requests addition, so ALUFunc=ADD and RegWrite=1. The second register file read is unused. The returned result is written into x.
The sign extension circuit retains the low sixteen bits and copies bit 15 into all sixteen new high positions:
sext(n)15:0​=n,sext(n)31:16​=16 copiesn15​⋯n15​​​.​
(3)
Thus sign extension preserves the signed two's complement value: 0x7fff becomes 0x00007fff, whereas 0x8000 becomes 0xffff8000. For both instructions, the architectural result above assumes no signed overflow; the full MIPS architecture specifies an overflow exception, which is outside this simplified datapath.
