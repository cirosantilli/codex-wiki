A MIPS R-type instruction has the 32-bit instruction encoding
6op​​ 5rs​​ 5rt​​ 5rd​​ 5shamt​​ 6funct​​.
(1)
For add $x,$y,$z, the processor register indices are rs=y, rt=z and rd=x, while shamt=0. The main opcode selects the R-type family and the function field selects addition. The register file reads its two operands from instruction bits 25:21 and 20:16. In the original datapath, RegDst=1 selects bits 15:11 as the destination, ALUSrc=0 selects the second register file output, and ALUFunc=ADD makes the arithmetic logic unit add its inputs. The result returns to wdata; RegWrite=1 writes it to x at the active clock edge. The zero output is irrelevant here.[ref]
A MIPS I-type instruction instead has the instruction encoding
6op​​ 5rs​​ 5rt​​ 16immediate​​.
(2)
For addi $x,$y,n, rs=y, rt=x, and the low sixteen bits contain the immediate operand. The register file supplies y to the first arithmetic logic unit input. Set RegDst=0 to select bits 20:16 for the destination, and ALUSrc=1 to select the extended immediate operand for the second input. The opcode directly requests addition, so ALUFunc=ADD and RegWrite=1. The second register file read is unused. The returned result is written into x.
The sign extension circuit retains the low sixteen bits and copies bit 15 into all sixteen new high positions:
sext(n)15:0​=n,sext(n)31:16​=16 copiesn15​⋯n15​​​.​
(3)
Thus sign extension preserves the signed two's complement value: 0x7fff becomes 0x00007fff, whereas 0x8000 becomes 0xffff8000. For both instructions, the architectural result above assumes no signed overflow; the full MIPS architecture specifies an overflow exception, which is outside this simplified datapath.

The arithmetic logic unit then performs bitwise OR between y and the zero-extended immediate operand and writes the result to x. Extend the arithmetic logic unit's control decoding if OR was not already available. Decode addi to ExtSign=1; the new signal is irrelevant for MIPS R-type instructions because ALUSrc=0.
Zero extension matters even when the most significant immediate bit is one: ori with 0x8000 must only affect the low half of the destination, whereas sign extension would incorrectly force every high bit to one.[ref]

Use byte addresses, so adjacent 32-bit array elements are four bytes apart. The following MIPS instructions include harmless sll $zero,$zero,0 instructions in every branch delay slot; the second load is followed by another independent instruction before its value is consumed, also accommodating an early MIPS architecture with a load-use delay. All mnemonics here denote individual machine instructions.
        beq   $t3,$zero,done  # n=0: do not access any array
        sll   $zero,$zero,0
loop:
        lw    $t4,0($t0)      # current a element
        lw    $t5,0($t1)      # current b element
        addiu $t0,$t0,4       # advance a; also separates lw from its use
        subu  $t6,$t4,$t5     # current difference, modulo 2^32
        sw    $t6,0($t2)      # store current c element
        addiu $t1,$t1,4
        addiu $t2,$t2,4
        addiu $t3,$t3,-1      # one fewer element remains
        bne   $t3,$zero,loop
        sll   $zero,$zero,0
done:
A loop invariant at the head of the loop, after k completed iterations, is that the three addresses point to elements k, the count is n−k, and every output element before k equals the corresponding difference. One iteration reads element k, stores its difference and advances to k+1, preserving the loop invariant. The remaining count is a nonnegative loop variant decreasing by one, so the loop ends with k=n.
The code uses subu to avoid signed-overflow traps: the suffix does not restrict the operands to unsigned values. Its precise result is
ci​≡ai​−bi​(mod232)(0≤i<n).​
(5)
For representable signed differences this is exactly ci​=ai​−bi​. If trapping signed arithmetic is required instead, use sub and assume all differences are representable. The arrays must occupy valid word-aligned storage with no address wrap; the usual separate output array avoids overwriting unread inputs.

        addu  $t0,$a0,$zero
        addu  $t1,$a1,$zero
        addu  $t2,$a2,$zero
        addu  $t3,$a3,$zero
        # insert the code of (i), including its initial zero-count test
        # use the local label array_diff_done in place of done
array_diff_done:
        jr    $ra
        sll   $zero,$zero,0
In the literal insertion, the done: line from (i) is the array_diff_done: line displayed here; it is not a second return block. Under the usual calling convention, temporary processor registers are caller-saved. This procedure calls no other procedure and changes no saved processor registers, so it needs no stack frame or saved return address.
For a 32-bit constant K, define HK​=⌊K/216⌋ and LK​=Kmod216 using its unsigned binary representation. Load it with lui followed by ori; both are single MIPS instructions. For base addresses A,B,C and count N, the main program is:
main:
        lui   $a0,H_A
        ori   $a0,$a0,L_A
        lui   $a1,H_B
        ori   $a1,$a1,L_B
        lui   $a2,H_C
        ori   $a2,$a2,L_C
        lui   $a3,H_N
        ori   $a3,$a3,L_N
        jal   array_diff
        sll   $zero,$zero,0
main_after_call:
        # c now contains the differences; continue the main program here
Here each H_... and L_... is an assembler-time numeric constant, not an executed operation. lui places the high half and clears the low half; ori inserts the low half without sign extension. Thus
(HK​≪16)ORLK​=K.​
(6)

Names live in directory entries. Each ordinary directory entry associates a component name with an inode number; the corresponding inode describes the file and locates its contents. A name is therefore not stored as the identity of the inode, and hard links can give one inode several names.
To resolve /var/mail/user, start from the root file-system directory's inode, read its directory entries and find var. Follow that entry's inode number to the var inode; read that file-system directory and find mail; repeat for user. The final inode supplies the file metadata and addresses needed to read the file data blocks. The intermediate file-system directories require search permission. This describes ordinary pathname traversal without a symbolic link or mount point changing the route.
component name⟶directory entry⟶inode⟶contents.​
(7)

An inode holds file metadata: object type, owner and group identities, access permissions, file size, access/modification/status-change timestamps, and the hard link count. A traditional inode uses a fixed number of direct pointers to file data blocks, followed by singly, doubly and sometimes triply indirect block pointers. A singly indirect block pointer reaches one address block whose entries point to file data blocks. A doubly indirect block pointer reaches a block of pointers to singly indirect address blocks; a triply indirect one adds another level. The file data blocks need not be physically contiguous.
This multilevel inode indexing keeps the inode compact. A small file uses direct pointers without allocating address blocks, while a large file allocates deeper address blocks only as needed. If each address block holds q addresses, the successive levels cover q,q2,q3 file data blocks. The logical file offset selects a path arithmetically, so random access does not require walking through all preceding file data blocks.
small files: direct access; large files: additional indirection levels.​
(9)

An access control list is attached to an object, such as a file, and lists which subjects or groups may perform which operations. Access requires checking the requesting identity against that object's list. A security capability is an unforgeable reference to an object carrying specified rights; possessing valid authority is what permits access. Protected storage or another integrity mechanism must prevent users manufacturing stronger security capabilities.
The traditional Unix owner/group/other read-write-execute permissions are a compact, restricted access control list: the inode records the owner, group and permission bits, and the operating system compares these against the caller's credentials.
Traditional Unix file protection is closest to access control lists.​
(10)
An already-open file descriptor can behave like a limited handle carrying rights, but that does not change the identity-based nature of the initial pathname permission check.

Use three D flip-flops whose stored bits A,B,C represent 4A+2B+C. Initialize them to 000. The Moore machine's output is this stored binary representation, and its state transition table is:
Present ABCNext A+B+C+
000001
001010
010011
011100
100101
101000
Treat the two unused state encodings 110,111 as don't-care conditions when minimizing the sum of products. With juxtaposition for AND, + for OR and a bar for NOT, one minimal choice is
DA​=AC+BC,DB​=BC+ABC,DC​=C.​
(18)
For DA​, the required ones at 011 and 100 cannot share one valid implicant: their differing bits would force inclusion of required zeros. Pair 011 with the unused 111 to get BC, and 100 with unused 110 to get AC. Neither term can lose a Boolean literal without covering a required zero.
For DB​, state 001 is isolated from every other required one and from the unused states by required zeros, so it forces the three-Boolean literal term ABC. State 010 pairs with unused 110 to give BC. Finally DC​=C is a single Boolean literal. Thus the three expressions are minimal sum of products expressions under the stated unused-state convention. In fact these choices also recover from 110→111→100, so initialization into an unused state eventually joins the intended modulo-six counter cycle.

Let the stored bits be G,H, with G most significant. The required Gray code transitions give
00→01→11→10→00,DG​=H,DH​=G.​
(19)
Connect H directly to the first D flip-flop's data input and feed G through one NOT gate to the second input. Drive both enable inputs with E and both clock inputs with the same clock. Thus E=0 holds both stored bits; E=1 takes the next Gray-code counter state at the active clock edge. Reset initializes GH=00.
With ordinary uncomplemented Q outputs, one NOT gate is minimal: wiring alone cannot produce G. If a D flip-flop already provides a complementary output, that output supplies the inversion without an external logic gate. This is a Moore machine because its output GH depends only on stored state; E controls transitions.

Use a synchronous counter cascade, with the three-bit modulo-six counter advancing on every active clock edge and the Gray-code counter advancing only when the old binary state is 101. Its enable can therefore be
E=AC.​
(20)
On the six valid binary states, AC=1 only at 101. Both digital counters sample the same clock: at an edge leaving 101, the binary output becomes 000 and GH simultaneously advances to the next Gray code. At all other edges GH holds. Starting from GHABC=00000, this gives exactly the listed 24-state sequence. Use the shared clock and an enable, rather than making a combinational terminal-state signal into a new clock.[ref]
For the output Y, every state with C=1 has Y=1. For C=0, the only extra high states are GH=01 with binary state 010, and GH=11 with binary state 000 or 100. On valid states these conditions are HGB and HGB, respectively. Hence
Y=C+HGB+HGB=C∨(H∧(G⊕B)).​
(21)
The lower circuit in the figure implements this with an AND for E, an exclusive or on G,B, an AND with H, and an OR with C. The resulting Morse code output blocks, in Gray code order 00,01,11,10, are
010101011101110111010101.
(22)
Across the two middle blocks these join to three three-clock highs separated by one-clock lows; the first and last blocks provide the three single-clock highs of each S. The specified table is a repeating SOS symbol pattern; its wraparound has a one-clock low, rather than an added inter-message pause. The output is a Moore machine decoding of current stored bits; its value changes after those bits settle.

Apply the elementary row operations from bottom to top: R4​←R4​−R3​, R3​←R3​−R2​, and R2​←R2​−R1​. This order ensures that each subtraction uses the original preceding row. The result is the upper triangular matrix
T=​a000​ab−a00​ab−ac−b0​ab−ac−bd−c​​.
(23)
Put δ1​=a, δ2​=b−a, δ3​=c−b, δ4​=d−c. Row i is either zero if δi​=0, or has its first nonzero entry in column i. Thus, for arbitrary real parameters, a row echelon form is obtained by retaining the nonzero rows of T in their existing order and moving every zero row to the bottom. This deals explicitly with vanishing parameters; an upper triangular matrix with an intermediate zero row is not yet a row echelon form.
The subtractions preserve the determinant, so the original matrix has
detM=a(b−a)(c−b)(d−c).
(24)
A square matrix is invertible exactly when its determinant is nonzero. Consequently,
M invertible⟺a=0,b=a,c=b,d=c.​
(25)
These conditions concern consecutive parameters: no ordering, positivity, or pairwise distinctness of all four is required. More generally the rank of a matrix here is the number of nonzero δi​, because the retained nonzero rows have distinct leading columns.

For a real m×n matrix A, the row space is the linear span of its rows in Rn, and the column space is the linear span of its columns in Rm. Its null space consists of the input vectors sent to zero:
Null(A)={x∈Rn:Ax=0}.
(29)
The rank of a matrix is
rankA=dimCol(A)=dimRow(A).​
(30)
The equality of row and column dimensions is the row-rank/column-rank theorem. Each displayed space is a linear subspace of the indicated ambient vector space.

The conjunction introduction rule derives ϕ∧ψ from proofs of ϕ and ψ in the current context. The disjunction elimination rule derives a common conclusion κ from ϕ∨ψ, a subproof of κ under temporary assumption ϕ, and a subproof of κ under temporary assumption ψ. The implication introduction rule derives ϕ→ψ by temporarily assuming ϕ and proving ψ.
The rectangular boxes delimit subproofs and the scope of their temporary assumptions. The disjunction elimination rule discharges the two case assumptions; the implication introduction rule discharges its antecedent assumption. Formulas depending on a boxed assumption cannot simply escape that box. Other undischarged assumptions remain in force, and nested boxes can access the assumptions of enclosing boxes.
Boxes record local assumptions and their discharge, not additional premises.​
(49)

A variable v is fresh for the relevant context when it occurs free in none of its undischarged assumptions. For the existential quantifier elimination rule, it must also not occur free in the final conclusion κ or the existential premise: it is a new eigenvariable, allowed in the temporary witness assumption ϕ(v) and formulas inside that witness subproof. Bound variable names can always be renamed to avoid collisions.
The premise ∃xϕ(x) guarantees some witness, without saying which object it is. Temporarily call one such witness v and assume ϕ(v). If the subproof yields κ without depending on any special identity or extra property of v, its conclusion holds whichever witness exists. The existential quantifier elimination rule therefore discharges ϕ(v) and retains only the original existential premise and other open assumptions.
Γ,ϕ(v)⊢κ⟹Γ,∃xϕ(x)⊢κ,v∈/FV(Γ,κ,∃xϕ(x)).​
(54)
This eigenvariable condition prevents inferring ϕ(v) for a previously chosen object merely from existence. In particular, ∃xQ(x) does not license Q(v) outside the discharged witness subproof.
