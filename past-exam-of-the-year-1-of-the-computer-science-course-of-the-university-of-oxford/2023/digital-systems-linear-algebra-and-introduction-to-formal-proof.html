Write an n-bit binary string as A=an−1​⋯a1​a0​, where each ai​∈{0,1} and an−1​ is most significant. Its unsigned interpretation and two's complement interpretation are
bin(A)=i=0∑n−1​ai​2i,twoc(A)=−an−1​2n−1+i=0∑n−2​ai​2i.​
(1)
Equivalently, twoc(A)=bin(A)−an−1​2n. The ranges are 0 through 2n−1 and −2n−1 through 2n−1−1, respectively. The same stored bits can therefore denote different integers depending on the chosen interpretation.

A logical right shift by k moves ai+k​ into position i and fills the high positions with zero. Its unsigned interpretation is
bin(ALSRk)=∑i=kn−1​ai​2i−k=:q.
(2)
Meanwhile the original unsigned interpretation decomposes as
a=2kq+ri=0∑k−1​ai​2i​​,0≤r≤2k−1.
(3)
By integer division, q=⌊a/2k⌋, exactly the unsigned quotient. Thus the source instruction puts the required quotient into r1. This is a proof from binary representation, rather than an assumption that every kind of right shift implements every kind of division. The displayed bit argument applies to 0≤k≤n, with endpoint operations implemented as a copy or zero where appropriate.

For a 32-bit machine word and 1≤k≤31, use a left bit shift followed by a logical right shift:
lsls r1, r0, #(32-k)
lsrs r1, r1, #(32-k)
The left shift discards all but the lowest k bits and moves those retained bits to the top. The logical right shift returns them to their original positions and fills the rest with zero. Hence r1 contains amod2k, the remainder identified in (b). For k=0 the remainder is zero; for k=32 it is a, so these endpoints can be handled directly.
On a reduced instruction set computer, a bit mask such as 2k−1 may not fit an instruction's immediate field. Masking may therefore require materializing the constant in another processor register, possibly using several instructions or a memory load. Small shift counts are directly encodable, so the two shifts can save code space, a temporary processor register, or a load. This is an architecture-dependent advantage, rather than a universal speed claim. The source's compact instruction forms support these immediate shifts, while their bitwise AND form takes its other operand from a processor register.[ref]

Let s=1{a<0}​, let b=1023s, and let u=(a+b)mod1024 denote the least nonnegative residue. Here a is a signed 32-bit two's complement value. The source instructions, annotated with their derived values, are:
rem1024:
    asrs r3, r0, #31    // r3 = -s: all zero bits or all one bits
    lsrs r3, r3, #22    // r3 = b = 1023*s
    adds r0, r0, r3     // r0 = a+b
    lsls r0, r0, #22    // r0 has word value (a+b)*2^22 modulo 2^32
    lsrs r0, r0, #22    // r0 = u = (a+b) modulo 1024, in 0,...,1023
    subs r0, r0, r3     // r0 = u-b
    bx lr              // return u-b
The first instruction is an arithmetic right shift, so it replicates the sign bit. The second is a logical right shift, turning the all-one word into 1023. The paired shifts then extract the low ten bits, as in (c). Their effect is the residue of a+b even if its two's complement interpretation is negative, because 1024 divides the word modulus 232. The adjusted value a+b is representable for every input: positive inputs are unchanged, and negative inputs gain only 1023.
For a≥0, b=0, so the return value is the usual nonnegative remainder amod1024. For a<0, put t=−a>0 as a mathematical integer, and write t=1024q+r with 0≤r<1024. If r=0, then u=1023 and the return value is zero. If 1≤r≤1023, then
u=(−t+1023)mod1024=1023−r,u−b=−r.
(4)
These are precisely the remainders for C integer division, whose quotient truncates towards zero. In every case the result has the dividend's sign or is zero, has magnitude below 1024, and satisfies a=1024qC​+rC​. The proof includes the smallest representable input: t=−a was used only in mathematical reasoning, not as an overflowing machine operation.[ref]

Use the same bias, then an arithmetic right shift by ten:
div1024:
    asrs r3, r0, #31    // -1 when a<0, otherwise 0
    lsrs r3, r3, #22    // b = 1023 when a<0, otherwise 0
    adds r0, r0, r3     // a+b, representable for every signed input
    asrs r0, r0, #10    // floor((a+b)/1024)
    bx lr
An arithmetic right shift of a two's complement integer computes division rounded down. For a≥0, this already equals truncation towards zero. For a<0, the signed power-of-two division by biasing identity is
trunc(a/1024)=⌊1024a+1023​⌋.​
(5)
Indeed, writing −a=1024q+r with 0≤r<1024 makes the adjusted numerator −1024q+(1023−r); its quotient rounded down is −q for every r, including zero. Thus the code returns the signed quotient in all cases and contains no data-dependent branch. The final bx lr simply returns to the caller.

Use a message-passing mutual exclusion server with an owner field and a FIFO queue. A request includes its client's identity. The server handles one received message at a time, and a client has at most one outstanding request. The following pseudocode assumes reliable message passing and compliant clients:
owner = NONE
waiting = empty FIFO queue

forever:
    (kind, client) = receive_from_any_client()
    if kind == REQUEST:
        waiting.push_back(client)
    else if kind == RELEASE:
        assert client == owner
        owner = NONE

    if owner == NONE and not waiting.empty():
        owner = waiting.pop_front()
        send(owner, GRANT)
A client sends REQUEST, waits for GRANT, runs its complete animation, and sends RELEASE before making another request.
The invariant proving mutual exclusion is: at most one client has received an unreturned grant, and that client is owner. Only the final block issues a grant, and it first requires no current owner. A valid release removes that ownership. Since clients use the display only while holding a grant, simultaneous use is impossible. The FIFO queue prevents accepted requests from being overtaken by later ones. With eventual message delivery, continued server execution, and finite animations, each accepted request is eventually served; these progress assumptions are separate from the safety invariant.

b OurBigBook.com
Use two FIFO queues, one for each priority class, and perform nonpreemptive strict-priority arbitration whenever the display becomes free:
owner = NONE
ordinary = empty FIFO queue
urgent = empty FIFO queue

forever:
    message = receive_from_any_client()
    if message.kind == REQUEST:
        assert message.priority in {0, 1}
        if message.priority == 1:
            urgent.push_back(message.client)
        else:
            ordinary.push_back(message.client)
    else if message.kind == RELEASE:
        assert message.client == owner
        owner = NONE

    if owner == NONE:
        if not urgent.empty():
            owner = urgent.pop_front()
        else if not ordinary.empty():
            owner = ordinary.pop_front()
        if owner != NONE:
            send(owner, GRANT)
The same ownership invariant proves mutual exclusion. Among requests already accepted by the server, every pending urgent request takes precedence over every ordinary one. Each class retains its own arrival order. A newly received urgent request goes ahead of waiting ordinary requests but waits for the current animation's RELEASE; the given protocol has no interruption or revocation operation.
This is strict priority at dispatch, based on requests the server has received. Requests still in transit cannot influence a decision. If the transport provides a mailbox-draining operation, the server may also collect all currently delivered requests before dispatching; the two-FIFO queue selection rule remains the same.
Strict priority does not guarantee starvation freedom for ordinary clients under an endless supply of urgent work. If urgent traffic eventually stops, accepted requests have only finitely many earlier requests, and all service times are finite, every pending ordinary request is eventually granted. Guaranteeing ordinary progress under unlimited urgent traffic would require a different fairness policy, such as limiting consecutive urgent grants; that would relax strict priority.

A LIFO stack can make waiting clients starve. Suppose client A waits at the bottom of the stack. Before each current owner releases, a fresh client submits a request. That newest request is pushed above A and is selected next. Every animation can finish promptly while A waits forever.
This is LIFO starvation: service completion alone does not ensure starvation freedom. A FIFO queue prevents newer same-priority requests from passing A, whereas replacing either priority-class FIFO queue by a LIFO stack adds this problem even within one priority class. Strict priority can already starve ordinary work, as in (b); the LIFO stack introduces a further unfairness that can also affect urgent work.

Use a three-sample run detector. Just before clock edge t, let two stored bits p and q hold the input values at edges t−1 and t−2. Initialise both to zero. With input at​, define
wt​=at​∧p∧q,p′=at​,q′=p.​
(6)
Primes denote the next stored state, with all assignments simultaneous at the clock edge. The output is the logical conjunction of the present input and its two preceding samples. By induction on clock edges, the stated interpretation of p,q is maintained, proving the required behaviour. Two bits of state suffice.

b OurBigBook.com
Store two bits: the output z, initially zero, and an armed bit e, initially one. Define the synchronous sequential circuit by
z′=z⊕(e∧c),e′=d∨(e∧¬c).​
(7)
Here ⊕ is exclusive or, and the input restriction c∧d=0 excludes conflicting commands. The output is the current stored z.
When armed, a sampled c=1 toggles z and clears e. Further c samples leave the output unchanged. A sampled d=1 sets e=1 without changing z, allowing a later c to toggle it again. The same clock edge cannot both rearm and trigger because c,d are never simultaneously high. Thus the first c toggles from zero to one, and subsequent toggles each require a new d followed by a later c.

Share the input-history bits of (a) between a high-run detector and a low-run detector. With p,q the two preceding input samples, put
c=a∧p∧q,d=¬a∧¬p∧¬q.
(8)
These detector outputs are mutually exclusive. Feed them into (b). An explicit four-bit synchronous sequential circuit, with initial state (p,q,e,z)=(0,0,1,0), is
p′=a,q′=p,e′=d∨(e∧¬c),z′=z⊕(e∧c).​
(9)
Every right-hand side uses the old state and the current input. In particular, the run detectors' combinational outputs are sampled by the toggle module at that same edge; there is no extra pipeline stage.
The first three consecutive high samples make c=1 at the third edge, toggling z and clearing e. Continuing high input cannot toggle it again. Only three consecutive low samples can make d=1 and rearm it; interrupted low runs do not suffice. After rearming, a new three-sample high run produces the next toggle. This proves the debounced toggle switch behaviour, including rejection of short high and low disturbances.

Four state bits are necessary and sufficient. For each output value, distinguish three armed situations, remembering a trailing high run of length 0,1,2, and three disarmed situations, remembering a trailing low run of length 0,1,2. Thus a direct minimal behavioural description has
2(3+3)=12 states,⌈log2​12⌉=4 bits.
(10)
All twelve situations are reachable. Different output values are immediately distinguishable. Within an armed group, a suitable number of high samples distinguishes the three run lengths by when the next toggle occurs. Within a disarmed group, a suitable number of low samples followed by three highs distinguishes the three rearming distances. An armed situation and a disarmed situation of the same output value are distinguished by an all-high continuation: the armed one eventually toggles and the disarmed one does not. Hence these twelve situations cannot be merged in a finite-state machine implementing the specification.
The shared-history design in (c) uses four bits, meeting this lower bound. Its sixteen encoded states have some behaviourally equivalent histories, so its encoding need not use only twelve combinations. Building two separate copies of (a) plus the two-bit module (b) would use six state-bearing elements; sharing the input history saves two.

Fix one common eigenvector v=0, and write AA⊤v=λv and BB⊤v=μv. By (d),
AA⊤BB⊤=A(A⊤B)B⊤=0,
(18)
so λμv=0 and at least one of the two eigenvalues is zero.
To exclude both being zero, use the kernel of a Gram product identity:
v⊤AA⊤v=∥A⊤v∥2,v⊤BB⊤v=∥B⊤v∥2.
(19)
If both products annihilate v, then A⊤v=B⊤v=0. By (b), v∈imL, and by (e), this is imB. On the other hand, B⊤v=0 makes v orthogonal to every vector in imB. In particular v is orthogonal to itself, so ∥v∥2=0 and v=0, a contradiction.
Therefore each specified common eigenvector belongs to exactly one of ker(AA⊤) and ker(BB⊤). Both eigenvalues are nonnegative by the displayed squared-norm identities, so the other eigenvalue is strictly positive. This is the spectral mechanism behind orthogonal null-space completion of a square matrix.
