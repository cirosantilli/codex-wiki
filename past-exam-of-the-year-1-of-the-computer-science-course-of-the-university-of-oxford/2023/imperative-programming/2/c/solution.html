Under exact integer arithmetic, the intended result is ⌈log2​x⌉, using the ceiling function. A sufficient loop invariant is
i≥0,y=2i,i=0 ∨ 2i−1<x.
(2)
Initially i=0,y=1, and the final disjunction is true. If the guard holds, the old value y=2i is below x. Incrementing i and doubling y therefore preserves y=2i and makes the new lower bound 2i−1<x true. At exit y≥x. If i=0, positivity of x forces x=1; otherwise 2i−1<x≤2i. Both cases establish the claimed postcondition. Doubling eventually reaches or exceeds any fixed positive x, proving algorithm termination in this arithmetic model. This is the doubling-loop ceiling logarithm argument.
The printed Scala implementation is not correct for its entire stated Int domain. Its y is an Int. For x>230, it reaches y=230, wraps to −231 on the next doubling, then becomes zero and stays zero. The guard remains true forever. The loop invariant above is valid for the printed code only when 1≤x≤230. Scala documents Int as a signed 32-bit value equivalent to Java's primitive int.[ref]
A corrected implementation for every positive Int input widens the doubling variable before any multiplication:
def ceilingLog2(x: Int): Int = {
  require(x > 0)
  var i = 0
  var y = 1L
  while (y < x.toLong) {
    i += 1
    y *= 2L
  }
  i
}
Now at most 31 iterations are needed and y≤231, safely within Long. The same loop invariant proves total correctness without the overflow gap.
