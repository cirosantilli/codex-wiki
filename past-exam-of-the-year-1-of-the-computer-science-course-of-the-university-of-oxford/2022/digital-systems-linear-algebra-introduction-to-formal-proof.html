For bits a,b, use two negation logic gates and two AND gates:
L=(¬a)∧b,G=a∧(¬b).​
(1)
The two unequal bit pairs activate their respective output; the equal pairs activate neither. In particular, a digital comparator never produces L=G=1.

b OurBigBook.com
Split each input into its more and less significant n-bit halves: a=2naH​+aL​ and b=2nbH​+bL​. Let the two digital comparators produce (LH​,GH​) and (LL​,GL​). The more significant halves are equal exactly when EH​=¬(LH​∨GH​). The comparator composition is therefore
L=LH​∨(EH​∧LL​),G=GH​∨(EH​∧GL​).​
(2)
Implement EH​ with a logical disjunction followed by a negation, then use two AND gates and two more logical disjunction logic gates. If aH​=bH​, the difference 2n(aH​−bH​) has magnitude at least 2n, whereas ∣aL​−bL​∣≤2n−1; hence the more significant comparison decides the result. If aH​=bH​, the lower comparison decides it. This proves correctness in every case using a constant number of extra logic gates.

c OurBigBook.com
Apply comparator composition recursively in a balanced binary tree, with one-bit digital comparators at its leaves. For a power of two n, the circuit size and circuit depth satisfy
S(n)=2S(n/2)+O(1),D(n)=D(n/2)+O(1).
(3)
There are n leaves and n−1 internal nodes, so the circuit size is O(n) and the combinational delay is O(logn). Here each fixed-fan-in logic gate has bounded delay. For arbitrary n, pad both inputs with leading zero bits to the next power of two, which is less than 2n; this preserves their unsigned interpretation and both bounds.

Use a hierarchical leading-zero counter. A block of 2j bits returns a zero flag z and j low count bits r: its count leading zeros result is the concatenation (z,r). Thus z=1 means that the block is entirely zero and r=0; otherwise z=0 and r is its leading-zero count. A one-bit block needs just z=¬x and no low count bits.
For a block of n=2k bits, run two such Boolean circuits on the upper and lower halves in parallel. Write their flags as zH​,zL​ and their k−1 low count bits as hi​,ℓi​. Set
z=zH​∧zL​,rk−1​=zH​∧¬zL​,ri​=(¬zH​∧hi​)∨(zH​∧ℓi​)(0≤i<k−1).​
(4)
The last expression is a two-input multiplexer. When the upper half is nonzero, its count is already the answer and rk−1​=0. When only the upper half is zero, rk−1​=1 supplies the contribution n/2 while the multiplexers supply the lower half's count. When both halves are zero, the answer is (1,0,…,0), representing n. This special encoding avoids an adder on the critical path.
Each node adds constant circuit depth, even though it uses O(k) logic gates for its parallel multiplexers. Hence
D(2k)=D(2k−1)+O(1)=O(k),S(2k)=2S(2k−1)+O(k)=O(2k).
(5)
Indeed the internal-node work is bounded by a constant times ∑j=1k​(n/2j)j<2n, and the n leaves add O(n). Delay is O(logn) and size is O(n), counting fixed-fan-in logic gates and the usual wire fan-out model.

Use the AAPCS32 convention: r0 holds the input address, r1 the length, and r0 receives the result. The following Thumb instruction set assembly language uses only scratch processor registers, so no callee-saved registers need saving. Assume the array is valid, halfword-aligned, and has nonnegative length; for the mathematical sum assume it fits a signed 32-bit two's complement integer.
.syntax unified
.thumb
.thumb_func
sum16:
    movs r2, #0             @ accumulated sum
    cmp  r1, #0
    ble  .Ldone             @ empty array; also returns 0 if n < 0
.Lloop:
    movs r3, #0             @ Thumb signed load needs a register offset
    ldrsh r3, [r0, r3]      @ signed halfword at a; offset read before r3 changes
    adds r2, r2, r3         @ include this signed value
    adds r0, r0, #2         @ advance by one short, not one byte
    subs r1, r1, #1         @ one fewer element remains
    bne  .Lloop
.Ldone:
    movs r0, r2             @ result register
    bx   lr                 @ leaf routine: lr was not overwritten
After j iterations, the loop invariant is that r2 contains the first j elements' sum, r0 points to element j, and r1 is n−j. The sign extension in ldrsh supplies the correct signed addend. One iteration preserves this loop invariant, and the decreasing remaining length proves algorithm termination. For the seven-element calls, the sum lies between −229376 and 229369, so it fits. For longer arrays that overflow, these instructions compute the sum modulo 232; that is not a claim about defined signed C programming language overflow behavior. The operand forms are those of the paper's reference sheet.[ref]

−s231+s∑i=1630​2i+∑i=015​bi​2i=−s216+s215+∑i=014​bi​2i=−s215+i=0∑14​bi​2i​.

Keep total in the callee-saved register r4, and the first returned sum in the callee-saved register r5. Suppose the surrounding function has made an aligned stack frame with the local seven-halfword array at the current sp, occupying fourteen bytes in a sixteen-byte slot. One possible frame setup is push {r4,r5,r6,lr} followed by sub sp,sp,#16; the earlier code initializes total, regular, and special before this fragment.
    ldr  r0, =regular       @ assembler literal load of the global array address
    movs r1, #7
    bl   sum16
    movs r5, r0             @ first sum must survive the next call

    add  r0, sp, #0         @ current frame's local special array
    movs r1, #7
    bl   sum16
    muls r0, r5, r0         @ second sum times first sum
    adds r4, r4, r0         @ update total
The AAPCS32 permits each call to overwrite r0–r3, r12, and condition flags, but requires preservation of r4–r8, r10, r11, and sp. Thus both r4 and r5 remain valid even if sum16 is replaced by another conforming implementation. bl changes the link processor register lr, so the enclosing function saves its own return address in its prologue. Its epilogue can use add sp,sp,#16 and pop {r4,r5,r6,pc}. The frame uses thirty-two bytes in total, preserving the required eight-byte stack pointer alignment at both calls.[ref]
The two calls may be evaluated in this order. Assume the product and final addition fit the signed 32-bit result expected by the source program; unlike each individual seven-element sum, their product need not fit. The assembly language operations retain their low 32 bits if this assumption fails, whereas signed integer overflow in the C programming language has different semantics.

Maintain the latest five temperature readings in a circular buffer, together with their running sum. The following C programming language code spells out the message passing interface rather than assuming a particular library: send(dst,&m) is a blocking synchronous message passing send; receive(src,&m) receives from the specified sender or ANY and returns the sender's identity; sendrec(dst,&m) atomically sends the request and waits for that sender's reply in the same message object. Successful, reliable operations are assumed. Message contents are copied by the interface.
enum { ANY = -1, TIMER = 1, TEMP = 2 };
enum { PULSE, PING, REQUEST, REPLY };
typedef struct {
    int type;
    int period_ms;
    double value;
} Message;

extern void send(int dst, const Message *m);
extern int receive(int src, Message *m);
extern void sendrec(int dst, Message *m);

void smooth(void) {
    double history[5] = {0};
    double sum = 0;
    int count = 0, next = 0;
    Message m = { .type = PULSE, .period_ms = 1000 };
    send(TIMER, &m);                 /* subscribe once */

    for (;;) {
        int sender = receive(count < 5 ? TIMER : ANY, &m);
        if (sender == TIMER && m.type == PING) {
            Message t = { .type = REQUEST };
            sendrec(TEMP, &t);       /* matching REPLY contains t.value */
            if (count == 5)
                sum -= history[next];
            else
                ++count;
            history[next] = t.value;
            sum += t.value;
            next = (next + 1) % 5;
        } else if (count == 5 && m.type == REQUEST) {
            Message answer = { .type = REPLY, .value = sum / 5.0 };
            send(sender, &answer);
        }
    }
}
Before the fifth reading, selective reception from TIMER prevents premature client requests from being accepted. Such clients wait at their synchronous sends; they are not given a partial arithmetic mean. Thereafter the operating-system process receives both timer messages and client requests. Each accepted PING initiates one measurement; each accepted client request returns the arithmetic mean of the five most recently completed measurements, without initiating another measurement or changing the circular buffer.
The loop invariant is that count is the number of valid readings, capped at five, sum is their sum, and next is the next unused slot during startup or the oldest slot afterwards. Removing the overwritten reading and adding the new one preserves this loop invariant. Each update and reply uses O(1) time complexity and O(1) storage, since the window length is fixed. Under timely sensor replies, timer delivery and process scheduling, measurements are initiated once per second. The next parts explain failures of these timing assumptions; the code does not promise one-second sampling when the sensor itself cannot sustain it.

b OurBigBook.com
With synchronous message passing, the smoothing operating-system process can still be waiting for TEMP when its next PING is due. If the timer service sends to subscribers serially, it blocks on this unready recipient and cannot deliver the other subscribers' ticks: one slow sensor can delay every timer client through head-of-line blocking. Once it resumes, implementations may deliver late ticks, drift from their schedule, or accumulate overdue work.
The consequence depends on the delivery model. With buffered sends the timer need not block immediately, but its queue can grow or overflow; the smoothing operating-system process still cannot process readings at a sustained rate faster than the sensor. A nonblocking notification mechanism or separate timer-delivery workers can isolate other subscribers, while coalescing missed ticks prevents an unlimited backlog. These changes do not make an over-slow sensor meet the original sampling rate.

c OurBigBook.com
With a synchronous reply, send(client,&answer) blocks until the client receives. An indefinitely unready client therefore stalls the smoothing operating-system process, which may in turn stall the timer service and its other clients as in the preceding part. If the client is merely delayed, this is blocking and delayed service; a deadlock requires a circular wait or a client that will never receive.
Requiring correctly used synchronous send-and-receive helps. A client calling sendrec(SMOOTH,&m) is committed to waiting for the matching reply as soon as its request has been accepted. This closes the scheduling window between a separate send and receive and prevents unrelated client computation from postponing that receive. It does not by itself fix slow measurements, arbitrary failures, circular dependencies between other services, or lack of CPU scheduling. With buffered replies the initial effect may instead be queue growth, depending on the message passing contract.

In a cooperative scheduler, a permanently runnable background operating-system process that never yields can monopolize the CPU. The timer service, smoothing operating-system process, and display may then fail to run even when their messages are ready. Correct message passing alone does not supply process scheduling.
Use timer-driven scheduling preemption, so an interrupt can force a context switch without cooperation. To give the measurement and display work bounded response despite background computation, use priority scheduling with the background operating-system process below the responsive services, or an explicit reservation policy. Round-robin scheduling gives CPU access among a fixed finite runnable set, but meeting a particular deadline additionally requires bounded service execution and sufficient CPU capacity.

Work over the field containing the stated n distinct eigenvalues of B; in a real formulation these must be real to obtain real eigenvectors. Choose one eigenvector for each distinct eigenvalue. By independence of eigenvectors for distinct eigenvalues, these n vectors are a basis. Consequently each eigenspace Eλ​(B) has dimension one: in an expansion in this eigenbasis, Bw=λw forces every coefficient with a different eigenvalue to vanish.
Now let v=0 be any eigenvector of B. By part (d), Av belongs to its one-dimensional eigenspace, so Av=μv for some scalar μ. This proves that v is an eigenvector of A, including the case Av=0, where μ=0. This is the crucial one-dimensional step in simple spectrum gives simultaneous diagonalization.

Use banded Gaussian elimination followed by back substitution. To distinguish the right-hand side from the upper-diagonal coefficients bi​, write it as ri​. If the modified pivot elements are nonzero, the tridiagonal elimination recurrences are
p1​=a1​,q1​=r1​,mi​=pi−1​ci−1​​,pi​=ai​−mi​bi−1​,qi​=ri​−mi​qi−1​(2≤i≤n).
(19)
They eliminate just the one entry below each pivot element. Solve the resulting upper bidiagonal matrix system by
xn​=qn​/pn​,xi​=(qi​−bi​xi+1​)/pi​(i=n−1,…,1).
(20)
There is a bounded number of arithmetic operations per row in each sweep, giving O(n) arithmetic operations and O(n) storage. The unpivoted recurrences cost 8n−7 arithmetic operations under the usual scalar-operation count.
For a general tridiagonal matrix, nonsingularity alone does not guarantee these pivot elements. If a zero or unsafe pivot element occurs, use partial pivoting between the current row and the next row. These are the only possible nonzero candidates in the current column; adjacent row swaps introduce at most a second upper diagonal. Tracking that fill-in keeps both Gaussian elimination and back substitution at O(n) arithmetic operations. For example, (01​10​) is invertible but requires a row swap. If the input is singular, report a zero final pivot element; a unique solution cannot be promised, and compatibility or free-variable analysis is a separate issue. No nonsingularity or safe-pivot assumption is silently inferred from the word tridiagonal.

The given logical implication is false exactly when A=B and C=D. For every literal on A,B,C,D, there is such a false Boolean valuation making that literal true. For a prescribed value of A or B, give the other the same value and choose C=D. For a prescribed value of C or D, give the other the opposite value and choose A=B.
Consequently no literal implies the whole propositional formula: there is no one-literal implicant. Even if auxiliary Boolean variables are allowed in the equivalent expression, a one-literal term on one of them fails too: fix any false Boolean valuation of the original four and set the auxiliary literal true. Use structural induction on the propositional formula. The induction claim is that its truth value under the all-one Boolean valuation is one. A variable has this truth value by definition. For the induction step, suppose the immediate subformulas α,β each have truth value one. Then
[[α∨β]]=1∨1=1,[[α∧β]]=1∧1=1,[[α→β]]=1→1=1.
