The map function transforms each head and recursively processes the tail. A right fold combines a head with the result for its tail, whereas a left fold passes an updated accumulator into the recursive call. In Haskell:
import Prelude hiding (map, foldr, foldl, concat)

map f [] = []
map f (x:xs) = f x : map f xs

foldr op e [] = e
foldr op e (x:xs) = op x (foldr op e xs)

foldl op e [] = e
foldl op e (x:xs) = foldl op (op e x) xs

concat = foldr (++) []
The last right fold uses list concatenation to replace each outer cons by appending its inner list. Thus concat [xs,ys,zs] = xs ++ (ys ++ (zs ++ [])). Its right fold association matters: appending a list traverses its left spine, so these equations traverse each inner spine once on finite inputs. The concise answer is
concat=foldr (++) [].​
(1)

Let P(zss) mean concat (map f zss) = f (concat zss). We use structural induction on lazy lists, including the bottom value and allowing arbitrary, possibly partial, inner lists.
For [], the left side is [] and the right side is f [] = []. For the bottom value ⊥, both map f and concat are strict functions in the outer spine, and the supplied strictness of f makes the right side f⊥=⊥ too.
For the cons case, assume P(zss) and write the new head as xs. The defining equations and the induction hypothesis give
concat(mapf(xs:zss))​=f(xs)++concat(mapfzss)=f(xs)++f(concatzss)=f(xs++concatzss)=f(concat(xs:zss)).​
(2)
The third equality is exactly the supplied list concatenation preservation law. No inspection of xs was required, so the argument includes partial inner lists and undefined elements.
This proves the identity for every finite outer spine ending in either [] or ⊥. In the usual pure Haskell semantics, these functions are Scott continuous maps. An infinite outer list is obtained as a limit by finite approximation of a lazy list; both composite functions preserve that limit. Equality on all its finite approximations therefore gives equality on the infinite outer list. Equivalently, P is an admissible predicate on lazy lists. Consequently
concat∘mapf=f∘concat.​
(3)
The continuity assumption is the usual semantic assumption for definable functions here; an extension from finite to infinite inputs cannot be justified by ordinary finite induction alone.

Let m,n be the two input lengths and suppose numeric comparisons cost constant time. The list-based set representation determines which representation invariant each answer must preserve.
For unsorted lists allowing repetition, retain every left-hand occurrence whose value appears on the right for set intersection, and use list concatenation for set union:
interR xs ys = [x | x <- xs, x `elem` ys]
unionR xs ys = xs ++ ys
The resulting lists represent exactly the desired sets; repeated entries are permitted. Membership by sequential search makes interR take O(mn) time complexity in the worst case. The list concatenation in unionR costs O(m) to build its copied left spine and shares ys; fully enumerating the resulting list costs O(m+n).
For unsorted, duplicate-free inputs, the same intersection keeps uniqueness, while the union retains xs and appends only right-hand elements absent from xs:
interU xs ys = [x | x <- xs, x `elem` ys]
unionU xs ys = xs ++ [y | y <- ys, not (y `elem` xs)]
Neither filtered list has internal repetitions, and the filter in unionU also excludes overlap with xs. Both operations have worst-case O(mn+m+n) time complexity, customarily written O(mn) when both lengths are positive. Using the original xs for each membership test avoids searching an ever-growing output.
For sorted, duplicate-free lists, compare only the two current heads:
interS [] ys = []
interS xs [] = []
interS (x:xs) (y:ys)
  | x < y = interS xs (y:ys)
  | x > y = interS (x:xs) ys
  | otherwise = x : interS xs ys

unionS [] ys = ys
unionS xs [] = xs
unionS (x:xs) (y:ys)
  | x < y = x : unionS xs (y:ys)
  | x > y = y : unionS (x:xs) ys
  | otherwise = x : unionS xs ys
When x<y, sortedness proves that x cannot occur anywhere in the right list, so it can be discarded from the set intersection or immediately emitted to the set union. The symmetric argument handles y<x; equal heads are consumed together. Each step consumes at least one input head, so both have O(m+n) worst-case time complexity. These bounds assume the sorted representation invariant is already established; sorting arbitrary inputs has its own cost.

Use permutation generation by insertion: recursively arrange the tail, then insert the removed head in every possible position.
inserts x [] = [[x]]
inserts x (y:ys) = (x:y:ys) : map (y:) (inserts x ys)

perms [] = [[]]
perms (x:xs) = concat (map (inserts x) (perms xs))
The map function in inserts prefixes y to each placement after the first position. For a list of length k, the number of results obeys I(0)=1 and I(k+1)=1+I(k), so mathematical induction gives I(k)=k+1. Every result still contains the same k old elements and the one inserted element.
Let P(n) be the length of perms xs for an input of length n. There is exactly one permutation of the empty list, namely the empty list itself: hence perms [] is [[]], with length one. For a nonempty input, each recursively obtained permutation has length n−1 and gives n placements. Thus
P(0)=1=0!,P(n)=nP(n−1),P(n)=n!.​
(5)
Length alone would not exclude repeated answers. Since the input elements are distinct, removing the distinguished element x from any result uniquely recovers both its placement and the shorter permutation. Hence different construction choices give different outputs, and every desired permutation is obtained by inserting x into its restriction to xs. For [a,b,c], this code yields [a,b,c], [b,a,c], [b,c,a], [a,c,b], [c,a,b], [c,b,a], each exactly once.

To agree with the example, preserve the first occurrence of each value. This first-occurrence duplicate removal is a right fold:
remalldups = foldr step []
  where step x ys = x : filter (/= x) ys
The folded tail has no repetitions by the induction hypothesis. The list filter removes any occurrence of the new head from that tail; prepending the head then gives exactly one occurrence of it, in its first input position. Other values retain their relative order. For the supplied example the intermediate folded results, from right to left, are [1], [3,1], [2,3,1], and [1,2,3]. Thus
remalldups[1,2,3,1]=[1,2,3].​
(6)
Under lazy evaluation, constructing x : ... does not first demand the folded tail. That observation is essential for the infinite cases below. The alternative step that first asks whether x belongs to the folded tail would lose this property and would also keep last occurrences instead of matching the stated example.

Assume a proper lazy list with defined elements and terminating equality tests. If infinitely many distinct values occur, first-occurrence duplicate removal produces an infinite list of distinct values, in first-occurrence order. To produce the next new value after k have appeared, the nested list filters need skip only a finite input prefix: an infinite collection of distinct values cannot all belong to the k already seen. The next new value therefore occurs at a finite position and is reached in finite work. Consequently
infinitely many distinct values ⟹ productive infinite output.​
(7)
This is a stream productivity claim, not a bounded-delay claim: arbitrarily long runs of repetitions can make successive delays arbitrarily large. Undefined elements or diverging equality tests invalidate the stated assumptions.

Each of the finitely many distinct values has a first occurrence at a finite position, so every one is eventually emitted. After the last new value, however, the list filters keep searching the remaining infinite input for another new value. They never observe a terminating []. Therefore the result has a finite visible prefix followed by the bottom value:
x1​:x2​:⋯:xk​:⊥,rather than [x1​,…,xk​].​
(8)
For example, remalldups (repeat 1) exposes 1 : ..., but demanding its tail diverges. This is the absence-detection obstruction for infinite lists: no finite inspection can certify that an unseen new value will never occur. The emitted values are correct, but computing the output length or proving the output empty after its last value does not terminate.

List concatenation exhausts one inner list before reaching the next. For example, with rows [0,2..] and [1], concat outputs the infinite even row and never reaches 1. First-occurrence duplicate removal cannot recover a value that its input stream never supplies. Hence
ordinary concatenation does not give a fair enumeration of infinite rows.​
(9)
The obstruction is separate from the undefined final tail in part (c): here a required distinct value is never emitted at all. A fair enumeration must give every row and every element within it a finite opportunity to contribute.

For two proper lazy lists, twiddle alternates heads, swapping which list is served after each output. Thus both input positions have finite waiting time. A tempting extension is remalldups . foldr twiddle [], but arbitrary empty rows make that insufficient: for [ [1,2] ] ++ repeat [], it emits 1 and then demands the combination of infinitely many empty rows before it can return to 2.
Use diagonal merging of lazy lists to avoid that obstruction. Maintain a finite active collection, add at most one new row per round, and take one head from every nonempty active row. The supplied twiddle combines those singleton contributions into a finite batch:
union' = remalldups . rounds []

rounds [] [] = []
rounds active [] = emit active []
rounds active (row:rows) = emit (active ++ [row]) rows

emit active rows = batch ++ rounds tails rows
  where (batch, tails) = sweep active

sweep [] = ([], [])
sweep ([]:rows) = sweep rows
sweep ((x:xs):rows) = (twiddle [x] heads, xs:tails)
  where (heads, tails) = sweep rows
Here rounds takes the finite active collection first and the not-yet-introduced outer list second. Because heads is a finite list, twiddle [x] heads emits x followed by those heads; the finite batch is then completely consumed before the next round. Empty exhausted rows are removed by sweep. No step tries to combine infinitely many not-yet-introduced rows.
Index rows and positions from zero. Row i is introduced in round i and contributes its element j in round i+j, if that element exists. Every earlier round inspects only finitely many rows. Therefore every occurrence has a finite emission time, proving fair enumeration. Applying first-occurrence duplicate removal gives
union′=remalldups∘finite-round diagonal enumeration.​
(10)
All outer and inner spines must be proper lazy lists and equality tests must terminate. Infinitely many empty rows after the final contribution still prevent certifying a terminating empty tail, just as part (c) predicts. Undefined input spines have the separate partial-list interleaving obstruction; the construction makes no promise to bypass them.

On two finite total lists, the equations agree. If either list is empty they return the other; if both have heads, expanding twiddle twice gives x : y : twiddle xs ys, exactly the third equation for twiddle'. The same finite-prefix reasoning proves agreement on infinite inputs with defined spines.
They differ on partial lists. Take the first argument [1] and the second argument ⊥. The original definition can emit its first head immediately:
twiddle [1] ⊥=1:twiddle ⊥ []=1:⊥.
(11)

twiddle′ [1] ⊥=⊥,twiddle′=twiddle.​

A divide-and-conquer algorithm splits an instance into smaller instances of the same kind, solves them recursively, and combines their answers. The smaller instances should be sufficiently smaller to ensure algorithm termination; the combination cost determines whether splitting saves work. The two halves of merge sort illustrate this separation.
Dynamic programming identifies a collection of subproblems and dependencies among them, solves each distinct subproblem once, and stores its answer. A table in dependency order or memoization prevents repeated evaluation of overlapping subproblems. For optimization, an optimal substructure argument justifies constructing an optimal answer from optimal smaller answers.
A greedy algorithm repeatedly makes a locally best feasible choice and commits to it. It avoids exploring alternative continuations. Algorithm correctness therefore needs a greedy-choice property, often proved by replacing the first choice of an optimal solution with the greedy choice without worsening it.
divide and combine; reuse subproblem answers; commit to safe local choices.​
(13)

Divide-and-conquer algorithms suit problems with largely independent, balanced subproblems and an inexpensive combination step. In merge sort, the two halves are independently sorted and merged in linear time. Its recurrence relation is T(n)=T(⌊n/2⌋)+T(⌈n/2⌉)+Θ(n), giving Θ(nlogn) time complexity.
Dynamic programming suits overlapping subproblems with a compact state description. For the coin change problem, let C(v) be the minimum number of coins needed to make amount v. With positive denominations D containing 1,
C(0)=0,C(v)=1+mind∈D, d≤v​C(v−d).
(14)
Every optimal nonempty answer has a last coin d and an optimal answer for v−d; otherwise replacing the remainder improves it. Filling C(0),…,C(V) takes O(V∣D∣) time complexity and O(V) space complexity. Repeated amounts are computed just once. This bound is in the numeric amount V, not its binary input length.
A greedy algorithm suits problems where one can prove a greedy-choice property. For unweighted interval scheduling, choose an interval with earliest finishing time, discard overlapping intervals, and repeat. Among optimal schedules, replace the first interval by the earliest-finishing one. The replacement finishes no later, so every later interval remains feasible. Applying the same argument to the remaining intervals proves optimality. After sorting by finish time, a single scan suffices.
These examples separate the relevant structural reasons: independent halves, repeated amount states, and an exchange argument certifying each irreversible choice.

In the coin change problem, take denominations {1,3,4} and target amount 6. The natural greedy algorithm repeatedly chooses the largest denomination not exceeding the remaining amount. It chooses 4, then 1, then 1, for three coins. Yet 3+3=6 uses only two.
Two is optimal: one coin cannot make 6 because denomination 6 is absent, and the displayed pair attains the lower bound. Therefore
greedy: 4+1+1 (3 coins);optimal: 3+3 (2 coins).​
(15)
The locally largest first coin loses the possibility of using the better pair of threes. This supplies a concrete failure of the greedy-choice property; optimal substructure alone does not justify the greedy choice. The dynamic programming recurrence from part (b) would compare all feasible first or last denominations and find the pair.

Heapsort uses Θ(n) time for bottom-up heap construction and O(logn) for each extraction, giving Θ(nlogn) worst-case time complexity. An iterative heapify down on an array uses O(1) auxiliary space complexity. Ordinary heapsort is not a stable sorting method.
Quicksort has balanced-case and average-case Θ(nlogn) time complexity when the input order supplies suitably distributed pivot ranks. With the prescribed first-element pivot, sorted inputs produce subproblems of sizes 0 and n−1, giving T(n)=T(n−1)+Θ(n)=Θ(n2). With the stated two-way partition convention, all-equal keys also give this worst case. There is no input-independent expected bound without a distribution or randomization assumption. For an in-place array implementation, the recursion stack is O(logn) when balanced and O(n) in the worst case; the functional list trace also allocates new partition spines and copied concatenation prefixes. Ordinary in-place quicksort is not stable sorting; the stable-partition list convention used in the trace can preserve equal-key order at additional allocation cost.
Counting sort uses Θ(n+k) time complexity for k possible consecutive integer keys. The stable sorting version uses Θ(n+k) auxiliary space complexity including the output array; counting and re-emitting bare keys needs only O(k) beyond its output. It is attractive when k is small, but a sparse huge key range makes both initialization and count storage expensive. It relies on indexing by bounded integer keys, so it is not subject to the comparison sorting lower bound.
heapsort: Θ(nlogn);quicksort worst case: Θ(n2);counting sort: Θ(n+k).​
(17)

An Oberon recursive procedure can implement the defining recurrence relation directly. Its precondition is n≥1; arithmetic is assumed to remain in the representable integer range.
PROCEDURE Fib(n: INTEGER): INTEGER;
  VAR result: INTEGER;
BEGIN
  IF n <= 2 THEN
    result := 1
  ELSE
    result := Fib(n-1) + Fib(n-2)
  END;
  RETURN result
END Fib;
Correctness follows by strong induction: the two base inputs give 1, and for n>2 the returned sum is Fn−1​+Fn−2​=Fn​. On each recursive branch the positive integer argument strictly decreases, while recursion stops at 1 or 2. The well-ordering principle therefore proves algorithm termination.
Fib(n)=Fn​(n≥1).​
(18)
The method repeats many subproblems and has exponential time complexity; termination alone does not make it efficient.

In tail recursion, each recursive call is a tail call: its result is returned directly, with no suspended addition or other work. A compiler can then reuse an activation record, giving constant stack use. This is a possible optimization, not a guarantee made by the source syntax. The direct Fibonacci number procedure in part (a) must retain information while waiting to add two recursive results.
Extend the Fibonacci numbers with F0​=0 and use the suggested quantity g(n,a,b)=aFn​+bFn−1​. For n>1,
aFn​+bFn−1​=(a+b)Fn−1​+aFn−2​=g(n−1,a+b,a),
(19)
while g(1,a,b)=a. This gives the Oberon procedures
PROCEDURE G(n, a, b: INTEGER): INTEGER;
  VAR result: INTEGER;
BEGIN
  IF n = 1 THEN
    result := a
  ELSE
    result := G(n-1, a+b, a)
  END;
  RETURN result
END G;

PROCEDURE FibTail(n: INTEGER): INTEGER;
BEGIN
  RETURN G(n, 1, 0)
END FibTail;
The assignment of the recursive result does not perform arithmetic after the call; it merely passes that result to RETURN, so the call is in tail recursion. A dialect permitting an immediate RETURN G(...) in the branch expresses the same control flow. The decreasing argument n−1 proves algorithm termination, and the displayed identity proves correctness by mathematical induction. Thus
Fn​=g(n,1,0),g(n,a,b)=g(n−1,a+b,a) (n>1).​
(20)
There are n−1 recursive steps, giving O(n) arithmetic operations. Stack use is O(1) with tail call elimination and O(n) without it. With unbounded integers, the growing Fibonacci numbers also make arithmetic costs grow; the linear bound counts arithmetic operations.

Replace the recursive transfer in part (b) by simultaneous state updates, using a temporary variable to preserve the old a:
PROCEDURE FibIter(n: INTEGER): INTEGER;
  VAR k, a, b, oldA: INTEGER;
BEGIN
  k := n; a := 1; b := 0;
  WHILE k > 1 DO
    oldA := a;
    a := a + b;
    b := oldA;
    k := k - 1
  END;
  RETURN a
END FibIter;
For original input N≥1, a loop invariant is
1≤k≤N,aFk​+bFk−1​=FN​.​
(21)
It holds initially because a=1,b=0,k=N. Each iteration preserves it by the identity from part (b). The loop variant is k−1, a nonnegative integer that decreases by one whenever the guard holds. On exit k=1, so the loop invariant gives aF1​+bF0​=a=FN​, exactly the returned answer. The procedure uses O(n) arithmetic operations and O(1) stored integer variables, without depending on compiler treatment of tail calls.

Represent the two recursively split arrays by adjacent half-open ranges of the original array. This avoids allocating a fresh pair at every call. The caller supplies a distinct work array with at least as many elements as a; only that work array is used for merging. The Oberon code is
PROCEDURE SortRange(VAR a, work: ARRAY OF INTEGER;
                    l, r: INTEGER);
  VAR m, i, j, k: INTEGER;
BEGIN
  IF r-l > 1 THEN
    m := l + (r-l) DIV 2;
    SortRange(a, work, l, m);
    SortRange(a, work, m, r);
    i := l; j := m; k := l;
    WHILE (i < m) & (j < r) DO
      IF a[i] <= a[j] THEN
        work[k] := a[i]; i := i+1
      ELSE
        work[k] := a[j]; j := j+1
      END;
      k := k+1
    END;
    WHILE i < m DO
      work[k] := a[i]; i := i+1; k := k+1
    END;
    WHILE j < r DO
      work[k] := a[j]; j := j+1; k := k+1
    END;
    k := l;
    WHILE k < r DO
      a[k] := work[k]; k := k+1
    END
  END
END SortRange;

PROCEDURE MergeSort(VAR a, work: ARRAY OF INTEGER);
BEGIN
  SortRange(a, work, 0, LEN(a))
END MergeSort;
For a range of length n>1, the left length is p=⌊n/2⌋ and the right length is q=⌈n/2⌉, so p≤q≤p+1 as required. Both are positive and smaller than n, giving the recursive loop variant analogue r−l for algorithm termination. Empty ranges are also harmless, although the question supplies a nonempty array.
For the first merge loop, regard the two sorted ranges as fixed input sequences B=a[l:m) and C=a[m:r). They are not overwritten during the merge. A loop invariant is that l≤i≤m, m≤j≤r, k−l=(i−l)+(j−m), and work[l:k) is the stable sorted merge of the consumed prefixes a[l:i) and a[m:j). Every emitted element is at most every remaining element. Taking the smaller head preserves this property, and choosing the left head on equality preserves stable sorting. The loop variant is
(m−i)+(r−j)=r−k.
(22)
It is nonnegative and decreases by one per iteration. On exit at least one range is exhausted.
For the second loop, the remaining left range is already sorted and any right remainder is absent whenever that loop runs. Appending the next left element preserves the same merge loop invariant; its loop variant is m−i. For the third loop, the left range is exhausted and the right remainder is appended in order; its loop variant is r−j. On completing both loops, work[l:r) is the complete sorted merge and k=r.
In the final copying loop, the loop invariant is that a[l:k) equals work[l:k), work[l:r) remains the correct sorted answer, and positions outside a[l:r) are unchanged. Its loop variant is r−k. At exit the whole answer has been copied back. By strong induction on range length, the recursive calls sort their halves, and the merge preserves the original multiset. Thus
MergeSort returns a sorted permutation of its input.​
(23)
The work array must not alias a: overwriting the source while merging would invalidate the merge loop invariant.

Each merge consumes and copies a total of n elements, so its time complexity is Θ(n). Hence
T(1)=Θ(1),T(n)=T(⌊n/2⌋)+T(⌈n/2⌉)+Θ(n).
(24)
At any level of the recursion tree, all active subranges are disjoint and together contain at most n elements. The total work per level is therefore O(n), and halving gives O(logn) levels. In fact the full run performs Θ(nlogn) work for n≥2.
The shared work array holds n elements, and the depth-first recursion has O(logn) simultaneous activation records with a constant number of scalar variables each. No recursive call allocates a fresh array. Therefore
time Θ(nlogn),auxiliary space Θ(n)+O(logn)=Θ(n).​
(25)
The work array is counted in the auxiliary space complexity even though the caller supplies it. If its actual allocated capacity is M>n, the reserved storage is Θ(M+logn); choosing capacity n gives the stated bound.

Use an Oberon record containing an active coefficient count and a bounded array of coefficients in ascending power order. A count of zero represents the zero polynomial; a count n+1 represents a0​+⋯+an​xn. Trailing zero coefficients are allowed, so the count need not be the degree of a polynomial plus one.
CONST Capacity = 1024;
TYPE Polynomial = RECORD
  len: INTEGER;
  coeff: ARRAY Capacity OF REAL
END;

PROCEDURE Horner(VAR p: Polynomial; x: REAL): REAL;
  VAR i: INTEGER; value: REAL;
BEGIN
  i := p.len; value := 0.0;
  WHILE i > 0 DO
    i := i-1;
    value := p.coeff[i] + x*value
  END;
  RETURN value
END Horner;
The representation invariant is 0≤len≤Capacity, with only indices below len significant. The parameter is passed by reference to avoid a full record copy; the procedure does not modify it.
Let L be the original coefficient count. At each guard test the loop invariant is
0≤i≤L,v=∑j=iL−1​aj​xj−i.
(26)
The empty sum is zero initially. If the old index is i>0, after decrementing and updating,
vnew​=ai−1​+x∑j=iL−1​aj​xj−i=∑j=i−1L−1​aj​xj−(i−1),
(27)
which preserves the loop invariant. The loop variant is i, decreasing by one until zero. At exit,
v=j=0∑L−1​aj​xj=p(x).​
(28)
This is exactly the right-to-left nesting of Horner's method, matching the supplied right fold. It uses O(L) arithmetic operations and O(1) additional scalar storage. REAL gives ordinary floating-point evaluation; the displayed identities specify the ideal arithmetic calculation, with the usual rounding in an actual floating-point implementation.

Add polynomials by adding equal-power coefficients, interpreting a missing coefficient as zero. Compute into a local record before assigning the output, so the result may safely be the same actual record as either input.
PROCEDURE Add(VAR p, q, result: Polynomial);
  VAR t: Polynomial; i: INTEGER; u, v: REAL;
BEGIN
  t.len := p.len;
  IF q.len > t.len THEN t.len := q.len END;
  i := 0;
  WHILE i < t.len DO
    u := 0.0; v := 0.0;
    IF i < p.len THEN u := p.coeff[i] END;
    IF i < q.len THEN v := q.coeff[i] END;
    t.coeff[i] := u+v;
    i := i+1
  END;
  result := t
END Add;
With L=max(p.len,q.len), the loop invariant is 0≤i≤L and, for 0≤k<i, t.coeff[k] is the sum of the two extended input coefficients at k. The loop variant is L−i. The inputs remain unchanged throughout the loop, and at exit every active coefficient is correct. The time complexity is O(L) for the active arithmetic; assigning the fixed-capacity record can additionally copy its full capacity.
For the product, each pair of input terms contributes ai​bj​xi+j. Initialize the active result to zero, then accumulate these pairwise contributions:
PROCEDURE Multiply(VAR p, q, result: Polynomial);
  VAR t: Polynomial; i, j, k: INTEGER;
BEGIN
  t.len := 0;
  IF (p.len > 0) & (q.len > 0) THEN
    t.len := p.len + q.len - 1
  END;
  (* Precondition: t.len <= Capacity. *)
  k := 0;
  WHILE k < t.len DO
    t.coeff[k] := 0.0; k := k+1
  END;
  IF t.len > 0 THEN
    i := 0;
    WHILE i < p.len DO
      j := 0;
      WHILE j < q.len DO
        t.coeff[i+j] := t.coeff[i+j]
                          + p.coeff[i]*q.coeff[j];
        j := j+1
      END;
      i := i+1
    END
  END;
  result := t
END Multiply;
The input representation invariants and the capacity precondition are assumed. No coefficient is accessed when either input is the zero polynomial. The initialization loop invariant says coefficients below k are zero; its loop variant is t.len-k.
For positive input lengths m,n, the outer loop invariant says that 0≤i≤m and each coefficient tk​ equals
∑0≤u<i​ ∑0≤v<nu+v=k​​au​bv​.
(29)
The inner loop invariant adds the contributions with u=i and 0≤v<j to that sum, while 0≤j≤n. The update adds exactly the next missing term at index i+j, preserving the inner loop invariant. The loop variants are m−i for the outer loop and n−j for the inner loop. On exit all pairs have contributed, yielding
(p+q)k​=ak​+bk​,(pq)k​=i+j=k∑​ai​bj​.​
(30)
The product uses O(mn+m+n) arithmetic operations and a temporary coefficient array of capacity Capacity. Both operations allow trailing zeros; no extra normalization loop is required. Only the active coefficients are meaningful, so inactive record entries are never read by these operations. As in part (a), floating-point coefficients implement these formulas subject to rounding.

Write x↑y=¬(x∧y) for a two-input NAND gate. Three elementary constructions are
¬x=x↑x,x∧y=(x↑y)↑(x↑y),x∨y=(x↑x)↑(y↑y).
(31)
The last identity is De Morgan's laws. To see that these operations suffice from first principles, take any finite truth table. For each row whose output is 1, form the conjunction of input literals that matches exactly that row: use xi​ when the row has xi​=1, and ¬xi​ when it has xi​=0. Disjoin all such conjunctions. On any input, precisely its matching row conjunction can be true, so this disjunctive normal form equals the desired Boolean function.
Replace each negation, conjunction and disjunction by the displayed NAND gate constructions, nesting two-input gates for longer conjunctions or disjunctions. Constant outputs are available too: for any input x, x↑(x↑x)=1, and NANDing that value with itself gives 0. Thus
NAND alone is functionally complete for Boolean functions of positive arity.​
(32)
A zero-input constant circuit additionally needs a supplied constant signal, such as a fixed logic supply. The positive-arity construction already covers constant-valued Boolean functions having one or more unused inputs.
For a three-input CMOS NAND gate, put three PMOS transistors in parallel from the positive supply VDD​ to the output Y, and three NMOS transistors in series from Y to ground. Each input controls one device in each network:
A high input turns on its NMOS transistor and turns off its PMOS transistor; a low input does the opposite. If A=B=C=1, every series NMOS transistor conducts and every PMOS transistor is off, pulling Y low. If any input is zero, its NMOS transistor breaks the series path and its PMOS transistor provides a path to VDD​, pulling Y high. Consequently
Y=ABC.​
(33)
For ideal settled inputs, the complementary networks do not simultaneously connect supply to ground. The CMOS arrangement gives a driven high or low output in every input case, rather than leaving the output floating.

A D flip-flop stores one bit. At its specified active clock edge, it samples D and, after its clock-to-Q delay, makes Q equal to that sampled value. Between active clock edges it retains the stored value. The input must meet the setup and hold time requirements around the sampling edge; a level-sensitive latch would have different behavior.
For a finite-state sequential circuit, encode the present state in a bank of D flip-flops. Feed their outputs q and the external inputs u to combinational logic computing the next-state function F(q,u), and connect those outputs to the flip-flop D inputs. A common clock signal then performs the simultaneous update
q+=F(q,u).​
(38)
Output combinational logic computes H(q) for a Moore machine or H(q,u) for a Mealy machine. Since any finite next-state and output table is a Boolean function, it has a Boolean circuit implementation. Initialization specifies the starting state, and unused state encodings require either a recovery rule or an initialization assumption. The clock period must accommodate propagation through the D flip-flops and intervening combinational logic before the next sampling edge.

A particularly transparent design uses six D flip-flops in a one-hot encoding. Let Qi​=1 mean that face i is displayed. Initialize Q1​=1 and Q2​=⋯=Q6​=0, and wire the next-state inputs as a ring:
D1​=Q6​,D2​=Q1​,D3​=Q2​,D4​=Q3​,D5​=Q4​,D6​=Q5​.​
(39)
All six D flip-flops share the same active clock edge. Each pulse moves the single stored 1 to the next position, giving the state-transition diagram cycle 1→2→3→4→5→6→1. The representation invariant “exactly one Qi​ is high” holds after initialization and is preserved by rotation. Six D flip-flops are more than the three-bit theoretical minimum, but their simple wiring gives a complete implementation without requiring that minimum.
Decode the seven lamps by their positions, with T,M,B denoting top, middle and bottom, and L,R denoting left and right. Let LC​ be the center lamp. In the original figure, face 2 uses top-left and bottom-right, while face 3 uses top-right and bottom-left plus center; the two diagonals must therefore have different controls.[ref] The required OR gate decoder is
LTL​=LBR​LTR​=LBL​LML​=LMR​LC​​=Q2​∨Q4​∨Q5​∨Q6​,=Q3​∨Q4​∨Q5​∨Q6​,=Q6​,=Q1​∨Q3​∨Q5​.​​
(40)
For example, only the center is high in state Q1​, the first diagonal is high in state Q2​, and in state Q6​ both outer columns are high while the center is low. This verifies all six layouts directly.
To implement the switch behavior, use a rapid common clock signal and a sampled enable S, high while the switch is pressed. Each next-state input is then selected between its advancing value and its own stored value:
Di​=(S∧Qprev(i)​)∨(S∧Qi​),prev(1)=6,prev(i)=i−1 (i>1).​
(41)
One multiplexer per D flip-flop implements that selection. While enabled the electronic dice advances; otherwise every D flip-flop reloads its own value and the display holds. The enable supplied to this synchronous design must be stable at sampling edges. A reset or preset facility must establish the specified one-hot initial state: an all-zero ring does not start itself.
With a rapid clock signal, uncertainty in human release timing makes the final face practically unpredictable. The sequential circuit itself is deterministic; this observation alone is not a proof that its six outcomes have equal probabilities.
