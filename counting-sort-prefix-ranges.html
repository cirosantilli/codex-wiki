Counting sort prefix ranges ([Sk​,Pk​))

 Home Computer science Algorithm Sorting algorithm Counting sort
OurBigBook.com Words: 278
For n≥0 sorting records with integer sort keys in {0,…,K−1}, where K≥1, let ck​ count the input occurrences of sort key k. Define two prefix sums:
Sk​=∑h=0k−1​ch​,Pk​=∑h=0k​ch​=Sk​+ck​.
(35)
The empty sum gives S0​=0. Here ck​,Sk​,Pk​ are counts of sorting records. Exactly Sk​ sorting records have smaller sort keys, so the output positions for sort key k form the half-open integer interval
{j∈Z:Sk​≤j<Pk​}=[Sk​,Pk​)∩Z.
(36)
Its right endpoint Pk​ is excluded: the last occupied array index is Pk​−1 when ck​>0.[ref]
For the seven-sorting record example, the frequency array, inclusive cumulative count array, and start array are
c=(2,1,3,1),P=(2,3,6,7),S=(0,2,3,6).
(37)
Thus sort keys zero, one, two and three occupy the integer intervals [0,2), [2,3), [3,6) and [6,7), respectively. In particular, the three sorting records with sort key two belong at array indices three, four and five. The inclusive cumulative count P2​=6 counts all six sorting records with sort keys at most two; six is the exclusive endpoint, not the final position of a sorting record with sort key two.
These integer intervals fit together because Pk​=Sk+1​ for k<K−1, and PK−1​=n. Their lengths Pk​−Sk​=ck​ add to n, so they partition all output positions without overlaps or gaps. An absent sort key contributes an empty integer interval: with frequencies (0,2,0,1), the endpoints are (0,2,2,3) and sort key two has range [2,2). For empty input, every count and endpoint is zero; every reserved integer interval is empty. This makes the same formulas cover missing sort keys and the empty case.
