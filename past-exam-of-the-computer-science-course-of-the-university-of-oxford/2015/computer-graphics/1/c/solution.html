Multiply the midpoint line decision by two to remove the fraction. At the current pixel (x,y), maintain
d=2f(x+1,y+1/2)=2Δy(x+1−x0​)−2Δx(y−y0​)−Δx.
(5)
At the initial endpoint this is d0​=2Δy−Δx. If E is chosen, the next decision midpoint is displaced by (1,0) and d increases by 2Δy. If NE is chosen, its displacement is (1,1) and d increases by 2(Δy−Δx). Both increments are constant, so the per-pixel work uses only integer arithmetic:
d0​=2Δy−Δx,incrE=2Δy,incrNE=2(Δy−Δx).​
(6)
The completed code, using the tie rule of part (b), is:
void midpointLine(int x0, int y0, int x1, int y1)
{
    int dx, dy, incrE, incrNE, d, x, y;
    x = x0; y = y0;
    dx = x1 - x0;
    dy = y1 - y0;
    incrE = 2 * dy;
    incrNE = 2 * (dy - dx);
    d = 2 * dy - dx;
    drawPoint(x, y);

    while (x < x1) {
        if (d < 0) {
            d += incrE;
        } else {
            d += incrNE;
            y++;
        }
        x++;
        drawPoint(x, y);
    }
    return;
}
Thus guard1 is x < x1, and guard2 is d < 0. Multiplication by two is the only multiplication. Signed decision variables are convenient because d and incrNE can be negative; this remains an integer arithmetic algorithm. A strictly unsigned hardware representation would need an equivalent biased or separated-sign encoding. As with the printed int skeleton, assume all intermediate values fit the chosen type; integer overflow would invalidate the mathematical decisions.
To verify the geometry, write k=x−x0​. The chosen ordinate is
y(x)=y0​+⌊2Δx2Δyk+Δx​⌋.
(7)
The midpoint line decision selects exactly this nearest integer, rounding halves upward. Its increment between successive columns is zero or one. At k=0 and k=Δx, it gives exactly y0​ and y1​, respectively, so both endpoints are included and the line segment has precisely Δx+1 distinct pixels.
For the illustrated endpoints (1,1) and (9,4), the ordinates are 1,1,2,2,3,3,3,4,4. In particular the exact ordinate at x=5 is 5/2, and the chosen pixel is (5,3).
