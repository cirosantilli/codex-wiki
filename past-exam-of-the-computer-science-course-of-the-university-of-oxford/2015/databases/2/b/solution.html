A simple valid database query plan uses a block nested-loop join with the salesperson records on the outside, checking both sale conditions during the same inner scan. It avoids materializing the potentially much larger set of matching sale pairs.
  • Read a block of salesperson records. Retain each empid, its name, and two initially false flags, one for each target price.
  • Scan all of Sales. Apply relational selection to disregard other prices. For each retained sale, match salespersonid against the identifiers in the current outer block, and set the corresponding price flag. Several matching sales only set the same flag again.
  • After the inner scan, output the names of outer records with both flags true. Repeat for the next outer block, then eliminate repeated names to implement set semantics.
Let p≤SPT be the actual number of salesperson data pages and k the number of outer data pages that fit along with the flags and working buffers. With the usual convention of B−2 outer pages, one inner input page and one output page, take k=B−2 for B≥3. If flag storage requires an extra reserved page, reduce k accordingly. The number of outer records is at most pSPR, and there are ⌈p/k⌉ outer blocks. Every such block requires a complete scan of the ST sales data pages.
Count a database page read or write as one I/O. Conservatively charge HSP​ to locate the first salesperson leaf and HS​ to locate the start of each inner scan; this permits a small double charge if a definition of height includes a data leaf. The estimated read cost is
Cread​=HSP​+p+⌈kp​⌉(HS​+ST),p≤SPT.​
(12)
In the common convention that scan startup and cached internal pages are ignored, the usual upper estimate is
SPT+⌈B−2SPT​⌉ST.​
(13)
For an empty outer input there are no inner scans. This database query plan requires neither a sorted sale input nor a price index. In particular, the clustered database index on invoiceno cannot locate records by price. The quantities TN and THO describe the amount of qualifying data; they do not justify replacing a complete scan cost ST by TN+THO. They can bound the retained work within each scan by roughly (TN+THO)SR sale records, if those page counts describe packed qualifying records. Comparison cost against the outer block is CPU work rather than additional I/O.
Finally let Dδ​ be the extra I/O for eliminating repeated output names, including any temporary writes and reads, and let w be the final result size in database pages if materialization is required. The total estimate is
C=Cread​+Dδ​+w.​
(14)
If enough additional memory is available to retain all distinct qualifying names while producing the stream, then Dδ​=0. This extra memory is an additional assumption, separate from the B join buffers. More generally, for q pages of raw qualifying names, external merge sort gives Dδ​=O(q[1+logB−1​max{1,⌈q/B⌉}]) for B≥3, including spooling. Names can be deduplicated during the merges. Counting this work matters because a database primary key on empid does not make names unique. No claim of optimality is needed for this database query plan.
