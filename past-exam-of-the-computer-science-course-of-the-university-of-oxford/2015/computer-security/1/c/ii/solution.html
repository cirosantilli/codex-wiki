For each candidate nonzero offset k∈{1,…,216−1}, expansion gives
Dk​Nk​​=c2​−c1​+2k3≡3k(m2+km+k2),=k(c2​+2c1​−k3)≡3km(m2+km+k2).​
(11)
Consequently, if Dk​ is invertible, the candidate is
mk​≡k(c2​+2c1​−k3)(c2​−c1​+2k3)−1(modn).​
(12)
Compute the modular multiplicative inverse using the extended Euclidean algorithm, then verify both mk3​≡c1​ and (mk​+k)3≡c2​(modn). The RSA cryptosystem cubing map is a bijection, so an accepted candidate cannot be a different plaintext with the same first ciphertext. This costs fewer than 216 trials, each involving polynomially many operations in the bit length of n.
There is a useful way to handle every denominator exception for a correct nonzero k. Compute g=gcd(Dk​,n). If 1<g<n, this greatest common divisor factors n, allowing ordinary RSA cryptosystem decryption. If g=n, then Dk​=0(modn). The permitted prime numbers are 2(mod3) and much larger than k, so k is invertible modulo each. The equation m2+km+k2=0 would make m/k a nontrivial cube root of one, impossible in a group of order coprime to three. Thus g=n cannot occur for the correct nonzero offset under these hypotheses.
If the bound in the question is read as also allowing k=0, then c1​=c2​ and there is no additional information: the problem reduces to inverting a single ordinary RSA cryptosystem ciphertext. The small-offset attack requires a nonzero difference; that is the natural reading of distinct related messages.
