Three advantages of integer arithmetic for raster graphics are:
  • Cheap, fast operations. Historically, integer addition, subtraction and shifts needed much less hardware and execution time than floating-point arithmetic, especially on machines without a floating-point unit. An incremental Bresenham's line algorithm needs only a few additions and a decision per pixel.
  • Exact decisions. Provided integer overflow is excluded, the scaled midpoint line decision is exact. There is no accumulated rounding error that can move a decision across a half-pixel boundary; equality has a reproducible tie rule.
  • Simple storage and hardware. Integer coordinates already identify pixels. An implementation can keep coordinates and decision variables in ordinary registers and use a small add/compare datapath, avoiding conversion between floating-point numbers and integer screen addresses.
These are historical and structural advantages, not a claim that every modern processor executes every integer operation faster. An integer implementation still needs sufficient width for its intermediate results. The compact answer is
fast elementary operations; exact decisions; simple hardware and storage.​

By exchanging axes, reversing endpoint order and reflecting coordinate signs where necessary, reduce a general line segment to the first octant:
Δx=x1​−x0​>0,0≤Δy=y1​−y0​≤Δx,m=ΔxΔy​∈[0,1].
(2)
The vertical case is handled by exchanging axes. In this octant, increasing x by one requires increasing y by either zero or one. Thus, from the currently plotted pixel (x,y) the candidates are E=(x+1,y) and NE=(x+1,y+1).
Use the implicit equation of the line
f(X,Y)=Δy(X−x0​)−Δx(Y−y0​).
(3)
At a fixed X, f(X,Y)>0 means that (X,Y) lies below the exact line. The midpoint line decision evaluates M=(x+1,y+1/2), halfway between the two candidate pixel centres. If f(M)<0, the exact line lies below M, so choose E; if f(M)>0, choose NE. At equality either candidate is equally near, but a fixed tie rule is essential. We choose NE on a tie throughout these solutions:
f(x+1,y+1/2)<0⇒E;f(x+1,y+1/2)≥0⇒NE.​
(4)
This chooses the closest vertical-grid pixel centre in each column, with ties rounded upward. Since 0≤m≤1, the result has one pixel per column and consecutive pixels share an edge or a corner.

Multiply the midpoint line decision by two to remove the fraction. At the current pixel (x,y), maintain
d=2f(x+1,y+1/2)=2Δy(x+1−x0​)−2Δx(y−y0​)−Δx.
(5)
At the initial endpoint this is d0​=2Δy−Δx. If E is chosen, the next decision midpoint is displaced by (1,0) and d increases by 2Δy. If NE is chosen, its displacement is (1,1) and d increases by 2(Δy−Δx). Both increments are constant, so the per-pixel work uses only integer arithmetic:
d0​=2Δy−Δx,incrE=2Δy,incrNE=2(Δy−Δx).​
(6)
The completed code, using the tie rule of part (b), is:
void midpointLine(int x0, int y0, int x1, int y1)
{
    int dx, dy, incrE, incrNE, d, x, y;
    x = x0; y = y0;
    dx = x1 - x0;
    dy = y1 - y0;
    incrE = 2 * dy;
    incrNE = 2 * (dy - dx);
    d = 2 * dy - dx;
    drawPoint(x, y);

    while (x < x1) {
        if (d < 0) {
            d += incrE;
        } else {
            d += incrNE;
            y++;
        }
        x++;
        drawPoint(x, y);
    }
    return;
}
Thus guard1 is x < x1, and guard2 is d < 0. Multiplication by two is the only multiplication. Signed decision variables are convenient because d and incrNE can be negative; this remains an integer arithmetic algorithm. A strictly unsigned hardware representation would need an equivalent biased or separated-sign encoding. As with the printed int skeleton, assume all intermediate values fit the chosen type; integer overflow would invalidate the mathematical decisions.
To verify the geometry, write k=x−x0​. The chosen ordinate is
y(x)=y0​+⌊2Δx2Δyk+Δx​⌋.
(7)
The midpoint line decision selects exactly this nearest integer, rounding halves upward. Its increment between successive columns is zero or one. At k=0 and k=Δx, it gives exactly y0​ and y1​, respectively, so both endpoints are included and the line segment has precisely Δx+1 distinct pixels.
For the illustrated endpoints (1,1) and (9,4), the ordinates are 1,1,2,2,3,3,3,4,4. In particular the exact ordinate at x=5 is 5/2, and the chosen pixel is (5,3).

The verifier can check the final geometric criterion directly, independently of the incremental decision variable. Set dx=x1​−x0​, dy=y1​−y0​, and define the scaled vertical residual
e=2dy(x−x0​)−2dx(y−y0​).
(8)
The exact line ordinate is y∗​=y0​+dy(x−x0​)/dx, so e=2dx(y∗​−y). Nearest-integer selection with upward ties is precisely
x0​≤x≤x1​,−dx≤e<dx.​
(9)
The strictness matters: at a half-integer ordinate the upper pixel has e=−dx and passes, whereas the lower pixel has e=dx and fails. Each column has exactly one accepted integer ordinate.
With reject() terminating verification unsuccessfully, suitable outline code is:
void checkPoint(int x, int y)
{
    Wide a = Wide(x) - x0;
    if (a < 0) reject();                    // inequality 1
    Wide b = Wide(x1) - x;
    if (b < 0) reject();                    // inequality 2

    Wide dx = Wide(x1) - x0;
    Wide dy = Wide(y1) - y0;
    Wide e = 2 * dy * a - 2 * dx * (Wide(y) - y0);
    Wide lower = e + dx;
    if (lower < 0) reject();                // inequality 3
    Wide upper = dx - e;
    if (upper <= 0) reject();               // inequality 4

    counter[x]++;
}
Wide denotes a signed integer type large enough for the products and differences, with conversion before subtraction. These are exactly four inequalities against zero, all applied to named integer variables. The arithmetic restriction on the drawing loop in part (c) does not restrict multiplication in this verifier. The screen endpoints are assumed valid, with 0≤x0​<x1​<MAX_SCREEN_WIDTH and valid endpoint ordinates, so indexing is safe after the first two checks. These endpoint and screen preconditions belong in initialization if they are not guaranteed by the caller.
No separate y-range tests are needed: for x between the endpoints, y∗​ lies in [y0​,y1​], and its nearest integer lies in the same interval because both bounds are integers. The counters defer detection of omissions and repetitions to part (e). As for every finite counter, use adequate capacity or a sticky failure on overflow; saturating each counter at two also suffices because only zero, one, and “more than one” matter.

After every proposed pixel has passed part (d), insist on exactly one call in every column of the closed endpoint interval:
void final()
{
    for (int x = x0; x <= x1; x++) {
        if (counter[x] != 1) reject();
    }
    accept();
}
Part (d) already rejected every out-of-range column and every incorrect ordinate. A zero counter now detects an omitted column; a counter greater than one detects a repeated call in that column. Because the residual interval in part (d) allows exactly one integer ordinate in each column, accepted calls in a repeated column must address the same pixel. Conversely, a counter of one in every column forces the complete set of nearest pixels, including both endpoints. Consecutive correct columns differ in ordinate by at most one, which proves that there are no gaps in the resulting thin line segment.
The verifier certifies the final plotted set; it need not require calls to arrive in increasing x order. Its final condition is simply
counter[x]=1for every x=x0​,…,x1​.​

Represent a point by the column of homogeneous coordinates (X,Y,Z,1)T. The actions of the four matrices are:
MatrixGeometric action and parameters
G(θ)A proper rotation about the x-axis: (X,Y,Z)↦(X,Ycosθ−Zsinθ,Ysinθ+Zcosθ). The angle θ is in radians, with the usual right-hand sense.
H(x,y,z)A translation by (x,y,z): (X,Y,Z)↦(X+x,Y+y,Z+z).
J(λ)Uniform scaling by λ: (X,Y,Z)↦(λX,λY,λZ). Positive λ gives a uniform dilation; λ=0 collapses the object to the origin; negative λ additionally reverses its direction through the origin.
K(f)Perspective projection from the origin onto the plane Z=f, where f=0 is the focal length in the chosen coordinate units.
The last operation produces (X,Y,Z,Z/f)T. It requires a perspective divide: divide the first three components by the last. For Z=0,
K(f):(X,Y,Z)⟼(ZfX​,ZfY​,f).​
(11)
This is why the last component of homogeneous coordinates cannot simply be discarded. Points with Z=0 have no finite projected position, and a visible scene normally uses Z>0 under this forward-axis convention. The first three transformations leave the last component equal to one and need no nontrivial divide. The displayed K retains no depth variation after division; it describes projection onto the image plane, rather than a complete depth-buffer mapping.

In the solid-modelling convention used here, a rigid-body transformation is an orientation-preserving rigid transformation, represented by a proper rotation and a translation. The proposed upper-left block S is orthogonal but has
S=​010​100​001​​,STS=I,detS=−1.
(16)
It is a reflection in the plane x=y. It preserves distances, but reverses handedness, so it cannot describe continuous motion of a rigid solid through proper rotations and translations. Some mathematical uses of rigid transformation include this orientation-reversing case; the determinant is the distinction relevant to the warning.
In a solid modeller, triangle winding and outward normal vectors must agree. A reflection reverses the winding: for edge vectors a,b,
(Sa)×(Sb)=det(S)S(a×b)=−S(a×b).
(17)
Simply transforming stored normal vectors by S while retaining the original vertex order therefore makes the geometric and stored normals disagree. Back-face culling, inside/outside tests and Phong reflection model calculations can then use the wrong side. Code assuming a positive oriented volume can likewise interpret the reflected solid incorrectly. A modeller can support reflections if it deliberately corrects these orientation conventions.
A suitable alternative rotates by −π/2 about z and then translates upward by height. Writing h=height,
T=​0−100​1000​0010​0h01​​,(x,y,z)↦(y,h−x,z).​
(18)
Its rotation matrix has determinant +1. The source bounds 0≤x≤h, 0≤y≤w, z=0 become 0≤x′≤w, 0≤y′≤h, z′=0, where w=width. A horizontal stripe y=kstep becomes the vertical stripe x′=kstep, so even the stripe positions from the left edge are preserved. The face's +z normal vector is also preserved.

Ry​(−π/2)Rz​(−π/2)=​0−10​001​−100​​,(x,y,z)↦(−z,−x,y),

Rz​(−π/2)Ry​(−π/2)=​001​100​010​​=P3×3​.​

At a surface point p, let N^ be the outward unit normal vector, V^ the unit vector from p toward the viewer, and L^ the unit vector from p toward the light. The incoming propagation direction is therefore −L^. The specular reflection direction R^ points away from the surface along the ideal reflected ray.
Resolve L^ into its normal and tangential components:
L^=(N^⋅L^)N^+(L^−(N^⋅L^)N^).
(25)
Reflection of the incoming direction preserves its tangential component and reverses its normal component. Equivalently, the outgoing direction has the same normal component as L^ and the opposite tangential component, giving
R^=2(N^⋅L^)N^−L^.​
(26)
The dot product identity shows ∥R^∥=1 when ∥L^∥=∥N^∥=1.
In the Phong reflection model, ambient lighting approximates unmodelled indirect illumination and is independent of these directions. The diffuse term models Lambertian reflectance and varies as max(0,N^⋅L^). The specular term models a highlight around R^ and varies as max(0,R^⋅V^)n, where n>0 controls its sharpness. For a visible front surface, a convenient per-colour-channel equation is
I=ka​Ia​+IL​[kd​max(0,N^⋅L^)+ks​χmax(0,R^⋅V^)n],​
(27)
where Ia​ is ambient illumination, IL​ is the source strength at the surface including any chosen attenuation, ka​,kd​,ks​≥0 are material weights, and χ is one when N^⋅L^>0 and zero otherwise. The weights can be colour-dependent. An idealized point source's incident strength decreases as inverse distance squared; the empirical equation can also use a prescribed attenuation law.
In degenerate geometric cases the effective weights switch off. A light behind or tangent to the surface contributes neither direct diffuse nor specular illumination. If R^⋅V^≤0, the specular term is zero. A viewpoint on the back side is rejected by back-face culling for a one-sided surface. A material with no highlight has ks​=0; with no diffuse response, kd​=0; without ambient illumination the ambient term vanishes. These zeros do not require renormalizing the other weights, and the empirical Phong reflection model does not impose a universal condition ka​+kd​+ks​=1. At coincident light/surface or eye/surface positions a direction cannot be normalized; such singular configurations require a separate convention, rather than substituting an undefined unit vector into the formula.

A bidirectional reflectance distribution function, or BRDF, describes how a surface scatters incident illumination into each outgoing direction. At a fixed surface point p and wavelength, its inputs are two directions above the surface, ωi​ toward the incident source and ωo​ toward the observer; equivalently these are two pairs of angular coordinates. Its output is the ratio of differential reflected radiance to differential incident irradiance:
fr​(p,ωi​,ωo​)=dEi​(p,ωi​)dLo​(p,ωo​)​,[fr​]=sr−1.​
(28)
Position and wavelength may be additional arguments when material properties vary. A colour implementation can return one value per colour channel. The BRDF is a material response, not the final outgoing light value: it must be combined with the incident illumination and the projected-angle factor.[ref]
For incident radiance Li​, the reflection part of the rendering equation is
Lo​(p,ωo​)=∫Ω+​fr​(p,ωi​,ωo​)Li​(p,ωi​)(N^⋅ωi​)dωi​.
(29)
Emission is added separately if the surface itself emits. This integral explains how a BRDF replaces the assumed material response of a local lighting model. For Lambertian reflectance, fr​=ρd​/π, so the cosine factor yields the diffuse term from part (a). A directional specular lobe supplies a highlight. The empirical Phong reflection model is an approximate angular-response model of this kind; its original direct specular term is not automatically a normalized, energy-conserving BRDF. The ambient term approximates missing illumination and is not itself a third direction-independent material scattering mechanism. More general BRDFs can reproduce measured surface behaviour, while illumination from other surfaces supplies indirect light in the rendering equation.

For single-shot ray tracing, construct one primary ray per pixel, normally through its centre on the image plane, with the camera centre as origin for perspective projection. Transform the ray into the scene's coordinates, or consistently transform all the scene geometry into camera coordinates.
Intersect that primary ray with the scene's triangles, using part (c), and retain the accepted hit with the smallest nonnegative parameter λ. This nearest-hit selection supplies visibility: farther surfaces cannot show through the first opaque surface. If there is no hit, write the background colour. At a hit p, obtain its material colour and front unit normal vector and set V^ toward the camera.
For each point light at ℓj​, form L^j​=(ℓj​−p)/∥ℓj​−p∥, calculate the specular reflection direction, and evaluate its diffuse and specular contributions using the Phong reflection model. Sum the contributions and add ambient illumination once:
I(p)=ka​Ia​+j∑​Ij​(p)[kd​max(0,N^⋅L^j​)+ks​χj​max(0,R^j​⋅V^)n].​
(35)
The coloured surface can supply colour-dependent diffuse weights, and each source can have its own colour. Convert the result into the output image's colour encoding and range. Single-shot here means direct local shading after one primary visibility ray; no reflected or transmitted secondary viewing rays are followed. Part (e) adds secondary visibility queries for the lights.

A bounding volume hierarchy is a tree whose leaves contain geometric primitives, here triangles, and whose internal nodes store cheap-to-test bounding volumes containing all descendant geometry. A bounding volume may be an axis-aligned bounding box or a sphere. The key containment guarantee is
ray misses a node’s bounding volume⇒ray misses every triangle below that node.​
(38)
Traverse from the root. Reject a whole subtree when its bounding volume is missed; otherwise visit its children and perform the full ray-triangle intersection test only at surviving leaves. Hitting a bounding volume is only permission to investigate, not evidence of hitting an enclosed triangle.
For nearest-hit queries, visit the nearer child first and keep the current nearest parameter. A second child whose volume begins farther away than this parameter can be pruned. For a shadow ray, restrict the traversal to the segment before the source and terminate at any blocker.
A flat list of N triangles needs up to N detailed tests per primary ray or shadow ray. A well-built bounding volume hierarchy can reject large groups with a few cheap tests and substantially reduce the average work. A balanced, well-separated scene often gives traversal resembling a short root-to-leaf search, but balance alone does not guarantee logarithmic query time: extensive overlap or an unfortunate ray can force examination of most or all leaves. Its advantage is spatial rejection, not a universal worst-case bound.

Path tracing estimates the rendering equation by a Monte Carlo method. Launch camera rays; at each surface hit sample an outgoing continuation direction according to a chosen probability density function, trace to the next hit, and continue through successive reflections. Accumulate emitted light or environment light with the product of scattering, cosine and inverse-density factors along the path. A bounce sampled with density p(ω) updates the path weight by
β←βp(ω)fr​(ω,ωo​)∣N^⋅ω∣​.​
(39)
Average many independently sampled paths per pixel. Multiple bounces account for indirect illumination, including colour bleeding between surfaces, instead of approximating all of it by one ambient constant. Termination can use Russian roulette: continue with probability q>0 and divide surviving weights by q, preserving the expected contribution. A fixed bounce cutoff is simpler but truncates transport.
The elementary strategy that obtains illumination only when a randomly continued path hits an emitter fails for ideal point lights. From a surface point, an ideal point source occupies zero solid angle; sampling a direction from an ordinary continuous probability density function hits that one direction with probability zero. Thus this strategy almost surely never discovers the light, regardless of the number of samples. An area emitter occupies nonzero solid angle and can be hit.
The qualification matters: practical path tracing can use point lights by explicitly sampling a source and connecting the current surface to it with a shadow ray, a technique called next-event estimation. For a point source the connection direction is known exactly, rather than discovered by a random hemisphere hit. Thus the restriction applies to naive emitter-hit path tracing, not to all path tracing algorithms.[ref]
