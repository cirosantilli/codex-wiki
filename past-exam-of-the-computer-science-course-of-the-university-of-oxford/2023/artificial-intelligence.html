a OurBigBook.com
Let V be the traversable squares and H⊆V the exits. Sample the state space at the end of each complete round, so a live state is s=(r,f)∈V×V with r=f. The given starting positions specify the initial state. The board and exits are fixed problem data, rather than changing components of the state space.
The rabbit has at most five actions: stay or move to one of its traversable orthogonally adjacent squares. A search transition model first applies that action, giving r′, and immediately checks for capture at r′=f. Otherwise hold r′ fixed and apply the fox rule twice, checking for capture after each step. A capture is terminal failure; it must not be overlooked merely because the fox could subsequently move elsewhere. A surviving successor is (r′,f′′). Equivalently, omit actions whose complete-round outcome is capture.
The goal test is the rabbit is on an exit after surviving the fox's entire turn: r′∈H and no capture occurred in that round. Merely entering an exit before the fox moves is insufficient. Each surviving search transition model step has cost one when minimizing rounds.
Only legal moves are considered when applying the stated horizontal preference: try a legal horizontal step that reduces horizontal separation, otherwise a legal vertical step that reduces vertical separation, otherwise stay. If a blocked preferred direction is instead interpreted as forcing a stay immediately, the counterexamples below and all completeness and optimality conclusions remain valid.

Write F=∣V∣≤mn. The ordered position pairs give at most F2 states, or F(F−1) live states after excluding capture. Thus the usual Big O notation estimate is O(m2n2). An additional terminal-failure marker changes this by only one.
For k distinguishable foxes, retain (r,f1​,…,fk​). Different foxes may share a square; none may share the rabbit's square in a live state. There are at most F(F−1)k live position tuples, giving O((mn)k+1). These counts describe possible encodings; obstacles, starting positions and the fixed fox rule can make the reachable state space much smaller.

The branching factor of the search tree is at most five, so through depth d it has at most
1+5+⋯+5d=45d+1−1​=O(5d)
(1)
nodes in Big O notation. With no depth bound, the search tree can be infinite, despite the finite state space: tree search retains different action histories even when they end at the same position pair.
For a concrete repeating history, use a two-row, three-column board, indexed from zero, with the sole obstacle (0,1), rabbit at (0,2) and fox at (0,0). Repeated rabbit stays leave the fox blocked horizontally with no vertical separation to reduce. Hence the same live state can repeat forever. An exit at (1,2) is nevertheless safely reachable in one round.

d OurBigBook.com
Breadth-first tree search is complete and optimal for minimizing rounds. If a successful escape has finite length d, there are only finitely many nodes at depths below d, since the branching factor is at most five. Breadth-first tree search therefore reaches a shallowest successful node after finite work, even if other branches continue forever.
It is an optimal search algorithm because every search transition model step costs one round, so minimum depth is exactly the desired minimum number of rounds. The goal test must be applied to the surviving complete-round successor. Here a complete search algorithm guarantees finding an escape when one exists; it need not terminate on every unsolvable instance.

e OurBigBook.com
Depth-first tree search is neither complete nor optimal for minimizing rounds.
For incompleteness, use the two-row, three-column board from part (c), with exit (1,2). If stay is the first action explored, depth-first tree search follows the repeating state forever. Moving the rabbit down instead survives the round: under legal horizontal-then-vertical movement the fox moves to (1,0) and then (1,1), leaving the rabbit safely at the exit. Thus a one-round escape exists but is never reached in this action order.
For nonoptimality, use an unobstructed one-row board with columns 0,…,6, initial fox column 0, initial rabbit column 4, and exits at columns 3 and 6. Moving left once escapes at column 3 with the fox at column 2. Moving right twice escapes at column 6 with successive fox positions 2,4. A depth-first tree search that explores the latter route first returns two rounds although one suffices. This counterexample supplies an actual returned, suboptimal escape independently of the infinite-branch example.

Ignore the fox and obstacles when estimating the remaining number of rabbit moves. Define the heuristic function
h(r,f)=e∈Hmin​(∣r1​−e1​∣+∣r2​−e2​∣).​
(2)
This is Manhattan distance to the nearest exit, a relaxation heuristic. Assume at least one exit; with none the instance is immediately unsolvable. The estimate is generally nonconstant and is not the perfect escape cost: obstacles can force detours, while pursuit can make an apparently nearby exit unreachable.
To prove it is a consistent heuristic, consider a surviving one-round transition from (r,f) to (r′,f′). Let e′ attain the minimum defining h(r′,f′). The triangle inequality for Manhattan distance and the rabbit's move bound give
h(r,f)≤d1​(r,e′)≤d1​(r,r′)+d1​(r′,e′)≤1+h(r′,f′).
(3)
Every successful terminal state has h=0. This proves consistency with unit round costs; summing the inequality along any successful route also proves that it is an admissible heuristic. Failed transitions need no successor estimate because they are discarded.

g OurBigBook.com
Breadth-first tree search remains complete but is not optimal for maximizing the bonus. Completeness depends on the finite branching factor and a finite successful depth, not on the objective used to compare escapes.
Use the one-row, seven-square example from part (e). The one-round escape at column 3 leaves the fox at column 2, so its graph distance to the exit, and hence the bonus, is 1. The two-round escape at column 6 leaves the fox at column 4, giving bonus 2. The earliest successful node therefore has bonus 1 when bonus 2 is achievable. Breadth-first tree search orders by rounds rather than terminal graph distance.

Breadth-first tree search is complete and is still not bonus-optimal. Fix any deterministic rule for choosing among equally short fox routes; the completeness argument again uses only the finite branching factor. The unobstructed corridor of part (g) has unique shortest paths, so its fox moves are exactly the same under the new strategy. The one-round bonus is 1 and the two-round bonus is 2, proving nonoptimality without any tie-breaking ambiguity.
If there is no route between fox and rabbit, the printed shortest-path rule needs a convention; letting the fox stay supplies a natural extension. The completeness argument is unchanged, and the counterexample above uses only connected squares. When the fox and rabbit initially belong to the same connected component of a graph, the shortest-path pursuit distance bound also makes every surviving branch finite. That additional property does not make the first escape maximize its bonus.

i OurBigBook.com
Depth-first tree search is complete under the stated initial reachability assumption, but is not bonus-optimal.
Let dt​ be the graph distance between fox and rabbit after round t, with d0​ their initial graph distance. Initial reachability makes d0​ finite, and ordinary moves preserve membership in their common connected component of a graph. After the rabbit's next move, the triangle inequality gives intermediate separation at most dt​+1. If that separation is at most two, the fox catches the rabbit that round. Otherwise the fox takes two steps along a shortest path, leaving
1≤dt+1​≤dt​−1.
(4)
Thus a successful surviving history has at most d0​−1 rounds; if it does not escape by then, the next round captures it. The shortest-path pursuit distance bound excludes infinite live branches, even when the rabbit stays. Together with the finite branching factor, it makes the whole relevant search tree finite, so depth-first tree search eventually finds an escape whenever one exists.
For nonoptimality, take the corridor of part (g) and let depth-first tree search try left first. It immediately returns the one-round escape with bonus 1, whereas trying right twice earns 2. The decreasing separation proves termination, not optimality of the first returned escape.

In STRIPS, a state records the true ground facts; under the closed-world assumption, an absent fact is false. An action with positive preconditions P, add effects A and delete effects D applies when P⊆S, producing (S∖D)∪A.
The given movement action adds the destination fact without deleting the old boat location. After its first crossing the boat can therefore be recorded at both banks, allowing physically impossible loading. Its source-bank symbol is also not a declared action parameter. Repair both issues by using the fully parameterized STRIPS action
Move(s,t):PAD​={isBank(s),isBank(t),notEqual(s,t),at(BOAT,s)},={at(BOAT,t)},={at(BOAT,s)}.​
(5)
Here notEqual(s,t) excludes a vacuous same-bank crossing. The two static inequality facts already supplied suffice.
The given loading action has no capacity check. Consecutive loads can put arbitrarily many items aboard. Introduce a nullary planning fluent Empty, true initially, and repair loading to
Load(x,s):PAD​={isItem(x),isBank(s),at(x,s),at(BOAT,s),Empty},={onBoat(x)},={at(x,s),Empty}.​
(6)
Unloading must restore Empty, as in part (c). Including the bank s explicitly as an action parameter removes the other unbound action variable. Equivalently, instantiate separate east-bank and west-bank actions.
These repairs establish the planning state invariants that the boat is at exactly one bank, each item is either at one bank or aboard, and at most one item is aboard. The first two hold initially and are preserved by deleting the former location when adding the new one; the capacity marker permits loading only when no item is aboard. Grounding implicit location variables alone would not repair the missing delete effect or the missing capacity check.

For i=1,…,n, execute
Load(ITEMi,EAST),Move(EAST,WEST),Unload(ITEMi,WEST),
(9)
and, if i<n, append Move(WEST,EAST) before the next iteration.
Each load starts with an empty boat beside an undelivered item. Each unload leaves that item west and restores the loading precondition. By mathematical induction on i, after iteration i the first i items are west and the remaining items are east. Thus the automated planning goal holds after 2n−1 crossings and 4n−1 actions for n≥1. For n=0, the empty plan already achieves the goal.

Replace the one-place marker Empty by three nullary planning fluents q0​,q1​,q2​, meaning that zero, one or two items are aboard. Initially only q0​ is true. Exactly one of these facts is maintained. No additional object constants are needed.
For compactness, define the common loading preconditions
L(x,s)={isItem(x),isBank(s),at(x,s),at(BOAT,s)}
(10)
and common unloading preconditions
U(x,s)={isItem(x),isBank(s),onBoat(x),at(BOAT,s)}.
(11)
The four STRIPS actions are
LoadFirst(x,s):PALoadLast(x,s):PAUnloadFirst(x,s):PAUnloadLast(x,s):PA​=L(x,s)∪{q0​},={onBoat(x),q1​},=L(x,s)∪{q1​},={onBoat(x),q2​},=U(x,s)∪{q2​},={at(x,s),q1​},=U(x,s)∪{q1​},={at(x,s),q0​},​DDDD​={at(x,s),q0​};={at(x,s),q1​};={onBoat(x),q2​};={onBoat(x),q1​}.​
(12)
Here the first unloading removes one of two items, and the last unloading removes the sole remaining item; items do not require fixed seat identities. The movement action remains as repaired in part (a) and changes none of the occupancy facts.
The planning state invariant is qj​ true exactly when j items are aboard. Every action changes the marker by the same amount as the actual onboard count, so it follows by mathematical induction from the initial empty boat. In particular, a third load is impossible.

LoadFirst(x,EAST), LoadLast(y,EAST), Move(EAST,WEST), UnloadFirst(y,WEST), UnloadLast(x,WEST).
(13)

LoadFirst(x,EAST), Move(EAST,WEST), UnloadLast(x,WEST).
(14)

Each group starts and ends with marker q0​, and its items finish west, proving all preconditions and the final goal by mathematical induction over the groups. For n≥1 there are ⌈n/2⌉ outward journeys and 2⌈n/2⌉−1 crossings in total; ⌈⋅⌉ is the ceiling function. Again n=0 needs no actions.

Keep the corrected one-place STRIPS model, replace the item constants and their initial typing facts by FOX,RABBIT,CARROT, and require all three west in the goal. The farmer travels with the boat, so the boat's bank also records where supervision is available. The new requirement concerns the bank being left: incompatible items may coexist at the farmer's current bank, but must not be left there together.
Here is a compilation using only ordinary positive STRIPS preconditions. Replace onBoat(x) everywhere by at(x,BOAT), extending the item's possible locations to
L={EAST,WEST,BOAT}.
(15)
The boat itself still has only bank locations, enforced by isBank. Initialize a static relation SafePair(p,q,s) for every p,q∈L and bank s except p=q=s. It states that two incompatible items at locations p,q are not both on the bank about to be left.
Introduce planning safety certificates SafeToSail(EAST) and SafeToSail(WEST), neither initially true. The following checking action grants a certificate:
Check(s,pF​,pR​,pC​):P={A​isBank(s),at(BOAT,s),at(FOX,pF​),at(RABBIT,pR​),at(CARROT,pC​),SafePair(pF​,pR​,s),SafePair(pR​,pC​,s)},={SafeToSail(s)},D=∅.​
(16)
Add SafeToSail(s) to the preconditions of Move(s,t). Every load, unload and move deletes both certificate facts. The other movement and capacity effects remain unchanged.
Deleting certificates on every location change prevents a stale safety check from authorizing a later unsafe departure. A certificate is granted only for the actual current locations and only when both incompatible pairs are separated on the departure bank. During a crossing the remaining bank is therefore safe; on arrival the farmer supervises the destination bank. This proves the required safety property by mathematical induction over crossings. The static SafePair facts are never changed.

For fair division, let J={1,…,m} and let the additive valuation of agent i be vi​(S)=∑j∈S​vij​. Use one variable Xi​ per agent, with constraint domain P(J), the power set of the items. Empty bundles are permitted in this original formulation.
Require pairwise disjoint sets:
Xi​∩Xℓ​=∅(1≤i<ℓ≤n).
(18)
Each such binary constraint involves exactly Xi​,Xℓ​. Require complete allocation by the single all-variable constraint
⋃i=1n​Xi​=J.
(19)
Finally impose the envy-free allocation binary constraints
vi​(Xi​)≥vi​(Xℓ​)(i=ℓ),
(20)
each on Xi​,Xℓ​. The two directions for a pair use different agents' additive valuations and must both hold. These conditions give precisely an ordered set partition of the items that is an envy-free allocation.

Use one variable Yj​ per item, with constraint domain {1,…,n}. Its value is the recipient agent. Every assignment automatically allocates each item exactly once, so separate coverage and disjointness constraints are unnecessary.
For every ordered pair i=ℓ, impose
j=1∑m​vij​1{Yj​=i}​≥j=1∑m​vij​1{Yj​=ℓ}​.​
(21)
Here 1 is an indicator function. The constraint involves every Yj​ with vij​=0; one may formally give it scope {Y1​,…,Ym​}, since zero coefficients make the other variables irrelevant. These constraints state envy-free allocation using the comparing agent's additive valuation on both sides. In contrast to part (a), they generally involve more than two variables.

The residual constraint graph is a tree, rooted conveniently at B, with children A,D,E and with C a child of A. Solve it by the tree-structured constraint satisfaction algorithm: enforce arc consistency from children toward their parents, then choose a surviving root value and select supported child values in the opposite direction.
For adjacent agents define the combined binary constraint
Riℓ​(X,Y)⟺X∩Y=∅,vi​(X)≥vi​(Y),vℓ​(Y)≥vℓ​(X).
(27)
A child-to-parent arc consistency step deletes each parent bundle with no compatible child bundle. Process the edges in the order A←C, B←A, B←D, B←E.
First, C needs a nonempty subset of {1,2}. Supporting C reduces A's constraint domain to
DA′​={{2},{3},{1,3},{2,3}}.
(28)
Indeed, {1} leaves only {2} for C but gives A value 2<3; {1,2} and {1,2,3} leave no possible item for C. Each of the four retained choices has a compatible choice for C.
Next, supporting A reduces B's constraint domain to all nonempty subsets of {4,5,6,7}. To see why item 3 cannot remain in B's bundle, a disjoint compatible A bundle from DA′​ would have to be {2}, but A then values its own bundle at 3 and B's at least at 6. Conversely any nonempty subset of {4,5,6,7} is compatible with A={2}.
Supporting D next reduces B's constraint domain to
{{6},{7},{4,6},{4,7},{6,7},{4,6,7}}.
(29)
If B held item 5, disjointness would force D={4}, whose value 1 is below D's value 4 for B's bundle. If B holds 4 but not 5, then D={5}, and B needs value at least 6 to avoid envying D. If B holds neither, D={4} supports every nonempty subset of {6,7}.
Finally, supporting E leaves
DB′​={{6},{7},{4,6},{4,7}}.
(30)
The removed choices contained both 6 and 7, leaving no item for E. Every displayed choice has a compatible choice for E.
Choose B={6}, then supported child values, giving
XA​={2},XB​={6},XC​={1},XD​={4},XE​={7}.​
(31)
Items 3,5 remain unallocated, which this variant expressly permits. To check every envy-free allocation inequality, the matrix of agents' additive valuations of these bundles, with rows and columns both ordered A,B,C,D,E, is
​30100​03002​20100​03010​03002​​.
(32)
Each diagonal entry is at least every entry in its row. The bundles are nonempty, pairwise disjoint, and contain only positively valued items, so all remaining requirements hold.
Why does selecting supported children suffice? The residual constraint graph has no graph cycle, so different child subtrees have no constraints between them. Child-to-parent arc consistency has already ensured a compatible continuation below every retained parent value. Applying this observation recursively proves that the downward choices complete a solution without backtracking. With N variables and maximum constraint domain size d, the basic compatibility checks require O(Nd2) time complexity in Big O notation, counting each binary constraint evaluation as one operation; evaluating bundle sums has its own input-dependent cost.
