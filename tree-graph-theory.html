Tree (graph theory)

 Home Mathematics Area of mathematics Combinatorics
OurBigBook.com Words: 8k Articles: 91
A tree is a nonempty connected graph containing no graph cycle. Think of seven locations joined so that everyone can reach everyone else, but no connection supplies an alternative route. For a finite simple graph with n≥1 vertices, three descriptions are equivalent: being a tree; having exactly one simple graph path between every pair of distinct vertices; and being a connected graph with exactly n−1 edges. Here a simple graph path repeats no vertex. Connectedness in the last description is essential. [ref]
For a concrete tree, label the vertices 1,…,7 and take the edges
E={12,13,24,25,36,67},
(1)
where ij abbreviates the unordered pair {i,j}. There are seven vertices and six edges. The unique graph path from 4 to 7 is 4,2,1,3,6,7, using five edges. The degree sequence in label order is (2,3,2,1,1,2,1): its sum is 12=2⋅6, as the degree-sum formula predicts. Each of 4,5,7 is a leaf of a graph, having vertex degree one.
Deleting edge 13 leaves precisely two connected components of a graph, on {1,2,4,5} and {3,6,7}. Every edge of a tree is a bridge in a graph. Instead add edge 57 to the original tree: it closes the unique existing graph path 5,2,1,3,6,7 into exactly one graph cycle. Thus a tree provides economical connections with no redundancy: a single failed link separates locations. Every finite tree with at least two vertices has at least two instances of a leaf of a graph; the endpoints of a longest graph path supply them. [ref]
The number n−1 alone proves nothing about connectedness: a cycle graph on 1,…,6 together with an isolated vertex 7 has seven vertices and six edges, yet is disconnected. Briefly, two different simple graph paths between the same vertices would contain a graph cycle. Repeatedly removing a leaf of a graph and its incident edge proves the tree count n−1 by mathematical induction, starting with one vertex and no edges.

Connected subgraph of a tree

Words: 136 Articles: 1
Tree (graph theory) OurBigBook.com
A nonempty connected subgraph of a tree. Between any two included vertices, it contains the unique tree path: its connectedness supplies a path, and the ambient tree has only one. Such subgraphs satisfy the Helly property. They need not contain every descendant of an included vertex in any chosen rooting, unlike the descendant-closed data-structure subtree convention.

Helly property for connected subgraphs of a tree

Words: 83
Connected subgraph of a tree OurBigBook.com
A finite family of nonempty connected subgraphs of a tree with pairwise nonempty intersections has a common vertex. For a finite ambient tree, prove this by deleting a leaf of a tree v. If one member is {v}, pairwise intersection proves the result immediately. Otherwise remove v from every member containing it. Each such member remains nonempty and connected and contains the unique neighbour of v. Hence every pair still intersects, even if its original intersection consisted only of v, and mathematical induction applies. This is the Helly property specialized to trees.

Regular tree (deg(x)=k(x∈V))

Words: 101 Articles: 1
Tree (graph theory) OurBigBook.com
An infinite connected tree is regular of degree k if every vertex has exactly k neighbours. Necessarily k≥2. For k=2 it is a two-sided infinite path. For k≥3, rooting it gives k children at the root and k−1 children at each other vertex; this constructs the unique such tree up to graph isomorphism.

Edge boundary of a finite forest in a regular tree (∣∂E​A∣=(k−2)∣A∣+2c(A))

Words: 49
Regular tree OurBigBook.com
For a nonempty finite vertex set A in a degree-k regular tree, its induced forest has ∣A∣−c(A) edges, where c(A) counts its components. Summing degrees and subtracting twice the internal edge count gives the displayed number of edges with exactly one endpoint in A. In particular it is at least (k−2)∣A∣+2.

An oriented tree is an orientation of every edge of an undirected tree. Its arrows need not all point towards, or away from, any one root. It is acyclic as a directed graph, but different orientations can have different embedding behaviour in tournaments.

Three-times-order tournament bound for oriented trees (∣V(T)∣=n≥2⟹T⊆every (3n−3)-vertex tournament)

Words: 86
Oriented tree OurBigBook.com
For a source-rooted oriented tree, let b count edges pointing towards the root and let c count nonempty connected components formed by those edges. A half-sparse median-order embedding exists in 2n+2(b−c) vertices. Remove forward leaves, or remove a terminal backward component of order m and replace it temporarily by 2m−2 outward leaves. Their images contain an in-arborescence copy of the component. Choose the direction and root to minimize (b−c,b) lexicographically; this makes the root a source and gives b−c≤(n−3)/2 unless the tree is already an arborescence. The stated bound follows.

An arborescence is a rooted oriented tree whose edges all point away from its root. Reversing every edge gives an in-arborescence. An n-vertex arborescence embeds in every tournament on 2n−2 vertices: repeatedly extend an outward leaf in a half-sparse median-order embedding. Depth-first traversal of a tree

Tree (graph theory) OurBigBook.com
A depth-first traversal starts at a root, recursively visits each child subtree, and returns along the entering edge. On a finite tree, the resulting closed walk traverses each edge exactly once in each direction.

Postorder traversal

Visit all child subtrees before visiting their parent. A depth-first traversal of a tree produces this order by processing a node on return from its recursive calls. It lets dynamic programming use the already computed answers of every child subtree.

Rooted tree

Words: 1k Articles: 22
Tree (graph theory) OurBigBook.com
A rooted tree is a tree with a distinguished vertex, its root of a tree r. Choosing r turns connections into a hierarchy: every other vertex has a unique parent in a rooted tree, the preceding vertex on its graph path from r. Conversely, the vertices whose parent in a rooted tree is v are the children in a rooted tree of v. Choosing the root of a tree changes this description, while the underlying edges remain the same. Arrows towards the root of a tree can encode the relationship, as in MIT's counting notes; the undirected tree itself needs no arrows. [ref]
In the seven-vertex tree above, choose r=1. The levels, grouped by graph distance from the root of a tree, are {1}, {2,3}, {4,5,6}, {7}. The children in a rooted tree of 2 are 4,5, and the parent in a rooted tree of 7 is 6. Choosing r=7 instead makes the levels {7}, {6}, {3}, {1}, {2}, {4,5}: now 6 has parent in a rooted tree 7, reversing their relationship. All six edges survive.
This hierarchy supports structural recursion: process the smaller rooted trees below each vertex, then combine their results. A depth-first traversal of a tree explores one branch before returning; breadth-first search processes successive levels. The lowest common ancestor identifies where two routes from the root of a tree last coincide. For 4,5 it is 2 when r=1. A binary tree imposes an additional restriction on children in a rooted tree; a general rooted tree has no such bound.

Rose tree

Rooted tree OurBigBook.com
A rose tree is an ordered rooted tree in which each vertex can have any finite number of children in a rooted tree. A labelled Haskell representation is data RTree a = Node a [RTree a]. Its tree fold has type (a -> [b] -> b) -> RTree a -> b: recursively fold the children, then combine their results with the current label. Unlike a binary tree, a rose tree has no fixed pair of child positions.

Perfect rose tree

Words: 77
Rose tree OurBigBook.com
A rose tree is perfect when all its leaves of a rooted tree have the same depth. This permits unequal branching counts and unary branches; perfectness alone does not require every internal vertex to have the same number of children. A bottom-up certificate returns Just 0 at a leaf, Just (h+1) when all child certificates are Just h, and Nothing otherwise. Structural induction proves that a certificate exists exactly when the tree is perfect: all root-to-leaf routes acquire one edge when attached to the new root.

Full ternary tree

Words: 152 Articles: 1
Rooted tree OurBigBook.com
A rooted tree in which every internal vertex has exactly three tree children. For a finite rooted tree with m tree leaves and internal outdegrees dv​, counting edges in two ways gives
m=1+∑v internal​(dv​−1).
(2)
Indeed, the number of edges is the total number of vertices minus one and also the sum of the internal outdegrees. Thus a full ternary tree with N internal vertices has m=1+2N tree leaves, always an odd number. More generally, if every internal vertex has either two or three tree children, m=1+N2​+2N3​. This parity controls the initial merge in ternary Huffman coding.

Perfect ternary tree (Nh​=(3h+1−1)/2)

Words: 74
Full ternary tree OurBigBook.com
A full ternary tree whose leaves all have the same depth. At depth j there are 3j vertices, so a tree with h+1 levels has Nh​=∑j=0h​3j=(3h+1−1)/2 vertices and 3h leaves, by the finite geometric series formula. For a rose tree representation, recursively flattening children and joining their lists with ordinary list concatenation copies each label once per ancestor. The work is therefore Θ((h+1)3h)=Θ(Nh​logNh​) when the complete output is demanded. Passing an already constructed suffix through the recursion instead emits each label once, giving Θ(Nh​) work.

Homeomorphic embedding of a rooted tree (T⪯S)

For finite rooted trees in the ancestor partial order, a rooted-tree homeomorphic embedding is an injective vertex map preserving lowest common ancestors: h(u∧v)=h(u)∧h(v). The image of the source root need not be the host root. Edge paths and branching are preserved, while paths may be subdivided in the larger tree.

Natural-sum ordinal rank of a finite rooted tree (o(T)=#U child subtree​ωo(U))

Words: 74
Homeomorphic embedding of a rooted tree OurBigBook.com
Give a leaf rank zero, and use Hessenberg natural sum over the immediate rooted subtrees. Every rank is below epsilon zero; conversely repeated exponentiation and finite summation encode every Cantor normal form below it. A rooted-tree homeomorphic embedding implies nondecrease of the rank. When roots match, child subtrees embed into distinct branches and exponentiation and natural sum preserve their inequalities. When the source root maps below the host root, its rank is bounded by that of a proper subtree, strictly below the host rank.

Adjacency-preserving rooted-tree embedding (T≤adj​S)

An adjacency-preserving rooted-tree embedding is an injective vertex map preserving the root and every adjacency. Because each root-to-vertex path maps to a simple path of the same length, vertex depths are preserved. This is more restrictive than a homeomorphic embedding of a rooted tree, which may stretch edges into paths. The branching-depth antichain of rooted trees shows that the adjacency relation is not a well-quasi-ordering.

Recursively repetition-free labelled tree (T(D))

For a label set D, define T(D) inductively: choose a root label d∈D and a finite repetition-free sequence of rooted trees in T(D∖{d}) as its children. Each object is a finite ordered rooted tree. Labels are distinct along each root-to-leaf path, and child rooted trees at a vertex are distinct as whole rooted trees. t0​=0,tm​=m∑k=0tm−1​​(tm−1​−k)!tm−1​!​.
(3)

Recursively repetition-free labelled trees preserve Dedekind-finiteness

Words: 73
Recursively repetition-free labelled tree OurBigBook.com
If D is an infinite Dedekind-finite set, then T(D) is another such set. Single-vertex rooted trees inject D into it. A countable sequence of distinct rooted trees gives finite lists of labels by the depth-first traversal of a tree in the prescribed child order. By countable union of explicitly ordered finite lists without choice, an infinite union of labels contradicts Dedekind-finiteness. A finite union F is equally impossible, since every rooted tree then lies in the finite set T(F), by mathematical induction on ∣F∣ using the recursive child rule. Thus no countably infinite subset of rooted trees exists.

Forest

Words: 318 Articles: 4
Tree (graph theory) OurBigBook.com
A forest is an undirected graph with no graph cycle; each of its connected components of a graph is a tree, including any isolated vertex. A finite forest with n vertices and c connected components of a graph has
∣E∣=n−c.
(5)
Indeed, a connected component of a graph with ni​ vertices contributes ni​−1 edges; adding these counts gives n−c. Equivalently, start with n isolated vertices: every added edge must join different connected components of a graph, reducing their number by one. Joining vertices already connected would create a graph cycle. [ref]
Deleting 13 in our example gives n=7, c=2, and five edges: the two trees contribute 3+2=5=7−2. Deleting 67 as well leaves 7 isolated, so c=3 and four edges. A forest therefore describes separate hierarchies or the intermediate stages of building a spanning tree. The acyclic graph condition accounts for missing connections without assuming that all locations are mutually reachable.

A two-component spanning forest of a finite connected graph is an acyclic spanning subgraph with exactly two connected components of a graph. It has ∣V∣−2 edges. Minimum-weight acyclic subgraph

Words: 87
Minimum spanning forest OurBigBook.com
Among all acyclic graphs contained in a finite weighted undirected graph, with no requirement to connect vertices, one optimum is obtained by keeping only strictly negative edges and computing their minimum spanning forest. Removing a nonnegative edge never worsens weight or creates a cycle. Within a connected component of the negative-edge subgraph, any disconnected candidate forest can be extended by a negative crossing edge, strictly improving its weight. Hence an optimum must span each such component and minimise its tree weight. Kruskal's algorithm on the negative edges therefore solves the problem. Zero-weight edges are optional when they preserve acyclicity.

Spanning tree

Words: 3k Articles: 33
Tree (graph theory) OurBigBook.com
A spanning tree of a connected graph G is a subgraph that is a tree and contains every vertex of G. Its edges must come from G. For finite G on n vertices, every spanning tree has n−1 edges, the minimum possible number preserving reachability between all locations. This makes a spanning tree a compact certificate that the original graph is connected. A minimum spanning tree additionally minimizes a specified total edge weight; merely selecting a spanning tree supplies no such optimization. [ref]
Let G be our seven-vertex tree with edge 57 added. It has seven edges and a graph cycle. Removing 57 gives the original spanning tree T; removing 13 instead gives another spanning tree T′. Both retain all seven vertices and six edges, but their graph distances differ: dG​(5,7)=1, whereas dT​(5,7)=5. In T′, dT′​(5,7)=1 but dT′​(1,3)=5, along 1,2,5,7,6,3, compared with dG​(1,3)=1. Preserving reachability permits longer journeys; breadth-first search can preserve graph distances from one chosen starting vertex.
To construct a spanning tree, repeatedly delete any edge on a graph cycle. Its endpoints remain joined through the rest of that graph cycle, so the deletion preserves connectedness. Finiteness ensures that this stops at a connected acyclic graph. Conversely, adding an omitted edge to a spanning tree creates its unique fundamental cycle; deleting any other edge on that graph cycle produces another spanning tree. The displayed exchange replaces 13 by 57. [ref]

A spanning tree with greatest total edge weight. Apply Kruskal's algorithm in decreasing weight order, or negate every edge weight and compute a minimum spanning tree. Every graph path within a maximum spanning tree solves the widest path problem between its endpoints.

Spanning-tree prefix exchange

Words: 116
Spanning tree OurBigBook.com
Suppose two spanning trees have the same first n edges in nondecreasing weight order. If the first tree's next edge e is no heavier than the second tree's next edge, it can be inserted into the second tree while preserving the common prefix and without increasing any sorted edge weight. If e already occurs there, it ties for the next position. Otherwise its fundamental cycle contains an edge f outside the prefix, since the prefix together with e is acyclic. Every such f is at least as heavy as e. Exchanging f for e preserves the spanning tree. Replacing a multiset entry by a no-larger entry cannot increase any order statistic. Tied edges can be ordered to preserve the prescribed prefix.

Minimum spanning tree (minT​∑e∈T​ce​)

Words: 2k Articles: 13
Spanning tree OurBigBook.com
A minimum spanning tree minimizes total edge weight among spanning trees of a connected weighted graph. It can be computed in polynomial time by repeatedly adding the least-weight edge joining two current components. The cut-exchange argument preserves the existence of an optimum containing every accepted edge. Removing an edge of a travelling-salesman tour gives a spanning tree, so its optimum is a lower bound on optimal tour cost.

Cut lemma for minimum spanning trees

Words: 77
Minimum spanning tree OurBigBook.com
Let an edge set F be contained in some minimum spanning tree, and let a cut of a graph have no crossing edge in F. Any least-weight edge crossing that cut of a graph can be added to F while preserving its containment in some minimum spanning tree. Insert the chosen edge into an optimum containing F, then remove another crossing edge from the resulting graph cycle; it is no lighter and cannot belong to F. Ties imply existence of an optimum containing the chosen edge, rather than membership in every optimum.

Borůvka's algorithm

Words: 138
Minimum spanning tree OurBigBook.com
Start with isolated vertices. In each round, determine the current connected components of a graph, choose a least-weight outgoing edge for each component, add their union, and recompute the components. With distinct weights, each chosen edge is the unique lightest edge across that component's graph cut. The minimum spanning tree cut property puts every such edge in every minimum spanning tree, so the selected edges remain acyclic. Every nonfinal component has an outgoing edge in a connected input, and merging makes progress until a spanning tree remains. Duplicate choices of the same edge are one set insertion.
Each new component contains at least two old components, so there are O(log∣V∣) rounds. Scanning all edges per round gives O(∣E∣log∣V∣) time. Equal edge weights require a consistent secondary order to avoid choosing a cycle of tied edges.
Otakar Borůvka formulated the distinct-cost minimum-connection problem in 1926.[ref]

Kruskal's algorithm

Words: 994 Articles: 3
Minimum spanning tree OurBigBook.com
Kruskal's algorithm constructs a minimum spanning tree of a finite connected graph with undirected edges and real edge weights. Start with all vertices and no edges, a forest of isolated vertices. Sort the edges by nondecreasing weight, then accept an edge exactly when its endpoints belong to different current connected components of a graph. Otherwise reject it: the existing graph path between its endpoints would close a graph cycle. Each acceptance merges two connected components of a graph. Stop after ∣V∣−1 acceptances, when the forest has become one spanning tree.
This is a greedy algorithm for economical network connection: only the next affordable connection and the current connected components of a graph matter. Unlike Prim's algorithm, which grows one reached tree, Kruskal's algorithm can grow several separate trees before joining them. The essential safeguard is avoiding a graph cycle, rather than simply buying the cheapest fixed number of edges.
Joseph Bernard Kruskal described this rule as Construction A on page 49 of his February 1956 paper, On the shortest spanning subtree of a graph and the traveling salesman problem; page 50 gives an exchange argument for distinct weights.[ref]

Kruskal safe edge

It holds initially for the empty edge set. Suppose the next accepted edge e joins a current connected component of a graph S to its complement. No earlier rejected edge crosses this cut of a graph: once its endpoints are in one connected component of a graph, subsequent merges never separate them. Thus e is a lightest edge across that cut of a graph.

∣Tn​∣=nn−2.
(10)

The labelled combinatorial structure includes the fixed labels: drawings, positions, and the order in which edges are listed do not create extra trees. For n=1, the single vertex with no edges is the unique tree; count it separately, since the Prüfer sequence construction requires n≥2. For n=2, the unique tree has edge {1,2} and corresponds to the empty Prüfer sequence. [ref]

For n≥2, a Prüfer sequence is the encoding of a labelled tree on {1,…,n} by a sequence
p=(p1​,…,pn−2​)∈{1,…,n}n−2.
(11)
Repeated labels are allowed, and their order matters. To encode the tree, repeatedly remove its smallest-labelled leaf of a graph together with its incident edge, recording the label of its unique neighbour. Stop when two vertices remain; do not record their final edge. Removing a leaf of a graph leaves a tree, so the procedure makes exactly n−2 deletions. The choice of the smallest label makes the encoding deterministic. [ref]

E={{1,2},{1,3},{3,4},{3,5},{5,6}}.

Breadth-first search

Words: 811 Articles: 2
Tree (graph theory) OurBigBook.com
Breadth-first search is a graph search that explores successive layers of graph distance from a starting vertex s. Here the graph is an undirected graph on a finite set of vertices, and distance counts edges, with no differing edge weights. Mark s as discovered, assign d(s)=0, and place it in a FIFO queue. Repeatedly remove the front vertex u and scan its adjacency list. Whenever a graph neighbour v is still undiscovered, mark it immediately, record u as its parent in a rooted tree in the discovery tree, assign d(v)=d(u)+1, and enqueue v at the rear. Marking on insertion ensures that another edge cannot enqueue the same vertex again. [ref]

E={AB,AC,BD,BE,CE,CF,EG,FG},

Processing C then skips the already discovered E and enqueues F, giving D,E,F. Processing D adds nothing. Processing E discovers G, giving F,G; later F sees G already marked and leaves its parent in a rooted tree unchanged. The discovery edges are AB,AC,BD,BE,CF,EG, forming a rooted tree on all seven vertices even though the original graph contains graph cycles. The discovery tree contains six edges; it need not contain every examined edge.
First arrival is shortest because the FIFO queue keeps assigned distances in nondecreasing order, with entries from at most two consecutive layers. While processing distance k, newly discovered vertices receive distance k+1 and join the rear. If an undiscovered vertex had a shorter graph path, its preceding vertex on that graph path would lie in an earlier layer and would already have discovered it. Thus d(v) is the minimum number of edges from s to v. This is a mathematical induction over the layers, not an assumption about the drawing. Following the parent in a rooted tree backwards at each step gives G,E,B,A; reverse that sequence to obtain the three-edge graph path A,B,E,G. A,C,F,G is another shortest graph path, but the specified graph neighbour order makes E discover G first. Changing that order can change the parent in a rooted tree without changing graph distances. [ref]
The shortest-route guarantee concerns the shortest path problem measured by edge count. It also minimizes total cost when every edge has the same positive cost. With unequal edge weights, first discovery need not minimize total cost; nonnegative costs can instead be handled by the Dijkstra algorithm. Breadth-first search is useful for minimum-hop routes and for finding all vertices within a specified graph distance. Its FIFO queue finishes an older layer before the next one, whereas depth-first search uses a call stack or explicit LIFO stack to pursue one branch immediately.
With adjacency lists and constant-cost discovery checks, together with constant worst-case or amortized analysis cost for FIFO queue insertion and removal, the time complexity is O(∣V∣+∣E∣) in Big O notation. Every reached vertex is enqueued and removed once, each incident edge is scanned at most twice in an undirected graph, and initializing all marks and distances takes O(∣V∣). The FIFO queue contains at most ∣V∣ vertices; the example's maximum is three. Discovery marks, distances and the recorded parent in a rooted tree for each nonroot vertex also give O(∣V∣) auxiliary space complexity, excluding the graph. An array that shifts every entry on front removal can lose the linear time complexity; the FIFO queue abstraction alone does not make removal constant-cost. Ordering the adjacency lists is a separate preprocessing cost.
A single start reaches only its connected component of a graph. Unreached vertices retain distance ∞ and have no recorded parent in a rooted tree. Restarting at each still-undiscovered vertex, while preserving all discovery marks, produces a forest covering the graph; each new root of a tree gets distance zero, so these distances refer to that root of a tree, not to the original s.

Maintain a FIFO queue of child iterators ordered by the breadth-first order of their parents. Consume a child from the front iterator and append a deferred iterator for that child's children; discard empty front iterators as needed. This enumerates descendants without first materializing a whole child list or level. On a locally finite tree, each node occurs after finitely many earlier outputs. If an earlier level is infinite, strict breadth-first order cannot put a deeper node at any finite output position; that obstruction is inherent in the requested ordering.
