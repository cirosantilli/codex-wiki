Three-bit majority decision tree (MAJ3​)

 Home Computer science Theoretical computer science Computational complexity theory Decision tree model Decision tree
OurBigBook.com Words: 284
Three votes give a small but revealing majority function:
m(x1​,x2​,x3​)={1,0,​x1​+x2​+x3​≥2,x1​+x2​+x3​<2.​
(13)
Our decision tree queries x1​, then x2​. If these bits agree, return their common value: two equal votes already force the majority function. If they disagree, query x3​ and return its value. The first two queries have a fixed order, but whether a third query occurs is adaptive.
Each internal label in the diagram names the next bit to inspect. Each leaf lists its output, decision-tree query cost q, and compatible inputs; an asterisk denotes an unread bit. The two shallow leaves each cover two inputs, while each deeper leaf covers one. Reading every bit would also compute the majority function, but would miss these exact shortcuts.
All eight inputs give the following exhaustive check. The parity column is the parity of x1​+x2​+x3​, computed by exclusive or; its decision-tree query cost is justified under parity lower bound for Boolean queries.

The worst inputs for this decision tree are 010,011,100,101, exactly those with x1​=x2​. Its actual depth is three. Every exact decision tree for this majority function has depth at least three: after the first query, an adversary can answer the second distinct query with the opposite bit, leaving the last bit decisive. Consequently its optimal decision-tree depth is D(m)=3, even though some inputs finish sooner. Every input has a two-bit query certificate, namely two agreeing votes; locating those votes can require a third query. This separates having a short query certificate from finding one.
