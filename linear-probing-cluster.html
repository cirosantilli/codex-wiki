Linear probing cluster

 Home Computer science Data structure Hash table Open addressing Linear probing
OurBigBook.com Words: 285 Articles: 1
A maximal consecutive run of occupied or deleted slots in linear probing, bounded by never-used slots when any exist; adjacency wraps around by modular arithmetic. Deleted slots still belong to the search run.[ref]
In the eight-slot example, array indices 0,1,2,3 form one linear probing cluster. Inserting absent hash table key 10 starts at 2, passes the occupied slots 2,3, and fills 4. This extends the same linear probing cluster despite 10 having a different initial array index from 0,8,16. A hash collision at the initial slot is enough to make later slots compete too.
For a worst-case family, insert integer hash table keys 0,m,2m,…,(n−1)m into an empty capacity-m array, using the hash function hm​(k)=kmodm, where 1≤n<m. They occupy array indices 0,…,n−1. Lookup of absent nm needs n+1 hash table probes. Taking n=⌊m/2⌋ gives hash table load factor at most 1/2 while the number of hash table probes grows with m. Thus occupancy alone cannot promise constant lookup work.
Before any rebuilding, bounded lookup, deletion by hash table key, and insertion with a duplicate check each have worst-case O(m) time complexity in Big O notation, assuming constant-cost hash function evaluation, array access and key equality. The counterexample gives a matching linear worst-case growth in the number of hash table probes. Hash table resizing is additional work; expensive string comparisons or hashing also fall outside these constant-cost assumptions.
