Longest increasing subsequence (L(x))

 Home Mathematics Area of mathematics Combinatorics Increasing subsequence
OurBigBook.com Words: 1k Articles: 1
A longest increasing subsequence is an increasing subsequence of maximum length. Write that length as L(x), with L(())=0 for the empty sequence; a nonempty input has 1≤L(x)≤n. Several selections can attain the same maximum. Here L uses the weak convention ≤; write L<​(x) for the maximum length of a strictly increasing subsequence. For (2,2,2), these lengths are three and one respectively; for an input with distinct values they agree.
For x=(4,1,3,2,2,5,0), the answer is L(x)=4, attained at indices (2,4,5,6), while L<​(x)=3. One useful interpretation is the smallest number of deletions needed to make the surviving sequence nondecreasing:
minimum deletions=n−L(x).
(9)
Indeed, keeping a longest increasing subsequence attains this bound, and any valid remaining sequence is an increasing subsequence, so cannot have more than L(x) terms. In this example the answer is 7−4=3. This makes L(x) a measure of how much order can be recovered without moving any observation.
A table that ends at each position. Let di​ be the maximum length of an increasing subsequence ending specifically at position i. The dynamic programming recurrence relation is
di​=1+max({0}∪{dj​:1≤j<i, xj​≤xi​}),L(x)=max1≤i≤n​di​(n>0).
(10)
The zero covers a selection consisting only of xi​. Otherwise its penultimate index is an eligible j; append xi​ to an optimal selection ending there. Fill entries in increasing index order. For strictly increasing subsequences, change the comparison to xj​<xi​. The strict version and reconstruction are developed in University of Toronto, CSC373 tutorial 4 solutions (2018), exercise 2; the weak version follows by allowing equality at the append step.
In the worked input, the weak table is (1,1,2,2,3,4,1) and the strict table is (1,1,2,2,2,3,1). At the second 2, equality extends the first 2 in the weak table. The final entry is only one, although the optimum is four: the best increasing subsequence need not finish at the last input position. Record a maximizing predecessor pi​=j whenever di​>1. Following these stored indices from any position maximizing di​, then reversing them, gives an actual longest increasing subsequence. For the weak example the backward chain is 6,5,4,2.
Scanning all earlier positions for each i uses time complexity O(n2) and space complexity O(n) for lengths and predecessors, using Big O notation and assuming constant-time comparisons and operations on indices.
Keep the easiest ending to extend. The faster algorithm maintains a minimum-tail table for increasing subsequences: Tℓ​ is the smallest final value of any length-ℓ increasing subsequence in the processed prefix. For equal lengths, a smaller ending permits every future extension allowed by a larger ending. Thus only one best ending per length is needed. The table is nondecreasing, since removing the last term of a length-(ℓ+1) selection gives Tℓ​≤Tℓ+1​. Start with an empty table. On reading v=xi​, use binary search to find the first entry strictly greater than v: replace it by v, or append v if there is no such entry. Its position is one beyond the longest existing length whose ending is at most v. See Liben-Nowell, Vee and Zhu, section 3.1 and Figure 1.
Duplicates determine the binary search rule: weak increase replaces the first Tℓ​>v, whereas strict increase replaces the first Tℓ​≥v. In Python these positions are returned by bisect_right(T, v) and bisect_left(T, v) respectively, counting positions from zero. Replace an entry or append; do not insert and shift the remaining entries. The documented equality rules are in Python documentation, bisect_left and bisect_right. Each search takes O(log(n+1)) comparisons, giving time complexity O(nlog(n+1)), conventionally O(nlogn) for n≥2, and space complexity O(L(x)) for the weak length alone.
A length certificate needs separate reconstruction. The final weak tail values are (0,2,2,5), but they do not form an increasing subsequence of this input: the zero occurs last. Each table entry certifies a selection of its own length; the entries need not come from one compatible selection. To recover a longest increasing subsequence during the fast algorithm, store a supplier index qℓ​ for each tail and a predecessor index for each input position. Before replacing slot r, save pi​=qr−1​, or no predecessor if r=1, then set qr​=i. Later replacements leave saved pi​ unchanged. Follow predecessors from the final qL(x)​ and reverse. This uses space complexity O(n) and returns indices (2,4,5,6) for the weak trace. The same construction works with the strict comparator; compare the two auxiliary arrays in CP Algorithms contributors, restoring the subsequence after binary search.
Deleting or changing one term. If x∖k deletes position k, then
L(x)−1≤L(x∖k)≤L(x).
(11)
Deleting cannot create a longer increasing subsequence; removing position k from a previously optimal selection loses at most one term. If x′ instead changes just the value at position k, both inputs have the same deleted sequence, so their lengths each lie between its length and its length plus one. Consequently ∣L(x′)−L(x)∣≤1. These bounds also hold for strictly increasing subsequences. In the weak example, deleting either 2 lowers the length to three, while deleting the final zero leaves it four. This is a Lipschitz bound for single-term edits, regardless of the numerical size of a replacement. Insertion has the same bound by reversing deletion, so m insertions, deletions or replacements can change L by at most m.
For historical context, [ref] studies the comparison count for distinct elements of a totally ordered set. Its distinctness assumption makes the weak and strict conventions coincide. No distinctness assumption is needed for the comparator-specific algorithms above.
