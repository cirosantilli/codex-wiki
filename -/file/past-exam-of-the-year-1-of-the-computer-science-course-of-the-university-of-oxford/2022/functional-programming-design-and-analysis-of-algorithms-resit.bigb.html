= Solution
{parent=a}

For finite <lists>, use <structural induction>: establish `P []`; then, for arbitrary `x` and `xs`, assume `P xs` and prove `P (x:xs)`. The <induction hypothesis> must quantify over any other parameters that need to change in the step.

For *all* <Haskell> <list> values, finite terminating spines are insufficient: also establish `P undefined`, and allow arbitrary, possibly undefined, heads in the cons step. This proves the equation for finite <partial lists> ending in the <bottom value>. An infinite <lazy list> is the limit of these finite approximations. Equations between pure definable <computable functions> are preserved by those limits, so the equation extends to infinite inputs. This last argument requires that admissibility property; an arbitrary logical property of <lists> need not have it. The distinction between `[]` and the <bottom value> is essential.<Haskell 2010 Language Report>[§3.1, Errors, and §3.17.2, Informal Semantics of Pattern Matching]{ref}

= b
{parent=1}
{scope}

= Solution
{parent=b}

Take compatible <function types> `f :: b -> c`, `g :: b -> a -> b`, and `h :: c -> a -> c`. The necessary conditions obtained from the two <induction base cases> are **strictness of `f` and the fusion equation**
$$
f(\bot)=\bot,\qquad f(g\ x\ y)=h\ (f\ x)\ y\quad\text{for all }x,y.
$$
At `zs = []`, the desired equation is exactly the displayed fusion equation. At `zs = undefined`, both <left folds> diverge because their <list> argument has no outer constructor; the equation therefore requires `f undefined = undefined`. This is the <strict function> condition. If only finite total spines were considered, the first condition would not be necessary.

These conditions also support the step. The <induction hypothesis> must hold for *every* accumulator and element. For `z:zs`, instantiate that hypothesis at `g x y` and `z`:
```
f (foldl g (g x y) (z:zs))
 = f (foldl g (g (g x y) z) zs)
 = foldl h (h (f (g x y)) z) zs
 = foldl h (h (h (f x) y) z) zs
 = foldl h (h (f x) y) (z:zs).
```
The middle rewrite uses the fusion equation at `x,y`. For pure <computable functions>, equality on infinite spines follows from finite approximations as in part (a).

= c
{parent=1}
{scope}

= Solution
{parent=c}

Prove the stronger equation, quantified over the accumulator:
$$
f(\operatorname{foldl}\ g\ a\ xs)=\operatorname{foldl}\ h\ (f\ a)\ xs\qquad\text{for all }a,xs.
$$
For `[]`, both sides are `f a`. For the <bottom value>, both sides are bottom because `f` is a <strict function>. For the cons step, the universal <induction hypothesis> allows the accumulator to become `g a x`:
```
f (foldl g a (x:xs))
 = f (foldl g (g a x) xs)
 = foldl h (f (g a x)) xs
 = foldl h (h (f a) x) xs
 = foldl h (f a) (x:xs).
```
Thus <structural induction> proves the claim for finite and finite partial spines; definable continuity extends it to infinite <lazy lists>. Pointwise equality is exactly the asserted equality of <function compositions>. This is the <left-fold fusion law>.

= d
{parent=1}
{scope}

= Solution
{parent=d}

Use a type with distinct values `a` and `n`, and let `s _ y = y`. Suppose a direct <right fold> with the same result type represented this <left fold>. The empty <list> forces `k = n`. The singleton <lists> force `c n n = n` and `c a n = a`. But then
```
foldr c k [a,n] = c a (c n n) = c a n = a,
foldl s n [a,n] = n.
```
Since `a /= n`, this is a <counterexample>. A direct <right fold> cannot recover whether its tail result `n` came from the empty <list> or from the singleton `[n]`. The obstruction already occurs on finite total inputs, so it also rules out an implementation valid on all <lazy lists>.

= e
{parent=1}
{scope}

= Solution
{parent=e}

Change the <right fold>'s result type to an accumulator-transforming <function type>:
```
foldlAsFoldr :: (b -> a -> b) -> b -> [a] -> b
foldlAsFoldr s n xs = foldr c id xs n
  where
    c x k a = k (s a x)
```
Thus **`c x k = \a -> k (s a x)` and `k = id`** in the question's notation. Here `c :: a -> (b -> b) -> (b -> b)`, and the fold's base value is the identity <function>, not the initial accumulator `n`.

The <recursion invariant> is `foldr c id xs a = foldl s a xs` for every `a`. For `[]`, both sides equal `a`. For a cons:
```
foldr c id (x:xs) a
 = c x (foldr c id xs) a
 = foldr c id xs (s a x)
 = foldl s (s a x) xs
 = foldl s a (x:xs).
```
At an undefined spine, applying the undefined folded <function> also gives the <bottom value>. The finite-approximation argument then covers infinite <lazy lists>. This is a <continuation representation of a left fold>: the result retains the operation still to be performed, avoiding the information loss in part (d).

= Solution
{parent=a}

A value-bearing <perfect binary tree> has size $w=2^{h+1}-1$, and the next size is $2w+1$. Suppose two size-$w$ trees have at least one smaller tree before them. The portion represented by these trees and that nonempty preceding portion has at least $2w+1$ elements. The greedy choice would have used a larger <perfect binary tree> instead, contradicting the specified representation. Three size-$w$ trees are likewise impossible, since $3w\geq2w+1$. Therefore **the only possible repeated size is a pair at the beginning**. This is the representation invariant of a <skew-binary random-access list>.

= b
{parent=2}
{scope}

= Solution
{parent=b}

A <Haskell> representation is:
```
import Prelude hiding (null, head, tail)

data RTree a = Leaf a | Node a (RTree a) (RTree a)
newtype List a = List [(Int, RTree a)]
```
Every tree stores a value at its root, including internal nodes. Interpret the <forest> by root-left-right <preorder traversal>, concatenating the results in <forest> order. Valid values have correct cached sizes, <perfect binary trees>, nondecreasing sizes and only the permitted initial duplicate. The raw constructors can express invalid representations, so the operations below assume valid values and should form the public interface. Sizes are assumed to fit in `Int`; the stated <time complexities> use constant-time size arithmetic.

The empty <skew-binary random-access list> contains no trees:

nil :: List a
nil = List []

null :: List a -> Bool
null (List []) = True
null _         = False

Both construction of `nil` and testing `null` take <constant time>.

= Solution
{parent=d}

Only the first two trees need inspection:
```
cons :: a -> List a -> List a
cons x (List ((w,t):(v,u):ts))
  | w == v = List ((2*w+1, Node x t u):ts)
cons x (List ts) = List ((1, Leaf x):ts)
```
When the first sizes agree, place `x` above those two <perfect binary trees>. Its <preorder traversal> is `x` followed by the old two traversals. No further size-$w$ tree can occur, so all remaining sizes are at least $2w+1$; equality creates at most the allowed initial duplicate. When the first sizes differ, adjoining a singleton is valid, including the case that the old first tree is also a singleton. These are exactly the two possible greedy representations after increasing the length by one. Each case creates a bounded number of constructors and inspects no tree interior, giving **worst-case $O(1)$ <time complexity>**. Existing trees are shared.

Repeated <constant-time> insertion constructs the representation:
```
fromList :: [a] -> List a
fromList = foldr cons nil
```
The <right fold> preserves order because `cons` prepends its argument. On a finite length-$n$ <list>, there are $n$ calls of `cons`; completely constructing the result takes **$\Theta(n)$ time** and $O(n)$ constructors. This claim concerns finite inputs, not productivity of conversion from an infinite <lazy list>.

= Solution

The first tree's root is the first element. Deleting that root either discards a singleton or exposes two equal-sized child trees:
```
head :: List a -> a
head (List ((_,Leaf x):_))     = x
head (List ((_,Node x _ _):_)) = x
head (List []) = error "head: empty list"

tail :: List a -> List a
tail (List ((_,Leaf _):ts)) = List ts
tail (List ((w,Node _ l r):ts)) =
  let h = w `div` 2 in List ((h,l):(h,r):ts)
tail (List []) = error "tail: empty list"
```
For a node of size $w=2h+1$, both children have size $h$. Their order agrees with the old <preorder traversal>, and they become the sole permitted initial duplicate. The rest of the <forest> was no smaller than the old root tree. Thus both operations preserve the representation invariant and take **worst-case $O(1)$ time** on a nonempty <skew-binary random-access list>.

Repeated root removal gives the conventional <list>:
```
toList :: List a -> [a]
toList rs
  | null rs   = []
  | otherwise = head rs : toList (tail rs)
```
The representation interpretation satisfies `toList (cons x rs) = x : toList rs`; alternatively, <structural induction> on the number of stored elements proves that each step emits exactly the next <preorder traversal> value. The output has $n$ cons cells, and each step takes <constant time>, so fully consuming it costs **$\Theta(n)$ time**. No repeated <list concatenation> is needed.

= Solution
{parent=h}

Skip whole trees using their cached sizes, then descend through one tree:
```
index :: List a -> Int -> a
index (List ts) i
  | i < 0     = error "index: negative index"
  | otherwise = seek ts i
  where
    seek [] _ = error "index: out of bounds"
    seek ((w,t):us) j
      | j < w     = at w t j
      | otherwise = seek us (j-w)
    at _ (Leaf x) 0 = x
    at w (Node x l r) j
      | j == 0 = x
      | j <= h = at h l (j-1)
      | otherwise = at h r (j-1-h)
      where h = w `div` 2
    at _ _ _ = error "index: invalid representation"
```
After skipping a size-$w$ tree, the desired index decreases by $w$. Inside a node, position zero is the root, positions $1,\ldots,h$ belong to the left child and the following $h$ positions to the right child. This proves correctness by <structural induction> on the search.

There are at most $\lceil\log_2(n+1)\rceil$ <forest> entries by the supplied bound, and each tree has logarithmic height. Consequently a valid query takes **$O(\log(n+1))$ time**, with logarithmic worst cases. On a conventional <linked list>, `xs !! i` follows $i$ links and costs $\Theta(i+1)$, hence $\Theta(n)$ in the worst case. The first element remains a <constant-time> query in either representation.

= Solution

The following shared step consumes exactly one input element per recursive call of `group1`:
```
prependRun :: Eq a => a -> [[a]] -> [[a]]
prependRun x xss = (x:same):rest
  where
    ~(same,rest) = case xss of
      [] -> ([],[])
      run@(y:_):runs
        | x == y    -> (run,runs)
        | otherwise -> ([],xss)

group1 :: Eq a => [a] -> [[a]]
group1 []     = []
group1 (x:xs) = prependRun x (group1 xs)
```
The helper's input consists of nonempty runs. If its first run starts with `x`, prepend `x` to that run; otherwise create a new singleton run. <Structural induction> proves that these are the maximal equal runs in order. The irrefutable pair binding `~(same,rest)` preserves <lazy evaluation>: the first output group exposes its initial `x` without inspecting the recursively grouped tail. Thus even an infinite constant input can expose the first group and each finite prefix of that group. Finite inputs take <linear time> when <equality tests> take <constant time>.

Use the same step from part (a):
```
groupFold :: Eq a => [a] -> [[a]]
groupFold = foldr prependRun []
```
The <right fold> obeys `groupFold [] = []` and `groupFold (x:xs) = prependRun x (groupFold xs)`, exactly the recursive equations already proved. Both implementations give the <bottom value> for an entirely undefined input spine. Their equal behaviour on finite <partial lists>, together with definable continuity, establishes equality on infinite <lazy lists> as well. The helper's irrefutable binding is what lets the first run be produced without demanding that all subsequent runs already exist.

= Solution
{parent=c}

A call can instead produce an entire run and recurse on the unused input:
```
groupRuns :: Eq a => [a] -> [[a]]
groupRuns [] = []
groupRuns (x:xs) = (x:ys) : groupRuns zs
  where (ys,zs) = span (== x) xs
```
Here `span` returns the longest matching <prefix of a list> and the remaining <suffix of a list>. Thus `x:ys` is the first maximal run, while `zs` begins the next run or is empty. Each recursive call produces one outer output element. The lazy pair binding permits output of the first constructor before the run's endpoint is known. Every finite input position is scanned a bounded number of times, so the <time complexity> is $\Theta(n)$ for unit-cost equality, including output construction.<Haskell 2010 Language Report>[Chapter 9, Standard Prelude, definition of span]{ref}

= Solution

The <list unfold> operation has the following <type signature> and definition:
```
unfoldr :: (s -> Maybe (a,s)) -> s -> [a]
unfoldr step s = case step s of
  Nothing     -> []
  Just (x,s') -> x : unfoldr step s'

groupUnfold :: Eq a => [a] -> [[a]]
groupUnfold = unfoldr next
  where
    next [] = Nothing
    next (x:xs) = Just (x:ys,zs)
      where (ys,zs) = span (== x) xs
```
The seed is the unprocessed <suffix of a list>. An empty seed terminates the unfold; otherwise `next` returns the first maximal run and precisely the seed for the next call. Substituting the definition of `unfoldr` recovers part (c)'s equations, proving correctness. The `Just` pair and first group constructor can be produced before `span` finishes, retaining the same <lazy evaluation> behaviour.

= Solution

Share the recursive pair and inspect the <predicate> once:
```
partition :: (a -> Bool) -> [a] -> ([a],[a])
partition _ [] = ([],[])
partition p (x:xs)
  | p x       = (x:yes,no)
  | otherwise = (yes,x:no)
  where ~(yes,no) = partition p xs
```
For a finite <list>, <structural induction> establishes that `yes` and `no` are the two required filtered subsequences. The guard evaluates `p x` once and prepends `x` to exactly one output, preserving input order in both. Fully consuming both results uses $n$ <predicate> applications and $\Theta(n)$ additional work. Sharing the recursive result avoids making separate recursive traversals. This is a <stable list partition>.

= Solution
{parent=f}

Choose the first unclassified element as the next <equivalence class representative>:
```
equiv :: Eq a => [a] -> [[a]]
equiv [] = []
equiv (x:xs) = (x:same) : equiv rest
  where ~(same,rest) = partition (== x) xs
```
Assume the `Eq` instance is an <equivalence relation>. The <stable list partition> collects every later occurrence equivalent to `x`, and `rest` contains none of that <equivalence class>. <Induction> therefore gives exactly one group per class, preserving order within each group and ordering groups by their first occurrence. For $d$ distinct classes, each input element is tested against at most $d$ representatives: the cost is $O(nd)$ and **$\Theta(n^2)$ in the all-distinct worst case**; a single class takes $\Theta(n)$.

The <equality-only grouping lower bound> shows that this worst case is unavoidable in the unrestricted equality-oracle model. On an all-distinct input, an untested pair could instead be equal without changing any observed comparison. Certifying that all $n$ elements belong to different classes therefore requires all $\binom n2$ pairwise <equality tests>.

= Solution
{parent=g}

A compatible `Ord` instance supplies a <total order>, so use <comparison sort> to put equal values together in $O(n\log n)$ time and then group adjacent equals in <linear time>. To preserve the first-occurrence group ordering of part (f), first tag every element with its original index and <stable sorting> by value. Group the sorted records by value; stability preserves their internal input order. Each group's first record carries its smallest original index. Sort the groups by that index and finally remove the tags. The second sort has at most $n$ records, so the total remains **$O(n\log n)$ time** and $O(n)$ storage. Merely returning the value-sorted groups could reorder the classes, so the index step matters when preserving the exact earlier convention. The stronger interface evades the equality-only lower bound by permitting order comparisons.

For finite even <lists>, these definitions take at most <linear time>:
```
halve :: [a] -> ([a],[a])
halve xs = splitAt (length xs `div` 2) xs

pairs :: [a] -> [(a,a)]
pairs [] = []
pairs (x:y:xs) = (x,y) : pairs xs
pairs [_] = error "pairs: odd length"
```
The length calculation and the prefix split each take $O(n)$ time. The second operation consumes two constructors per step and emits one pair. Under the stated even-length precondition, neither definition encounters an unmatched final element.

= Solution

Join either two halves or successive pairs:
```
unhalve :: ([a],[a]) -> [a]
unhalve (xs,ys) = xs ++ ys

unpairs :: [(a,a)] -> [a]
unpairs = foldr (\(x,y) zs -> x:y:zs) []
```
By the defining property of `splitAt`, concatenating the two halves restores the original <list>. For `unpairs`, <structural induction> on the even input proves that its first pair restores its first two elements and the recursive result restores the rest. Thus both requested <function compositions> are the identity. Fully consuming either result takes at most <linear time>; <list concatenation> only copies the left half once.

= Solution

Interleave equal halves, or collect the first and second components of adjacent pairs:
```
riffle :: [a] -> [a]
riffle = unpairs . uncurry zip . halve

unriffle :: [a] -> [a]
unriffle = unhalve . unzip . pairs
```
For halves `as` and `bs` of equal length, `pairs (riffle xs) = zip as bs`, and `unzip (zip as bs) = (as,bs)`. Therefore `unriffle (riffle xs) = xs`. Conversely, starting from the adjacent pairs of any even <list>, separating the components, halving their concatenation and zipping them restores those same pairs. Hence `riffle (unriffle xs) = xs` too. Every stage takes <linear time>. This <perfect out-shuffle> leaves the first and last positions fixed.

**For the defined shuffle, `count 52 = 8`.** The printed assertion about seven shuffles is inconsistent with the actual <permutation>. Number positions from zero. On an even length $n>2$, a position $i<n-1$ moves to $2i\bmod(n-1)$, while the last position stays fixed. Indeed, positions in the first half move to $2i$, and positions in the second half move to $2i-(n-1)$. Consequently the number sought is the <multiplicative order> of $2$ modulo $n-1$:
```
count :: Int -> Int
count n
  | n < 0 || odd n = error "count: nonnegative even length required"
  | n <= 2 = 1
  | otherwise = go 1 (2 `mod` m)
  where
    m = toInteger n - 1
    go k r
      | r == 1    = k
      | otherwise = go (k+1) ((2*r) `mod` m)
```
Here the identity's period means the least *positive* number of applications, so the empty and two-element <lists> have period one. Since $n-1$ is odd, $2$ is invertible modulo $n-1$, ensuring termination. Using `Integer` for residues avoids overflow in doubling; the mathematical correctness assumes the returned period fits `Int`. The algorithm uses one modular update per shuffle in the period, rather than constructing each shuffled deck.

For $n=52$, $2^8\equiv1\pmod{51}$, whereas $2$, $2^2$ and $2^4$ are not congruent to one, ruling out every proper divisor of eight. After seven shuffles, the original position $1$ is at position $26$, not back at $1$.

This single position already disproves a seven-step return; the modular calculation proves that the whole <permutation> returns after eight.

= Solution

Apply the supplied bitonic-merging fact directly:
```
merge :: Ord a => [a] -> [a]
merge xs = rounds (levels (length xs)) xs
  where
    levels n
      | n <= 1    = 0
      | otherwise = 1 + levels (n `div` 2)
    order (x,y)
      | x <= y    = (x,y)
      | otherwise = (y,x)
    pass = unpairs . map order . pairs . riffle
    rounds 0 ys = ys
    rounds r ys = rounds (r-1) (pass ys)
```
For length $n=2^k$, `levels n = k`. Each `pass` performs exactly the required shuffle and adjacent compare-exchange operations. The supplied fact therefore proves that `rounds k` yields ascending order from a <bitonic sequence>. Each pass preserves the <multiset> of entries and costs $\Theta(n)$, giving **$\Theta(n\log n)$ time** for $n\ge2$. Length one needs no pass. The definition also harmlessly returns `[]` on empty input.

= Solution

Sort the two halves ascending, reverse the second, and concatenate to form a <bitonic sequence>:
```
sort :: Ord a => [a] -> [a]
sort []  = []
sort [x] = [x]
sort xs  = merge (sort as ++ reverse (sort bs))
  where (as,bs) = halve xs
```
For a power-of-two length greater than one, both halves are smaller powers of two. By <induction>, the recursive calls return ascending <permutations> of their respective inputs. Reversal makes the second half descending, so part (e)'s precondition holds and `merge` sorts their concatenation without losing entries. This proves both <sortedness> and <sorting permutation preservation>. Its <recurrence relation> is $T(n)=2T(n/2)+\Theta(n\log n)$, so summing the levels gives **$\Theta(n(\log n)^2)$ time**. Equal keys cause no difficulty; ascending and descending here permit equality. This is a <bitonic sorting algorithm>.

= Solution

For the first <recurrence relation>, the <master theorem> compares $n^2$ with $n^{\log_2 6}$. Since $2<\log_2 6$, the recursive leaves dominate and the answer is **$\Theta(n^{\log_2 6})$**. More explicitly, the work at depth $j$ is $n^2(6/4)^j$, a growing <geometric series> that stops at depth $\log_2 n-O(1)$, where its sum has that order.

For the second <recurrence relation>, each step subtracts two and adds one until reaching a base case. For integral $n>4$ there are $\lceil(n-4)/2\rceil$ steps, so $T(n)=1+\lceil(n-4)/2\rceil$ and the answer is **$\Theta(n)$**.

The third set of printed requirements is inconsistent. The specified base values and its <recurrence relation> give $T(n)=1$ identically, as <strong induction> immediately verifies: $4\cdot1-4\cdot1+1=1$. In particular $T(8)=1$, while the extra condition demands $T(8)>2T(4)=2$. Thus **no <function> satisfies all the printed conditions**. Dropping that extra inequality gives **$\Theta(1)$**.

The likely intended growth calculation can nevertheless be made precise, without treating it as a solution of the contradictory data. On dyadic arguments put $U_j=T(2^j)$. Its equation has the general form
$$
U_j=1+(A+Bj)2^j,
$$
because $U_j-1$ has characteristic equation $(r-2)^2=0$. The printed values $U_1=U_2=1$ force $A=B=0$. With suitably different initial values, the condition $U_j>2U_{j-1}$ for arbitrarily large $j$ instead requires $B2^j-1>0$, hence $B>0$ and $U_j=\Theta(j2^j)$, or $T(n)=\Theta(n\log n)$. That last order describes corrected initial data, not the paper as printed. All three bullets belong to this single marked part.

= b
{parent=5}
{scope}

= Solution
{parent=b}

Maintain the two largest entries of each segment, counting repeated values as separate entries. A singleton returns its value and a sentinel $-\infty$ for its missing runner-up. Split a longer segment into two nonempty halves, recursively obtain $(m_L,s_L)$ and $(m_R,s_R)$, and combine them by
$$
(m,s)=\begin{cases}
(m_L,\max(s_L,m_R)),&m_L\ge m_R,\\
(m_R,\max(m_L,s_R)),&m_L<m_R.
\end{cases}
$$
For example, an implementation on an indexed <sequence> can use:
```
top2(lo, hi):
    if hi-lo == 1: return (a[lo], -infinity)
    mid = (lo+hi)//2
    (mL,sL) = top2(lo,mid)
    (mR,sR) = top2(mid,hi)
    if mL >= mR: return (mL, max(sL,mR))
    else:        return (mR, max(mL,sR))
```
The result is `top2(0,n)`. The global maximum is one of the two child maxima. Once its side is identified, the global second maximum is either that side's runner-up or the other side's maximum; the displayed formula exhausts these possibilities. This proves the <divide-and-conquer algorithm> by <induction> on segment length. There are $n$ leaves and $n-1$ constant-cost combinations, so its <time complexity> is **$\Theta(n)$**, with $O(\log n)$ recursive stack space for balanced splits. A `Maybe` value can replace the formal sentinel for a generic ordered element type. If both largest entries are equal, both are returned; a second *distinct* value is a different specification.

= Solution
{parent=c}

For each segment retain its total weight $S$, largest possibly-empty prefix weight $P$, largest possibly-empty suffix weight $Q$, and largest possibly-empty internal contiguous weight $B$. The <maximum-subarray segment summary> combines adjacent segments as
$$
\begin{aligned}
S&=S_L+S_R,\\
P&=\max(P_L,S_L+P_R),\\
Q&=\max(Q_R,S_R+Q_L),\\
B&=\max(B_L,B_R,Q_L+P_R).
\end{aligned}
$$
An empty segment has all four values zero. For a singleton of weight $x$, use $(x,\max(0,x),\max(0,x),\max(0,x))$. The recursive procedure splits into halves, computes their summaries and applies these four formulas; the root's $B$ is the desired maximum weight.

To return an actual subsequence, attach half-open endpoints to each of $P,Q,B$. A prefix endpoint starts at its segment's left boundary, and a suffix endpoint ends at its right boundary, including empty prefixes and suffixes. Store the interval belonging to whichever candidate wins a maximum. The crossing candidate joins a left suffix to a right prefix, which meet at the split point; the other candidates keep their child endpoints. Choose an empty interval on ties at weight zero. Return the root's winning interval as a slice of the original input. This augmentation still has constant-size state and constant-time combinations.

For correctness, a prefix either stays inside the left half or consists of the entire left half and a right prefix. The suffix argument is symmetric. An optimal contiguous segment either lies in one half or crosses the split, in which case it consists of a left suffix and a right prefix. Each upper bound in the formulas is attained by its recorded candidate, proving exactness. Empty candidates ensure that an all-negative input returns the empty subsequence.

There are $\Theta(n)$ tree nodes, each using a constant number of additions and comparisons. The <divide-and-conquer algorithm> therefore takes **$\Theta(n)$ time** and $O(\log n)$ stack space, plus the cost of copying the returned slice if a copy is required. In the stated example it selects zero-based interval $[3,6)$ of weight **8**. Carrying all four summary values avoids rescanning the halves at each split.

Use positive integral item weights and a nonnegative integral capacity. For the <unbounded knapsack problem>, define $K(c)$ to be the best value with total weight *at most* $c$. Then
$$
\boxed{K(c)=\max\bigl(\{0\}\cup\{v_i+K(c-w_i):1\le i\le n,\ w_i\le c\}\bigr),\quad K(0)=0.}
$$
The zero candidate is the empty selection, so unused capacity is allowed and an empty set of fitting items causes no problem. Every nonempty feasible selection has some last item $i$; removing one copy leaves a feasible solution at capacity $c-w_i$. Its value is bounded by the corresponding candidate. Conversely, taking an optimal smaller selection and adding that item attains the candidate, proving the <recurrence relation> by <optimal substructure>. Positive weights make every dependency strictly smaller.

Fill capacities in increasing order. There are $W+1$ entries, each scanning $n$ items, so the <dynamic programming> takes $O(nW)$ time and $O(W)$ storage. A winning item pointer at each capacity reconstructs the chosen multiplicities. These are capacity-dependent, <pseudopolynomial> bounds. For zero-weight items, any positive value makes the repetition problem unbounded; nonpositive-value zero-weight items may simply be discarded before using the recurrence.

= Solution

Capacity alone cannot say which items have already been used. For the <0-1 knapsack problem>, let $D(i,c)$ use only the first $i$ items, each at most once. Then
$$
\boxed{D(0,c)=0,\qquad D(i,c)=\begin{cases}
D(i-1,c),&w_i>c,\\
\max\{D(i-1,c),\ v_i+D(i-1,c-w_i)\},&w_i\le c.
\end{cases}}
$$
The two alternatives omit item $i$ or take it. In the latter case its remaining companions must solve the smaller problem using the first $i-1$ items; otherwise replacing them would improve the whole selection. Both branches reduce the item index, so taking item $i$ cannot take it again. This establishes the <recurrence relation> and <optimal substructure>.

Fill rows in increasing $i$ and return $D(n,W)$. There are $O(nW)$ entries with constant work each. Store the decisions for reconstruction; value-only computation uses $O(W)$ space by keeping two rows, or by scanning capacities downwards in a single row. A forward scan in a single row would instead allow repetitions. Nonnegative integral weights suffice for this version, including zero-weight items, because the item index always decreases.

= Solution

This version of <Kadane's algorithm>, named for <Joseph Born Kadane>, permits the empty subsequence. For $j\ge1$, let $E_j$ be the maximum of zero and the weight of a contiguous subsequence ending exactly at position $j$. Let $B_j$ be the best weight anywhere in the first $j$ positions. Use
$$
\boxed{E_0=B_0=0,\qquad E_j=\max(0,E_{j-1}+a_j),\qquad B_j=\max(B_{j-1},E_j).}
$$
A segment ending at $j$ either extends one ending at $j-1$ or starts at $j$; the zero candidate permits discarding a negative predecessor and the empty answer. Any best segment of the first $j$ positions either ends at $j$ or already occurs in the first $j-1$. These two decompositions prove the <dynamic programming> equations by <induction>.

Here is an implementation returning endpoints, using zero-based indexing:
```
best_segment(a):
    end_weight = best_weight = 0
    start = best_lo = best_hi = 0
    for j in range(len(a)):
        trial = end_weight + a[j]
        if trial <= 0:
            end_weight = 0
            start = j+1
        else:
            end_weight = trial
        if end_weight > best_weight:
            best_weight = end_weight
            best_lo, best_hi = start, j+1
    return (best_lo, best_hi, best_weight)
```
There is exactly **one addition per input element**, hence $n$ additions and $O(n)$ comparisons. Auxiliary storage is $O(1)$. The all-negative case retains interval $[0,0)$ and weight zero. The example returns $[3,6)$ and weight **8**, hence the desired contiguous subsequence.

The <Dijkstra algorithm> finalises <vertices> in the order **$1,3,2,5,4$**. After finalising $1$, tentative distances to $2,3$ are $3,2$. Finalising $3$ sets the distance to $5$ to $4$. Finalising $2$ sets the distance to $4$ to $6$. Finalising $5$ improves the distance to $4$ to $5$; its <edge> to $2$ proposes $5$ and causes no improvement. The final distance vector in <vertex> order is **$(0,3,2,5,4)$**. All weights are positive, so every finalisation is justified by the usual <label-setting shortest-path algorithm> invariant. The method is named for <Edsger W. Dijkstra>.

The intermediate states of the <Bellman-Ford algorithm> depend on <edge> order. Specify in-place <edge relaxation> in lexicographic directed-edge order:
$$
(1,2),(1,3),(2,3),(2,4),(3,5),(5,2),(5,4).
$$
Starting with $(0,\infty,\infty,\infty,\infty)$, the first pass changes the vector as follows; omitted relaxations make no change:
$$
\begin{array}{c|ccccc}
\text{after edge}&d_1&d_2&d_3&d_4&d_5\\\hline
(1,2)&0&3&\infty&\infty&\infty\\
(1,3)&0&3&2&\infty&\infty\\
(2,4)&0&3&2&6&\infty\\
(3,5)&0&3&2&6&4\\
(5,4)&0&3&2&5&4
\end{array}
$$
The next pass makes no change, allowing early termination. If all $|V|-1=4$ passes are performed, passes two through four retain **$(0,3,2,5,4)$**.

For the synchronous convention, where every relaxation reads only the previous row, the <synchronous Bellman-Ford recurrence> instead gives
$$
\begin{array}{c|ccccc}
\text{allowed edges}&d_1&d_2&d_3&d_4&d_5\\\hline
0&0&\infty&\infty&\infty&\infty\\
1&0&3&2&\infty&\infty\\
2&0&3&2&6&4\\
3&0&3&2&5&4\\
4&0&3&2&5&4
\end{array}
$$
Both conventions reach the same shortest distances. The algorithm's eponyms are <Richard Bellman> and <L. R. Ford Jr.>.

= Solution

Let $N=|V|$ and replace every <edge> weight by **$w'(e)=Nw(e)+1$**. Call the supplied shortest-path routine once using these new weights, and return its path in the original graph. For every path $P$,
$$
w'(P)=Nw(P)+|P|,
$$
where $|P|$ is its number of <edges>. Positive original weights imply positive transformed weights, so a shortest route can be taken to be simple and has at most $N-1$ <edges>. Distinct integral original weights of paths differ by at least one. Thus if $w(P)<w(Q)$ for simple paths, then
$$
w'(Q)-w'(P)=N\bigl(w(Q)-w(P)\bigr)+|Q|-|P|\ge N-(N-1)>0.
$$
For equal original weights, the transformed comparison is exactly the comparison of hop counts. Therefore every transformed shortest path minimises original weight first and number of <edges> second, proving the <integer-weight shortest-path tie-breaking lemma>. The transformation costs $O(N+|E|)$ time, followed by one subroutine call. Weights gain only $O(\log N)$ bits; exact arithmetic should be used if multiplying machine-sized weights might overflow. If $t$ is unreachable, it remains unreachable.

Use a <dynamic programming state> indexed by an <edge> budget. Put $D_0(s)=0$ and $D_0(v)=\infty$ for $v\ne s$, then for $r=1,\ldots,k$ compute
$$
\boxed{D_r(v)=\min\left(D_{r-1}(v),\ \min_{(u,v)\in E}\{D_{r-1}(u)+w(u,v)\}\right).}
$$
Every route using at most $r$ <edges> either already uses at most $r-1$, or ends with some <edge> $(u,v)$ whose preceding route uses at most $r-1$. Conversely every finite candidate in the displayed equation is attained by such a route. This proves the <hop-bounded shortest-route recurrence> by <induction> on $r$, even when weights are negative.

In each round, copy the previous distance row and relax every <edge> into the new row, always reading from the old row. An in-place pass would allow several new <edges> in one round and violate the <edge> budget. Store a predecessor record for every selected candidate, either a carry to $(r-1,v)$ or the incoming <edge> from $(r-1,u)$. Following records backwards from $(k,t)$ and reversing the collected <edges> returns the actual optimum route; an infinite final distance means no feasible route exists.

Only <vertices> incident to an <edge>, together with $s,t$, need distance fields. In a graph representation whose <edges> reference <vertex> records, initialise those fields by visiting both endpoints of every <edge>, then $s,t$; repeated initialisations are harmless. In each round, first copy old fields to new fields by another complete endpoint pass, and only then begin the relaxation pass. Copying the same endpoint several times before any relaxation also does no harm. Thus each round costs $O(m+1)$, with no scan of isolated <vertices>, and for $m,k\ge1$ the total is **$O(km)$ time**. An implementation that instead initialises full arrays for all <vertices> has the conventional bound $O(|V|+km)$. For $k=0$ or no <edges>, only the empty route $s=t$ can succeed.

To realise reconstruction without a dense table, associate a persistent route record with each finite distance. A successful relaxation in round $r$ creates a record containing the new <edge> and a pointer to the old round's route record at its source; a carry shares its record. All reads use old-round records. At most $km$ such records are created, taking $O(km)$ space, and the returned chain has at most $k$ <edges>. Distances alone need only two fields per relevant <vertex>.

Here “route” uses the standard edge-budget shortest-path convention permitting repeated <vertices>; a bounded budget prevents an arbitrarily long negative-cycle traversal. If “path” instead requires <vertex> simplicity with unrestricted negative weights, this recurrence does not enforce that extra restriction. With nonnegative weights, removing cycles gives a simple optimum within the same budget.

= Solution

To find a <minimum-weight acyclic subgraph>, filter to the subgraph $G_-$ containing only **strictly negative-weight <edges>**, and run <Kruskal's algorithm> on those <edges>, accepting an <edge> exactly when it joins different current components. Return the resulting <forest>, with any omitted <vertices> regarded as isolated. Zero-weight <edges> may be omitted without worsening the objective.

To prove correctness, first remove all nonnegative <edges> from any feasible <acyclic graph>; removing them preserves acyclicity and cannot increase weight. Thus an optimum using only negative <edges> exists. Inside a connected component of $G_-$, any <forest> not yet connected can be extended by a negative crossing <edge>: some such <edge> exists because the original component is connected. Adding it preserves acyclicity and strictly reduces total weight. Consequently an optimum must span each component of $G_-$, and its restriction there must be a <minimum spanning tree>. <Kruskal's algorithm> finds exactly the resulting <minimum spanning forest> of $G_-$. This proves optimality among all acyclic subgraphs, including disconnected ones.

With $m_-$ negative <edges>, filtering costs $O(|V|+|E|)$, sorting costs $O(m_-\log(m_-+1))$, and the <union-find> operations take $O((|V|+m_-)\alpha(|V|))$ time. A standard overall bound is **$O(|V|+|E|\log(|E|+1))$ time**. If there are no negative <edges>, the empty <edge> set is optimal.

= Solution
{parent=d}

Assume the graph is connected so that a <minimum spanning tree> exists, and let $T$ be the output of <Kruskal's algorithm>. With distinct weights there is a strict total <edge> ordering. Suppose another <minimum spanning tree> $T'\ne T$ existed. Choose $e\in T\setminus T'$ and increase only $w(e)$ by a positive $\varepsilon$ so small that the strict ordering of *all* <edge> weights remains unchanged. For a finite graph such an $\varepsilon$ exists, using less than the gap to the next larger weight; if $e$ is largest, any sufficiently small positive increase works.

Running <Kruskal's algorithm> again examines exactly the same order and makes exactly the same component decisions. It therefore still returns $T$, which must remain optimal for the perturbed weights. But $T$ has become more expensive by $\varepsilon$, while $T'$ is unchanged. They had equal original weight, so now $T'$ is cheaper, a contradiction. This proves that <distinct weights imply a unique minimum spanning tree>.

The converse is **false**. A triangle with <edge> weights $1,1,2$ has a unique <minimum spanning tree>, consisting of its two weight-one <edges>. Its total is $2$, while either other spanning tree has total $3$. Thus equal <edge> weights permit, but do not force, multiple optimum trees. The same perturbation proof applies componentwise to a <minimum spanning forest>.
