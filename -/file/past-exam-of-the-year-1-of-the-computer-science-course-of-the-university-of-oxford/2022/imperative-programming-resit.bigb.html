= Imperative programming (resit)

Imperative Programming Part 1.

=== a
{scope}

==== i
{scope}

===== Solution

Use a `Double` base so that the reciprocal is not truncated by <integer division>. Repeated multiplication gives the requested linear-work approximation to <Euler's number>.

```
def eaLinear(n: Int): Double = {
  require(n > 0)
  val base = 1.0 + 1.0 / n.toDouble
  var i = 0
  var result = 1.0
  while (i < n) {
    result *= base
    i += 1
  }
  result
}
```

In exact arithmetic over the <real numbers>, the <loop invariant> is $0\leq i\leq n$ and $result=base^i$. It holds initially, one multiplication establishes the next exponent, and at exit $i=n$ gives the specified power. The nonnegative <loop variant> is $n-i$. **There are exactly $n$ loop multiplications**, hence $\Theta(n)$ in <asymptotic analysis>, and one division to form the base. With <floating-point arithmetic>, the invariant describes the intended exact result; the actual output has the corresponding rounding errors.

==== ii
{scope}

===== Solution

Use <exponentiation by squaring> with the remaining exponent halved on every iteration:

```
def eaFast(n: Int): Double = {
  require(n > 0)
  var remaining = n
  var base = 1.0 + 1.0 / n.toDouble
  var result = 1.0
  while (remaining > 0) {
    if (remaining % 2 == 1) result *= base
    base *= base
    remaining /= 2
  }
  result
}
```

Writing $a=1+1/n$, the exact-arithmetic <loop invariant> is $remaining\geq0$ and $result\,base^{remaining}=a^n$. For an <even integer> exponent $2q$, replace the base by its square and the exponent by $q$. For an <odd integer> exponent $2q+1$, first multiply the accumulator by the base and then make the same replacement. Both preserve the product. The <loop variant> is `remaining`, which strictly decreases while positive. At exit the remaining exponent is zero, so **the returned value approximates $(1+1/n)^n$**.

There are $L=\lfloor\log_2 n\rfloor+1$ iterations, $L$ squarings and one accumulator multiplication for each set <bit> of $n$: between $L+1$ and $2L$ multiplications. Thus the bound is $\Theta(\log n)$ as $n\to\infty$, or $\Theta(1+\log n)$ including the small case $n=1$. All power variables are `Double`; no unintended `Int` squaring occurs.

=== b
{scope}

==== Solution

Maintain the reciprocal <factorial> term rather than calculating large <factorials> separately:

```
def eb(n: Int): Double = {
  require(n > 0)
  var i = 0
  var term = 1.0
  var sum = 1.0
  while (i < n) {
    i += 1
    term /= i.toDouble
    sum += term
  }
  sum
}
```

The exact-arithmetic <loop invariant> is $0\leq i\leq n$, $term=1/i!$, and $sum=\sum_{k=0}^{i}1/k!$. It holds for $i=0$ because $0!=1$. Dividing by the new index produces the next reciprocal <factorial>; adding it extends the partial sum. The <loop variant> is $n-i$. At exit the sum includes **all terms from $0$ through $n$**, using exactly $n$ divisions and no multiplications in the loop. In particular, the initial `1.0` accounts for the zero-index term. The work bound is $O(n)$, with constant <auxiliary space>.

=== c
{scope}

==== Solution

Avoid forming the enormous powers in the original ratios. Put $a=1+1/n$, $b=1+1/(n-1)$ and $k=n-1$; algebra gives
$$
e_c(n)=(n+1)a\,a^k-nb^k.
$$
Use <simultaneous exponentiation by squaring> to compute the two powers with one loop and a shared remaining exponent:

```
def ec(n: Int): Double = {
  require(n > 1)
  val dn = n.toDouble
  val a = 1.0 + 1.0 / dn
  val b = 1.0 + 1.0 / (dn - 1.0)
  var remaining = n - 1
  var u = a
  var v = b
  var pa = 1.0
  var pb = 1.0
  while (remaining > 0) {
    if (remaining % 2 == 1) {
      pa *= u
      pb *= v
    }
    u *= u
    v *= v
    remaining /= 2
  }
  ((dn + 1.0) * a) * pa - dn * pb
}
```

The exact-arithmetic <loop invariant> is $remaining\geq0$, $pa\,u^{remaining}=a^{n-1}$ and $pb\,v^{remaining}=b^{n-1}$. The <even integer> and <odd integer> cases preserve both equalities in parallel. The <loop variant> is `remaining`. On termination, the displayed expression is exactly the desired approximation in the ideal arithmetic model. For $L=\lfloor\log_2(n-1)\rfloor+1$, the loop uses at most $4L$ multiplications, followed by three more: **$O(\log n)$ multiplications and one loop**.

Converting `n` to `Double` before adding one also avoids overflowing `n + 1` at `Int.MaxValue`. The algebra avoids power overflow but does not remove <catastrophic cancellation>: the final subtraction combines quantities of order $n e$ to obtain a result of order $e$. For sufficiently large $n$, <floating-point rounding> can outweigh the mathematical truncation error. For example, at `n == 1000000` this `Double` computation returns approximately **`2.7180521293`**, although the exact formula is approximately **`2.71828182845916`**. Arbitrarily many requested decimal digits require increased arithmetic precision, not simply a larger `Int` argument.

=== d
{scope}

==== Solution

**Use the reciprocal-<factorial> sum for increasing accuracy.** Let $d$ be the requested number of decimal places and use absolute error tolerance proportional to $10^{-d}$. Expanding $\log(1+1/n)$ gives $e_a(n)=e-e/(2n)+O(n^{-2})$ and $e_c(n)=e+e/(24n^2)+O(n^{-3})$, so these are genuine first nonzero error orders. The first approximation needs $n$ of order $10^d$. Even its fast implementation therefore uses $\Theta(d)$ multiplications, while the linear version uses exponentially many in $d$. The third approximation needs $n$ of order $10^{d/2}$, but its fast powering still uses $\Theta(d)$ multiplications, with two parallel accumulators and a cancellation-prone subtraction.

For the <Taylor series> sum, <Stirling's formula> gives $\log(n!)=\Theta(n\log n)$, so a sufficient term count grows as **$n=\Theta(d/\log d)$**. Its divisions therefore grow more slowly than the multiplication counts of either fast-power alternative. More concretely, its positive tail satisfies
$$
0<e-e_b(n)\leq\frac1{(n+1)!}\sum_{j=0}^{\infty}\frac1{(n+2)^j}=\frac{n+2}{(n+1)(n+1)!}.
$$
The first omitted term also gives a lower bound $1/(n+1)!$. This is the <reciprocal-factorial series remainder bound>, supplying an explicit stopping certificate rather than relying only on <Big O notation>. It follows by bounding every successive tail denominator factor below by $n+2$.

The sum also avoids subtraction of nearly equal large values and has small positive terms, making it numerically preferable. For a particular small accuracy request, constants and actual term counts may be compared directly; an asymptotic error bound alone does not prove a universal finite-input operation ranking. With ordinary `Double`, sufficiently many tiny positive terms stop changing the rounded sum, so beyond machine precision a higher-precision version is necessary regardless of the formula.

=== a
{scope}

==== Solution

Use an optional pair of <array indices>, so failure is distinct from every valid position:

```
def search(f: Array[Array[Int]], x: Int): Option[(Int, Int)]
```

**`Some((i,j))` denotes a match; `None` denotes absence.** The extra <array> argument makes the dependence on the searched data explicit; if `f` is already enclosed in the surrounding scope, it can instead be omitted. For all implementations below, assume `f` is non-null, its rows are non-null and rectangular, and it remains unchanged during the search. Empty dimensions are permitted.

=== b
{scope}

==== Solution

Without order information, inspect entries one row at a time:

```
def searchUnordered(f: Array[Array[Int]], x: Int): Option[(Int, Int)] = {
  val n = f.length
  val m = if (n == 0) 0 else f(0).length
  var i = 0
  while (i < n) {
    var j = 0
    while (j < m) {
      if (f(i)(j) == x) return Some((i, j))
      j += 1
    }
    i += 1
  }
  None
}
```

The outer <loop invariant> excludes every entry in earlier rows; the inner one also excludes columns before `j` in the current row. Failed <equality tests> preserve these exclusions. The inner and outer <loop variants> are $m-j$ and $n-i$, respectively. A successful return identifies an actual match, while exhaustion excludes the entire <array>. At most $nm$ entries are inspected.

The source's “at least $O(nm)$” should be read as a worst-case **$\Omega(nm)$ lower bound**, using the correct asymptotic direction. If any entry were left unread on an all-nonmatching input, changing only that entry to $x$ would leave the observations identical while changing the answer. Thus every always-correct procedure needs $nm$ inspections in the worst case, and this algorithm achieves $\Theta(nm)$ entry inspections. Empty dimensions return absence; the asymptotic claim concerns nonempty arrays.

=== c
{scope}

==== Solution

Use a <lower-bound search> separately in each nondecreasing row:

```
def searchRows(f: Array[Array[Int]], x: Int): Option[(Int, Int)] = {
  val n = f.length
  val m = if (n == 0) 0 else f(0).length
  if (m == 0) return None
  var i = 0
  while (i < n) {
    var lo = 0
    var hi = m
    while (lo < hi) {
      val mid = lo + (hi - lo) / 2
      if (f(i)(mid) < x) lo = mid + 1
      else hi = mid
    }
    if (lo < m && f(i)(lo) == x) return Some((i, lo))
    i += 1
  }
  None
}
```

The outer <loop invariant> says there is no match in earlier rows. The inner invariant is $0\leq lo\leq hi\leq m$, with every value before `lo` smaller than $x$ and every value from `hi` onward at least $x$. <Sortedness> justifies each exclusion, and `hi - lo` strictly decreases. At exit, a match in this row exists exactly when the lower-bound index is inside the row and holds $x$. Failure extends the outer exclusion.

The cost is **$O(n(1+\log m))$**, conventionally written $O(n\log m)$ for $m\geq2$; the extra one matters when a row has a single entry. Storage is constant. The source's column ranges must use indices strictly below $m$, since `f(i)(m)` is outside the <array>.

=== d
{scope}

==== Solution

Assume both dimensions are positive so the top-right entry exists. If **`f(0)(m-1) == x`**, it is already a match. If it is smaller than $x$, the entire first row is smaller, since it is that row's maximum; discard the first row. If it is larger than $x$, the entire last column is larger, since it is that column's minimum; discard the last column. This is the <staircase matrix search> elimination step. Row and column monotonicity are both needed for the respective conclusions.

=== e
{scope}

==== Solution

Maintain a remaining rectangle with its top-right corner at `(i,j)`:

```
def searchMonotone(f: Array[Array[Int]], x: Int): Option[(Int, Int)] = {
  val n = f.length
  val m = if (n == 0) 0 else f(0).length
  var i = 0
  var j = m - 1
  while (i < n && j >= 0) {
    val v = f(i)(j)
    if (v == x) return Some((i, j))
    else if (v < x) i += 1
    else j -= 1
  }
  None
}
```

The <loop invariant> is that any match must lie in rows $i,\ldots,n-1$ and columns $0,\ldots,j$. Smaller corner values exclude the current row, larger ones exclude the current column, as shown in part (d). The <loop variant> $(n-i)+(j+1)$ is nonnegative while the rectangle is nonempty and decreases by one on every unsuccessful inspection. When the loop exits, the rectangle is empty, so absence is established.

**At most $n+m-1$ entries are inspected when both dimensions are positive**, giving $O(n+m)$ <running time> and $O(1)$ <auxiliary space>. An empty dimension causes no entry access. Duplicates do not affect the argument, since every exclusion uses a <strict inequality> relative to the target.

Imperative Programming Part 2.

=== a
{scope}

==== Solution

The abstract <FIFO queue> state is a finite <sequence> $q:[A]$, initially empty. Because the interface returns `Int` length, use the representable-size model $0\leq|q|\leq Int.MaxValue$. Its operations are:

```
trait Queue[A] {
  // State q: finite sequence of A; initially [].
  // Pre: length(q) < Int.MaxValue. Post: q = q0 ++ [x].
  def enqueue(x: A): Unit

  // Pre: q is nonempty. Post: return head(q0); q = tail(q0).
  def dequeue(): A

  // Post: q = [].
  def clear(): Unit

  // Post: q unchanged; return q.isEmpty.
  def isEmpty: Boolean

  // Post: q unchanged; return length(q).
  def length: Int
}
```

The unchanged-state clauses on the two queries are part of their <postconditions>. `dequeue` removes exactly the oldest remaining element, while `clear` discards all entries regardless of the old state. The size bound can be omitted in an unbounded mathematical model, but it must be reconciled with fixed-width lengths in an implementation.

=== b
{scope}

==== Solution

A node needs a stored value and one successor reference:

```
final class QueueNode(val value: Int, var next: QueueNode)
```

A null successor terminates the chain. The stored value need not be mutable for a <FIFO queue>, because enqueue creates a node and dequeue removes one rather than changing its payload.

=== c
{scope}

==== Solution

Keep a head, a tail and a cached length:

```
private var first: QueueNode = null
private var last: QueueNode = null
private var size = 0
```

The <representation invariant> requires $0\leq size\leq Int.MaxValue$ and a finite acyclic <null-terminated linked list> of exactly `size` nodes starting at `first`. When `size == 0`, both endpoints are null. Otherwise `last` is precisely the final reachable node and `last.next == null`.

The <abstraction function> maps the chain from first to last to its payload <sequence>. Initially all pointers are null and the cached size is zero, giving the empty abstract queue. A tail pointer makes append constant-time; the cached size makes the `length` query constant-time without traversing the chain.

=== d
{scope}

==== Solution

Use the <trait> and node definition above. The reference to a “stack” in this part is a wording error: the declared class and operations implement a <FIFO queue>.

```
class ListQueue extends Queue[Int] {
  private var first: QueueNode = null
  private var last: QueueNode = null
  private var size = 0

  def enqueue(x: Int): Unit = {
    require(size < Int.MaxValue, "queue size limit")
    val fresh = new QueueNode(x, null)
    if (last == null) first = fresh
    else last.next = fresh
    last = fresh
    size += 1
  }

  def dequeue(): Int = {
    require(first != null, "empty queue")
    val answer = first.value
    first = first.next
    size -= 1
    if (first == null) last = null
    answer
  }

  def clear(): Unit = {
    first = null
    last = null
    size = 0
  }

  def isEmpty: Boolean = size == 0
  def length: Int = size
}
```

Appending links the fresh node after the old tail, or establishes both endpoints when empty. Removing the head preserves the tail unless the final node was removed, in which case both endpoints become null. Clearing only discards the endpoint references; it need not visit or overwrite unreachable nodes. Thus all operations are **$O(1)$ in the usual pointer-operation/allocation cost model**, with later <garbage collection> excluded from an individual operation's bound. The <representation invariant> and <abstraction function> show the specified <sequence> changes, including empty/singleton transitions.

=== a
{scope}

==== Solution

A <list header> is a permanent dummy node that represents the list boundary rather than a data entry. A <circular linked list> links the last node back to the first or to the header. A <singly linked list> stores only a successor; a <doubly linked list> stores both successor and predecessor references.

A header provides a stable object even for an empty list, makes insertions and deletions at the ends resemble interior operations, and can hold metadata such as the vector length in this question. In a circular header-based representation, the empty list is the header linked to itself.

A <doubly linked list> permits backward traversal and constant-time unlinking of a known node without searching for its predecessor. It uses an extra reference per node and requires more pointer updates and a stronger consistency invariant. Finding a node by an arbitrary index can still require a linear scan: bidirectional links alone do not provide random access.

=== b
{scope}

==== i
{scope}

===== Solution

Within the sparse-vector implementation, use:

```
class Node(var value: Double, val index: Int,
           var prev: Node, var next: Node)
```

The header's `index` is the fixed vector dimension, so it need not change after construction. For a data node it is the coordinate index. The <representation invariant> requires a finite simple cycle through the header, reciprocal predecessor/successor links, strictly increasing indices in the forward data-node traversal, indices in $[0,dimension)$, and a nonzero value at every data node. The header's value is ignored. The <abstraction function> assigns stored values to their indices and zero to all missing coordinates.

The numerical code below takes entries to be finite `Double` values. Excluding NaN and infinities makes the relationship to a real <sparse vector> explicit; arithmetic results still follow ordinary <floating-point arithmetic>.

==== ii
{scope}

===== Solution

**A single header with `index == n`, and with both `next` and `prev` pointing to itself, represents the entirely zero vector.** It has no data nodes. The ignored header value can be `0.0`. The vector dimension remains $n$, even though the number of stored nonzero entries is zero.

=== c
{scope}

==== Solution

Permit any nonnegative dimension, including the empty vector:

```
def makeZeroVector(size: Int): Node = {
  require(size >= 0, "negative vector length")
  val head = new Node(0.0, size, null, null)
  head.prev = head
  head.next = head
  head
}
```

This establishes the circular-link <representation invariant> in $O(1)$ time and uses one header regardless of the number of implicit zeros. For the nonzero dimension mentioned in part (b), simply use `size > 0` at that call site.

=== d
{scope}

==== Solution

Assume `vector` is a well-formed header satisfying the sparse-vector <representation invariant>; checking that whole invariant on each operation would require traversing the list. Check the requested bounds and value, then find the first stored coordinate at or after the target.

```
def setElement(vector: Node, value: Double, index: Int): Unit = {
  require(vector != null)
  require(0 <= index && index < vector.index)
  require(value != 0.0 && !value.isNaN && !value.isInfinity)
  var p = vector.next
  while ((p ne vector) && p.index < index) p = p.next
  if ((p ne vector) && p.index == index) p.value = value
  else {
    val fresh = new Node(value, index, p.prev, p)
    p.prev.next = fresh
    p.prev = fresh
  }
}
```

The scan excludes all smaller stored indices. An existing coordinate is updated without duplicating it; otherwise the new node is spliced immediately before `p`, with both directions repaired. The header also serves as the insertion boundary after the final data node. Strict index order and nonzero storage are preserved. The cost is **$O(k)$ search and $O(1)$ pointer work**, where $k$ is the number of stored entries.

=== e
{scope}

==== Solution

An absent coordinate already has value zero. If found, unlink its node in both directions:

```
def zeroElement(vector: Node, index: Int): Unit = {
  require(vector != null)
  require(0 <= index && index < vector.index)
  var p = vector.next
  while ((p ne vector) && p.index < index) p = p.next
  if ((p ne vector) && p.index == index) {
    p.prev.next = p.next
    p.next.prev = p.prev
  }
}
```

Identity comparison with the header prevents treating its dimension field as a data index. The splice preserves reciprocal links even when removing the only data node: the two header links then point to the header again. All other coordinates are unchanged, and an absent coordinate causes no mutation. **The <running time> is $O(k)$**, with constant work after the node is located.

=== f
{scope}

==== Solution

Append nonzero entries in increasing index order; repeatedly calling `setElement` would unnecessarily rescan earlier entries and could make construction quadratic.

```
def makeVector(elems: Array[Double]): Node = {
  require(elems != null)
  val head = makeZeroVector(elems.length)
  var tail = head
  var i = 0
  while (i < elems.length) {
    val v = elems(i)
    require(!v.isNaN && !v.isInfinity)
    if (v != 0.0) {
      val fresh = new Node(v, i, tail, head)
      tail.next = fresh
      head.prev = fresh
      tail = fresh
    }
    i += 1
  }
  head
}
```

The <loop invariant> says that the list represents exactly the nonzero entries of the processed input prefix, in their original coordinate order, and `tail` is the final node or the header when none exist. Every append preserves the cycle and ordering. At exit, all input coordinates have their intended values. **Construction takes $O(n)$ time and $O(k)$ data nodes**, where $n$ is the <array> length and $k$ the number of nonzeros, plus one header. The input <array> is unchanged.

=== g
{scope}

==== Solution

Use <sparse dot product by merging indices>: only equal coordinate indices can contribute, so merge the two increasing index streams:

```
def dotProduct(vec1: Node, vec2: Node): Double = {
  require(vec1 != null && vec2 != null)
  require(vec1.index == vec2.index, "dimension mismatch")
  var p = vec1.next
  var q = vec2.next
  var answer = 0.0
  while ((p ne vec1) && (q ne vec2)) {
    if (p.index < q.index) p = p.next
    else if (q.index < p.index) q = q.next
    else {
      answer += p.value * q.value
      p = p.next
      q = q.next
    }
  }
  answer
}
```

The <loop invariant> states that the accumulator contains all common-coordinate products already passed, while no unprocessed smaller coordinate can acquire a future partner. If one current index is smaller, the other list has no remaining entry at that index, so its product is zero. Equal indices add their product and advance both. Once either list ends, all remaining coordinates of the other have zero partners.

Thus the code computes the <dot product> in coordinate order, subject to <floating-point rounding>, using **$O(k_1+k_2)$ time and constant auxiliary storage**. It does not scan implicit zeros or alter either vector, and it also handles both arguments referring to the same header.

=== a
{scope}

==== i
{scope}

===== Solution

A flattened Boolean <array> stores the whole board in $N^2$ entries, with cell $(x,y)$ at position `y*N + x`. For the pictured board, its bottom-to-top rows are **`111111 | 111100 | 111100 | 110000 | 000000 | 000000`**.

A column-height <array> uses only $N$ entries: column $x$ contains exactly the cells below height $h(x)$. The pictured board is **$h=(4,4,3,3,1,1)$**, with 16 occupied cells. The alternatives are essentially different because the first stores every cell and the second encodes the boundary of an <order ideal>.

==== ii
{scope}

===== Solution

For the flattened Boolean <array>, the <abstraction function> selects the true cells. A suitable <representation invariant> requires the occupied cells to form a <order ideal>: an occupied $(x,y)$ implies occupancy of every $(i,j)$ with $i\leq x,j\leq y$. Deleting a northeast rectangle preserves that property.

For column heights, the invariant is $N\geq h(0)\geq h(1)\geq\cdots\geq h(N-1)\geq0$, and the <abstraction function> is $B=\{(x,y):0\leq x<N,\ 0\leq y<h(x)\}$. A legal move replaces every $h(i)$ for $i\geq x$ by $\min(h(i),y)$, preserving the invariant. This is an <order-ideal board representation>.

For a fair comparison, allow either representation a scalar cached token count: `Count` and `Legal` then take $O(1)$ in both. Without that cache, counting needs $\Theta(N^2)$ Boolean inspections versus $\Theta(N)$ height additions. A move takes $O(N^2)$ in the worst case in the flattened representation and $O(N)$ with heights. Displaying the full square takes $\Theta(N^2)$ character positions in either. Heights use **$\Theta(N)$ <array> entries rather than $\Theta(N^2)$**, so they are superior for the requested operations; their initialization also takes only $\Theta(N)$ time.

=== b
{scope}

==== Solution

Use column heights and update the cached count by the number of removed cells:

```
class Chomps(N: Int) {
  require(N > 0 && N.toLong * N.toLong <= Int.MaxValue)
  private val height = Array.fill(N)(N)
  private var remaining = (N.toLong * N.toLong).toInt

  def Count(): Int = remaining

  def Legal(x: Int, y: Int): Boolean =
    0 <= x && x < N && 0 <= y && y < height(x)

  def Move(x: Int, y: Int): Unit = {
    require(Legal(x, y), "illegal move")
    var i = x
    while (i < N && height(i) > y) {
      remaining -= height(i) - y
      height(i) = y
      i += 1
    }
  }

  def Display(): Unit = {
    require(N < 10, "single-digit display labels required")
    var y = N - 1
    while (y >= 0) {
      print(y + "  ")
      var x = 0
      while (x < N) {
        print(if (y < height(x)) "* " else "  ")
        x += 1
      }
      println()
      y -= 1
    }
    print("   ")
    var x = 0
    while (x < N) { print(x + " "); x += 1 }
    println()
  }
}
```

The strengthened <representation invariant> includes $remaining=\sum_i h(i)$. The move loop's processed columns have their final truncated heights, unprocessed columns retain their old heights, and each subtraction removes exactly the corresponding height reduction. Because heights are nonincreasing, once a column is no higher than `y`, neither is any later column; stopping there is valid. A legal move removes at least one token and leaves a <order ideal>.

The constructor computes $N^2$ in `Long` and checks representability before converting, avoiding <integer overflow> in the cached `Int` count. `Legal` rejects out-of-range coordinates before indexing. The methods meet the bounds in part (a); `Display` additionally checks its stated single-digit-label assumption.

The missing <preconditions> are **$0\leq pos\leq|d|$ for insertion** and **$0\leq pos<|d|$ for deletion and indexing**. The inclusive endpoint permits appending; deletion or access at the length is invalid. Specify the initial state, for example $d=[]$, as well as the read-only <frame conditions>: indexing returns the indicated character and preserves $d$, while `length` returns $|d|$ and preserves $d$.

The insertion and deletion clauses already describe the new <sequence>, but their returned values and effects should be interpreted against the old state. For a machine-sized length, insertion also requires $|d|<Int.MaxValue$. These clauses complete the document <abstract data type> without prescribing one storage representation.

{scope}

===== Solution

A mutable character buffer supplies a cached length and constant-time indexed access:

```
class DocImp extends Doc {
  private val data = scala.collection.mutable.ArrayBuffer.empty[Char]

  def insert(pos: Int, ch: Char): Unit = {
    require(0 <= pos && pos <= data.length)
    require(data.length < Int.MaxValue)
    data.insert(pos, ch)
  }

  def delete(pos: Int): Char = {
    require(0 <= pos && pos < data.length)
    data.remove(pos)
  }

  def apply(pos: Int): Char = {
    require(0 <= pos && pos < data.length)
    data(pos)
  }

  def length: Int = data.length
}
```

The <representation invariant> is that `data` is a well-formed private <dynamic array> of at most `Int.MaxValue` characters. Its <abstraction function> is the buffer's character <sequence>. Initialization is empty; insertion and removal at the checked position implement exactly the required <sequence> edits, and the queries do not modify it.

**`length` and indexing are $O(1)$** because a <dynamic array> stores its used length and supports address arithmetic for indexed access. An insertion or deletion at position $p$ in a document of length $L$ shifts $O(L-p)$ entries; insertion can additionally resize the backing storage, giving amortized $O(L-p+1)$ time and worst-case $O(L)$ for one operation. Deletion is $O(L-p)$ with an additional constant term.

Building a document by appending the characters of a length-$L$ string costs **$O(L)$ amortized time**, since geometric capacity growth copies a total of only $O(L)$ entries. Thus this implementation does not have the quadratic append behavior of repeated immutable-string concatenation. A known final length can also be reserved in advance. The bounds use the usual <amortized analysis> of a <dynamic array>.<Performance Characteristics of Scala 2.13 collections>[Mutable <sequence> table: ArrayBuffer constant indexed access and amortized constant append]{ref}

Use a fixed-size count <array> and protected hooks defining a stable character-to-slot mapping. The default hooks count the ASCII lowercase interval. The document must start empty, and all subsequent edits must pass through the <mixin> methods, as they do for `new DocImp with CharCountPlugin`.

```
trait CharCountPlugin extends Doc {
  protected def firstCounted: Char = 'a'
  protected def numberCounted: Int = 26
  protected def slot(ch: Char): Int = {
    val k = ch.toInt - firstCounted.toInt
    if (0 <= k && k < numberCounted) k else -1
  }
  private lazy val totals = Array.fill(numberCounted)(0)

  abstract override def insert(pos: Int, ch: Char): Unit = {
    val k = slot(ch)
    super.insert(pos, ch)
    if (k >= 0) totals(k) += 1
  }

  abstract override def delete(pos: Int): Char = {
    val removed = super.delete(pos)
    val k = slot(removed)
    if (k >= 0) totals(k) -= 1
    removed
  }

  def count(ch: Char): Int = {
    val k = slot(ch)
    require(k >= 0, "character is outside the counted alphabet")
    totals(k)
  }
}
```

The additional <representation invariant> is that each <array> slot equals the number of corresponding characters in the current document. Initially all counts are zero. Each successful underlying edit changes exactly one relevant count, while a failed position check throws before any count is changed. Returning the actual deleted character lets deletion adjust the correct slot.

`count` takes **$O(1)$ time for the fixed alphabet**, as do the <mixin>'s additions to edit cost. The lazy <array> avoids reading subclass-overridden size hooks during <trait> construction; the hooks must remain stable. An extension can override the interval hooks, or override `slot` with another fixed finite mapping. This is <stackable modification by a trait>: `abstract override` permits the method to call the next implementation of `super`, supplied here by `DocImp`.<Scala 2.13 classes and objects specification>[Abstract override and <trait> linearization]{ref}

===== Solution

Cache only a requested current element. Merely constructing the <cursor>, or asking whether it is nonempty, must not fetch a value from the <iterator>:

```
def asCursor[T](it: Iter[T]): Cursor[T] = new Cursor[T] {
  private var cached: Option[T] = None

  def hasCurrent: Boolean = cached.nonEmpty || it.hasNext

  def current: T = {
    if (cached.isEmpty) {
      require(it.hasNext, "empty cursor")
      cached = Some(it.next())
    }
    cached.get
  }

  def next(): Unit = {
    if (cached.nonEmpty) cached = None
    else {
      require(it.hasNext, "empty cursor")
      it.next()
      ()
    }
  }
}
```

The <abstraction function> for the adapter is `it.seq` when no value is cached and `[cachedValue] ++ it.seq` otherwise. Fetching `current` removes one underlying <iterator> value but saves it, so the <cursor>'s abstract <sequence> is unchanged; repeated reads return the same value. Advancing either discards that cache or consumes one uncached <iterator> value. No following element is prefetched.

A too-eager implementation could call `it.next()` at construction, or fetch a new element immediately after every advance, even when the client never requests it. That can trigger unnecessary work or nontermination on a difficult stream. This <lazy iterator-to-cursor adapter> avoids both behaviors and checks the underlying access <preconditions> itself. The wrapped <iterator> is assumed to be used exclusively through the adapter; independent external consumption would invalidate the shared-state abstraction.

Keep a <FIFO queue> of pending child <iterators>, ordered by the breadth-first order of their parents. Defer even the call creating a node's children until that <iterator> reaches the front and is needed:

```
def breadthFirst[T](node: Node[T]): Iter[Node[T]] = {
  def childrenLater(n: Node[T]): Iter[Node[T]] = new Iter[Node[T]] {
    private lazy val children = n.children()
    def hasNext: Boolean = children.hasNext
    def next(): Node[T] = {
      require(children.hasNext, "empty child iterator")
      children.next()
    }
  }

  val pending = scala.collection.mutable.Queue.empty[Iter[Node[T]]]
  pending.enqueue(childrenLater(node))

  new Iter[Node[T]] {
    private def normalize(): Unit = {
      while (pending.nonEmpty && !pending.head.hasNext) pending.dequeue()
    }
    def hasNext: Boolean = {
      normalize()
      pending.nonEmpty
    }
    def next(): Node[T] = {
      normalize()
      require(pending.nonEmpty, "no more descendants")
      val answer = pending.head.next()
      pending.enqueue(childrenLater(answer))
      answer
    }
  }
}
```

Here **“descendants” excludes the supplied root**: the first output is its first child. A self-inclusive convention can prepend `unitIter(node)` without changing the traversal logic. The queue invariant says its <iterators> enumerate the still-unreported children of already encountered parents, in parent breadth-first order. Consuming one child appends that child's deferred <iterator> after all earlier parents' pending children. Exhausted child <iterators> contribute nothing and can be discarded. This proves increasing depth and sibling order without constructing a complete level in advance.

This <lazy breadth-first traversal with child iterators> never eagerly materializes all children or the whole tree. A finite prefix can therefore be traversed on a genuinely infinite tree. As with any strict breadth-first ordering, an infinite earlier level prevents reaching a deeper level; no algorithm can place a deeper node after every member of an infinite earlier level at a finite output position. For a <locally finite tree>, every finite-depth level is finite and each descendant is eventually reached, assuming the underlying <iterator> operations terminate. Fresh child <iterators> and exclusive ownership of consumed <iterator> states are essential to this argument.

```
    }

}
```

==== Solution

A <complete multiset> is a finite-support signed count function. An absent key has count zero; negative counts are allowed. One simple default implementation uses a protected immutable association list with unique keys and nonzero values. Its default is empty, and optimized subclasses may override the public queries.

```
trait CompleteMultiSet[T] {
  // Representation contract: finite, immutable, unique keys, nonzero counts.
  protected def entries: List[(T, Int)] = Nil

  def count(t: T): Int =
    entries.find { case (key, _) => key == t }.map(_._2).getOrElse(0)

  lazy val present: Seq[T] = entries.map(_._1)

  private def combine(other: CompleteMultiSet[T],
                      op: (Int, Int) => Int): CompleteMultiSet[T] = {
    val keys = (present.toList ++ other.present.toList).distinct
    val resultRows = keys.flatMap { t =>
      val n = op(count(t), other.count(t))
      if (n == 0) Nil else List((t, n))
    }
    new CompleteMultiSet[T] {
      override protected val entries: List[(T, Int)] = resultRows
    }
  }

  def +(other: CompleteMultiSet[T]): CompleteMultiSet[T] =
    combine(other, (a, b) => java.lang.Math.addExact(a, b))

  def -(other: CompleteMultiSet[T]): CompleteMultiSet[T] =
    combine(other, (a, b) => java.lang.Math.subtractExact(a, b))

  def max(other: CompleteMultiSet[T]): CompleteMultiSet[T] =
    combine(other, (a, b) => math.max(a, b))

  def min(other: CompleteMultiSet[T]): CompleteMultiSet[T] =
    combine(other, (a, b) => math.min(a, b))

  def <=(other: CompleteMultiSet[T]): Boolean =
    (present.toList ++ other.present.toList).distinct.forall { t =>
      count(t) <= other.count(t)
    }

  override def toString: String =
    present.distinct.filter(t => count(t) != 0)
      .map(t => s"$t:${count(t)}").mkString("{", ", ", "}")
}
```

The <representation invariant> and <abstraction function> assign the association-list value at a stored key and zero elsewhere. Every operation preserves both operands and returns a fresh immutable value. The <finite-support pointwise operations> principle makes the support union sufficient because every operation sends $(0,0)$ to zero. It is necessary for signed counts: **the empty value is not at most a value having count $-1$ at one key**, although the empty left support alone would give a vacuous true comparison. Likewise, pointwise minimum can retain a negative count appearing only in the other operand.

**`present == List()` represents the all-zero, empty <complete multiset>.** The list-backed default `count` takes $\Theta(1)$ time for a first-entry hit or an empty list, and $\Theta(N)$ in the worst case for a missing or final key, assuming constant-cost key equality. The default binary operations can consequently take quadratic time; they are deliberately simple defaults, not optimized implementations. The lazy `present` avoids an early call to a subclass's representation during initialization.

Counts use `Int`, so addition and subtraction explicitly throw `ArithmeticException` when the mathematical result is unrepresentable instead of silently wrapping. Equivalently, their mathematical <precondition> requires representable result counts. This machine-size restriction is separate from permitting negative counts.

Keep a private immutable hash-map value in a mutable variable. Each update computes a complete replacement from snapshots and commits it once; this handles self-aliasing and arithmetic failure without partially modifying the receiver.

```
class MultiSetVarImp[T] extends MultiSetVar[T] {
  private var table = Map.empty[T, Int]

  def count(t: T): Int = table.getOrElse(t, 0)
  def present: Seq[T] = table.keys.toVector

  def copy(other: CompleteMultiSet[T]): Unit = {
    val saved = other.present.distinct.iterator
      .map(t => (t, other.count(t))).filter(_._2 != 0).toMap
    table = saved
  }

  private def snapshot(other: MultiSetVar[T]): Map[T, Int] =
    other.present.distinct.iterator
      .map(t => (t, other.count(t))).filter(_._2 != 0).toMap

  private def update(other: MultiSetVar[T], op: (Int, Int) => Int): Unit = {
    val left = table
    val right = snapshot(other)
    val keys = left.keySet ++ right.keySet
    val builder = Map.newBuilder[T, Int]
    keys.foreach { t =>
      val n = op(left.getOrElse(t, 0), right.getOrElse(t, 0))
      if (n != 0) builder += ((t, n))
    }
    val replacement = builder.result()
    table = replacement
  }

  def +(other: MultiSetVar[T]): Unit =
    update(other, (a, b) => java.lang.Math.addExact(a, b))

  def -(other: MultiSetVar[T]): Unit =
    update(other, (a, b) => java.lang.Math.subtractExact(a, b))

  def max(other: MultiSetVar[T]): Unit =
    update(other, (a, b) => math.max(a, b))

  def min(other: MultiSetVar[T]): Unit =
    update(other, (a, b) => math.min(a, b))

  def <=(other: CompleteMultiSet[T]): Boolean = {
    val left = table
    (left.keySet ++ other.present).forall { t =>
      left.getOrElse(t, 0) <= other.count(t)
    }
  }
}
```

The <representation invariant> is a finite map of nonzero counts with no representation exposed to callers. The <abstraction function> adds implicit zero elsewhere. `getOrElse` implements that default; `keys` enumerates stored keys; `distinct` removes repeated input support entries; `toMap` builds an independent immutable map; and the builder accumulates the next representation before it is assigned. The private immutable snapshots remain stable while the new state is computed.

For self-addition, both snapshots contain the same old counts, so they double; self-subtraction yields empty support; self-max and self-min leave the value unchanged. A distinct operand is never assigned or mutated. An overflow exception during building occurs before the final assignment, so the receiver remains unchanged. These are instances of <snapshot-before-update semantics>.

Lookup is expected $O(1)$ under standard hash assumptions. Enumerating `present` takes $O(K)$ for support size $K$. Combining two instances of this implementation takes expected $O(K+M)$ time and temporary storage, including snapshot construction. For an arbitrary argument implementation, add the costs of its `count` calls: copying a default list-backed <complete multiset> can require $\Theta(M^2)$, whereas copying the hash-backed version is expected linear. No generic interface can guarantee another implementation's query cost. Inputs are assumed to have finite, complete support enumerations and stable counts during an operation; concurrent mutation would need a separate synchronization contract.
