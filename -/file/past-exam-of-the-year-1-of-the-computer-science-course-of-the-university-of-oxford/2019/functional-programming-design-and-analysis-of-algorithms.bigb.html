== 1
{scope}

=== a
{scope}

==== Solution

The <right fold> replaces the two <list> constructors by its two arguments; the <left fold> instead updates an accumulator while traversing the <list>.

```
foldr :: (a -> b -> b) -> b -> [a] -> b
foldr c z []     = z
foldr c z (x:xs) = c x (foldr c z xs)

foldl :: (b -> a -> b) -> b -> [a] -> b
foldl s a []     = a
foldl s a (x:xs) = foldl s (s a x) xs
```

Thus **`foldr` is the natural <list fold>**: it preserves the constructor arrangement while replacing `[]` by `z` and `(:)` by `c`. In particular, `foldr (:) [] = id`. More generally, the <fold factorisation criterion> says that the defining equations characterize the corresponding <structural recursion>. Association and <lazy evaluation> are separate: the accumulator in this definition of <left fold> is not automatically evaluated at each step.<Haskell 2010 Language Report>[Chapter 9, PreludeList: foldr and foldl]{ref}

=== b
{scope}

==== Solution

For every accumulator $a$, <pattern matching> makes `foldl s a undefined` the <bottom value>. Now use <structural induction> on a finite <list prefix> ending in the <bottom value>. The induction step is `foldl s a (x:ps) = foldl s (s a x) ps`; the induction hypothesis applies to *every* accumulator, including `s a x`. Consequently every such finite approximation has result $\bot$.

An infinite <lazy list> is the limit of its finite prefixes, each interpreted as a <finite approximation of a lazy list>. Definable <Haskell> operations are <Scott continuous maps>, so the result on the infinite <lazy list> is the supremum of the results on these approximations. Every result is $\bot$, hence **`foldl s a xs = undefined` on every infinite input spine**, irrespective of whether `s` would inspect the accumulator.

For a concrete separation, choose `s = (&&)`, `a = True`, and `xs = False : repeat True`. The <left fold> is $\bot$, whereas the <right fold> returns **`False`** after observing the first element: `False && r` does not demand `r`. It is reaching the end of the input spine, rather than strictness of the combining operation, that prevents this <left fold> from returning.

=== c
{scope}

==== Solution

Over <integers>, choose **`s = c = (+)` and `a = b = 0`**. The <left fold> and <right fold> both compute the <sum> of a finite <list>.

=== d
{scope}

==== Solution

Over <integers>, choose **`s = (-)`, `c = flip (-)`, and `a = b = 0`**. The <left fold> and <right fold> both compute the negative of the <sum> of a finite <list>. The combining <functions> differ: `s 1 2 = -1`, whereas `c 1 2 = 1`.

=== e
{scope}

==== Solution

Let $F=\mathrm{foldl}\ (\ominus)\ 0$, using the specified operation $u\ominus v=v-u$. Direct evaluation gives $F([])=0$, $F([0])=0$, $F([1])=1$, and $F([1,0])=-1$.

Suppose $F=\mathrm{foldr}\ c\ b$ with the same <integer> result type. The empty <list> forces $b=0$. The two singleton calculations force $c\ 0\ 0=0$ and $c\ 1\ 0=1$. But then
$$
F([1,0])=c\ 1\ (c\ 0\ 0)=c\ 1\ 0=1,
$$
contrary to $F([1,0])=-1$. **No such `c,b` exist.** This is the information restriction in the <fold factorisation criterion>: equal folded tails must remain indistinguishable after the same head is attached. A larger, <function>-valued result type can retain the missing information, as the <continuation representation of a left fold> does below.

=== f
{scope}

==== Solution

Assign $y:u$ and $x:v$. The application `s y x` forces $s:u\to v\to w$ for a fresh type $w$; applying `f` to that result forces $f:w\to r$. No further equations identify these four type variables. The <principal type> is therefore

```
k :: (u -> v -> w) -> v -> (w -> r) -> u -> r
k s x f y = f (s y x)
```

Every compatible typing is an instance of this one, because <type inference> imposed precisely the two application constraints and no class constraints.

=== g
{scope}

==== Solution

Fix `s` and put $R(xs,a)=\mathrm{foldr}\ (k\ s)\ \mathrm{id}\ xs\ a$. The <right fold> equations give
$$
R([],a)=a,\qquad R(x:xs,a)=R(xs,s\ a\ x).
$$
These are exactly the <left fold> equations. <Structural induction>, with the induction hypothesis quantified over *all* accumulators, proves equality on finite terminating <lists>.

To include the other input spines, first observe that both applied expressions give $\bot$ on an undefined spine. The same induction proves equality on every finite prefix ending in $\bot$: the step `k s x f a` demands the continuation `f` when its result is demanded. Finally use that the two applied operations are <Scott continuous maps>, taking the limit over prefixes interpreted as a <finite approximation of a lazy list>. This covers infinite spines, on which both applied expressions are $\bot$, and proves the identity for all <lists> under the stated <Haskell> semantics. The intermediate <right fold> builds an accumulator-transforming <function>; it does not provide a terminating <left fold> of an infinite <list>.

=== a

==== Solution

Include nonpositive counts and exhausted input explicitly:

```
take :: Int -> [a] -> [a]
take n _      | n <= 0 = []
take _ []             = []
take n (x:xs)         = x : take (n-1) xs

drop :: Int -> [a] -> [a]
drop n xs     | n <= 0 = xs
drop _ []             = []
drop n (_:xs)         = drop (n-1) xs
```

The tests on the count precede inspection of the input <list>. Thus `take 0 undefined = []`, while `drop 0 undefined = undefined`, exactly as these <list prefix> and <list suffix> operations require. No element value is inspected merely to traverse the spine.<Haskell 2010 Language Report>[Chapter 9, PreludeList: take and drop]{ref}

=== b
{scope}

==== Solution

A shared <recursion> computes both components:

```
split :: Int -> [a] -> ([a],[a])
split n xs | n <= 0 = ([],xs)
split _ []         = ([],[])
split n (x:xs)     = (x:ys,zs)
  where (ys,zs) = split (n-1) xs
```

For a defined count and a spine with $m$ available constructors before termination, each of `take` and `drop` makes $\min(\max(n,0),m)$ recursive calls, whereas `split` makes that many once. **The number of recursive calls is halved.** The <irrefutable pattern> in the local pair binding also avoids evaluating the recursive pair merely to expose the first output element.

On <proper lazy lists> this has the intended two component values. There is a small <bottom value> distinction outside that domain: the displayed single-pass definition must inspect a positive-count input spine before returning its outer pair, whereas the literal expression `(take n xs, drop n xs)` exposes the pair constructor even if `xs` is undefined. The algorithmic answer concerns the two components and the stated call count; it need not silently claim equality under a test that observes this outer constructor alone.

=== c
{scope}

==== Solution

For the paper's <leaf-labelled binary tree>, the combining operation receives the results of the two subtrees, and the other argument handles a leaf:

```
foldTree :: (a -> b) -> (b -> b -> b) -> Tree a -> b
foldTree f g (One x)   = f x
foldTree f g (Two l r) = g (foldTree f g l) (foldTree f g r)
```

Its constructor equation is **`foldTree One Two = id`**. More generally, a <function> `h` satisfying `h (One x) = f x` and `h (Two l r) = g (h l) (h r)` equals `foldTree f g` on finite <trees>, by <structural induction>. This is the <tree fold> specialized to a datatype with labels only at leaves, rather than at internal nodes.

=== d
{scope}

==== Solution

Both versions preserve left-to-right leaf order:

```
flatten :: Tree a -> [a]
flatten (One x)   = [x]
flatten (Two l r) = flatten l ++ flatten r

flattenFold :: Tree a -> [a]
flattenFold = foldTree (\x -> [x]) (++)
```

The <tree fold> replaces each leaf by a singleton <list> and each internal node by <list concatenation>. The defining equations of `flattenFold` are consequently those of `flatten`, proving their equality by <structural induction>.

=== e
{scope}

==== Solution

Let $n$ be the number of leaves; the total number of nodes is $2n-1$. <List concatenation> copies its left operand. For a <tree> whose left subtree contains $n-1$ leaves at each successive internal node, these copied lengths are $1,2,\ldots,n-1$. Their <sum> is $n(n-1)/2$, so the worst-case <running time> is **$\Theta(n^2)$**.

A <difference list> representation avoids copying prefixes:

```
flattenFast :: Tree a -> [a]
flattenFast t = go t []
  where
    go (One x)   acc = x:acc
    go (Two l r) acc = go l (go r acc)
```

The <recursion invariant> is `go t acc = flatten t ++ acc`. The leaf case is immediate; the internal-node case uses <associativity> of <list concatenation>. Each node is visited once and each leaf contributes one output constructor, giving **$\Theta(n)$ <running time>** when the result is fully consumed. This is <linear flattening of a binary tree> and does not assume balance.

=== f
{scope}

==== Solution

The necessary domain is a finite, nonempty <list>: the datatype has no representation of an empty leaf sequence, and the supplied size-based balance condition does not specify an infinite-size construction.

```
build :: [a] -> Tree a
build []  = error "build: empty input"
build [x] = One x
build xs  = Two (build ys) (build zs)
  where
    (ys,zs) = split (length xs `div` 2) xs
```

For length $n\ge2$, the two nonempty pieces have $\lfloor n/2\rfloor$ and $\lceil n/2\rceil$ elements. Their sizes differ by at most one, and both are shorter than the input. <Induction> therefore proves termination and the required <leaf-balanced binary tree> property at every node. The same <induction>, using `ys ++ zs = xs`, proves `flatten (build xs) = xs`. This straightforward implementation takes $O(n\log n)$ <running time>; computing the length repeatedly is acceptable here because no faster construction was requested.

=== g
{scope}

==== Solution

Use the input <list> as the seed of the <tree unfold>:

```
buildUnfold :: [a] -> Tree a
buildUnfold = unfold step
  where
    step []  = error "build: empty input"
    step [x] = Left x
    step xs  = Right (split (length xs `div` 2) xs)
```

On a singleton seed, `unfold` produces the same leaf as `build`; on a longer finite seed, it recursively builds the same two pieces. <Induction> on input length proves **`buildUnfold = build` on finite nonempty inputs**. The empty-input qualification remains essential: a <tree unfold> cannot supply a missing empty-tree constructor.

=== a
{scope}

==== Solution

Use coordinates with row and column in $\{0,1,2\}$:

```
type Place  = (Int,Int)
type Places = [Place]
type Board  = (Places,Places,Places)
data Player = O | X deriving (Eq,Ord,Show)
```

The components of `Board` record the positions occupied by `O`, occupied by `X`, and still empty, respectively. On a nonterminal legal board, **equal occupied counts mean `O` moves next; one extra `O` means `X` moves next**.

The <type synonym> does not enforce the <representation invariant>: coordinates are in range; each component has no duplicates; the three represented <sets> form a <set partition> of the nine positions; and the occupied counts differ as just described. Both players cannot have won. A winning `O` board has one extra `O`, and a winning `X` board has equal counts. More fundamentally, a legal <tic-tac-toe> state has a legal alternating history that stops at the first win: satisfying a type alone never licenses continuing an already completed game.

=== b
{scope}

==== Solution

The empty occupancy <sets> leave all nine coordinates available:

```
empty :: Board
empty = ([],[],[(r,c) | r <- [0..2], c <- [0..2]])
```

This board satisfies the <representation invariant> and gives `O` the next move.

=== c
{scope}

==== Solution

Assume the board satisfies the <representation invariant>. Reject completed boards and occupied or out-of-range coordinates; testing membership in the empty component covers both coordinate failures.

```
finished :: Board -> Bool
finished (os,xs,es) = won os || won xs || null es

play :: Board -> Place -> Board
play b@(os,xs,es) q
  | finished b     = error "play: completed game"
  | q `notElem` es = error "play: unavailable place"
  | length os == length xs = (q:os,xs,rest)
  | otherwise             = (os,q:xs,rest)
  where rest = filter (/=q) es
```

Here `won` is defined in part d. Moving one available coordinate into the appropriate occupied component preserves the <set partition> and the alternating-count rule. Checking completion first preserves the no-moves-after-a-win invariant.

=== d
{scope}

==== Solution

Construct each possible winning line, then test whether one is contained in the player's occupancy <set>:

```
winningLines :: [Places]
winningLines =
  [[(r,c) | c <- [0..2]] | r <- [0..2]] ++
  [[(r,c) | r <- [0..2]] | c <- [0..2]] ++
  [[(i,i) | i <- [0..2]], [(i,2-i) | i <- [0..2]]]

won :: Places -> Bool
won ps = any (\line -> all (`elem` ps) line) winningLines
```

The <list comprehension> generates three rows, three columns and two diagonals. Each has exactly three coordinates; therefore `all` holds precisely when every coordinate of that line is occupied by this player. Taking `any` over the eight lines proves the win test correct.

=== e
{scope}

==== Solution

Record the outcome at the first completed board and otherwise branch over every available move:

```
data Outcome = Winner Player | Draw deriving (Eq,Ord,Show)

finals :: Board -> [(Board,Outcome)]
finals b@(os,xs,es)
  | won os    = [(b,Winner O)]
  | won xs    = [(b,Winner X)]
  | null es   = [(b,Draw)]
  | otherwise = concatMap (\q -> finals (play b q)) es
```

The <recursion> terminates because each recursive call decreases the number of empty positions by one. For correctness, induct on that number. A completed board contributes exactly its own outcome. Otherwise every legal continuation has a unique first available move, and the induction hypothesis covers exactly all completions after that move. <List concatenation> collects these branches without extending completed games. Repeated final positions are allowed here because the computation deliberately explores every legal move sequence.

=== f
{scope}

==== Solution

Different move orders can lead to the same position, and the two occupancy <lists> also retain irrelevant insertion order. Thus this <search tree> repeatedly solves the same remaining game. For example, swapping the order of two `O` moves while leaving the intervening `X` moves legal can reach the same occupied <sets>.

Canonicalize each state by sorted occupancy <sets>, or by two <bitboards>, and apply <memoization> or a visited-state <set>. Expand each canonical position once, stopping at terminal states, and collect terminal positions in a <set>. There are at most $3^9$ cell assignments, many of which are illegal; this is much smaller than a <tree> of move permutations. **Store positions, not histories, when the requested output is distinct final positions.** Board rotations and reflections can reduce work further if handled as an additional equivalence: if the output must retain every oriented board, reconstruct those distinct orientations rather than silently returning one representative per symmetry class.

=== a
{scope}

==== Solution

For <proper lazy lists>, the generic condition is **a finite first <list>, or an empty second <list>**. A finite first <list> reaches its terminating constructor, after which <list concatenation> exposes the second one. An infinite first <list> never yields control to the second; it therefore cannot deliver occurrences originating there unless there are none. This concerns input occurrences, rather than an accidental overlap of the two inputs' value <sets>.

A first spine ending in the <bottom value> also prevents access to the second <list>. Such inputs require the partial-input qualification in part c; a visible prefix is different from a terminating finite <list>.

=== b
{scope}

==== Solution

Swap roles after emitting one element:

```
interleave :: [a] -> [a] -> [a]
interleave []     ys = ys
interleave (x:xs) ys = x : interleave ys xs
```

While both <lists> are nonempty, the <function> alternates between them. Their $j$-th input occurrences appear after at most $2j+2$ output steps, counting positions from zero; once either <list> ends, the other is returned directly. Every output constructor comes from one input constructor, and every input occurrence is eventually selected. This proves <fair enumeration> and <productivity> on the two <proper lazy lists>, including two infinite ones.

=== c
{scope}

==== Solution

**No universally correct sequential <Haskell> implementation has that guarantee for <partial lists>.** Compare `undefined` paired with `[v]`, and `[v]` paired with `undefined`, where the element type is arbitrary. A generic program cannot fabricate `v`; it must eventually inspect an input spine to obtain it. Whichever input it first demands can be chosen to be the undefined one, blocking access to the available element in the other input.

In particular, the implementation in part b can emit a defined prefix and then block when alternation reaches an undefined tail. <Lazy evaluation> postpones demands; it cannot recognize that a demanded computation will never finish. The result is the <partial-list interleaving obstruction>, not an objection to fairness under the proper-input hypothesis. Additional concurrent primitives would change the computational model.<Haskell 2010 Language Report>[§3.1, errors and nontermination; §3.17, demands made by pattern matching]{ref}

=== d
{scope}

==== Solution

Use <diagonal merging of lazy lists>: introduce one new row each round, and advance every active row once. Each round contains finitely many active rows, even when the outer <list> is infinite.

```
fairConcat :: [[a]] -> [a]
fairConcat = concat . levels []
  where
    levels [] [] = []
    levels active pending =
      let (new,rest) = case pending of
            []     -> ([],[])
            r:rs   -> ([r],rs)
          live = [r | r@(_:_) <- active ++ new]
      in map head live : levels (map tail live) rest
```

Number rows and positions within each row from zero. An occurrence at $(i,j)$ is emitted in round **$i+j$**: its row enters in round $i$ and advances once per subsequent round. All earlier rounds and each round's output are finite, so every required occurrence appears after finite work. `live` discards only empty rows, and `head` emits only existing entries; no new value is invented.

\Image[functional-programming-design-and-analysis-of-algorithms-fair-enumeration.png]
{title=<Diagonal merging of lazy lists> visits every finite row-position pair after finitely many rounds}

Simply nesting `interleave` is unsafe here: `foldr interleave [] ([1,2] : repeat [])` emits `1` and then demands an undefined merge of the infinitely many empty rows before it can emit `2`. The finite-round construction avoids that starvation. There is still an unavoidable termination qualification: after the last actual output, infinitely many empty pending rows cannot be certified empty in finite work. The result can then have an undefined tail instead of a terminating `[]`. Every required occurrence has nevertheless appeared; no generic <algorithm> can promise a proper completed output in that exceptional situation, by the <absence-detection obstruction for infinite lists>.

=== e
{scope}

==== Solution

The ordinary <list comprehension> exhausts the inner <list> before advancing the outer one. Therefore it enumerates every argument pair when **`ys` is finite**, or when **`xs` has at most one element**. If `ys` is infinite and `xs` has two or more elements, it stays with the first outer element forever and misses every pair with a later outer occurrence. Applying a constant `f` might hide missing pairs as duplicate values; it does not make the enumeration fair.

An empty-result caveat remains when `ys = []` and `xs` is infinite: the literal comprehension traverses infinitely many empty rows and does not return a terminating empty <list>. Its occurrence requirement is vacuous, but its <productivity> as an empty-result computation fails. An explicit empty-input test avoids that particular failure.

=== f
{scope}

==== Solution

Merge the rows with `fairConcat`, retaining explicit empty-input cases:

```
fairPair :: (a -> b -> c) -> [a] -> [b] -> [c]
fairPair _ [] _  = []
fairPair _ _  [] = []
fairPair f xs ys = fairConcat [[f x y | y <- ys] | x <- xs]
```

For nonempty <proper lazy lists>, the occurrence `f (xs!!i) (ys!!j)` belongs to row $i$, position $j$, so the proof in part d puts it in round $i+j$. This supplies **every pair after finite work**, even when both input <lists> are infinite. The guards also return `[]` for either empty factor without traversing infinitely many empty rows.

=== g
{scope}

==== Solution

For a **finite outer <list>** of <proper lazy lists>, use the fair binary product from part f:

```
cp :: [[a]] -> [[a]]
cp []       = [[]]
cp (xs:xss) = fairPair (:) xs (cp xss)
```

The empty family has one selection, the empty selection. For a nonempty finite family, each selection consists uniquely of one first-factor occurrence followed by a selection from the remaining factors. <Induction> on the number of factors, together with the fairness of `fairPair`, proves that every such selection is produced and no invalid selection is introduced. Infinite factors are allowed: in particular, the three-factor example is enumerated fairly. If any factor is empty, the finite-family computation returns the empty product.

The printed hypothesis also permits an *infinite outer* <proper lazy list>. **No <function> can satisfy the full enumeration requirement for all such inputs.** Take `repeat [0,1]`. Its mathematical <Cartesian product> contains every infinite binary sequence and is <uncountable>. If a result <list> enumerated these sequences as $z_0,z_1,\ldots$, the binary sequence $b$ with $b_i=1-z_i(i)$ would differ from the $i$-th listed sequence at position $i$, contradicting completeness. This is an <uncountability obstruction to enumerating infinite Cartesian products>. The finite-outer qualification is a necessary repair to the specification, not a restriction imposed for convenience by the code.

{scope}

=== a
{scope}

==== Solution

A <divide-and-conquer algorithm> handles a small input directly; otherwise it divides the input into smaller instances, recursively solves them, and combines their answers. With $a$ equally sized subproblems of size approximately $n/b$ and nonrecursive work $f(n)$, its <recurrence relation> has the form $T(n)=aT(n/b)+f(n)$, with constant-size base cases, $a\ge1$ and $b>1$.

Write $p=\log_b a$. The basic <master theorem> gives the following cases, with a fixed $\varepsilon>0$:

* If $f(n)=O(n^{p-\varepsilon})$, then **$T(n)=\Theta(n^p)$**.
* If $f(n)=\Theta(n^p)$, then **$T(n)=\Theta(n^p\log n)$**.
* If $f(n)=\Omega(n^{p+\varepsilon})$ and the regularity condition $af(n/b)\le cf(n)$ holds eventually for some $c<1$, then **$T(n)=\Theta(f(n))$**.

For the common extended middle case, $f(n)=\Theta(n^p\log^k n)$ with fixed $k\ge0$ gives $T(n)=\Theta(n^p\log^{k+1}n)$. A <recursion tree> explains the three cases: work is dominated by its leaves, spread across comparable levels, or dominated by its top levels. The regularity condition in the last case is part of the theorem, not an optional simplification.

=== b
{scope}

==== Solution

For an ascending <sorted array>, maintain a candidate interval $[\ell,r]$ initially containing every index. Compare the target with the middle entry at $m=\lfloor(\ell+r)/2\rfloor$. Equality returns $m$; if the target is smaller, replace $r$ by $m-1$; if larger, replace $\ell$ by $m+1$. An empty interval reports absence.

The <loop invariant> is that any target occurrence still possible lies inside the candidate interval. <Sortedness> justifies discarding the appropriate half after each unequal comparison. The interval length decreases to at most half its previous length, establishing termination and correctness. After $t$ unsuccessful comparisons there are at most $n/2^t$ candidates, so at most $\lfloor\log_2n\rfloor+1$ comparisons suffice for $n\ge1$. Each iteration uses constant work on a random-access <array>. Thus **<binary search> takes $O(\log(n+1))$ <running time>**, conventionally written $O(\log n)$ for nontrivial input sizes. Empty input is handled in constant time.

=== c
{scope}

==== Solution

Assume ascending <sorted arrays>; descending storage can be accessed in reverse index order without copying. Among $2n$ entries, the requested rank is **$k=n+1$ in ascending order**, not $n$. Repeated values occupy repeated ranks.

Choose $i$ entries from the first <array> and $j=k-i$ from the second, using their prefixes. The feasible range is $\max(0,k-n)\le i\le\min(n,k)$. Write $A_L=A[i]$, $A_R=A[i+1]$, and similarly $B_L,B_R$ at $j$, with missing left endpoints replaced by $-\infty$ and missing right endpoints by $+\infty$. These are conceptual sentinels, not extra stored entries.

Use <binary search> over the feasible values of $i$:

* If $A_L>B_R$, there are too many entries from $A$ on the left; decrease the upper bound to $i-1$.
* If $B_L>A_R$, there are too few entries from $A$ on the left; increase the lower bound to $i+1$.
* Otherwise return **$\max(A_L,B_L)$**.

For correctness, in the last case every left entry is no greater than every right entry, and exactly $k$ entries lie on the left. Their <maximum> is therefore the $k$-th smallest entry. The failed inequalities are monotone in the searched index: increasing $i$ raises the $A$ boundary and decreases the $B$ boundary, so it cannot repair $A_L>B_R$; the other case is symmetric. A partition of the first $k$ entries of a merged ordering supplies an admissible solution, including ties. Each step halves an interval with at most $n+1$ choices, giving **$O(\log(n+1))$ <running time> and $O(1)$ <auxiliary space>**. This is a <two-sorted-array order statistic> without constructing the merged <array>.

=== d
{scope}

==== i
{scope}

===== Solution

If coordinate $j$ is not an <essential variable of a function>, changing that coordinate alone never changes the output, for *any* values of the other coordinates. Take two inputs with the same $i$-th coordinate. Change their other coordinates one at a time to transform the first input into the second. Every such change is inessential, so all intermediate outputs are equal.

Define $f_i(t)=f(1,\ldots,1,t,1,\ldots,1)$, with $t$ in position $i$. The preceding argument gives **$f(x_1,\ldots,x_n)=f_i(x_i)$**. Since $i$ is essential, $f_i$ is nonconstant. The conclusion depends on the full “for every context” negation of essentiality, not merely on testing a coordinate at one selected input.

==== ii
{scope}

===== Solution

If $n=1$, return its sole index without a query. Otherwise first evaluate $f(t,t,\ldots,t)$ for $t=1,\ldots,d$ until two different outputs are found. Part i says these outputs are precisely $f_i(t)$, so two values $a,b$ with $f_i(a)\ne f_i(b)$ must exist. This uses at most $d$ calls to the <function-evaluation oracle>.

Maintain a candidate index <set> $S$, initially all indices. Split $S$ into two nearly equal pieces and choose one, $H$. Query the input that is $b$ on $H$ and $a$ everywhere else. Its output equals $f_i(b)$ exactly when $i\in H$, and otherwise equals $f_i(a)$. Retain the indicated half and repeat until one index remains.

The <loop invariant> is $i\in S$, and the witness outputs keep each test unambiguous. There are at most $\lceil\log_2 n\rceil$ splitting queries. The total is **at most $d+\lceil\log_2n\rceil$ evaluations**, which is $O(d\log n)$ for $n\ge2$, and in fact a stronger additive bound. Only oracle calls are being counted; explicitly constructing each query vector can require $O(n)$ ordinary work. This is <identification of a unique essential variable>.

==== iii
{scope}

===== Solution

Restrict the unknown <function> to the $n$ possibilities $f^{(i)}(x)=1$ if $x_i=1$, and $2$ otherwise. Each has exactly one <essential variable>, even if the allowed alphabet has more than two values. Every oracle answer in this restricted family is one <bit>.

A correct adaptive deterministic <algorithm> must distinguish all $n$ possibilities. A binary <decision tree> of depth $q$ has at most $2^q$ leaves, so $2^q\ge n$. Therefore **$q\ge\lceil\log_2n\rceil=\Omega(\log n)$**. Restricting the answer family is essential to the argument: unrestricted integer-valued answers need not have binary branching. Combined with part ii, this gives optimal logarithmic <query complexity> for fixed $d$.

==== i

===== Solution

Store a <complete binary tree> in a one-indexed <array> $A[1..n]$, level by level. Index $i$ has <parent in a rooted tree> $\lfloor i/2\rfloor$ for $i>1$ and possible <children in a rooted tree> $2i$ and $2i+1$, present only when their indices are at most $n$. The <max-heap> condition is $A[\lfloor i/2\rfloor]\ge A[i]$ for every $i>1$.

Following these inequalities from the <root of a tree> to any entry proves that **$A[1]$ is a <maximum>**. The <heap order> does not sort siblings or unrelated branches. The <complete binary tree> has height $\lfloor\log_2 n\rfloor$, which bounds how far any single repair can travel. Store the current heap size separately from the <array>'s capacity.

==== ii
{scope}

===== Solution

Assume the subtrees rooted at the <children in a rooted tree> of $i$ already obey the <max-heap> condition. Compare $A[i]$ with each present child and choose an index of the largest of these at most three keys. If that index is $i$, stop. Otherwise exchange the two keys, continue at the chosen child, and repeat. This is <sift down>, with the inequality reversed from a minimum-oriented <binary heap>.

The exchange repairs the old root position because its new key dominates both child roots; only the subtree receiving the displaced key can still be defective. This <recursion invariant> proves correctness. Each exchange descends one level and costs constant work, so **the worst-case <running time> is $O(h)$ for subtree height $h$, hence $O(\log n)$**. A small key at the root of a suitably ordered heap must descend to a leaf, so the logarithmic worst-case bound is attained.

==== iii
{scope}

===== Solution

Leaves already obey the <heap order>. Process indices $\lfloor n/2\rfloor,\lfloor n/2\rfloor-1,\ldots,1$, calling the preceding repair at each. When an index is processed, its descendants have already been processed, so the repair's precondition holds. The resulting <array> is a <max-heap>.

The bound obtained by charging $O(\log n)$ to every call is unnecessarily large. The number of nodes with height at least $h$ is at most $\lfloor n/2^h\rfloor$. Therefore
$$
\sum_v(1+\operatorname{height}(v))
\le n+\sum_{h\ge1}\lfloor n/2^h\rfloor<2n.
$$
The total repair work is thus **$O(n)$**, and the loop itself has a linear number of iterations, giving **$\Theta(n)$** for this <bottom-up heap construction>. Most nodes are near the leaves and require little repair.

=== b
{scope}

==== Solution

A <maximum priority queue> stores keyed entries and supports insertion, inspection and removal of an entry with greatest key, and key increases. A <max-heap> gives the following <running times>, with the size/capacity cost of the backing <array> accounted for separately:

* `maximum`: return the root key in **$O(1)$** time.
* `insert`: append at the next available leaf, then use <sift up> until the <heap order> holds, in **$O(\log n)$** time.
* `extractMaximum`: save the root, replace it by the last entry, reduce the size, and use <sift down>, in **$O(\log n)$** time.
* `increaseKey(i,k)`: reject $k<A[i]$; otherwise set the new key and use <sift up>, in **$O(\log n)$** time.
* `isEmpty` and `size`: inspect the stored size in **$O(1)$** time; construct a queue from $n$ keys by <bottom-up heap construction> in **$\Theta(n)$** time.

Empty-queue inspections and removals need an explicit failure result. The index argument to `increaseKey` must identify the entry's *current* location: if callers use item handles, update their location records during swaps.

=== c
{scope}

==== Solution

Given the target's current heap index $i$, remove it as follows. If $i=n$, discard the last entry. Otherwise replace $A[i]$ by $A[n]$ and reduce $n$ by one. If the replacement is larger than its <parent in a rooted tree>, use <sift up>; otherwise use the maximum-oriented <sift down> from $i$.

Only comparisons incident to the replacement can initially violate the <heap order>. If it exceeds its parent, it also dominates the old children because the old key dominated those children and was no larger than the parent; an upward repair suffices. Otherwise the upward comparison is valid and only a downward repair can be needed. Thus **removal takes $O(\log n)$ worst-case time** after the location is known. Searching an unindexed heap for an arbitrary specified key can instead require $\Theta(n)$ time; the logarithmic bound does not include such a search.

==== i

===== Solution

Only arrange switches towards `A`. For every <vertex> $u$, compute its degree $\deg(u)$ and the current number $c(u)$ of neighbours preferring `A`. Put the `B` <vertices> in a <max-heap> with key $q(u)=2c(u)-\deg(u)$. Maintain each <vertex>'s current heap <array> index during exchanges.

While the queue is nonempty and its <maximum> key is positive, extract that <vertex> $u$, show it its neighbours' preferences, append $u$ to the answer sequence, and set its preference to `A`. For every neighbour $v$ still preferring `B`, increase $c(v)$ by one and use `increaseKey` to increase its heap key by two. Stop when every remaining key is nonpositive.

A positive key means precisely a strict majority of `A` neighbours, so every listed move is legal. Degrees never change; `A` neighbours never revert in this chosen sequence. An isolated `B` <vertex> has key zero and cannot be converted. Initialization costs $O(|V|+|E|)$, there are at most $|V|$ extractions, and each <edge> causes at most two neighbour inspections and at most a constant number of key updates. The required bound is therefore **$O((|V|+|E|)\log(|V|+1))$**. A simple work queue of newly eligible <vertices> can even implement the same <monotone threshold activation> in $O(|V|+|E|)$ time, since a <vertex> needs to be enqueued only once.

==== ii
{scope}

===== Solution

Let $C$ be the final `A` <set> produced by the <algorithm>. It contains the initial `A` set, and every <vertex> outside $C$ has at most half its neighbours in $C$: otherwise its final key would still be positive. Thus $C$ is closed under the activation rule.

Now consider *any* legal sequence, including sequences which change some `A` preferences back to `B`. We prove by <induction> that its current `A` set is always a <subset> of $C$. This is true initially. A switch to `B` preserves the inclusion. If a <vertex> outside $C$ were to switch to `A`, its `A` neighbours would all lie in $C$, so their number could not exceed half its degree. Such a switch is forbidden. A switch inside $C$ also preserves the inclusion.

Consequently every attainable final `A` set has size at most $|C|$. The <algorithm> supplies a legal sequence attaining $C$ itself, so **its sequence is optimal**. This <closure dominance for asynchronous threshold switching> proves more than a local-greedy claim: temporary losses of `A` <vertices> cannot unlock an additional <vertex> outside the activation closure.

=== a

==== Solution

Use unit-cost insertion, deletion and substitution of one symbol. Their minimum total cost is the <edit distance>. Let $D[i,j]$ be the <edit distance> between the first $i$ symbols of the first sequence and the first $j$ of the second. Initialize $D[i,0]=i$ and $D[0,j]=j$. For $i,j>0$ compute
$$
D[i,j]=\min\left\{D[i-1,j]+1,\ D[i,j-1]+1,\ D[i-1,j-1]+[x_i\ne y_j]\right\}.
$$
The cases delete the final source symbol, insert the final target symbol, or align the two final symbols, paying one for substitution and zero for a match. Every optimal alignment ends in one of these cases, and each case extends a valid shorter alignment. <Induction> on $i+j$ proves the <dynamic programming> recurrence correct.

Fill rows or columns in increasing order so every dependency is already available. There are $(m+1)(n+1)$ entries with constant work per interior entry: **$O(mn)$ <running time>** for nonempty sequences, or $O((m+1)(n+1))$ including the boundary cases. The full table has <space complexity> $O(mn)$; two rows give $O(n)$ <auxiliary space> when only the distance is wanted. Predecessor choices in the full table recover an optimal edit sequence.

==== i
{scope}

===== Solution

For nonnegative <integer> amount $v$, let $M[t]$ be the minimum number of coins making amount $t$. Set $M[0]=0$ and compute, in increasing order of $t$,
$$
M[t]=1+\min_{i:x_i\le t} M[t-x_i],\qquad 1\le t\le v.
$$
An empty candidate <set> has <minimum> $\infty$. Here denomination $1$ ensures that every nonnegative amount is attainable. Removing one coin from an optimal nonempty solution gives a smaller amount, and adding any allowed last coin gives a feasible solution; these two directions prove the recurrence by <induction> on $t$.

Return **whether $M[v]\le k$**. This solves the at-most-$k$ decision without needing a separate dimension for $k$. The table for the <minimum coin change recurrence> takes **$O(nv)$ <running time> and $O(v)$ <space complexity>**. The bound is <pseudopolynomial time>: the amount, rather than its binary encoding length, appears in it. Amount zero needs zero coins.

==== ii
{scope}

===== Solution

During the computation in part i, record an index $\operatorname{last}[t]$ attaining the minimum at every positive amount. Starting with $t=v$, print $x_{\operatorname{last}[t]}$ and replace $t$ by $t-x_{\operatorname{last}[t]}$, continuing until $t=0$.

Every step decreases the amount and reduces the table entry by exactly one. The printed denominations therefore sum to $v$ and their number is exactly $M[v]$, proving optimality. **The total <running time> is $O(nv+M[v])$**, including the output; $M[v]\le v$ because denomination $1$ is available. The predecessor <array> adds $O(v)$ to the <space complexity>. This is reconstruction from the <dynamic programming> certificate, not the largest-denomination <greedy algorithm>, which need not be optimal for arbitrary denominations.

==== iii
{scope}

===== Solution

Let $M_i[t]$ use only the first $i$ available coins. Initialize $M_0[0]=0$, $M_0[t]=\infty$ for $t>0$, and use
$$
M_i[t]=\min\{M_{i-1}[t],\ 1+M_{i-1}[t-x_i]\},
$$
omitting the second term when $t<x_i$. The alternatives exclude the current coin or use it once; both refer to the previous row, so it cannot be used twice. <Induction> on $i$ proves correctness, and **$M_n[v]$** is the required answer, including $\infty$ when no selection works.

The <running time> is **$O(nv)$**. A single amount <array> reduces <auxiliary space> to **$O(v)$** if each coin updates amounts in *descending* order, $t=v,v-1,\ldots,x_i$. Then $M[t-x_i]$ still describes the previous row. Ascending updates would reuse the same coin and solve a different, unlimited-supply problem.

==== i

===== Solution

The printed formula for the <edge> label has mismatched variable names. The type-correct reading is $x_i=\sigma(v_{i-1},v_i)$. Interpret the requested route as a <directed walk> of consecutive labelled <edges>, allowing repeated <vertices>; the distinction from a vertex-simple <directed path> is discussed below.

Let $R_t$ be the <set> of <vertices> reachable from the specified start after reading exactly the first $t$ labels. Initialize $R_0=\{v_0\}$ and update
$$
R_t=\{v:\text{there is }(u,v)\in E\text{ with }u\in R_{t-1}\text{ and }\sigma(u,v)=x_t\}.
$$
After $k$ stages, answer **yes exactly when $R_k\ne\varnothing$**. A <directed walk> realizing a prefix decomposes into a walk realizing the shorter prefix and one correctly labelled final <edge>; conversely every such extension is valid. This proves the <dynamic programming> invariant by <induction> on $t$. Store reachable <vertices> in Boolean <arrays> and scan the <edges> per stage. The <running time> is $O(k(|V|+|E|))$ with $O(|V|)$ rolling-table <space complexity>, in addition to <graph> storage. The empty label sequence is realized by staying at $v_0$.

If “path” is instead required to mean vertex-simple, augment the state to $(S,v)$, where $S$ is the <set> of visited <vertices>. Start with $R_0(\{v_0\},v_0)$ and extend a matching <edge> to $w$ only when $w\notin S$, replacing $S$ by $S\cup\{w\}$. This gives an exact <dynamic programming> <algorithm> for that interpretation too; reject immediately when $k\ge|V|$. A straightforward bound is $O(k2^{|V|}(|V|+|E|))$ <running time> with $O(2^{|V|}|V|)$ rolling-table storage. The exponential distinction is substantive: all labels equal and $k=|V|-1$ include the <Hamiltonian path> problem from a fixed start. The efficient layered recurrence answers the consecutive-edge interpretation without pretending to enforce distinct <vertices>.

==== ii
{scope}

===== Solution

Use the multiplicative score exactly as defined in the paper. Let $P_t(v)$ be the largest score of a matching length-$t$ route ending at $v$. Initialize $P_0(v_0)=1$ and mark all other entries unreachable. For each stage, clear the new layer and inspect matching <edges> from reachable entries:
$$
P_t(v)=\max_{\substack{(u,v)\in E,\ \sigma(u,v)=x_t\\u\text{ reachable at stage }t-1}} P_{t-1}(u)\,p(u,v).
$$
An empty candidate <set> is marked unreachable, rather than given score zero: a genuine route may have score zero. A Boolean reachability table or a sentinel $-1$ with a guard before multiplication distinguishes the cases. Store the maximizing predecessor <edge> at each reachable layer entry, retaining one on a tie.

Multiplication by a nonnegative <edge> factor preserves order, so replacing a prefix by a larger-scoring matching prefix cannot worsen its extension. <Induction> proves this <maximum-product edge-labelled walk> recurrence correct. Choose a reachable final entry of greatest score and follow its layer-indexed predecessors backwards to reconstruct the answer. If no final entry is reachable, report that no matching route exists, even though all numeric scores might otherwise look like zero.

The <running time> is $O(k(|V|+|E|))$, and rolling scores have <space complexity> $O(|V|)$, while retaining all reconstruction pointers gives <space complexity> $O(k|V|)$. For the vertex-simple interpretation, retain the visited <set> in each state as in part i, prohibit revisits and maximize the same products over those states. This exact exponential-state variant preserves both the zero-score distinction and predecessor reconstruction. If the starting <vertex> is unrestricted rather than inherited from part i, initialize $P_0(v)=1$ for every <vertex>. The calculation needs no independence assumption beyond the paper's definition of a product score; repeated physical edge-activation events would require a separate probabilistic model.

=== a
{scope}

==== Solution

Initialize $d[s]=0$ and $d[v]=\infty$ elsewhere. Perform $|V|-1$ full passes over the directed <edges>, applying <edge relaxation> $d[v]\gets\min\{d[v],d[u]+w(u,v)\}$ whenever $d[u]$ is finite. For an <undirected graph>, process each <edge> in both directions. Stop early if a pass makes no change.

Each finite label records the cost of a discovered <directed walk>, so it never understates the true infimum. After $t$ passes, relaxation has propagated along every route of at most $t$ <edges>, so the label is no greater than the cost of any such route. If no reachable negative-cost closed walk exists, an optimal route can be chosen without repeated <vertices> and has at most $|V|-1$ <edges>. These inequalities prove that the final labels are the desired <shortest path> lengths.

An additional pass checks for an improving <edge> from a reachable <vertex>. If one exists, report a reachable negative-cost cycle: finite shortest distances cannot be assigned to <vertices> reachable from that cycle. Mark those <vertices> by forward reachability if individual $-\infty$ answers are wanted. In particular, a reachable negative undirected <edge> becomes a negative two-arc closed walk under the bidirected interpretation; generic signed weights do not guarantee finite answers.

Each pass costs $O(|E|)$, giving **$O(|V||E|)$** for the usual <Bellman-Ford algorithm> bound. Including initialization gives $O(|V|+|V||E|)$, which also handles an edgeless <graph> honestly; these coincide in order when $|E|\ge1$.

=== b
{scope}

==== Solution

All <edge> lengths are positive, so run the <Dijkstra algorithm> from every source $s$, retaining distances $d_s$ and a <shortest-path tree> of its reachable component. Each run takes $O((|V|+|E|)\log(|V|+1))$ with a <binary heap>. The following scans after each run use only $O(|E|)$ additional work.

For a <directed graph>, inspect every closing <edge> $(u,s)$ and consider $d_s(u)+w(u,s)$ when $u$ is reachable. The <tree> route from $s$ to $u$ followed by this <edge> is a closed walk. Every directed cycle supplies one such upper bound by choosing any of its <vertices> as $s$; the shortest route to its predecessor is no longer than the corresponding cycle segment. Positivity lets any repeated portion be removed, so the smallest candidate is **the shortest directed-cycle length**.

For an <undirected graph>, do *not* combine an <edge> with the distance between its endpoints indiscriminately: that can count traversal of one bridge out and back as a false cycle. Instead inspect only <edges> $\{u,v\}$ absent from the current <shortest-path tree>, with both endpoints reachable, and consider
$$
d_s(u)+w(u,v)+d_s(v).
$$
The two <tree> routes and this non-tree <edge> contain a genuine cycle. If they share a prefix, its cost is counted twice, so that cycle is no longer than the candidate. Every candidate is consequently at least the global shortest-cycle length.

To prove equality is attained, take a shortest cycle $C$ and a source $s$ on it. If either cycle <edge> incident to $s$ is absent from the <tree>, its candidate uses a shortest route no longer than the rest of $C$, so it is at most the length of $C$. Otherwise both incident <edges> are in the <tree>, and their other endpoints lie in different branches below $s$. Along the remaining segment of $C$, some <edge> crosses between different branches. Such an <edge> is not a <tree> <edge>. The two distances to its endpoints are bounded by the two corresponding, disjoint segments of $C$ from $s$; their sum plus the crossing <edge> is at most the length of $C$. Thus some candidate is no greater than the optimum, completing the proof.

Return the smallest finite candidate, or report acyclicity if none exists. The total <running time> is **$O((|V|^2+|V||E|)\log(|V|+1))$**, as required. The ordinary convention is a simple <graph>; if parallel <edges> are allowed, track actual <edge> identities when excluding <tree> <edges>, and treat a self-loop as its own cycle rather than discarding it. This is <shortest cycle by repeated shortest-path trees>.

==== i

===== Solution

Find a <topological sorting> of the <directed acyclic graph>. Initialize $L[s]=0$ and $L[v]=-\infty$ for $v\ne s$. Process <vertices> in that order. At a reachable <vertex> $u$, update each outgoing <edge> by $L[v]\gets\max\{L[v],L[u]+w(u,v)\}$, and retain a predecessor whenever an improvement is made.

Every path to a <vertex> ends at an earlier <vertex> in the <topological sorting>. Thus, when $v$ is processed, all possible final-edge candidates for $v$ have already been considered. <Induction> along the order proves that **$L[v]$ is the <longest path> length from $s$**, with $-\infty$ exactly for unreachable <vertices>. Signed weights cause no problem because the <graph> has no directed cycle. The <running time> is **$O(|V|+|E|)$**, and predecessor pointers recover a maximizing path.

==== ii
{scope}

===== Solution

Permit every <vertex> to start a path: initialize $L[v]=0$ for all $v$, then perform the same maximum-relaxation pass in <topological sorting> order. Equivalently, the recurrence is
$$
L[v]=\max\left(0,\ \max_{(u,v)\in E}\{L[u]+w(u,v)\}\right).
$$
The zero option starts a fresh, zero-edge path; the other options extend an optimal path ending at a predecessor. The largest final entry is therefore **the longest path length in the <graph>**, allowing a zero-edge path. This takes $O(|V|+|E|)$, which is **$O(|V|^2)$** for the ordinary simple-graph representation.

If at least one <edge> is required, keep the same prefix values but return $\max_{(u,v)\in E}(L[u]+w(u,v))$ instead of $\max_vL[v]$. That variant correctly returns a negative optimum when all nonempty paths have negative weight, and reports no nonempty path if the <edge> set is empty. No all-pairs repetition is needed.

==== i
{scope}

===== Solution

Sort the two dimension vectors separately into ascending order, $a_1\le\cdots\le a_d$ and $b_1\le\cdots\le b_d$. Then return **true exactly when $a_i<b_i$ for every $i$**. Sorting costs $O(d\log d)$ and the coordinate comparisons cost $O(d)$.

Sufficiency follows by matching corresponding ranks and translating that rank matching back to the original axes. For necessity, suppose $a_k\ge b_k$ for some $k$. The $d-k+1$ dimensions $a_k,\ldots,a_d$ must all be assigned to strictly larger target dimensions. None of the first $k$ sorted target dimensions is large enough, leaving at most $d-k$ eligible slots. The <pigeonhole principle> gives a contradiction. This proves the <sorted-coordinate criterion for box containment>, including ties: equality fails the required strict fit.

==== ii
{scope}

===== Solution

Read “subsequence” in its usual sense: selected indices increase in the given input order. First sort each box's dimension vector, in $O(nd\log d)$ total time. Let $F[j]$ be the maximum number of boxes in a fitting <subsequence> ending at index $j$. Process $j=1,\ldots,n$ and compute
$$
F[j]=1+\max\bigl(\{F[i]:i<j,\ a_{i,r}<a_{j,r}\text{ for every }1\le r\le d\}\cup\{0\}\bigr).
$$
The last selected box before $j$, if any, supplies exactly one of these candidates; conversely an optimal candidate subsequence can be extended by $j$. <Induction> on $j$ proves the <box nesting> recurrence. Store a maximizing predecessor index and reconstruct from an index maximizing $F[j]$. For $n=0$, return the empty subsequence.

There are $O(n^2)$ candidate pairs, each requiring $O(d)$ coordinate comparisons. Hence **$O(nd\log d+n^2d)$ <running time> and $O(nd+n)$ storage** suffice, including sorted vectors, table entries and reconstruction pointers. It is unnecessary to store every fitting pair.

If “subsequence” was intended to allow arbitrary reordering, build the containment <directed acyclic graph> instead: include every fitting ordered pair, then find its longest chain. Strict increase of the smallest sorted dimension gives a <topological sorting> by that dimension. The same pair-testing bound applies, but the index restriction must then be removed. These two interpretations differ: input boxes $(3,3),(2,2)$ have a longest order-preserving subsequence of one box, but an unrestricted nesting chain of two.
