= Floating-point arithmetic
{wiki}
{title2=$\pm(d_0.d_1\cdots d_{p-1})_\beta\,\beta^e$}

<Floating-point arithmetic> represents a <real number> by a sign, a fixed number of significant digits, and a scale. It trades exactness for a compact representation spanning many orders of magnitude. The picture shows the essential compromise: with the same precision, large numbers have wider gaps between representable neighbors. Thus accuracy is naturally relative to magnitude, rather than a fixed distance along the <number line>.

\Image[floating-point-spacing.png]
{title=Eight normalized four-bit binary values in each of three intervals, with gaps doubling from one eighth to one half}

In radix $\beta$, an <integer> at least two, a nonzero normalized value has the <positional notation>
$$
y=\pm\left(d_0+\frac{d_1}{\beta}+\cdots+\frac{d_{p-1}}{\beta^{p-1}}\right)\beta^e,\qquad 1\leq d_0<\beta,\quad 0\leq d_j<\beta\ (j\geq1),
$$
where the digits and exponent $e$ are <integers>. The parenthesized factor is the significand; $p$ counts all its significant digits, including the leading digit. Normalization means $d_0\ne0$, so the same value has one such representation. The allowed exponents satisfy $e_{\min}\leq e\leq e_{\max}$. Finite precision restricts the available digits, while the exponent bounds restrict the range. Zero needs a separate representation. This scales a digit string in <positional notation> by a power of its base.https://docs.oracle.com/cd/E19957-01/806-3568/ncg_goldberg.html[David Goldberg, What Every Computer Scientist Should Know About Floating-Point Arithmetic, §Floating-point Formats, 1991; Oracle's authorized edited reprint]{ref}

For positive normalized values in $[\beta^e,\beta^{e+1})$, increasing the last digit by one gives the constant neighbor spacing
$$
\Delta_e=\beta^{e-p+1}.
$$
At the next scale, the spacing is multiplied by $\beta$. In the <binary numeral system> with $p=4$, the values in $[1,2)$ are $1,1.125,1.25,\ldots,1.875$; those in $[2,4)$ are $2,2.25,\ldots,3.75$; those in $[4,8)$ are $4,4.5,\ldots,7.5$. The respective gaps are $1/8$, $1/4$, and $1/2$. Although absolute resolution deteriorates with magnitude, $\Delta_e/y$ stays between $\beta^{-p}$ and $\beta^{1-p}$. This scale invariance is why <floating-point arithmetic> suits both microscopic and astronomical calculations.

The IEEE 754 binary64 format uses the <binary numeral system> with $p=53$, including an implicit leading one for normalized values, and normal exponents $-1022\leq e\leq1023$. Its 64 stored <binary digits> comprise one sign digit, 11 exponent digits and 52 trailing significand digits. <Subnormal numbers> extend the range toward zero with a different leading-digit rule. In rounding to nearest, an operation returns the representable value closest to its exact result; a tie goes to the value whose last significant <binary digit> is even. <Machine epsilon> describes the gap just above one, whereas <unit roundoff> bounds a single relative rounding error in the normal range. These format and rounding rules are presented in MIT's floating-point lecture.https://ocw.mit.edu/courses/18-335j-introduction-to-numerical-methods-spring-2019/2f313023ae3404bc217a81a31b227170_MIT18_335JS19_lec2.pdf[Per-Olof Persson, MIT 18.335J, Lecture 2: Floating-Point Arithmetic, the IEEE Standard, slides 6–9, 2019]{ref}

Even an ordinary terminating decimal can require rounding in the <binary numeral system>. The <rational number> $0.1=1/10$ has the repeating <positional notation> $0.0001100110011\ldots{}_2$. Every finite binary <fraction> has a reduced <denominator> that is a power of two, so the factor five in $10$ prevents an exact finite binary representation. In binary64, the exact stored values of three decimal literals and their computed <sum> are
$$
\begin{array}{c|c}
\text{Python expression}&\text{exact stored rational number}\\\hline
0.1&3602879701896397/36028797018963968\\
0.2&3602879701896397/18014398509481984\\
0.3&5404319552844595/18014398509481984\\
0.1+0.2&1351079888211149/4503599627370496
\end{array}
$$
The exact <sum> of the first two stored <rational numbers> is $10808639105689191/36028797018963968$, halfway between two binary64 values. The even-last-digit tie rule rounds it upward. The printed result is `0.30000000000000004`, one step $2^{-54}$ above stored `0.3`, so `0.1 + 0.2 == 0.3` is false. Both conversion of the inputs and rounding of the <addition> matter here.

To reproduce the table on a Python installation using binary64, inspect exact <fractions> rather than only their printed decimal representations:
``
import sys
assert (sys.float_info.radix, sys.float_info.mant_dig) == (2, 53)
for value in (0.1, 0.2, 0.3, 0.1 + 0.2):
    print(repr(value), value.as_integer_ratio())
print(0.1 + 0.2 == 0.3)  # False
``
Python's `as_integer_ratio()` returns a pair of <integers> whose quotient equals the stored finite value exactly.https://docs.python.org/3.14/library/stdtypes.html#float.as_integer_ratio[Python 3.14 documentation, float.as_integer_ratio]{ref} Exact <rational numbers> are also useful for checking <floating-point arithmetic>: a short decimal printout can hide the approximation being made.

Historically, David Goldberg's March 1991 ACM Computing Surveys paper explained representation, rounding and <catastrophic cancellation> together with the IEEE standard's design choices. Oracle provides an authorized edited reprint. Its enduring lesson is practical: use the spacing to understand <roundoff error>, and inspect intermediate values when mathematically equivalent <algorithms> behave differently.https://docs.oracle.com/cd/E19957-01/806-3568/ncg_goldberg.html[Goldberg, 1991, reprint notice and §§Rounding Error, Cancellation]{ref}

= Floating-point operation
{parent=Floating-point arithmetic}

= Flop
{synonym}

A floating-point operation is one arithmetic operation on values represented in <floating-point arithmetic>. Algorithmic counts commonly count addition, subtraction, multiplication and division separately. A fused multiply-add can therefore count as two arithmetic operations even when executed by one hardware instruction. Such counts describe work, while elapsed time also depends on memory traffic, parallelism and the implementation.

= Floating-point addition
{parent=Floating-point arithmetic}

To add two finite <floating-point numbers>, compare their <exponents>, shift the smaller <significand> to a common <exponent>, add or subtract the signed <significands>, normalize the result, and apply <floating-point rounding>. Extra low-order <bits> are needed to determine correct rounding when shifting or cancellation discards information. A carry beyond the leading digit increases the <exponent>; cancellation can decrease it. Unlike exact real <addition>, this operation need not be associative. Changing the child evaluation order in a fixed <binary expression tree> need not change its parenthesization, whereas reassociation changes which intermediate results undergo <floating-point rounding>.

= Half-precision floating-point number
{synonym}

A sixteen-<bit> <floating-point representation> with one sign <bit>, five <exponent> <bits> and ten stored fraction <bits>. For sign $s$, stored <exponent> $E$ and fraction <integer> $F$, normal finite values are
$$
(-1)^s(1+F2^{-10})2^{E-15},\qquad1\leq E\leq30,\quad0\leq F<1024.
$$
The implicit leading one gives eleven significant <binary digits>. With $E=0$, the value is $(-1)^sF2^{-24}$, including signed zero at $F=0$ and <subnormal numbers> otherwise. The stored <exponent> $E=31$ is reserved for infinities at $F=0$ and <NaN> otherwise. The positive normal range is $2^{-14}$ through $65504$; the least positive <subnormal number> is $2^{-24}$.

= Double precision
{synonym}

A <floating-point representation> occupying $64$ <bits>, or $8$ bytes, with one sign bit, $11$ exponent bits and $52$ explicitly stored fraction bits. The implicit leading bit of a normal number gives $53$ bits of significand precision. Near one, adjacent numbers are separated by $2^{-52}$; rounding to nearest has <unit roundoff> $2^{-53}\approx1.11\times10^{-16}$ in the normal range. These are relative precision scales, distinct from underflow limits or a universal absolute error bound.<IEEE arithmetic in Oracle's Numerical Computation Guide>[Chapter 2, IEEE Arithmetic Model and Double Format, Table 2-5]{ref}

= Floating-point overflow
{parent=Floating-point arithmetic}

Floating-point overflow occurs when the magnitude of a computed result exceeds the largest finite representable <floating-point number>. Large values of an <exponential function> are a common source. In a normalized weighted sum, replacing exponentials $e^{r_i}$ by $e^{r_i-r_{\max}}$ before division prevents this particular overflow while leaving the normalized weights unchanged; this is an application of the <log-sum-exp> construction.

= Not a number
{synonym}

A special <floating-point arithmetic> value representing an undefined or unrepresentable numerical result. A displayed <NaN> is not a numerical zero and is not a valid <p-value>.

= Floating-point rounding
{parent=Floating-point arithmetic}

Replacement of an exact real arithmetic result by a representable <floating-point number> under a specified rounding rule. Repeated products can depend on evaluation order, so a recursive rewrite intended to reproduce a floating-point loop should preserve its sequence of accumulator operations. An exact algebraic invariant does not by itself establish equality of rounded machine results.

= Floating-point underflow
{parent=Floating-point arithmetic}

<Floating-point underflow> occurs when a nonzero numerical result is smaller in magnitude than the representable range or loses precision in the subnormal range. A long product of probabilities can become zero despite a mathematically positive result. Adding <logarithms> avoids forming the product; adding alternative path probabilities then requires <log-sum-exp> or controlled rescaling.

= Significand
{parent=Floating-point representation}
{title2=$m$}
{wiki}

The significant-digit factor $m$ in a <floating-point representation> $(-1)^s m\,\beta^e$, where $s$ is the sign <bit>, $\beta$ the radix and $e$ the <exponent>. For a normal positive binary <significand>, $1\leq m<2$, and the leading one need not be stored. In a <subnormal number>, the leading digit is zero at the minimum normal <exponent> scale. The <significand> is a numerical factor, distinct from the stored trailing fraction <bits> that encode part of it.

= Compensated summation

<Compensated summation> retains a correction for low-order information lost to <roundoff error> in successive <floating-point arithmetic> additions. <Kahan summation> is a common implementation; it can substantially reduce accumulated error when many terms are added.

= Machine epsilon
{parent=Floating-point arithmetic}
{wiki}
{title2=$\epsilon_{\rm mach}=\beta^{1-p}$}

= Machine precision
{synonym}

Here <machine epsilon> means the gap from one to the next larger value in normalized <floating-point arithmetic>:
$$
\epsilon_{\rm mach}=\operatorname{next}(1)-1=\beta^{1-p}.
$$
It is a relative resolution scale near one, not the smallest positive representable value and not a fixed absolute error for all magnitudes. In binary64, $p=53$ gives
$$
\epsilon_{\rm mach}=2^{-52}\approx2.220446049250313\times10^{-16},\qquad u=2^{-53}\approx1.1102230246251565\times10^{-16},
$$
where $u$ is <unit roundoff> for rounding to nearest. Some authors instead call $u$ their <machine epsilon>; MIT 18.335J uses this half-gap convention. Always check which definition an error bound uses.https://ocw.mit.edu/courses/18-335j-introduction-to-numerical-methods-spring-2019/2f313023ae3404bc217a81a31b227170_MIT18_335JS19_lec2.pdf[Persson, MIT 18.335J, Lecture 2, slides 3, 8–9: the half-gap convention]{ref}

The gap below one is smaller: the preceding binary64 value is $1-2^{-53}$, whereas the next value above one is $1+2^{-52}$. Under nearest-even rounding, `1.0 + 2.0**-53` is exactly `1.0`: the exact <sum> is a tie and one has the even final <binary digit>. By contrast, `1.0 + 2.0**-52` is the next value. Thus searching for the smallest increment that changes one by trial <addition> also depends on the rounding convention. At $2^{53}$ the next larger binary64 value is $2^{53}+2$, illustrating why a small absolute increment can disappear at large magnitude.

= Scale-aware stopping criterion for Newton iteration
{parent=Machine epsilon}
{title2=$|x_{n+1}-x_n|\le C\epsilon\max(1,|x_n|)$}

Near a well-conditioned simple root, a numerically stable <Newton root-finding iteration> cannot usually resolve steps far below the local spacing of <floating-point numbers>. That spacing has relative scale comparable to <machine epsilon> $\epsilon$, motivating the displayed position-based criterion with a modest constant $C$. It combines an absolute scale near zero with a relative scale for large inputs. A residual-only test is changed by rescaling the equation, whereas the root and exact Newton step are unchanged. A tiny step alone is not a universal accuracy certificate: derivative errors, stagnation and cycles require separate consideration.

= Unit roundoff
{parent=Floating-point arithmetic}
{title2=$u=\tfrac12\beta^{1-p}$}

For <floating-point arithmetic> with precision $p$ in radix $\beta$ and rounding to nearest, <unit roundoff> is the half-gap scale $u=\beta^{1-p}/2$. If a nonzero exact <real number> $z$ lies in the normal finite range, its nearest rounded value satisfies
$$
\operatorname{fl}(z)=z(1+\delta),\qquad |\delta|\leq u.
$$
Indeed, the absolute distance to the nearest value is at most $\Delta_e/2$, and $|z|\geq\beta^e$ gives the bound. For a correctly rounded <addition>, <subtraction>, <multiplication> or <division>, apply this estimate to the exact result of that one operation on the stored operands. The bound does not include earlier <roundoff error> or automatically bound a whole <algorithm>. Results outside the finite range and tiny <subnormal numbers> require separate treatment. Rounding in a directed mode also changes the bound.https://docs.oracle.com/cd/E19957-01/806-3568/ncg_goldberg.html[Goldberg, 1991, §§Relative Error and Ulps, Exactly Rounded Operations]{ref}

= Subnormal number
{parent=Floating-point arithmetic}
{wiki}
{title2=$k\beta^{e_{\min}-p+1},\quad 1\leq k<\beta^{p-1}$}

= Denormalized number
{synonym}

A <subnormal number> is a nonzero representable value smaller in magnitude than the least positive normalized value $\beta^{e_{\min}}$. Keep the exponent scale fixed at $e_{\min}$ and allow a zero leading digit: the positive values are $k\beta^{e_{\min}-p+1}$ for <integers> $1\leq k<\beta^{p-1}$. This fills the gap toward zero with constant absolute spacing, at the cost of fewer significant digits. Goldberg describes this gradual approach to zero and why it matters for differences of small numbers.https://docs.oracle.com/cd/E19957-01/806-3568/ncg_goldberg.html[Goldberg, 1991, §Denormalized Numbers]{ref}

For binary64 the least positive normalized value is $2^{-1022}$, and <subnormal numbers> are spaced by $2^{-1074}$. With nearest rounding and gradual underflow enabled, an exact result $z$ with $|z|<2^{-1022}$ has absolute rounding error at most $2^{-1075}$. A uniform relative bound by <unit roundoff> fails here: $z=2^{-1075}$ rounds to zero under the even-last-digit tie rule, giving relative error one. <Machine epsilon> measures resolution near one; it does not measure the distance from zero to the first positive value.

= Catastrophic cancellation
{parent=Floating-point arithmetic}
{wiki}
{title2=$\sqrt{1+x}-1=\dfrac{x}{\sqrt{1+x}+1}$}

<Catastrophic cancellation> occurs when <subtraction> of nearly equal approximations removes their matching leading digits and exposes earlier <roundoff error>. The <subtraction> can itself be exact on the stored operands: the information may already have been lost while obtaining them. Goldberg distinguishes this from cancellation of accurately known quantities, which can be harmless.https://docs.oracle.com/cd/E19957-01/806-3568/ncg_goldberg.html[Goldberg, 1991, §Cancellation]{ref}

For $x>0$, consider the single <real-valued function>
$$
f(x)=\sqrt{1+x}-1=\frac{x}{\sqrt{1+x}+1}.
$$
The <rationalization of a square-root difference> proves equality in exact <arithmetic>. The two evaluations use the same input $x$, but the direct version first forms a value near one and then subtracts one. The rearranged version keeps the small input in its <numerator> and divides by a <denominator> near two.

\Image[floating-point-cancellation.png]
{title=Direct and rationalized evaluation of a small square-root difference against a high-precision reference for the same binary64 inputs}

For binary64 `x = 1e-16`, the rounded <sum> `1.0 + x` is one, so `sqrt(1.0 + x) - 1.0` is zero. The rationalized evaluation returns approximately $5\times10^{-17}$. A 100-digit Decimal calculation using the exact stored input gives relative errors of one and about $2.50\times10^{-17}$ respectively. At `x = 1e-12`, the direct result is about $5.0004445029\times10^{-13}$, with relative error $8.89\times10^{-5}$; the rearranged result is about $4.99999999999875\times10^{-13}$, with relative error $1.21\times10^{-17}$.

The plot uses `Decimal.from_float(x)` to preserve the binary input exactly, computes $x/(\sqrt{1+x}+1)$ at 100 decimal digits, and verifies the reference at 160 digits. Exact conversion of a stored binary value is documented by Python.https://docs.python.org/3.14/library/decimal.html#decimal.Decimal.from_float[Python 3.14 documentation, Decimal.from_float]{ref} Each error is $|\widehat f-f|/|f|$, with the computed result converted exactly to Decimal before comparison. Hence the curves measure evaluation error for one common input, rather than a mixture of input conversion error and evaluation error. The plotted interval $10^{-16}\leq x\leq10^{-1}$ is far above the <subnormal number> range.

The original problem is well conditioned with respect to relative changes in $x$. Using the <derivative> $f'(x)=1/(2\sqrt{1+x})$ and <rationalization of a square-root difference>, its relative <condition number> is
$$
\kappa_f(x)=\left|\frac{xf'(x)}{f(x)}\right|=\frac{\sqrt{1+x}+1}{2\sqrt{1+x}},\qquad \frac12<\kappa_f(x)<1\quad(x>0).
$$
It tends to one as $x$ tends to zero. The direct evaluation instead introduces the intermediate difference $s-1$ with $s=\sqrt{1+x}$; an error of order <unit roundoff> in $s$ is large relative to $f(x)\approx x/2$. This is a failure of the chosen <algorithm>'s accuracy despite a small <condition number> for the same <real-valued function>. The rationalized evaluation avoids that intermediate <catastrophic cancellation>, retaining relative accuracy near the <unit roundoff> scale throughout the plotted interval. Recognizing this structure can improve a calculation far more than merely printing extra digits.
