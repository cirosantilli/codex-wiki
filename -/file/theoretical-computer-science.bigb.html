= Formal language
{parent=Theoretical computer science}
{wiki}

A formal language is a set of finite strings over a fixed finite alphabet.

= L-system
{parent=Formal language}
{c}

A parallel string-rewriting system: at each generation, every symbol is replaced simultaneously by its assigned word. Symbols can also encode drawing commands such as moving forward or turning. Large recursively defined drawings can be queried without expanding the whole word by precomputing the length, displacement, and rotation of each expanded block.

= Binary string
{parent=Formal language}
{title2=$\{0,1\}^{<\omega}$}

A <binary string> is a finite word over the alphabet $\{0,1\}$. There are $2^n$ strings of length $n$. Finite <binary strings> have an effective <bijection> with <natural numbers>, so computable enumerability and immunity apply to sets of strings.

= Counting binary strings with bounded ones
{parent=Binary string}
{title2=$\#\{w:\#0(w)=n,\ \#1(w)\le m\}=\binom{n+m+1}m$}

A <binary string> with $n$ zeroes and $j$ ones is determined by its $j$ one-positions, giving $\binom{n+j}j$ possibilities. Sum for $0\le j\le m$ and apply the <hockey-stick identity>. Equivalently, distribute at most $m$ ones among the $n+1$ gaps around the zeroes and add a slack count; <stars and bars> counts $n+2$ nonnegative counts summing to $m$.

= Self-delimiting binary code
{parent=Binary string}

A self-delimiting code permits a decoder to identify the end of a code without an external length marker. Encoding a binary word of length $\ell$ by $\ell$ ones, a zero and the word uses $2\ell+1$ bits. This yields an $O(\log n)$ description of a <natural number> in an incompressibility proof.

= Concatenation of formal languages
{parent=Formal language}
{title2=$LM=\{uv:u\in L,\ v\in M\}$}

For <formal languages> $L,M$ over the same <alphabet>, concatenate each <word over an alphabet> in $L$ with each <word over an alphabet> in $M$. This operation is associative, has identity $\{\varepsilon\}$ and absorbing element the <empty language>.

= Empty language
{parent=Formal language}
{title2=$\varnothing$}

The <formal language> containing no <words over an alphabet>. It differs from the language containing only the <empty word>, which is a multiplicative identity for <concatenation of formal languages>.

= Turing machine
{parent=Theoretical computer science}
{c}
{wiki}

A Turing machine is an abstract computational model with a finite control, an unbounded tape and a head that reads, writes and moves on the tape.

= Blank symbol
{parent=Turing machine}
{title2=$\square$}

A designated tape <alphabet> symbol occupying unused cells of a <Turing machine>. It is excluded from the input <alphabet>, so a finite input <word> occupies a finite region of an otherwise blank tape.

= Turing machine encoding
{parent=Turing machine}
{c}
{title2=$\operatorname{enc}(M)$}

A finite <string> describing a <Turing machine>'s states, <alphabets>, transition rules and designated initial and halting states. Standard encodings have a <decidable language> of valid descriptions. A syntactic property of an encoding need not be an <extensional property of programs>; for example, adding an unreachable state changes state count without changing the accepted <formal language>.

= Multitape Turing machine
{parent=Turing machine}
{wiki}

A <Turing machine> with a fixed finite number of tapes and a head for each tape. One transition reads the scanned symbols, updates them and moves the heads. This model accepts the same <computably enumerable languages> as a <single-tape Turing machine>, but step counts can differ.

= Single-tape Turing machine
{parent=Turing machine}

A <Turing machine> with one read-write tape. Every <multitape Turing machine> can be simulated by a <single-tape Turing machine>, using delimited tape portions and marked head positions. The simulation preserves the accepted <formal language> and whether a computation halts, while possibly increasing <time complexity>.

= Read-only-from-left Turing acceptor
{parent=Turing machine}

= ROFL
{c}
{synonym}

A deterministic <single-tape Turing machine> that leaves every scanned symbol unchanged and moves one cell right after every nonhalting transition. Such machines decide exactly the <regular languages>. A <deterministic finite automaton> simulates the finite control, with accepting states determined by the blank-only continuation after the <input>; conversely, a machine simulating a <deterministic finite automaton> halts on the first blank.

= Instantaneous description of a Turing machine
{parent=Turing machine}
{title2=$C$}

= Turing machine configuration
{c}
{synonym}

An instantaneous description records the current control state, head position, and tape contents. For a tape blank outside a finite window, a word $h\,u\,q\,v\,h$ records the symbols $u$ to the left of the head and $v$ from the scanned cell rightward, with unrecorded cells blank. If $v$ is empty, the head scans an implicit blank. Extra outer blanks can represent the same infinite tape. The <instruction of a Turing machine> determines its successor description.

= Next-configuration relation
{parent=Instantaneous description of a Turing machine}
{title2=$C\vdash_M C'$}

For a <Turing machine>, the one-step <binary relation> between <Turing machine configurations> specified by its <Turing machine instructions>. Its <reflexive transitive closure> $\vdash_M^*$ describes any finite number of computation steps, including zero.

= Instruction of a Turing machine
{parent=Turing machine}
{title2=$\delta(q,a)=(p,b,D)$}

= Turing machine instruction
{c}
{synonym}

For a deterministic single-tape <Turing machine>, an instruction reads a state $q$ and scanned tape symbol $a$, writes $b$, changes state to $p$, and moves the head one cell left, one cell right, or not at all according to $D$. The state and tape alphabets are finite; an undefined transition halts. A dedicated terminal state can be introduced by directing undefined transitions to it without changing whether computation halts.

= Two-stack encoding of a Turing tape
{parent=Turing machine}
{title2=$c=(q,L,R)$}

Encode the cells immediately left of the head in a reversed positional stack $L$, and the current and right cells in $R$. Quotient and remainder by the alphabet base read and remove cells; multiplication by that base pushes a cell. The resulting local tape transitions are <primitive recursive>, which makes them directly implementable on <Church numerals>.

= Modular machine
{parent=Turing machine}
{title2=$\mathcal M$}

A modular machine of modulus $m>1$ acts on pairs in $\mathbb N^2$. Each instruction $(a,b,c,R)$ or $(a,b,c,L)$ has $0\le a,b<m$ and $0\le c<m^2$, and at most one instruction is assigned to each residue pair $(a,b)$. The two transition types are $(mu+a,mv+b)\mapsto(m^2u+c,v)$ and $(mu+a,mv+b)\mapsto(u,m^2v+c)$. These finite arithmetic operations can encode a <Turing machine>; a designated terminal configuration can have a nonrecursive <halting set>.

= Group encoding of a modular machine
{parent=Modular machine}

A <modular machine> can be encoded by <HNN extensions> of $K=\mathbb Z^2*\langle t\rangle$. The kernel of $K\to\mathbb Z^2$ has a <free basis of a group> $t(r,s)=x^{-r}y^{-s}tx^ry^s$. Associated-subgroup maps send these basis elements according to the two arithmetic transition types. In the resulting group, membership of $t(r,s)$ in the subgroup generated by $t$ and the instruction stable letters is equivalent to $(r,s)\in H_0(\mathcal M)$. One more <HNN extension> centralizes that finitely generated subgroup, converting membership to equality and hence to the <word problem for a group>.

= Halting set at a designated terminal configuration
{parent=Modular machine}
{title2=$H_0(\mathcal M)$}

For a <modular machine> whose $(0,0)$ is terminal, $H_0(\mathcal M)$ is the set of configurations whose forward computation reaches exactly $(0,0)$, including the zero-step computation there. It may differ from the set of configurations stopping at any terminal configuration. Determinism makes membership invariant along each instruction edge.

= Deterministic computation

In a deterministic computation, every configuration and input symbol determine at most one next configuration.

= Reversible computation
{parent=Turing machine}

A reversible computation has an injective transition function, so its preceding configuration can be recovered from its current configuration. Any finite classical computation can be simulated reversibly while retaining enough workspace to <uncomputation>[uncompute] its temporary results.

= Reversible circuit

A reversible circuit is composed of bijective gates. The <Toffoli gate> is universal for reversible Boolean computation when ancillary bits are available.

= Function oracle
{parent=Oracle machine}

= Function-evaluation oracle
{synonym}

A <function oracle> supplies access to an unknown <function> $f$: given an allowed input $x$, one query returns $f(x)$. <Query complexity> counts these accesses separately from known local computation. A classical query receives one definite answer; a <quantum oracle> specifies coherent access through a <unitary operator>, allowing inputs in <quantum superposition>. The distinction is part of the access model, not a change to the mathematical function.

A <Boolean quantum oracle> preserves $x$ and adds a one-<bit> value $f(x)$ into an answer <qubit> by <exclusive or>. On known <computational-basis states>, its output determines the same value as a classical <function oracle> query.

= Boolean operation
{parent=Theoretical computer science}
{c}
{title2=$f:\{0,1\}^n\to\{0,1\}$}

A <Boolean operation> is a <Boolean function> taking <truth values> encoded as <bits>: $0$ means false and $1$ means true. These operations supply the concrete two-valued interpretation of a <Boolean algebra>. A <Boolean valuation> fixes the inputs; a <truth table> lists every possible input. With two input <bits> there are four rows.

The basic <logical connectives> are <logical conjunction> (AND, $P\wedge Q$, both true), <logical disjunction> (OR, $P\vee Q$, at least one true), <exclusive or> (XOR, $P\oplus Q$, exactly one true), and <logical negation> (NOT, $\neg P$, the opposite value). OR is inclusive: it accepts the case where both inputs are true.<Discrete Mathematics: An Open Introduction (3rd edition) by Oscar Levin/3.1 Propositional Logic>[Discrete Mathematics: An Open Introduction (3rd edition) by Oscar Levin; Discrete Mathematics: An Open Introduction, 3rd edition by Oscar Levin, §3.1, Truth Tables: conjunction, disjunction and negation tables]{ref}

\Image[boolean-operation-truth-grid.png]
{title=Four input pairs distinguish <logical conjunction>, inclusive <logical disjunction>, <exclusive or>, and <logical negation>}

For an original program-condition example, let $P$ mean “the backup is recent” and $Q$ mean “the backup is verified”. A rule requiring a recent, verified backup uses <logical conjunction>; one accepting either qualification uses <logical disjunction>. A rule flagging a mismatch between the two qualifications uses <exclusive or>. A recent, verified backup gives $(P,Q)=(1,1)$: AND and OR accept it, while XOR does not flag it. The last row of the <truth table> makes this difference explicit.

The same small <Boolean operations> build larger tests and <Boolean circuits>. In a <programming language>, the value of a condition and the procedure for evaluating it both matter. For Boolean operands, <Python>'s `and`, `or`, and `not` implement these <logical connectives>. Evaluation proceeds from the left; `and` skips its right operand if the left is false, and `or` skips it if the left is true. More generally, `and` and `or` return an operand, whereas `not` returns a Boolean.<Python 3.14 documentation/Expressions, Python 3.14 language reference>[Python 3.14 documentation; Python Language Reference, version 3.14, §6.11 Boolean operations: evaluation order and returned operands]{ref}

For example, the <Python> condition `denominator != 0 and numerator / denominator > 2` avoids <division> by zero because the <logical conjunction>'s second test is evaluated only when the first succeeds. Reversing the tests preserves the abstract <truth table> for defined operands but can raise a division-by-zero error handled through <exception handling>. A rewrite involving a <side effect> must also preserve the needed evaluation behavior.

= Boolean operations on events
{parent=Boolean operation}
{c}

<Events> turn <Boolean operations> into operations on <sets>. For a die with <sample space> $U=\{1,2,3,4,5,6\}$, let $A=\{2,4,6\}$ be the <event> “even outcome” and $B=\{4,5,6\}$ the <event> “outcome at least four”. At outcome $u$, use the <indicator functions> $P=\mathbf1_A(u)$ and $Q=\mathbf1_B(u)$. Then
$$
\begin{aligned}
\text{AND: }A\cap B&=\{4,6\},&\text{OR: }A\cup B&=\{2,4,5,6\},\\
\text{XOR: }A\mathbin\triangle B&=\{2,5\},&\text{NOT }A:\ U\setminus A&=\{1,3,5\}.
\end{aligned}
$$
Thus <logical conjunction> becomes <set intersection>, <logical disjunction> becomes <set union>, <exclusive or> becomes <symmetric difference>, and <logical negation> becomes the <complement of a set> within $U$. Outcome four satisfies both <events>, so inclusive <logical disjunction> includes it and <exclusive or> excludes it. If the die is fair, these four <events> have <probabilities> $1/3$, $2/3$, $1/3$, and $1/2$, respectively. No assumption of <independent events> is needed for the <set> identities; indeed $A$ and $B$ here are not <independent>, since $1/3\ne(1/2)(1/2)$.

= Bitwise XOR
{synonym}

<Exclusive or> returns one exactly when its two input <bits> differ. Its <truth table> gives $0\oplus0=0$, $0\oplus1=1$, $1\oplus0=1$, and $1\oplus1=0$. The identities
$$
P\oplus Q=(P\vee Q)\wedge\neg(P\wedge Q)
=(P\wedge\neg Q)\vee(\neg P\wedge Q)
$$
express <exclusive or> using <logical conjunction>, <logical disjunction>, and <logical negation>. The first expression accepts at least one input and then excludes both; the second explicitly lists the two accepted input pairs.

For numerical <bits>, <exclusive or> is <addition> in <modular arithmetic> modulo two:
$$
x\oplus y=(x+y)\bmod2.
$$
The <binary operation> is <commutative> and <associative>, because <addition> modulo two has those properties. It satisfies $x\oplus0=x$, $x\oplus1=\neg x$, and $x\oplus x=0$. These identities explain why a <bit> can be toggled and restored with the same operation.

On <binary strings> of equal length, bitwise <exclusive or> applies the one-<bit> rule separately at each position. For example,
$$
1010\oplus0110=1100,\qquad1100\oplus0110=1010.
$$
A <bit mask> of $0110$ toggles exactly the middle two <bits>. Applying the mask twice restores the original <binary string>: each selected <bit> changes twice, and each unselected <bit> stays fixed. This positional operation is distinct from taking the <exclusive or> of the overall <truth values> of two <integers>.

= Exclusive or toggles and parity
{parent=Exclusive or}

For <bits> $x_1,\ldots,x_n$, repeated <exclusive or> computes the <parity> of the number of ones:
$$
x_1\oplus\cdots\oplus x_n=\left(\sum_{i=1}^n x_i\right)\bmod2.
$$
An <induction> proves this: the first <bit> gives its own <parity>, and appending a zero preserves it while appending a one changes it. The <binary string> $10110$ has three ones, so its <parity bit> is one. Append that <parity bit> to obtain $101101$, whose six <bits> have even <parity>. Flipping the second <bit> produces $111101$ and changes the combined <exclusive or> to one, detecting an error. Flipping the third <bit> as well produces $110101$, with four ones and combined <exclusive or> zero: an even number of flips can escape this check.

For three inputs, repeated <exclusive or> means an odd number of true inputs, rather than exactly one: $1\oplus1\oplus1=1$. The “exactly one” description applies to the two-input <exclusive or>. This distinction matters when translating a requirement that exactly one option be selected into a program condition.

= NOT
{c}
{synonym}

<Logical negation> exchanges zero and one: $\neg0=1$ and $\neg1=0$. For a numerical <bit> $x$, this is $1-x$; applying <logical negation> twice restores $x$. It acts on the entire <propositional formula> in its scope. Parentheses therefore matter: $\neg(P\vee Q)$ says that neither condition holds, while $(\neg P)\vee Q$ also accepts every case where $Q$ holds. At $(P,Q)=(1,1)$ their values are zero and one.

On a <set>, <logical negation> becomes taking a <complement> in a fixed <universal set>. In <Boolean operations on events>, “not even” selects $\{1,3,5\}$. “Not both even and at least four” selects $\{1,2,3,5\}$; it does not require both qualifications to fail. <De Morgan's laws> make the scope of these compound negations precise.

= De Morgan laws
{c}
{synonym}

<De Morgan's laws> exchange <logical conjunction> and <logical disjunction> when a <logical negation> moves across them:
$$
\neg(P\wedge Q)\equiv(\neg P)\vee(\neg Q),
\qquad
\neg(P\vee Q)\equiv(\neg P)\wedge(\neg Q).
$$
Here $\equiv$ denotes <logical equivalence>: the two <propositional formulas> agree under every <Boolean valuation>.<Discrete Mathematics: An Open Introduction (3rd edition) by Oscar Levin/3.1 Propositional Logic>[Discrete Mathematics: An Open Introduction (3rd edition) by Oscar Levin; Discrete Mathematics: An Open Introduction, 3rd edition by Oscar Levin, §3.1, Logical Equivalence: definition, Example 3.1.3 and De Morgan's Laws box]{ref}

A complete verification uses the four rows of a <truth table>. In input order $(0,0),(0,1),(1,0),(1,1)$, both sides of the first <logical equivalence> have output sequence $(1,1,1,0)$; both sides of the second have $(1,0,0,0)$. A proof in words is equally short: failure of “both” means at least one failure, whereas failure of “at least one” means both fail. The differing middle rows explain why simply pushing <logical negation> inward without changing AND to OR is wrong.

For the <events> in <Boolean operations on events>, the corresponding <set> identities are
$$
U\setminus(A\cap B)=(U\setminus A)\cup(U\setminus B)=\{1,2,3,5\},
$$
$$
U\setminus(A\cup B)=(U\setminus A)\cap(U\setminus B)=\{1,3\}.
$$
One can prove these identities by checking an arbitrary <set element> $u\in U$: its two membership <truth values> obey <De Morgan's laws>. The same reasoning works for any two <subsets> of a common <universal set>.

\Image[de-morgan-event-regions.png]
{title=<De Morgan's laws> shade the same <set> whether a compound <event> is complemented first or its component <events> are complemented first}

For a nested program test, let $R$ mean “backup recent”, $V$ mean “backup verified”, and $O$ mean “manual override authorized”. Rejecting when neither an acceptable backup nor an override is present gives
$$
\neg\bigl((R\wedge V)\vee O\bigr)
\equiv\bigl((\neg R)\vee(\neg V)\bigr)\wedge\neg O.
$$
The transformed condition reads “backup stale or unverified, and no override”. Apply the second of <De Morgan's laws> at the outside, then the first at the inner <logical conjunction>. For $(R,V,O)=(1,0,0)$ it rejects; changing only $O$ to one makes it accept. With Boolean operands in <Python>, `not ((recent and verified) or override)` and `((not recent) or (not verified)) and (not override)` have the same result and inspect the operands in the same order, with the same skipped operands.

= De Morgan dual of a Boolean function
{c}
{parent=De Morgan's laws}
{title2=$f^*(x)=\neg f(\neg x)$}

= De Morgan dual
{c}
{synonym}

For a <Boolean function> $f$ of $n$ input <bits>, define its <De Morgan dual> by complementing every input, applying $f$, and complementing the output:
$$
f^*(x_1,\ldots,x_n)=1-f(1-x_1,\ldots,1-x_n).
$$

<De Morgan's laws> say that the <De Morgan dual> of <logical conjunction> is <logical disjunction>, and conversely. The constant zero <Boolean function> becomes constant one. This is different from merely negating the output: for AND, output <logical negation> gives one at $(0,0)$, whereas the <De Morgan dual> gives zero there.

Taking the <De Morgan dual> twice restores the original <Boolean function>:
$$
(f^*)^*(x)=1-\bigl(1-f(x)\bigr)=f(x).
$$
Here each input is complemented twice as well. For a <Boolean formula> built from AND, OR, NOT and constants, its <De Morgan dual> can therefore be obtained by exchanging AND with OR and zero with one throughout, leaving input names and NOT in place. A structural <induction> proves the rule: it holds for an input and each constant, <De Morgan's laws> handle the two binary <logical connectives>, and double <logical negation> handles NOT. This symmetry lets one translate a complex test systematically instead of guessing where its failures occur.

= Computational complexity theory
{parent=Theoretical computer science}
{wiki}

Computational complexity theory classifies <computational problem>[computational problems] by the resources needed to solve them.

= Bit complexity
{parent=Computational complexity theory}

The number of elementary operations on <bits> required by an <algorithm>. Arithmetic-operation counts treat operations on entire <integers> as units, whereas <bit complexity> charges for the sizes of their operands. An <algorithm> using few multiplications can therefore require substantially more bit operations when the operands grow. State the model when comparing bounds for <repeated squaring> or <dynamic programming> counts.

= Parameterized complexity
{parent=Computational complexity theory}
{wiki}

<Parameterized complexity> studies an <algorithm>'s resource use as a function of both the encoded <input> length $N$ and a distinguished <nonnegative integer> parameter $k$. A small solution size, a dimension or a structural property of a <graph> can serve as the parameter. <Fixed-parameter tractability> allows arbitrary computable dependence on $k$ while keeping the exponent of $N$ independent of $k$.

= Kernelization
{parent=Parameterized complexity}
{wiki}

A <kernelization> is a <polynomial-time algorithm> mapping a parameterized <decision problem> instance $(I,k)$ to an equivalent instance $(I',k')$ of the same problem, with both encoded length $|I'|$ and parameter $k'$ bounded by a computable <function> of $k$. Equivalent means that both instances have the same yes/no answer. The bound need not be a <polynomial> in $k$; a polynomial kernel is the stronger requirement that it is. For a decidable problem, exhaustively solving the bounded output leaves only a computable dependence on $k$, so <kernelization> yields <fixed-parameter tractability>.

= Fixed-parameter tractable problem
{synonym}

A parameterized <decision problem> is <fixed-parameter tractable> if an <algorithm> decides every instance of encoded length $N$ and parameter $k$ in <running time> at most $f(k)N^c$, for a computable <function> $f$ and a constant $c$ independent of $k$. The distinction is in the exponent: $2^kN^3$ has this form, whereas an $N^k$ bound alone does not establish <fixed-parameter tractability>. Branching on an uncovered <edge> gives a <fixed-parameter tractable> <vertex cover decision problem>.

= Element distinctness problem
{parent=Computational complexity theory}

Decide whether all input elements are distinct. In the <comparison model>, this needs $\Omega(n\log n)$ comparisons in the worst case. An accepting decision-tree leaf for distinct keys must force a total order: incomparable keys could otherwise be made equal consistently with its strict comparison outcomes. Thus the $n!$ possible orders require different accepting leaves, giving a decision-tree depth of at least $\log_3(n!)=\Omega(n\log n)$ even for three-way comparisons.

= Comparison model
{parent=Computational complexity theory}

A model in which an algorithm learns the relative order or equality of input keys by comparisons. Lower-bound reductions must preserve the information available to each comparison; transforming numbers and allowing stronger tests without justification can change the model. For intervals $(2z_i,2z_i+1)$ built from integers, every endpoint comparison can be simulated by comparing original keys and then fixed offsets.

= Ternary comparison
{parent=Comparison model}

A single comparison returning one of three outcomes: less than, equal to, or greater than. A <comparison model> may count this as one operation even when a programming language expresses the outcomes using multiple Boolean tests. <Binary search> on ordered keys uses one such comparison per inspected position.

= Equivalence of weighted formula utility representations
{parent=Computational complexity theory}

Given two <weighted formula utility representations> with binary <rational numbers> as weights, decide whether their values agree on every <Boolean valuation>. This problem is <co-NP>-complete.

For membership, a valuation witnessing unequal values certifies non-equivalence. Evaluate all <propositional formulas> and add their weights exactly in <polynomial time>. For hardness, compare the one-rule base $\{(\theta,1)\}$ with the empty base. They are equivalent exactly when $\theta$ is an <unsatisfiable Boolean formula>. Thus even very small weighted rule bases express a universal equivalence question.

= co-NP

{c}

= coNP
{synonym}
{c}

The class of <decision problems> whose complements belong to <NP>. Equivalently, negative instances admit polynomially bounded witnesses verifiable in <polynomial time>. A problem is <co-NP>-complete when it is in <co-NP> and every problem in <co-NP> has a <polynomial-time reduction> to it. Unsatisfiability of a <propositional formula> is a basic example: its complement is the <NP>-complete <Boolean satisfiability problem>.

= Query complexity
{parent=Computational complexity theory}
{title2=$Q(f)$}

The number of accesses to an unknown input needed to solve a specified task. The input might be a string with individually readable entries, or an implicitly supplied function. A complete statement specifies deterministic, randomized, or quantum access, the accepted error, and worst-case or expected cost. <Quantum query complexity> permits coherent input access through a <quantum oracle>.

= Identification of a unique essential variable
{parent=Query complexity}
{title2=$d+\lceil\log_2n\rceil\text{ queries suffice}$}

Suppose an unknown <function> on $\{1,\ldots,d\}^n$ has exactly one <essential variable>. Query the diagonal inputs $(t,\ldots,t)$ to find two coordinates values $a,b$ giving distinct outputs; at most $d$ <function-evaluation oracle> calls suffice because the unary dependence is nonconstant. A query taking value $b$ on an index subset $H$ and $a$ outside it then tests whether the essential coordinate lies in $H$. Repeated halving locates it in at most $\lceil\log_2n\rceil$ further queries. If $n=1$, no query is needed.

For a matching lower bound with fixed $d$, restrict to $f^{(i)}(x)=1$ when $x_i=1$ and $2$ otherwise. Every query has only two possible replies. A binary <decision tree> distinguishing the $n$ possible essential indices needs at least $n$ leaves and depth $\lceil\log_2n\rceil$. <Integer> outputs in the unrestricted problem need not be binary; the restricted family is what makes this <query complexity> argument valid.

= Classical query complexity of linear Boolean function identification
{parent=Query complexity}
{title2=$D(n)=n$}

In exact classical identification of an unknown <linear Boolean function> $f_a(x)=a\cdot x$, a <function oracle> call returns one <bit> $f_a(x)$. The <query complexity> is exactly $n$ for $n\ge1$. Queries on the <standard basis> inputs $e_j$ reveal $a_j$, proving sufficiency. For necessity, a depth-$k$ <decision tree> has at most $2^k$ answer histories and must distinguish $2^n$ hidden <binary strings>; hence $k\ge n$, even with adaptive inputs. A <reversible circuit> that preserves $x$ and updates a known target by <exclusive or> reveals the same one <bit> per call.

There is also a useful <linear algebra> proof. Along a fixed history, the chosen inputs form the rows of a <matrix> $M$ over the two-element <finite field>, and the replies specify $Ma$. If there are $k<n$ queries, the <rank-nullity theorem> gives a nonzero <vector> $v$ with $Mv=0$. Then $a$ and $a+v$ give identical replies throughout this history. This also explains why adaptive choices cannot evade the bound: equal earlier replies force the same later choices.

= Communication complexity
{parent=Computational complexity theory}
{wiki}

Communication complexity studies how much information distributed parties must exchange to compute a function of their separately held inputs. Local computation is free; the resource being counted is communicated bits or qubits, with the allowed shared randomness, <quantum entanglement> or other correlations specified separately. For a <Boolean function> $f(x,y)$, a one-way exact protocol has the receiver output $f$ correctly for every input after a single message. <One-bit computation using Popescu–Rohrlich boxes> shows that this resource measure changes drastically if ideal superquantum boxes are available.

= Entanglement-assisted promised equality protocol
{parent=Communication complexity}
{title2=$\langle\Omega|\Omega_{xy}\rangle=1-2d_H(x,y)/n$}

For even positive $n$, share the <maximally entangled state> $|\Omega\rangle=n^{-1/2}\sum_{i=0}^{n-1}|ii\rangle$. Each party applies a <phase oracle> from its input <binary string>, producing $|\Omega_{xy}\rangle=n^{-1/2}\sum_i(-1)^{x_i+y_i}|ii\rangle$. Its overlap with $|\Omega\rangle$ is the displayed expression because the <Hamming distance> counts exactly the negative signs. Under the promise $d_H(x,y)\in\{0,n/2\}$, the output either equals $|\Omega\rangle$ or is <orthogonal> to it. Sending one subsystem lets the receiver distinguish the cases with the <projective measurement> $\{|\Omega\rangle\langle\Omega|,I-|\Omega\rangle\langle\Omega|\}$. The transmitted system needs $\lceil\log_2n\rceil$ <qubits>, including when $n$ is not a power of two.

= Promise problem
{parent=Computational complexity theory}

A <promise problem> consists of disjoint sets of YES and NO instances. An algorithm or verifier must obey its correctness guarantees only on their union. Energy problems with separated thresholds are naturally <promise problems> because intermediate-energy instances require no prescribed answer.

= Quantum complexity theory
{parent=Computational complexity theory}
{wiki}

Quantum complexity theory studies resources needed by <quantum circuits> and quantum algorithms, including time, workspace, and <quantum query complexity>. Its models specify which input oracles and gate implementations are available; counting oracle calls is different from counting all elementary gates.

= BQP
{c}
{parent=Quantum complexity theory}
{title2=$\mathsf{BQP}$}

<BQP> is the class of <promise problems> decided by uniform polynomial-size <quantum circuits> with bounded error. Completeness $2/3$ and soundness $1/3$ are conventional; <BQP error reduction> shows that other fixed separated thresholds give the same class.

= BQP error reduction
{c}
{parent=BQP}

Independent runs of a <BQP> algorithm with fresh <ancilla qubits> can be combined by a classical threshold rule. If completeness exceeds soundness by $\gamma$, a <Hoeffding inequality> bounds the error after $r$ runs by $e^{-r\gamma^2/2}$. Polynomial repetition handles inverse-polynomial gaps. This does not automatically preserve the restricted gate and measurement rules of a <stoquastic circuit>.

= Quantum witness
{parent=Quantum complexity theory}
{title2=$|w\rangle\in(\mathbb C^2)^{\otimes m}$}

A <quantum witness> is a polynomial-size <quantum state> supplied to a verifier as evidence for a YES instance. The verifier fixes its own <ancilla qubits> independently. Pure <quantum witnesses> suffice when maximizing a linear acceptance functional on <density operators>. <Quantum witnesses> are not generally restricted to basis vectors or product states.

= StoqMA
{c}
{parent=Quantum complexity theory}
{title2=$\mathsf{StoqMA}(a,b),\quad1/2\leq b<a\leq1$}

<StoqMA> is a restricted quantum-verifier class using <stoquastic circuits> and polynomial-size <quantum witnesses>. A YES instance has a <quantum witness> accepted with probability at least $a$; on a NO instance every <quantum witness> has acceptance at most $b$, with an inverse-polynomial gap $a-b$. An optimal <quantum witness> can be chosen with nonnegative amplitudes, since the <witness acceptance operator> is entrywise nonnegative. The <quantum witness> is generally a superposition, rather than a <computational basis> vector. The <stoquastic acceptance floor> explains the lower limit $b\geq1/2$ for a nontrivial soundness promise.

= QMA
{parent=Quantum complexity theory}
{c}

<QMA> is the class of <promise problems> with a polynomial-size quantum witness checked by a uniform polynomial-size <quantum circuit>. YES instances have an accepting witness with probability at least $2/3$; NO instances have acceptance at most $1/3$ for every witness, including mixed states. The verifier's acceptance is linear in the witness <density operator>. Inverse-polynomial or exponentially small error can be obtained through <QMA error reduction>.

= Witness acceptance operator
{parent=QMA}
{title2=$F=J^\dagger U^\dagger\Pi UJ$}

For <quantum witness> embedding $J$, verifier unitary $U$ and accepting projector $\Pi$, the <witness acceptance operator> is the positive contraction $F=J^\dagger U^\dagger\Pi UJ$. The maximum acceptance over normalized <quantum witnesses> is $\lambda_{\max}(F)$ by the <Rayleigh quotient>. Restricting to basis <quantum witnesses> only tests its diagonal entries and need not find that maximum.

= Trace-power witness optimization
{parent=Witness acceptance operator}
{title2=$\lambda_{\max}(F)^d\leq\operatorname{Tr}(F^d)\leq D\lambda_{\max}(F)^d$}

For a positive <witness acceptance operator> on dimension $D$, large trace powers approximate its largest <eigenvalue>. With an $m$-qubit <QMA> <quantum witness> and $d=2m+2$, the usual NO instances give $\operatorname{Tr}(F^d)<2^{-d}$ and YES instances give a value above $2^{-d}$. A closed product-index expansion computes the trace by recomputation with polynomial storage, avoiding logarithms and roots in a real-arithmetic implementation.

= QMA error reduction
{parent=QMA}
{c}
{title2=$\epsilon\leq(2\sqrt2/3)^r$}

Starting from completeness $2/3$ and soundness $1/3$, run an odd number $r$ of parallel copies and take majority. The <QMA parallel repetition with entangled witnesses> argument proves soundness for arbitrary repeated witnesses. Exponential <Markov's inequality> gives majority error at most $(2\sqrt2/3)^r$. Hence $O(\log(1/\epsilon))$ copies suffice for error $\epsilon$, with polynomial overhead when the target error is inverse-polynomial or exponentially small in input length.

= QMA parallel repetition with entangled witnesses
{parent=QMA}
{c}

Independent verifier circuits on $r$ witness registers induce a threshold acceptance effect built from tensor products of $M$ and $I-M$, where $M$ is the <quantum verifier acceptance operator>. In a product eigenbasis of $M$, the effect's <eigenvalues> are threshold probabilities for independent <Bernoulli random variables> with parameters given by the selected eigenvalues of $M$. Bounding every parameter on a NO instance bounds the effect's <operator norm>, even if the actual submitted witness is entangled. Independence is used only for the spectral calculation, not assumed for the witness.

= Quantum verifier acceptance operator
{parent=QMA}
{title2=$M=(I\otimes\langle0|)V^\dagger\Pi_{\rm acc}V(I\otimes|0\rangle)$}

A verifier with clean ancillas and a designated output measurement induces an effect $0\leq M\leq I$ on the witness register. Its acceptance probability is $\operatorname{Tr}(M\rho)$, and the largest possible acceptance is $\|M\|$. Spectral bounds on $M$ make the soundness quantifier over all witnesses, including entangled repeated witnesses, explicit.

= Quantum query complexity
{parent=Quantum complexity theory}

The quantum query complexity of a task counts uses of an input oracle by a <quantum circuit>, for a specified success probability. Known gates and workspace operations are not counted as oracle queries, although they contribute to the circuit's full runtime. An efficient query bound therefore need not, by itself, be an efficient gate bound.

= Quantum oracle
{parent=Quantum query complexity}
{title2=$U_f|x,y\rangle=|x,y\oplus f(x)\rangle$}

A <quantum oracle> supplies coherent access to a function through a specified <unitary operator>. For a function with <binary string> output, the standard construction retains the input and adds the output into an answer <quantum register> by bitwise <exclusive or>. This operation is its own inverse, even when the function is not <injective>. A <Boolean quantum oracle> is the single-output-bit case; <Simon's algorithm> uses several answer <qubits>. Other encodings, such as a <modular-addition quantum oracle> or a <phase gate> encoding, require their own explicit query conventions.

= Phase oracle
{parent=Quantum oracle}
{title2=$O_f|x\rangle=(-1)^{f(x)}|x\rangle$}

A phase oracle encodes a <Boolean function> in the signs of <computational basis> states. Its diagonal entries have <modulus> one, so it is a <unitary operator>. The usual convention $O_f$ changes the sign when $f(x)=1$. A complemented convention $U_f|x\rangle=(-1)^{f(x)\oplus1}|x\rangle$ instead changes the sign when $f(x)=0$, with $U_f=-O_f$; $\oplus$ denotes <exclusive or>. The two conventions differ by a <global phase> when used without coherent control, but the <global phase of a controlled quantum gate> makes that difference observable when the <quantum oracle> is controlled.

= One-query constancy obstruction for phase oracles
{parent=Phase oracle}
{title2=$M>2\implies Q_E(\text{constancy};\text{phase oracle})>1$}

An unrestricted <Boolean function> on $M>2$ inputs cannot be classified as constant or nonconstant with certainty using a single <phase oracle> query, even with <quantum ancillas>. Write a purified query input as $|\Psi\rangle=\sum_x|x\rangle|a_x\rangle$ with $p_x=\|a_x\|^2$ and $\sum_xp_x=1$. The zero <constant function> leaves it unchanged; the function supported only at $j$ produces a vector with <inner product> $1-2p_j$ with it. <Perfect discrimination of pure states requires orthogonality>, forcing $p_j=1/2$ for all $j$ and thus $M=2$, a contradiction. This is an <exact quantum query complexity> obstruction for all nonconstant inputs, rather than the restricted promise used by the <Deutsch-Jozsa algorithm>.

= Polynomial method for quantum query lower bounds
{parent=Quantum query complexity}
{title2=$\deg(f)\le2Q_E(f)$}

After $T$ input-bit queries, every <probability amplitude> is a <polynomial> of degree at most $T$, because the bit-query matrix entries are affine in the input bits. An acceptance <probability> is a sum of squared absolute amplitudes and has <polynomial degree> at most $2T$. <Multilinear reduction on the Boolean cube> does not increase degree. Exact acceptance therefore implies $Q_E(f)\ge\lceil\deg(f)/2\rceil$. For bounded error the acceptance polynomial only approximates the <Boolean function>; its exact representing degree is not the relevant bound.

= Exact quantum query complexity
{parent=Quantum query complexity}
{title2=$Q_E(f)$}

The least worst-case number of input-oracle calls made by a <quantum circuit> that computes a <Boolean function> with zero error on every input. Known <unitary gates> and classical processing do not count toward this quantity; their runtime is a separate cost.

= Exact two-query majority algorithm
{parent=Exact quantum query complexity}
{title2=$Q_E(\operatorname{MAJ}_3)=2$}

One exact parity query determines whether the first two bits agree. If they agree, a second query reads one of them; otherwise it reads the third bit. Those values respectively determine the three-bit <majority function>. The matching lower bound follows from its degree-three <multilinear polynomial>.

= Quantum collision finding
{parent=Quantum query complexity}

Given a <function> $f$ with an $m$-bit output, accessed through the <unitary operator> $U_f|x\rangle|y\rangle=|x\rangle|y\mathbin\oplus f(x)\rangle$, quantum collision finding asks for distinct inputs with equal outputs. Here $\oplus$ is bitwise <exclusive or> on the $m$-bit answer <quantum register>. The distinctness requirement excludes the uninformative pair $(x,x)$. For a two-to-one function on $N$ inputs, <Grover search algorithm> methods yield a cube-root <quantum query complexity>, despite a square-root cost for finding a partner of just one preselected input.

= Brassard–Høyer–Tapp collision algorithm
{c}
{parent=Quantum collision finding}
{title2=$O(N^{1/3})$}

Query a known set of $m$ inputs and store its output table. If no <function collision> occurs there, each of its $m$ distinct outputs has exactly one partner in the complement, for a two-to-one function. A <compute-phase-uncompute construction> marks those partners using two function queries and reversible table comparison. <Known-subset Grover search> then uses $O(\sqrt{(N-m)/m})$ such phase queries. Including table preparation and a final verification query gives
$$
T(m)=m+O\!\left(\sqrt{\frac{N-m}{m}}\right)+1.
$$
Choosing $m\asymp N^{1/3}$ balances both terms and gives $T(m)=O(N^{1/3})$. The <Grover rotation angle> rounding bound gives success tending to one. This is a query bound; it does not make reversible table lookup free in a gate or physical-memory cost model.

= Decision tree model
{parent=Computational complexity theory}
{wiki}

The decision tree model computes a function by adaptively querying input coordinates.

= Decision tree
{parent=Decision tree model}

= Deterministic Boolean query algorithm
{synonym}

A <decision tree> represents a <deterministic computation> of a known <Boolean function> $f:\{0,1\}^n\to\{0,1\}$ by inspecting <input> <bits>. Each internal <vertex> of its <binary tree> names a coordinate $i$ to query, its two outgoing <edges> carry answers 0 and 1, and each leaf carries the <output> 0 or 1. Starting at the <root of a tree>, read the named <bit>, follow its answer <edge>, and repeat until a leaf is reached. Correctness requires the leaf's label to equal $f(x)$ for every <input> $x$.<Complexity Measures and Decision Tree Complexity: A Survey by Harry Buhrman and Ronald de Wolf>[Buhrman and de Wolf, Complexity Measures and Decision Tree Complexity: A Survey, section 3.1, manuscript p. 5: deterministic trees and D(f)]{ref}

The next coordinate, or the decision to stop, can depend on earlier answers: this is adaptive querying. The same <input> always follows the same <graph path>; adaptivity does not require randomness. A correct leaf must have the same <output> for every completion of the observed <bits>. Thus a <decision tree> can stop as soon as the observations form a <query certificate>. Querying an already known coordinate adds no information, so we use <decision trees> without repeated coordinates on a <graph path>; an efficient tree also removes queries made after the <output> is already forced.

The motivation is exact computation with shortcuts. If inspecting an <input> entry is expensive, the question is how much of the <input> must actually be read. The <decision-tree query cost> counts these inspections, while local calculations on known values are free in this model; this cost need not equal an implementation's <time complexity>. Here the <Boolean function> is specified in advance and must be computed exactly on every <input>. <Decision tree learning> instead fits a predictor from data, with a different objective.

= Three-bit majority decision tree
{parent=Decision tree}
{title2=$\operatorname{MAJ}_3$}

Three votes give a small but revealing <majority function>:
$$
m(x_1,x_2,x_3)=\begin{cases}1,&x_1+x_2+x_3\geq2,\\0,&x_1+x_2+x_3<2.\end{cases}
$$
Our <decision tree> queries $x_1$, then $x_2$. If these <bits> agree, return their common value: two equal votes already force the <majority function>. If they disagree, query $x_3$ and return its value. The first two queries have a fixed order, but whether a third query occurs is adaptive.

= Parity lower bound for Boolean queries
{parent=Decision tree}
{title2=$D(\operatorname{PARITY}_n)=n$}

For three <bits>, the <Boolean function> $p(x)=x_1\mathbin\oplus x_2\mathbin\oplus x_3$ outputs one when $x_1+x_2+x_3$ is odd, where $\oplus$ denotes <exclusive or>. Unlike the <three-bit majority decision tree>, an exact <decision tree> computing <parity> must inspect all three <bits> on every <input>. If any coordinate is unread, two completions differing only at that coordinate follow the same observed <graph path> but have opposite <parity>. A single leaf cannot correctly label both.

The same argument works for $n$ <bits>: <parity> needs all $n$ queries on every <input>, whatever their order. Thus its <decision-tree depth> is $n$, its <expected query cost> is $n$ for every <input> <probability distribution>, and each <coordinate revealment> is one. The algorithm remains required to be correct on the whole <Boolean cube>, even if the chosen <probability distribution> assigns some <inputs> zero <probability>; a promise restricting permitted <inputs> would be a different <computational problem>.

= Decision-tree query cost
{parent=Decision tree}
{title2=$q_T(x)$}

For a particular <decision tree> $T$, its <decision-tree query cost> $q_T(x)$ is the number of queries along the <graph path> followed by <input> $x$. Its actual tree depth is
$$
h(T)=\max_{x\in\{0,1\}^n}q_T(x).
$$
The query <vertices> count as operations; each is followed by one answer <edge>. Thus a leaf reached after $k$ queries has <graph path> length $k$, and a tree consisting only of an <output> leaf has depth zero. With no repeated coordinates, $0\leq q_T(x)\leq n$. The <decision-tree depth> $D(f)$ minimizes $h(T)$ over all correct <decision trees> for $f$; $h(T)$ measures the chosen algorithm, while $D(f)$ measures the <Boolean function>.

Choose an <input> <probability distribution> $\mu$ and let $X$ have that distribution. Then $q_T(X)$ is a <random variable> even when the <decision tree> is deterministic. Its <probability mass function> describes how often each path length occurs, and its <expected value> is the <expected query cost>. None of these quantities changes the actual maximum depth of $T$.

= Expected query cost
{parent=Decision-tree query cost}
{title2=$\mathbb E_\mu[q_T(X)]$}

For a fixed <decision tree> $T$ and <input> <probability distribution> $\mu$, its <expected query cost> is
$$
\mathbb E_\mu[q_T(X)]=\sum_{x\in\{0,1\}^n}\mu(x)q_T(x).
$$
Under the <discrete uniform distribution> on the eight three-<bit> <inputs>, the <three-bit majority decision tree> has
$$
\Pr(q_T(X)=2)=\Pr(q_T(X)=3)=\frac12,\qquad \mathbb E[q_T(X)]=2\cdot\frac12+3\cdot\frac12=\frac52=2.5.
$$
This is an exact average, not a fractional query made during one execution. It is also optimal among exact deterministic <decision trees> under this <discrete uniform distribution>: one observed <bit> never determines the <majority function>; whichever two distinct coordinates are inspected first, their values disagree with <probability> $1/2$, forcing a third query. In comparison, querying all three <bits> unconditionally has the same actual depth three but <expected query cost> three.

For an arbitrary <input> <probability distribution>, the same fixed <three-bit majority decision tree> gives $\mathbb E_\mu[q_T(X)]=2+\Pr_\mu(X_1\ne X_2)$. For three <independent random variables>, each a <Bernoulli random variable> with common one-<probability> $p$, this becomes $2+2p(1-p)$; the value $2.5$ depends on $p=1/2$. Averaging over <inputs> should also be distinguished from averaging over an algorithm's internal random choices at a fixed <input>.<Every decision tree has an influential variable by Ryan O'Donnell and others>[O'Donnell, Saks, Schramm and Servedio, Every decision tree has an influential variable, sections 1.1–1.2, pp. 1–2: worst-input expected randomized cost R(f) versus input-distribution average Δ(T)]{ref}

= Coordinate revealment
{parent=Decision-tree query cost}
{title2=$\delta_i(T,\mu)$}

The <coordinate revealment> of coordinate $i$ for a <decision tree> $T$ under <input> <probability distribution> $\mu$ is
$$
\delta_i(T,\mu)=\Pr_{X\sim\mu}(T\text{ queries coordinate }i).
$$
It depends on the chosen <decision tree> and the <probability distribution>, not just on the <Boolean function>. Since no coordinate is queried twice on a <graph path>, <indicator functions> give
$$
q_T(X)=\sum_{i=1}^n\mathbf 1_{\{T\text{ queries }i\}},\qquad \mathbb E_\mu[q_T(X)]=\sum_{i=1}^n\delta_i(T,\mu).
$$
The second equality uses <linearity of expectation>; it does not require <independence of random variables> or a <product measure>. The cited paper defines these inspection <probabilities> and their sum for <product measures>; the displayed <indicator function> argument extends the identity to any <input> <probability distribution>.<Every decision tree has an influential variable by Ryan O'Donnell and others>[O'Donnell, Saks, Schramm and Servedio, Every decision tree has an influential variable, section 1.2, p. 2: δ_i(T) and Δ(T); section 3.1, p. 6: distinct coordinates along each root–leaf path]{ref}

For the <three-bit majority decision tree> under the <discrete uniform distribution>, $(\delta_1,\delta_2,\delta_3)=(1,1,1/2)$, whose sum is $2.5$. Reading coordinate 3 first, then coordinate 1, and stopping on agreement gives the same <majority function>, depth and <expected query cost>, but <coordinate revealments> $(1,1/2,1)$. The asymmetry belongs to the chosen query order. <Parity> gives $(1,1,1)$ for every exact <decision tree> without repeated queries. If repeated queries were charged, inspection <probabilities> would count distinct coordinates; total query count would instead require expected multiplicities.

= Decision-tree depth
{title2=$D(f)$}
{parent=Decision tree}

The <decision-tree depth> $D(f)$ of a <Boolean function> $f$ is the smallest possible maximum number of <input> coordinates queried along any root-to-leaf <graph path> of a <decision tree> computing $f$:
$$
D(f)=\min_{T\text{ computes }f}\max_{x\in\{0,1\}^n}q_T(x)=\min_{T\text{ computes }f}h(T).
$$
The actual depth $h(T)$ of a particular <decision tree> can exceed this optimum. A <constant function> admits a depth-zero tree even though an inefficient algorithm could inspect its entire <input> before returning that constant. <Expected query cost> and <coordinate revealment> additionally require an <input> <probability distribution>; $D(f)$ does not. The <three-bit majority decision tree> and three-<bit> <parity> both have optimal <decision-tree depth> three, although only the former has the two-query shortcuts described above.

= Certificate complexity of a Boolean function
{parent=Decision-tree depth}
{title2=$C(f)=\max_x\min\{|S|:S\text{ certifies }f(x)\}$}

= Query certificate complexity
{synonym}

A <query certificate> fixes some input coordinates to their values in a chosen input and must force the output for every completion. The smallest such size is $C(f,x)$; maximizing over accepted or rejected inputs gives $C_1(f)$ or $C_0(f)$, and maximizing both gives $C(f)$. A one-sided maximum over an empty output class is defined as zero. This is <query certificate> complexity, distinct from polynomial verification of a witness in <NP>.

= Query certificate
{parent=Certificate complexity of a Boolean function}
{title2=$S\subseteq\{1,\ldots,n\}$}

For a <Boolean function> $f$ and a chosen input $x$, a set of coordinates $S$ is a <query certificate> if every $y$ agreeing with $x$ on $S$ has $f(y)=f(x)$. It fixes actual input bits rather than supplying an independently guessed <certificate (complexity)> to an NP verifier. Minimizing its size at each input and then maximizing gives <query certificate complexity>.

= Evasive Boolean function
{parent=Decision-tree depth}
{title2=$D(f)=n$}

A <Boolean function> is evasive when every deterministic <decision tree> computing it has a worst-case path that queries all input bits. The <alternating-sum criterion for decision-tree evasiveness> is one sufficient method for proving this lower bound.

= Alternating-sum criterion for decision-tree evasiveness
{parent=Evasive Boolean function}
{title2=$\sum_x(-1)^{\operatorname{wt}(x)}f(x)\ne0\Longrightarrow D(f)=n$}

A leaf reached before all $n$ input bits are queried leaves at least one coordinate free. Flipping that coordinate pairs its inputs with opposite alternating signs and equal output. Thus every such leaf contributes zero. If the total alternating sum is nonzero, a depth below $n$ is impossible.

= Decision-tree adversary for a threshold function
{parent=Decision-tree depth}

To prove that a threshold function requires every input bit in the worst case, an adversary answers queries while keeping completions on both sides of the threshold possible. If this remains true until the final unqueried bit, every decision tree has depth equal to the number of variables.

A <search problem> whose states are words of fixed length, with a transition changing exactly one letter and requiring the resulting word to belong to a specified dictionary. Dictionary restrictions may force a longer solution or make the target unreachable.

= Goal state
{parent=Search problem}

A state satisfying a problem's <goal test>. Whether its generation or its later selection terminates a <search algorithm> affects optimality for algorithms such as <A-star search>. A <goal state>'s remaining optimal cost is zero, whereas its accumulated <path cost> need not be zero.

= Path cost
{parent=Search problem}
{title2=$g(n)=\sum_{e\in\operatorname{path}(n)}c(e)$}

The sum of step costs along the action history represented by a <search node>. Positive costs give lower bounds on <search depth>, and the same physical state can have different <path costs> when reached along different histories. <Uniform-cost search> orders by accumulated cost; <A-star search> adds an estimate of remaining cost.

= Step cost
{parent=Path cost}
{title2=$c(s,a,s')$}

A <step cost> is the cost of one action or transition in a <search problem>. The accumulated <path cost> is the <sum> of the <step costs> along its action history. A uniform positive lower bound on <step costs> makes every bounded-cost action history have bounded <search depth>; positivity of each individual term alone does not establish such a bound.

= Adversarial search
{parent=Search problem}

Exploration of a <game tree> containing choices by competing decision makers. A maximizing node chooses the largest successor value; a minimizing opponent chooses the smallest. Known random outcomes instead require chance nodes and <expected values>, as in <expectimax>. A <game tree> representation can combine controlled choices and chance without assuming that chance maliciously chooses its worst outcome.

= Expectiminimax
{parent=Adversarial search}

= Expectminimax
{synonym}

<Backward induction> on a finite <game tree> containing maximizing choices, minimizing choices and <chance nodes>. Terminal <utilities> are backed up by $\max$, $\min$ and $\sum_jp_jV_j$, respectively. Exact <chance node> evaluation generally needs every positive-<probability> outcome; ordinary <alpha-beta pruning> does not transfer unchanged because one child's value does not bound the full weighted sum.

= Expectimax
{parent=Adversarial search}

A <game tree> evaluation rule using maxima at the controlled player’s decision nodes and <expected values> at chance nodes:
$$
V(s)=\max_a V(T(s,a)),\qquad V(s)=\sum_{s'}P(s'\mid s)V(s'),
$$
respectively. Terminal <utilities> fix the boundary values. These rules exactly optimize a finite-horizon <expected utility> objective by <backward induction>. For cyclic infinite-horizon reachability problems, a finite <Markov decision process> formulation and <value iteration> replace naive expansion of an infinite <game tree>. Start with one at successful terminal states and zero elsewhere, keep terminal values fixed, and apply the maximizing/expectation backups repeatedly. The $t$th iterate is the greatest success <probability> achievable within $t$ transitions, by <backward induction>. These values are nondecreasing and bounded by one. For every policy, eventual success is the increasing <set union> of success within finite horizons, so its <probability> is the <limit> of those finite-horizon <probabilities>. Taking the supremum over policies and horizons in either order proves that the iterates converge to the optimal eventual-success <probability>. The limiting fixed-point equations can also admit larger solutions, so the initialization from terminal-success indicators matters.

= Simultaneous rendezvous distance
{parent=Search problem}
{title2=$\lceil d(p,q)/2\rceil$}

Two controlled walkers on the same connected <undirected graph> can each traverse one <edge> or wait in each unit-cost step. If they meet only by occupying the same <vertex> at the same time, their minimum meeting time is
$$
\left\lceil\frac{d(p,q)}2\right\rceil,
$$
where $d$ is the <shortest path> distance. A common meeting point after $t$ steps implies $d(p,q)\le2t$ by the <triangle inequality>. Conversely, choose a middle <vertex> of a shortest connecting <graph path>; both walkers reach it within $\lceil d/2\rceil$ steps, and the earlier arrival waits. The wait is essential when the path length is an <odd integer>. This distance on the joint <Cartesian product> <state space> is a <consistent heuristic>: each joint move changes the walkers’ separation by at most two. Replacing $d$ by an obstacle-free <Manhattan distance> preserves <admissible heuristic> and <consistent heuristic> guarantees.

= Partially observable search
{parent=Search problem}

A <search problem> in which the available observations need not identify the current physical state. The controller must choose the same action for physical states that its observed history cannot distinguish. A <belief state> summarizes those possibilities; <contingent planning> selects future actions according to subsequent observations.

= Sensorless planning
{parent=Partially observable search}

= Conformant planning
{synonym}

<Sensorless planning> chooses one action <sequence> that succeeds from every possible initial physical state without receiving distinguishing observations during execution. A <belief state> is a <set> of possibilities. For a deterministic <search transition model> $T$, an applicable action maps $B$ to $\{T(s,a):s\in B\}$; for nondeterministic outcomes, take the <union> of all possible successors. Applicability must hold for every member of $B$, and success requires the resulting <belief state> to be a <subset> of the physical goal <set>.

Every fixed action <sequence> preserves inclusion of the initial <belief states>. Consequently, a successful <plan> for $B$ also succeeds for every <subset> of $B$. Success on a <superset> is an additional requirement, so cannot be inferred from success on $B$ alone. This property supports <incremental belief-state search>.

= Incremental belief-state search
{parent=Sensorless planning}

An <incremental belief-state search> initially plans for a small <subset> $B_0$ of the possible initial states, then tests the candidate <plan> on the full initial <belief state> $B$. If a state in $B$ makes an action inapplicable or fails the final <goal test>, add that counterexample to $B_0$ and solve the enlarged problem. The new search may need to revise the entire <plan>, rather than append actions to the previous candidate.

With finitely many initial states and a complete finite-model solver for each restricted problem, at most $|B|$ state additions are required. Failure to find a <plan> even for a restricted <subset> proves that none can work for the whole <belief state>. A candidate that passes full validation is a genuine <plan> for <sensorless planning>. The advantage is selective tracking: a small number of representative initial states may force a universally successful <plan> without constructing the full <power set> search space.

= Belief state
{parent=Partially observable search}
{title2=$B\subseteq S$}

Without a prior <probability distribution>, a belief state is the <set> of physical states still compatible with an observed history. If the physical <search transition model> is deterministic, $T(s,a)$, and the sensor map is $O$, action $a$ followed by observation $o$ gives
$$
B'_{a,o}=\{T(s,a):s\in B,\ O(T(s,a))=o\}.
$$
For a <set>-valued outcome relation, replace the image by the <set union> of all possible successors before filtering. A guaranteed-success <goal test> requires every member of the surviving <belief state> to satisfy the physical goal. A probabilistic belief is instead a posterior <probability distribution>, requiring a specified prior and observation law.

= Relaxation heuristic
{parent=Search problem}

A <heuristic function> obtained by solving an easier problem that permits every original transition and possibly additional ones, with original transitions costing no more in the easier problem. Every original solution remains available, so the easier optimum is an <admissible heuristic>.

If $h$ is the exact distance to the relaxed goal set, each original transition also gives $h(s)\le c(s,a,s')+h(s')$ by taking that transition and then a relaxed optimal continuation. Thus this construction gives a <consistent heuristic> when original goals have relaxed distance zero. For a four-direction grid walk, deleting obstacles gives <Manhattan distance>; deleting a pursuer's capture constraint supplies another relaxation. The resulting estimate can remain finite when the original goal is unreachable.

= Abstraction heuristic
{parent=Relaxation heuristic}
{title2=$h_{\mathrm{abs}}$}

Map original states to simpler abstract states, include every projected original transition at no greater cost, and map original goals to abstract goals. An original goal-reaching <graph path> then projects to an abstract goal-reaching walk, so the exact abstract distance is an <admissible heuristic>. A <pattern database> stores such distances for repeated lookup.

= Pattern database
{parent=Abstraction heuristic}

A table of precomputed exact abstract goal distances used as an <abstraction heuristic>. Retaining a subset of the disks of a <Tower of Hanoi> instance gives a smaller abstract puzzle: moving an ignored disk does not change the abstract state, and moving a retained disk projects to a legal abstract move. Taking maxima of <pattern database> estimates preserves admissibility; summing them requires an additional cost-partition argument.

= Delete-relaxation heuristic
{parent=Relaxation heuristic}
{title2=$h^+$}

For positive-precondition <STRIPS> with a positive conjunctive goal, remove every delete effect and use the exact shortest relaxed <plan> cost. Every original <plan> still succeeds in the relaxed model because facts can only accumulate, so its relaxed optimum is an <admissible heuristic>. The cost of an arbitrary relaxed <plan> is an upper bound on the relaxed optimum and need not be an <admissible heuristic> for the original problem.

= Consistent heuristic
{parent=Search problem}
{title2=$h(s)\le c(s,a,s')+h(s')$}

A <heuristic function> is consistent if $h(g)=0$ at every goal and
$$
h(s)\le c(s,a,s')+h(s')
$$
for every permitted transition $s\xrightarrow{a}s'$ with step cost $c(s,a,s')$. Summing these inequalities along a finite route to a goal gives $h(s)\le$ its total cost. Taking the minimum over such routes proves that every <consistent heuristic> is an <admissible heuristic>.

= Admissible heuristic
{parent=Search problem}
{title2=$h(s)\le h^*(s)$}

A <heuristic function> bounded above by the minimum remaining goal cost $h^*(s)$. When no goal is reachable, take $h^*(s)=\infty$. Admissibility is a lower-bound guarantee, rather than a statement that the estimate is usually numerically accurate. Ignoring constraints can produce a <relaxation heuristic> because it enlarges the available solution set.

= Admissible heuristic combination
{parent=Admissible heuristic}

If $h_1,h_2\le h^*$, their pointwise minimum, pointwise maximum and each <convex combination> $\alpha h_1+(1-\alpha)h_2$ with $0\le\alpha\le1$ are <admissible heuristics>. Each inequality follows directly by comparison with $h^*$. The maximum has <heuristic dominance> over the minimum and every such <convex combination>.

A sum need not be an <admissible heuristic>: two exact estimates of the same cost-one remaining action sum to two. A sufficient condition for a valid additive construction is separate nonnegative action-cost allocations $c_1,c_2$ with $c_1+c_2\le c$, and estimates bounded by the corresponding optimal allocated costs. Every goal-reaching <graph path> then costs at least $h_1+h_2$ under its original costs. Taking the minimum proves admissibility without counting the same work twice.

If $h_1,h_2$ are <consistent heuristics>, their maximum, minimum and fixed <convex combinations> are also <consistent heuristics>. For the maximum, choose an index attaining it at the source and bound its successor by the successor maximum. For the minimum, choose an index attaining it at the successor and bound the source minimum by that component. For a <convex combination>, multiply the two consistency inequalities by their nonnegative weights and add them. All these combinations vanish at goals when the inputs do.

= Heuristic function
{parent=Search problem}
{title2=$h(s)$}

A <function> estimating the remaining cost from a state $s$ to a goal in a <search problem>. The estimate is an <admissible heuristic> when it never exceeds the true minimum remaining cost. A <consistent heuristic> satisfies an additional local inequality along each permitted transition.

= Perfect heuristic
{parent=Heuristic function}
{title2=$h^*(s)$}

The exact minimum remaining <path cost> from a state to a <goal state>, with value $\infty$ when no goal is reachable. For nonnegative step costs, $h^*(g)=0$ at goals and $h^*(s)\le c(s,s')+h^*(s')$ on every transition. Thus a <perfect heuristic> is a <consistent heuristic> and an <admissible heuristic>. It measures remaining cost; a <greedy best-first search> decision using only this number can still take an excessively costly incoming <edge>.

= Ordinal heuristic comparator
{parent=Heuristic function}
{title2=$\kappa(n,m)=n\iff h^*(n)\le h^*(m)$}

A comparison oracle revealing the ordering of remaining optimal costs without returning their magnitudes. It supplies enough information for <greedy best-first search>. Its ordering alone does not provide the numerical differences needed to compare sums with independently varying accumulated costs. For $g(n)=5$, $g(m)=1$, remaining costs $(1,2)$ and $(1,10)$ have the same pairwise order but give opposite orderings of $g+h^*$.

= Heuristic dominance
{parent=Heuristic function}

A <heuristic function> $h_2$ dominates $h_1$ if $h_2(s)\ge h_1(s)$ everywhere. When both are <admissible heuristics>, the larger estimate is at least as informative for <A-star search>: for a fixed accumulated path cost $g$ and optimal solution cost $C^*$, $g+h_2<C^*$ implies $g+h_1<C^*$. This compares the compulsory search region, not arbitrary tie handling at $C^*$, evaluation overhead or wall-clock time.

= Goal test
{parent=Search problem}

A condition deciding whether a state successfully completes a <search problem>. Its timing must agree with the <search transition model>: arriving at a destination before an adversary's compulsory response need not be a successful terminal state.

= Search transition model
{parent=Search problem}

The rule giving the successor state of each permitted state-action pair in a <search problem>. A compound action may include deterministic environmental responses. If a game state is sampled at full-turn boundaries, its <search transition model> must still detect terminal events occurring inside the turn. Otherwise an intermediate failure can be incorrectly hidden by the final position. All information needed for future successors and the <goal test> must be encoded in the state or supplied as fixed problem data.

= Search tree
{parent=Search problem}

A <rooted tree> whose nodes are partial search states and whose children are possible next choices. Leaves represent completed candidates or terminated branches. <Backtracking> traverses this tree while storing the current path, and <search pruning> removes branches that cannot yield a useful completion.

= Search depth
{parent=Search tree}
{title2=$d(n)$}

The number of action edges between a <search node> and the root of its <search tree>. It is zero at the root. When every step costs more than $\epsilon>0$, a positive-depth node satisfies $g(n)>d(n)\epsilon$, connecting depth finiteness to <path cost> bounds.

= Search node
{parent=Search tree}

An entry in a <search tree> representing a particular action history. It normally stores the current state, its parent, its last action and accumulated <path cost> $g$. Distinct <search nodes> can represent the same state; identifying them changes <tree search> into a form of <graph search> and requires an appropriate repeated-state policy.

= Search frontier
{parent=Search tree}

The generated but unexpanded <search nodes> maintained by a <search algorithm>. <Best-first search> selects the next expansion from this frontier using a <priority queue> or an equivalent ordering operation. A lower-bound argument about a frontier node on an optimal path is central to <A-star search> correctness.

= Branching factor
{parent=Search tree}

The number of children of a node in a <search tree>, or an upper bound on that number over the tree. With branching factor at most $b$ and depth at most $d$, a complete traversal visits at most $1+b+\cdots+b^d$ nodes.

= Constraint satisfaction problem
{parent=Search problem}

Assign values from specified domains to variables so that all stated constraints hold simultaneously. A partial assignment can be rejected when it violates a constraint or leaves an unassigned variable with no permissible value. <Backtracking> applies this test during a <depth-first search>.

= Constraint hypergraph
{parent=Constraint satisfaction problem}

The <hypergraph> whose <vertices> are the <variables> of a <constraint satisfaction problem> and whose <hypergraph edges> are its constraint scopes. Several constraints can have the same scope. An incidence drawing uses extra scope nodes for display; these do not become extra <variables> of the original problem. Ordinary <treewidth> of a <constraint hypergraph> refers to <treewidth> of its <primal graph>, equivalently to a <tree decomposition> covering each whole scope, not to generalized hypergraph width measures.

= Primal graph
{parent=Constraint hypergraph}

The <graph> with one <vertex> per <variable> and an <edge> between distinct <variables> occurring in a common constraint scope. Each <hypergraph edge> of the <constraint hypergraph> becomes a <clique>. A <constraint satisfaction problem> consisting only of <all-different constraints> on a common <constraint domain> is exactly a <proper graph colouring> problem on this <primal graph>.

= Cardinality constraint
{parent=Constraint satisfaction problem}
{title2=$\sum_i X_i=k,\quad X_i\in\{0,1\}$}

A <cardinality constraint> restricts how many members of a specified collection are selected or satisfy a property. For <Boolean variables>, exactly $k$ selected entries gives the displayed <sum>; upper and lower bounds give at-most and at-least variants. <Constraint propagation> can maintain the number already selected and the number still available. A requirement involving many <variables> is a global constraint, even when it has a compact arithmetic description.

= Nonattacking knights problem
{parent=Constraint satisfaction problem}

Choose $k$ distinct squares of an $n\times n$ chessboard so that no chosen pair has absolute coordinate differences $(1,2)$ or $(2,1)$. One <constraint satisfaction problem> representation has $k$ square-valued <variables>, requiring distinctness and pairwise nonattack. Another has one <Boolean variable> per square, a <cardinality constraint> fixing their <sum> to $k$, and one mutual-exclusion constraint for every <edge> of the <knight attack graph>. The first has fewer <variables> when $k$ is small but represents each unlabelled placement up to $k!$ times; the second uses only binary <constraint domains> and sparse local attack restrictions.

= Knight attack graph
{parent=Nonattacking knights problem}

The <knight attack graph> has one <vertex> per chessboard square and an <edge> between squares linked by a knight move. A nonattacking placement is an <independent set>. Colouring squares by the <parity> of the coordinate <sum> makes this a <bipartite graph>, because every knight move changes that <parity>. Every <vertex> has <degree> at most eight, with fewer attacks near the boundary.

= Direct SAT encoding of finite-domain constraints
{parent=Constraint satisfaction problem}
{title2=$\varphi_P$}

Represent each original value choice $X_i=v$ by a <Boolean variable> $p_{i,v}$ and impose an <exactly-one constraint> for each original <variable>. For every forbidden tuple $(v_i)_{i\in S}$ of a constraint with scope $S$, add the <Boolean clause> $\bigvee_{i\in S}\neg p_{i,v_i}$. A complete original assignment satisfies every constraint exactly when its one-hot indicators satisfy all these <Boolean clauses>: each forbidden-tuple <Boolean clause> excludes precisely that joint choice. A <satisfying assignment> decodes by reading the unique true indicator for each original <variable>.

For <constraint domain> sizes $q_i$, pairwise uniqueness requires $\sum_i\binom{q_i}{2}$ <Boolean clauses>. If a constraint has $f_C$ forbidden tuples and arity $r_C$, its contribution is $f_C$ <Boolean clauses> and $r_Cf_C$ <literal> occurrences. Thus bounded arity gives a polynomial-size encoding in explicitly listed domains, whereas enumerating a succinct high-arity relation can be exponential in its description length. <Unit propagation> on this encoding can be weaker than <arc consistency> on the original <binary constraints>.

= Cutset conditioning
{parent=Constraint satisfaction problem}

Enumerate assignments to a <cycle cutset>, reject internal violations, filter all crossing <binary constraints>, and solve the residual <forest> by <tree-structured constraint satisfaction>. A full solution restricts to one enumerated cutset assignment; the residual tree passes preserve all its values. Conversely, a consistent cutset assignment combined with supported residual solutions satisfies every constraint. These observations prove completeness and soundness.

With $n$ <variables>, maximum <constraint domain> size $q$ and cutset size $k$, there are at most $q^k$ assignments and $O((n-k)q^2)$ residual tree work per assignment. Internal cutset and crossing-constraint tests require additional accounting. The method is attractive when a small <cycle cutset> is available.<CS 188 constraint ordering and structure notes>[§2.4.1, Structure, cutset conditioning]{ref}

= Degree heuristic
{parent=Constraint satisfaction problem}

Choose an unassigned <variable> constrained to the greatest number of other unassigned <variables>. This is commonly a tie-breaker after <minimum remaining values>. The relevant <vertex degree> is computed in the remaining <constraint graph>, rather than counting neighbors already assigned. It aims to make each decision constrain many future decisions without changing the solution <set>.

= Unary constraint
{parent=Constraint satisfaction problem}

A restriction on the value of one <variable>. In a finite-domain <constraint satisfaction problem>, it can be applied by deleting disallowed values from that <variable>'s <constraint domain> before search. It introduces no <edge> in the binary <constraint graph>.

= Hidden-variable encoding
{parent=Constraint satisfaction problem}

Replace a finite many-variable relation $R(X_1,\ldots,X_k)$ by one auxiliary <variable> $Y$ whose domain is the allowed tuples of $R$, together with <binary constraints> equating each tuple coordinate to its corresponding $X_i$. Any original satisfying assignment extends to exactly its allowed tuple, and any satisfying encoded assignment projects to a solution of $R$. The tuple domain can be large; the transformation changes arity, not necessarily representation size efficiently when $R$ is succinct.

= N-queens problem

= N-queen problem
{synonym}
{c}

Place $N$ queens on an $N\times N$ chessboard so that none share a row, column or diagonal. One <constraint satisfaction problem> encoding uses a column variable $C_r\in\{1,\ldots,N\}$ for each row, with $C_r\ne C_s$ and $|C_r-C_s|\ne|r-s|$ whenever $r\ne s$. = Queens completion problem
{parent=N-queens problem}

Complete a prescribed subset of occupied cells to a solution of the <N-queens problem> while retaining every prescribed queen. In a row-variable <constraint satisfaction problem>, a clue $(r,c)$ gives the singleton <constraint domain> $D_r=\{c\}$. Conflicting clues prove impossibility immediately, but nonattacking clues need not extend to a full solution. <Backtracking> decides the finite problem; <hill climbing> can search large candidate boards without an exhaustive guarantee.

= Tree-structured constraint satisfaction
{parent=Constraint satisfaction problem}

A binary <constraint satisfaction problem> whose <constraint graph> is a <tree>. Restrict <constraint domains> by unary conditions first. Choose a <rooted tree> orientation and process children before parents. For each child $j$ of $i$, retain in $D_i$ only values having a compatible value in the already reduced $D_j$. Thus every retained parent value has support in each child subtree.

If the root <constraint domain> becomes empty, no solution exists. Otherwise choose any root value, then recursively choose supported child values. A child-to-parent <arc consistency> pass need not enforce full <arc consistency> in both directions; the chosen directional condition suffices for this construction.

The proof uses <mathematical induction> on subtrees. A retained leaf value satisfies its unary requirements. Each retained parent value has a supported value in every child subtree. Those subtree solutions can be combined because the <tree> has no <edges> between different child subtrees. Therefore every retained parent value extends to a whole subtree solution, and every retained root value extends to a complete solution without <backtracking>.

For $N$ variables and maximum <constraint domain> size $d$, scanning all value pairs once per <edge> costs $O(Nd^2)$ <time complexity> in <Big O notation>, when one <binary constraint> evaluation has unit cost. If a constraint requires summing bundle values, its evaluation cost must also be counted.

= Arc consistency
{parent=Constraint satisfaction problem}

A directed requirement for a <binary constraint> $R_{ij}$: every remaining $x\in D_i$ has at least one support $y\in D_j$ with $(x,y)\in R_{ij}$. Revising the arc $i\to j$ deletes unsupported values from $D_i$; it does not directly delete values from $D_j$. Full <arc consistency> requires the condition in both directions on every <edge> of the <constraint graph>. On general <graphs>, it need not imply that a complete solution exists.

= Full-sweep arc consistency
{parent=Arc consistency}

Compute an <arc-consistency closure> by revising every directed constrained pair in complete sweeps until one sweep deletes nothing. The first sweep is unconditional. With $v$ variables, maximum <constraint domain> size $d$, and $e$ constrained pairs, at most $vd$ deletions permit at most $vd+1$ sweeps. At $O(d^2)$ per revision plus $O(v)$ per emptiness scan, a direct <time complexity> bound is $O((vd+1)(ed^2+v))$. <AC-3> uses a work list to avoid scanning unrelated arcs after each local change.

= Arc-consistency closure
{parent=Arc consistency}

The greatest componentwise subdomains of given finite initial <constraint domains> satisfying every directed <arc consistency> condition, allowing empty subdomains. Repeated sound revisions to a fixed point produce this same closure regardless of revision order, provided every affected arc is eventually reconsidered.

For the proof, fix subdomains $E_i$ of the initial $D_i$ satisfying <arc consistency>. If all current $D_i$ contain $E_i$, every value in $E_i$ has a support in $E_j\subseteq D_j$, so revising $i\to j$ preserves $E_i$. <Mathematical induction> shows that every revision preserves every such family $E$. At termination the current domains themselves satisfy <arc consistency>, so they are the greatest such family. Algorithms that stop immediately on the first empty <constraint domain> need not finish computing the closure, but correctly establish that no complete solution exists.

= AC-3
{parent=Arc consistency}
{c}

= AC3
{synonym}
{c}

An <arc consistency> <algorithm> maintaining a work list of directed constrained variable pairs. Revising $i\to j$ deletes each value of $D_i$ with no compatible value in $D_j$. If $D_i$ shrinks, incoming arcs $k\to i$ are reconsidered; the just-used neighbor $j$ need not be included, since deleted values had no support in $D_j$ and hence supported no surviving value there. Initially empty <constraint domains> are rejected before processing.

Each deletion preserves every complete solution: a solution using the removed value would supply its missing support. Therefore an empty <constraint domain> certifies impossibility. Successful termination establishes <arc consistency> but need not establish satisfiability. A triangle of two-valued inequality constraints supplies a counterexample: all values have pairwise support, but no assignment can satisfy all three inequalities.

For $v$ variables, $e$ constrained pairs and maximum <constraint domain> size $d$, assume constant-time compatibility tests for combined pair relations. A revision costs $O(d^2)$, and each shrinking source <constraint domain> can cause at most $d$ rounds of reconsideration of its incoming arcs. Thus there are $O(ed)$ revisions and <time complexity> $O(v+ed^3)$. Fixed $d$, including two-valued <constraint domains>, gives linear time in $v+e$.

A complexity class is a collection of <computational problem>[computational problems] sharing specified resource bounds and a computational model.

= Time complexity
{parent=Complexity class}
{wiki}
{title2=$T(n)$}

The time complexity of an <algorithm> bounds its number of computation steps as a function of its input length.

Specify both the size parameter and the operations counted. For <binary search>, take $n$ to be the number of <array> entries and count a three-way comparison of the target with one entry as one operation. Code using separate equality and less-than tests may perform two primitive tests per inspected entry; this changes a constant factor. The <input> size in bits is a different parameter when entries have variable-length representations.

Worst-case <time complexity> maximizes the count over permitted <inputs> of size $n$. An absent target forces $n$ comparisons in <linear search>. For <binary search>, the worst-case count is $\lfloor\log_2 n\rfloor+1$ for $n\geq1$, attained by a target larger than every entry. Both have a best case of one comparison when the first inspected entry matches.

In <Big O notation>, the worst-case bounds are $O(n)$ and $O(\log n)$ respectively. Here $T(n)=O(g(n))$ means that fixed constants $C,n_0$ exist with $T(n)\leq Cg(n)$ for all $n\geq n_0$. It is an upper bound, so a logarithmic count is also $O(n)$; the sharper bound communicates its scaling better. The base of the <logarithm> changes only a constant factor.

For $n=1{,}000{,}000$, <linear search> can require $1{,}000{,}000$ comparisons, whereas <binary search> needs at most $20$, since $2^{19}\leq n<2^{20}$. Doubling $n$ adds just one to the worst-case <binary search> count. These are operation counts, not measured machine runtimes. Translating them into logarithmic execution time assumes constant-cost indexed access, comparison and index arithmetic. Long entries can make comparison expensive; a <linked list> does not provide constant-cost access to an arbitrary middle index. Building or sorting the <array> is additional work: <merge sort> can provide order for many subsequent searches, but its cost belongs in the analysis too.

= Exponential time
{parent=Time complexity}

A <time complexity> bounded by $2^{p(n)}$ for a <polynomial> $p$, where $n$ is the encoded <input> length. This usage includes bounds such as $2^{n^2}$; it need not mean only $2^{O(n)}$.

= EXPTIME
{parent=Exponential time}
{c}
{wiki}

The <complexity class> of <formal languages> decidable in deterministic <exponential time>. = Linear speedup theorem
{parent=Time complexity}
{wiki}
{title2=$T_c(n)\leq T(n)/c+n+O(1)$}

For every constant $c>0$, a deterministic <multitape Turing machine> with more than one tape and <time complexity> bounded by $T(n)$ has an equivalent machine with the same tape count and bound $T(n)/c+n+O(1)$, allowing a larger finite control and tape <alphabet>. Blocks of old symbols become single new symbols, and finite control implements blocks of old steps. The linear overhead accounts for initial <input> packing. If $T(n)/n\to\infty$, the overhead can be absorbed to obtain any fixed constant speed increase for sufficiently large <inputs>. This does not supply unlimited speed increases for operations on fixed hardware.<Computational Complexity, slides 1 by Paul W. Goldberg (2023)>[Slides 47–48, PDF pp. 62–63: formal statement and block-simulation construction]{ref}

= Unit-cost model
{parent=Time complexity}

A computation-cost convention assigning constant cost to specified primitive operations. For exact unbounded <integer> arithmetic this can differ substantially from <bit complexity>: a multiplication of increasingly large values is one primitive operation but requires more bit operations. State which convention is used when estimating an <algorithm>'s running time.

= Combinatorial explosion
{parent=Time complexity}

A combinatorial explosion is a rapid increase in the number of candidates generated by a search over combinations, often exponential or factorial in an input parameter. For example, listing all <subsets> of an $n$-element <set> produces $2^n$ candidates, while listing all <permutations> produces $n!$ candidates. In contrast, listing only fixed-size $q$-element <subsets> has <time complexity> at least $\binom nq=\Theta(n^q)$ for fixed $q$: potentially large, but polynomial rather than exponential in $n$.

= Pseudopolynomial time
{parent=Time complexity}

= Pseudopolynomial
{synonym}

A <time complexity> polynomial in numerical input values, which need not be polynomial in their binary encoding lengths. For example, an $O(nW)$ <knapsack> algorithm depends on the capacity $W$, while its input representation needs only $O(\log(W+1))$ bits for that capacity.

= Quadratic time
{parent=Time complexity}
{title2=$O(n^2)$}

A <time complexity> bounded by $O(n^2)$ for input size $n$. Examining every ordered pair of entries with constant work per pair has this bound.

= Linear time
{parent=Time complexity}
{title2=$O(n)$}

A <time complexity> bounded by $O(n)$ for input size $n$. A single pass with constant work per input entry has this bound.

= Constant time
{parent=Time complexity}
{title2=$O(1)$}

A <time complexity> bounded by $O(1)$ independently of input size, under a stated computational cost model. Fixed-size machine arithmetic may be constant time, whereas <arbitrary-precision arithmetic> depends on operand length.

= Pseudo-polynomial time
{parent=Time complexity}
{wiki}

An <algorithm> has <pseudo-polynomial time> when its running time is bounded by a <polynomial> in the numerical magnitudes of input quantities, rather than necessarily in their encoded length. The <dynamic programming> table for the <0-1 knapsack problem> uses $O(nW)$ arithmetic operations for $n$ items and capacity $W$. A <binary numeral system> encoding needs only $O(\log(W+1))$ bits for that capacity, so the table bound can be exponential in the number of capacity bits. This distinction does not claim that every input requires exponential work.

= Amortized analysis
{parent=Time complexity}
{title2=$\widehat c_i=c_i+\Phi_i-\Phi_{i-1}$}

<Amortized analysis> bounds the total cost of every permitted <sequence> of operations from a specified initial state. An amortized $O(1)$ bound means that some constants $a,b$ satisfy $\sum_{i=1}^m c_i\leq am+b$ for every such <sequence> of length $m$. The cost model and allowed operations are part of the claim; <Big O notation> alone does not specify them.

* A worst-case bound for one operation limits its cost in any reachable state. Summing these separate maxima can overestimate the cost of a whole <sequence> because expensive states may take many cheap operations to rebuild.
* An <amortized analysis> limits the total over every allowed <sequence>, including an unfavourably chosen one. Dividing that bound by the number of operations is a deterministic guarantee about the <sequence>.
* A probabilistic average-case analysis bounds an <expected value> under a stated <probability distribution> on <inputs>. For a <randomized algorithm>, an <expected value> can instead average over its random choices. Neither interpretation is required by a deterministic <amortized analysis>.

This distinction, and the credit and <potential method> viewpoints, are developed in <R. Endre Tarjan>'s 1985 paper https://epubs.siam.org/doi/10.1137/0606031[Amortized Computational Complexity], sections 1–2, pp. 306–308. The <dynamic array doubling> example below shows how an expensive operation can pay for itself through the cheap operations that precede it.

= Weighted binary counter cost
{parent=Amortized analysis}
{title2=$C(n,k)=\sum_{i=0}^{k-1}2^i\lfloor n/2^i\rfloor$}

For an initially zero $k$-bit <binary counter>, suppose changing <bit> $i$ costs $2^i$. It changes exactly $\lfloor n/2^i\rfloor$ times in $n$ increments. Consequently the total is $\Theta(n\min\{k,1+\log_2 n\})$ for $n,k\geq1$. The upper bound counts at most $n$ cost at each active position; the lower bound uses $\lfloor x\rfloor\geq x/2$ for $x\geq1$. This shows why exponential position costs cancel the decreasing carry frequencies that make the ordinary <binary counter> have constant <amortized cost>.

= Amortized time complexity
{parent=Amortized analysis}
{title2=$T(m,n)\leq ma(n)+I(n)$}

An <amortized analysis> can bound the total <time complexity> $T(m,n)$ of every allowed <sequence> of $m$ operations by $ma(n)+I(n)$, where $n$ is a size parameter and $I(n)$ accounts for initialization or the specified initial state. The bound $a(n)$ is then an amortized per-operation <time complexity>. Dividing the total bound by $m$ explains the averaging; it is a guarantee over every permitted <sequence>, without an assumed <probability distribution> on requests. Individual operations can cost more than $a(n)$.

= Dynamic array doubling
{parent=Amortized analysis}
{title2=$T(n)=n+C_n-1$}

Consider a <dynamic array> holding fixed-size entries. Its size $n$ is the number of occupied slots and its capacity $C$ is the number of allocated slots. Start with $n=0$, $C=1$. The only operation is append: if $n=C$, allocate a new <array> of capacity $2C$, copy the $C$ existing entries, and release the old <array>; then write the new entry and increase $n$ by one. There is no reserve operation, deletion or shrinking in this model.

Count one unit for writing the new entry and one unit per existing entry copied during resizing. Thus the $i$th append has actual cost $c_i=1$ without resizing and $c_i=C+1$ when the old capacity $C$ is full. Copying an entry, including its read and write, is one counted action. Allocation, deallocation, index <arithmetic operations> and the initial one-slot allocation are outside this exact count. If these add only a constant per ordinary append and a linear cost per resize, the <Big O notation> conclusions still hold, with different constants; costly entry copies require their own cost model.

The first ten costs are $1,2,3,1,5,1,1,1,9,1$. For example, append $9$ copies eight entries and writes one, so $c_9=9$. At that point the capacity becomes $16$, but the total cost of all nine appends is only $24$.

For $n\geq1$, the final capacity is $C_n=2^{\lceil\log_2 n\rceil}$. Every earlier capacity $1,2,4,\ldots,C_n/2$ was copied once. This <geometric series> sums to $C_n-1$, including the empty sum when $n=1$. Therefore <aggregate analysis> gives the exact total
$$
T(0)=0,\qquad T(n)=\sum_{i=1}^n c_i=n+C_n-1,\qquad n\leq C_n<2n\quad(n\geq1).
$$
Consequently $T(n)<3n$, so append has amortized $O(1)$ cost in <Big O notation> for every prefix from this empty initial state. The values being appended do not affect the count. In contrast, an append to a full <dynamic array> with $n$ entries costs $n+1$: its worst-case cost is $O(n)$, and actually grows linearly along full-capacity states. A bound on total work does not promise a constant response time for each call.

The same policy controls <computer memory>: after each completed append, $n\leq C_n<2n$ for $n\geq1$, so fewer than $n$ slots are unused. This is a bound on the retained backing <array>, with fixed-size slots. During a resize from full capacity $k$ to $2k$, a copying implementation can temporarily hold both <arrays>, totalling $3k$ allocated slots before releasing the old one. Thus the retained-capacity bound does not bound this temporary peak by twice the live size. Allocator metadata and separately allocated objects are additional <computer memory> costs.

The <geometric series> is the source of the efficiency. If capacity instead increases by one each time, the same count becomes $n+1+2+\cdots+(n-1)=n(n+1)/2$, a quadratic total. <Dynamic array doubling> buys a linear total with bounded spare capacity, even when the final length is unknown.

= Potential method
{parent=Amortized analysis}
{wiki}
{title2=$\Phi(D)$}

The <potential method> assigns a number $\Phi(D)$ to each state $D$ of a <data structure>. Let $D_i$ be the state after operation $i$, $\Phi_i=\Phi(D_i)$, and $c_i$ its actual cost. Its <amortized cost> is the actual cost plus the change in potential. Summing and cancelling adjacent potentials gives a <telescoping sum>:
$$
\widehat c_i=c_i+\Phi_i-\Phi_{i-1},\qquad
\sum_{i=1}^m c_i=\sum_{i=1}^m\widehat c_i+\Phi_0-\Phi_m.
$$
If $\Phi_0=0$ and every reachable $\Phi_i\geq0$, the sum of <amortized costs> bounds the actual total for every prefix. A nonzero initial potential contributes the explicit additive term $\Phi_0$. Potential is proof bookkeeping; the <algorithm> need not store it.<CS 312 at Cornell University/Lecture 20: Hash tables and amortized analysis>[CS 312 at Cornell University; CS 312, lecture 20, “Amortized analysis”: definition of amortized time and cancellation of successive potential changes]{ref}

For <dynamic array doubling>, choose
$$
\Phi(n,C)=\max(0,2n-C).
$$
The <potential method> now starts at $\Phi(0,1)=0$. After every nonempty reachable state, $C<2n$, so the maximum equals $2n-C$. There are just three cases for append:

* First append: $(0,1)$ becomes $(1,1)$, so $c_1=1$ and $\widehat c_1=1+(1-0)=2$.
* Later append without resizing: $C$ stays fixed and $n$ increases by one, so $\Delta\Phi=2$ and $\widehat c_i=1+2=3$.
* Append to a full capacity $k$: $(k,k)$ becomes $(k+1,2k)$, so the potential changes from $k$ to $2$. Hence $\widehat c_i=(k+1)+(2-k)=3$, including the resize from capacity one to two.

For every $n\geq1$, the total charge is $2+3(n-1)=3n-1$, and the <telescoping sum> proves
$$
T(n)=3n-1-\Phi(n,C_n)\leq3n-1.
$$
This agrees exactly with $T(n)=n+C_n-1$. The unmodified choice $2n-C$ has initial value $-1$, so calling it nonnegative at the empty state would be incorrect. It also works if that initial constant is retained in the identity; alternatively, $2n-C+1$ starts at zero and is nonnegative on these reachable states. The maximum above keeps a literal nonnegative credit balance from the beginning. The proof covers append alone; allowing reserve or arbitrary deletion changes the reachable states and requires a new argument.

In the <potential method>, an operation's <amortized cost> is $\widehat c_i=c_i+\Phi_i-\Phi_{i-1}$. It can exceed or fall below its actual cost $c_i$. The endpoint potentials determine how the total charge compares with the total actual cost.

= Aggregate analysis
{parent=Amortized analysis}

<Aggregate analysis> bounds the total cost of a whole <sequence> directly, then divides by its length to obtain an amortized bound. Summing the copied capacities as a <geometric series> in <dynamic array doubling> is an example.

= Accounting method
{parent=Amortized analysis}
{wiki}

= Savitch's theorem
{parent=Nondeterministic space complexity class}
{wiki}
{title2=$\mathrm{NSPACE}(s)\subseteq\mathrm{SPACE}(s^2),\quad s\geq\log n$}
{c}

= Savitch theorem
{c}
{synonym}

Reachability within $2^k$ steps can be tested by enumerating a midpoint and recursively testing two half-paths. Configurations have $O(s)$ bits and recursion depth $O(s)$, yielding deterministic space $O(s^2)$. The <space-bound discovery by exit reachability> permits this simulation without assuming that the supplied function $s$ is constructible.

= Space-bound discovery by exit reachability
{parent=Savitch's theorem}
{title2=$m\leftarrow2m$}

For a bounded-space machine, start with a logarithmic work budget and test accepting reachability and reachability of a transition leaving the budget. Accept if acceptance is found, double the budget if an exit is reachable, and otherwise reject. If all paths use at most $Cs(n)$ space, doubling stops at $O(s(n))$. Each budget test uses the <Savitch theorem> recursion and the storage is reused. The method discovers a sufficient bound without computing $s(n)$.

= Deterministic space complexity class
{parent=Space complexity}
{title2=$\mathrm{SPACE}(s(n))$}

= SPACE
{c}
{synonym}

Languages decidable by deterministic <Turing machines> using $O(s(n))$ work-tape cells with a read-only input. Input-head addresses take $O(\log n)$ bits, while the input itself is not charged to work space. The definition does not require the bound to be computed by the deciding machine.

= PSPACE
{parent=Deterministic space complexity class}
{c}
{title2=$\mathbf{PSPACE}$}

PSPACE consists of decision problems solvable using a polynomial amount of work space. Running time may be exponential. Enumerating all polynomial-length relation encodings and reusing working storage preserves this bound, as does complementation. In particular fixed-sentence <second-order logic> model checking lies in PSPACE.

= Polynomial-register real-arithmetic computation
{parent=Space complexity}

A <polynomial-register real-arithmetic computation> stores polynomially many real numbers and may use arbitrarily many additions, subtractions and multiplications, with comparison tests for decisions. Register count does not bound precision or time. Fixed gate constants or sufficiently accurate computable approximations must be specified. This resource model is distinct from ordinary bit-cost computation.

= Logarithmic space
{parent=Space complexity}
{wiki}

A logarithmic-space computation uses $O(\!\log n)$ work-tape cells on inputs of length $n$.

= Binary addition in logarithmic space
{parent=Logarithmic space}

For canonical positive <binary numeral system> inputs, a <logspace transducer> can emit the canonical representation of their <sum> most significant digit first. Count the operand lengths, compute the final <arithmetic carry> to determine output length, and then compute each requested result digit by restarting the least-significant-first column recurrence. Each pass uses only a fixed number of $O(\log n)$-<bit> indices and one <arithmetic carry>. The <binary-addition carry invariant> proves correctness. <Logspace composition by recomputation> consequently permits any <L> property of the resulting digit <string>, including being a <binary palindrome>, to be tested without storing the sum.

= Logspace transducer
{parent=Logarithmic space}

A deterministic <Turing machine> with read-only <input>, $O(\log(n+2))$ work space, and successive write-only output whose contents it cannot inspect. A transducer for a total function halts on every <input>. It has a <polynomial> number of internal <Turing machine configurations>, so a halting run emits only a <polynomial> number of symbols. The unreadable output position does not affect subsequent transitions.

= Logspace-computable function
{parent=Logspace transducer}

A total <function> computed by a halting <logspace transducer>. Its output may be much longer than its work tapes. <Logspace-computable functions> compose using <logspace composition by recomputation>.

= Logspace composition by recomputation
{parent=Logspace-computable function}
{title2=$f,g\in\mathrm{FL}\Longrightarrow g\circ f\in\mathrm{FL}$}

To simulate $g$ on the virtual <input> $f(x)$, store the simulated <input>-head position and rerun the <logspace transducer> for $f$ whenever an <input> symbol is requested. Count emitted symbols until the requested position is reached. The intermediate output has <polynomial> length, so its positions take $O(\log n)$ <bits>, and the work space of $g$ is also $O(\log n)$. Storage used by successive recomputations is reused. This proves closure of <logspace-computable functions> under composition and transitivity of <logspace many-one reductions>.

= Directed cycle detection
{parent=NL-complete}

Decide whether a <directed graph> has a nonempty directed cycle; self-loops count. This problem is <NL-complete>. Membership guesses a returning walk of at most the vertex count. For hardness, layer a reachability instance into $N+1$ layers with wait arcs, then add only the backward edge from the target in the last layer to the source in the first. The otherwise acyclic layering has a cycle exactly when the original target is reachable. Zero-length paths must not be treated as cycles.

= Even-length directed reachability
{parent=ST-connectivity}

Decide whether a finite <directed graph> has an even-length directed <walk> from a specified source $s$ to a specified target $t$. <Vertices> may repeat and a zero-length <walk> is allowed. The <NL>-completeness proof uses the <graph> of pairs $(v,b)$ with $b\in\{0,1\}$ tracking <integer parity>: every original <edge> flips $b$, and acceptance means reaching $(t,0)$ from $(s,0)$. At most $2|V|-1$ steps are needed in the parity <graph>. For hardness, subdivide every <edge> of an ordinary reachability instance into two directed <edges>. Both constructions are computable by <logspace transducers>. Requiring a simple <path in a graph> in the original <graph> changes the question; deleting an odd closed portion need not preserve <integer parity>.

= Strongly NP-complete
{synonym}

An <NP> <decision problem> is strongly <NP-complete> when its <NP-hardness> persists with numerical parameters written in the <unary numeral system>. An important proof method bounds every relevant numerical value by a <polynomial> in the remaining explicit <input> size. For the <clique decision problem>, values $k>|V(G)|$ can be mapped to one fixed no-instance; otherwise writing $1^k$ takes only <polynomial time>. The distinction is representation-sensitive, so an explicit <graph> encoding must be specified.

= Subset cover problem
{synonym}

Given subsets $S_1,\ldots,S_m$ of a finite universe, the decision problem asks whether at most $k$ of them cover the universe. It is <NP-complete>. If $k<m$, existence of a cover by at most $k$ subsets is equivalent to existence of a cover by exactly $k$, by adding unused subsets. The promise that every element occurs in some subset loses no hardness: an uncovered element can be detected in polynomial time and mapped to a fixed negative instance.

= Set cover reduction to equilibrium support
{parent=Set cover problem}

Assume $2\leq k<m$ and $\bigcup_iS_i=S$. Construct a two-player game with row $i$ for $S_i$ and columns $0,1,\ldots,n$. Column $0$ pays both players one; column $j>0$ pays $(1,0)$ when $j\in S_i$, and $(0,k/(k-1))$ otherwise. There is a <Nash equilibrium> whose row player's <support of a mixed strategy> has size $k$ exactly when $k$ rows cover the universe. A uniform mixture on a cover makes column $0$ a <best response>. Conversely, if some element is uncovered by the support, the column player's <best responses> are uncovered elements and the row player's current payoff is zero. The union promise provides a profitable row deviation. Without the union promise the equivalence is false: a globally uncovered element is a <best response> against every row mixture.

= Cook-Levin theorem
{c}
{parent=NP-completeness}
{wiki=Cook–Levin_theorem}
{title2=$\mathrm{SAT}\text{ is NP-complete}$}

Every <NP> verifier can be compiled into a polynomial-size <Boolean circuit> whose inputs encode its <certificate (complexity)>, and then into an equisatisfiable <conjunctive normal form> by a <Tseitin transformation>. This gives a <polynomial-time many-one reduction> from every <NP> language to <SAT>. Checking a guessed assignment proves membership, so <SAT> is <NP-complete>.

= Subset sum
{synonym}

Given finitely encoded nonnegative integers $s_i$ and target $t$, the subset sum problem asks whether some subset sums to $t$. Taking equal item weights and profits reduces it to testing whether a <0-1 knapsack problem> with capacity $t$ attains value $t$.

= Subset sum dynamic programming
{parent=Subset sum problem}
{title2=$D_i(t)$}

For indexed occurrences with <positive integer> weights, let $D_i(t)$ record whether a <subset> of the first $i$ entries has sum $t$. The recurrence chooses whether the last occurrence is absent or present: $D_i(t)=D_{i-1}(t)\lor D_{i-1}(t-a_i)$, with an out-of-range term false. Initialize only sum zero true. Descending one-dimensional updates prevent reusing the current occurrence. Time is $O(ns)$ for target $s$ and space $O(s)$; positivity permits immediate rejection above the total. With weights bounded by $k$, the total is at most $nk$, making the bound <polynomial> in $n,k$.

= Special sum set
{parent=Subset sum problem}

A finite <set> $A$ of <positive integers> such that nonempty <disjoint sets> contained in $A$ have different <sums>, and the larger subset has the larger <sum> when their sizes differ. For $a_1<\cdots<a_n$, the size condition is equivalent to $a_1+\cdots+a_{k+1}>a_{n-k+1}+\cdots+a_n$ for $1\le k\le\lfloor(n-1)/2\rfloor$: the left side is the smallest possible sum of $k+1$ elements and the right side the largest sum of $k$ elements.

= Boolean satisfiability
{c}
{synonym}

The <Boolean satisfiability problem> asks whether a <Boolean formula> has an assignment making it true. A complete assignment is a <Boolean valuation>: it gives every <Boolean variable> a <truth value>, consistently at all occurrences. A <satisfying assignment>, also called a <model of a Boolean formula>, makes the entire <Boolean formula> true. A solver's answer `SAT` asserts that at least one <satisfying assignment> exists; `UNSAT` asserts that the input is an <unsatisfiable Boolean formula>. These are statements about existence, rather than the <truth value> under one particular <Boolean valuation>.

For <conjunctive normal form>, or <CNF>, write
$$
F=C_1\land\cdots\land C_m,
\qquad C_i=\ell_{i1}\lor\cdots\lor\ell_{ik_i}.
$$
Each <Boolean literal> $\ell$ is a <Boolean variable> or its <logical negation>. Each <Boolean clause> uses inclusive <logical disjunction>: one true <Boolean literal> suffices. The outer <logical conjunction> requires every <Boolean clause> to succeed under the same <Boolean valuation>. Choosing a different <Boolean valuation> for each <Boolean clause> would answer a different question.

Consider the original three-<Boolean variable> example
$$
F=(x\lor y)\land(\neg x\lor z)\land(\neg y\lor\neg z),
\qquad C_1=x\lor y,\quad C_2=\neg x\lor z,\quad C_3=\neg y\lor\neg z.
$$
At the <Boolean valuation> $(x,y,z)=(0,1,0)$, the <Boolean literals> in $C_1$ have values $(0,1)$, those in $C_2$ have values $(1,0)$, and those in $C_3$ have values $(0,1)$. Every <Boolean clause> therefore has <truth value> one, so $F$ has <truth value> one: this is a <satisfying assignment>.

\Image[satisfiability-assignment-clause-evaluation.png]
{title=An original <satisfying assignment> evaluated through <Boolean literals>, three <Boolean clauses>, and their <logical conjunction>}

The complete <truth table> has $2^3=8$ <Boolean valuations>. Exactly two are <satisfying assignments>: $(0,1,0)$ and $(1,0,1)$. In particular, $(1,1,1)$ satisfies the first two <Boolean clauses> but falsifies the third, so satisfying most <Boolean clauses> does not suffice for <SAT>. That different objective belongs to <maximum satisfiability>.

\Image[satisfiability-eight-assignment-truth-table.png]
{title=All eight <Boolean valuations> of the original <CNF> example, with its two <satisfying assignments> highlighted}

A short proof of completeness avoids listing all eight rows. If $x=0$, the <Boolean clause> $C_1$ forces $y=1$, after which $C_3$ forces $z=0$; $C_2$ is already true. If $x=1$, $C_2$ forces $z=1$, after which $C_3$ forces $y=0$; $C_1$ is already true. These two cases exhaust the <truth values> of $x$ and produce precisely the two <satisfying assignments> above.

<Verifying a satisfying assignment> and finding a <satisfying assignment> are different tasks. Given a candidate, evaluate the <Boolean formula> once; finding a candidate requires choosing compatible <truth values> across all its <Boolean clauses>. The <Cook-Levin theorem> says that general <SAT> is <NP-complete>, even though a proposed <satisfying assignment> is efficiently checkable. Its proof encodes a bounded <nondeterministic computation> as a <Boolean formula> whose <satisfying assignments> describe accepting computations. <Stephen A. Cook>'s 1971 paper established this connection between <computational complexity theory> and <propositional logic>.<The Complexity of Theorem-Proving Procedures by Stephen A. Cook>[The Complexity of Theorem-Proving Procedures by Stephen A. Cook, 1971, §1, Theorem 1 and proof, pp. 2–3 of the revision-3 transcription: CNF encodes accepting computations]{ref}

A concrete use is checking finite configuration rules. Let $x$ mean that an optional feature is enabled, $y$ that a fallback is selected, and $z$ that the feature's required component is installed. Require a feature or fallback, require the component whenever the feature is enabled, and forbid using the fallback with that component. <Logical implication> rewrites the second rule $x\to z$ as $\neg x\lor z$; <De Morgan's laws> rewrite the third rule $\neg(y\land z)$ as $\neg y\lor\neg z$. Their <logical conjunction> is exactly $F$, so its two <satisfying assignments> give the two allowed configurations. The usefulness of <SAT> lies in expressing local rules uniformly while demanding one globally consistent <Boolean valuation>. The conclusion concerns exactly these encoded rules.

= SAT solver
{parent=Boolean satisfiability problem}
{c}

An <algorithm> or software system that decides whether a <Boolean formula> has a <satisfying assignment>, usually returning one when it exists. <Unit propagation> and <clause learning> are important mechanisms in modern <SAT solvers>. A reduction must be correct and its representation costs counted before the performance of the downstream <SAT solver> is relevant.

= Clause learning
{parent=SAT solver}

Deriving additional <Boolean clauses> implied by the original <Boolean formula>, usually after analyzing a conflict in search. A learned <Boolean clause> excludes a failed combination of choices on subsequent branches without removing any <satisfying assignment>.

= Unit propagation
{parent=SAT solver}

If all but one <literal> of a <Boolean clause> are false under a partial <Boolean valuation>, the remaining <literal> must be true in any extension satisfying the clause. Repeatedly make such forced assignments, remove satisfied <Boolean clauses> and remove false <literals> from the others. An empty <Boolean clause> proves that the current partial <Boolean valuation> has no satisfying extension. This is sound because every step is forced by an original or already implied <Boolean clause>; it is not by itself a complete <SAT> decision procedure.

= Exactly-one constraint
{parent=Boolean satisfiability problem}
{title2=$\sum_{i=1}^{q}p_i=1$}

A restriction requiring exactly one member of a <set> of <Boolean variables> to be true. A direct <conjunctive normal form> encoding combines one at-least-one <Boolean clause>, $p_1\lor\cdots\lor p_q$, with $\binom q2$ at-most-one <Boolean clauses>, $\neg p_i\lor\neg p_j$ for $i<j$. The first supplies existence and the second supplies uniqueness. For $q=0$, the empty at-least-one <Boolean clause> correctly makes the condition unsatisfiable.

= Satisfying assignment
{parent=Boolean satisfiability problem}
{title2=$v\models F$}

= Model of a Boolean formula
{synonym}

A <satisfying assignment> is a complete <Boolean valuation> $v$ for which a <Boolean formula> $F$ has <truth value> one, written $v\models F$. The notation describes a relation between the <Boolean valuation> and the <Boolean formula>. For the example in <Boolean satisfiability problem>, $(0,1,0)$ is a <model of a Boolean formula> $F$, whereas $(0,0,0)$ is not. <SAT> asks for existence of at least one <satisfying assignment>, rather than for every <Boolean valuation> to work; the latter condition makes $F$ a <tautology>.

= Quadratic-size formula with prescribed model count
{parent=Satisfying assignment}
{title2=$|\varphi_k|=O(n^2),\quad\#\operatorname{SAT}(\varphi_k)=k$}

For each $0\leq k\leq2^n$, a <propositional formula> over $n$ specified variables can have exactly $k$ <satisfying assignments> and length $O(n^2)$. For $0<k<2^n$, interpret a <Boolean valuation> as the <binary number> $x_1\cdots x_n$ and test whether it is less than $k=b_1\cdots b_n$.

For every position $i$ with $b_i=1$, use a conjunction asserting that all earlier <bits> equal $b_j$ and $x_i=0$, leaving later <bits> unrestricted. Take the disjunction of these terms. Each satisfying assignment has a unique first differing position, so the terms are disjoint, and their counts sum to $\sum_{i:b_i=1}2^{n-i}=k$. Their combined length is $O(1+2+\cdots+n)=O(n^2)$. Use <logical falsity> and <logical truth> at the two endpoints. The count is over all $n$ variables, including those absent from an individual term or from the whole formula.

= Verifying a satisfying assignment
{parent=Satisfying assignment}
{title2=$O(n+m+L)$}

For a <CNF> input with $n$ <Boolean variables>, $m$ <Boolean clauses>, and $L$ <Boolean literal> occurrences, first check that the supplied <Boolean valuation> gives each input <Boolean variable> exactly one <truth value>. Evaluate each <Boolean literal> by lookup or <logical negation>, each <Boolean clause> by <logical disjunction>, and the <Boolean formula> by <logical conjunction>. Indexed <Boolean variables> and constant-cost lookups give an $O(n+m+L)$ operation count; with a finite <binary string> encoding the check still takes <polynomial time>. Thus a <satisfying assignment> is a <certificate in computational complexity> for <SAT>, proving that <SAT> belongs to <NP>. Finding it by exhaustive checking can require $2^n$ candidate <Boolean valuations>; this enumeration cost is not a lower bound on every possible <SAT> <algorithm>.<CS 252, Lecture 8: Constraint Satisfaction Problems (Carnegie Mellon University)>[CS 252, Lecture 8: Constraint Satisfaction Problems, p. 3, §3 opening paragraph: assignments as certificates and membership in NP]{ref}

= Unsatisfiable Boolean formula
{parent=Boolean satisfiability problem}
{title2=$\nexists v:\ v\models F$}

An <unsatisfiable Boolean formula> has no <satisfying assignment>. For
$$
G=x\land\neg x,
$$
the <Boolean valuation> $x=0$ falsifies the first <Boolean clause>, and $x=1$ falsifies the second. Both possible <truth values> fail, proving `UNSAT`. Each <Boolean clause> alone has a <satisfying assignment>, but their <logical conjunction> does not: compatibility is the central issue. By contrast, finding just one failed <Boolean valuation> for a general <Boolean formula> only rejects that candidate. Finding one successful <Boolean valuation> proves `SAT`; proving `UNSAT` requires excluding every candidate, possibly with a compact argument rather than a full <truth table>.

= Partial Boolean assignment
{parent=Boolean satisfiability problem}
{title2=$v:S\to\{0,1\},\quad S\subseteq\operatorname{Var}(F)$}

A <partial Boolean assignment> gives <truth values> to some of a <Boolean formula>'s <Boolean variables>. An extension is a complete <Boolean valuation> agreeing on the assigned <Boolean variables>. In <CNF>, a <Boolean clause> containing a true assigned <Boolean literal> is already satisfied; a <Boolean clause> whose every <Boolean literal> is assigned false rules out all extensions. A <Boolean clause> with no true assigned <Boolean literal> and at least one unassigned <Boolean variable> is unresolved. An unresolved <Boolean clause> need not have a compatible extension with the other <Boolean clauses>.

For $F$ in <Boolean satisfiability problem>, setting $x=y=0$ already falsifies $C_1$, so both choices of $z$ can be discarded. Setting only $x=0$ leaves $C_1$ unresolved and forces $y=1$ if a <satisfying assignment> is to survive; then $C_3$ forces $z=0$. Branching on an unassigned <Boolean variable> into its two <truth values> and discarding branches with a false <Boolean clause> is sound: every <satisfying assignment> follows one branch and cannot extend a false <Boolean clause>. If all branches are eliminated, the original <Boolean formula> is an <unsatisfiable Boolean formula>.

= 2-satisfiability
{parent=Boolean satisfiability problem}
{wiki}
{title2=$2\text{-SAT}$}

= 2-SAT
{c}
{synonym}

<2-satisfiability> restricts <SAT> to <CNF> in which each <Boolean clause> has at most two <Boolean literals>. The example in <Boolean satisfiability problem> is therefore a <2-SAT> instance. Unlike general <SAT> and <3-SAT>, <2-SAT> has a <polynomial-time algorithm>; its tractability concerns finding a <satisfying assignment> or deciding that none exists, not merely checking a candidate. <3-SAT> allows up to three <Boolean literals> per <Boolean clause> and is <NP-complete>, even though it includes many individually easy instances such as this one.<CS 252, Lecture 8: Constraint Satisfaction Problems (Carnegie Mellon University)>[CS 252, Lecture 8: Constraint Satisfaction Problems, pp. 1–2, §2 examples 1 and 3; p. 3, §3 classification items 1 and 3]{ref}

The key <logical equivalence> is
$$
a\lor b\equiv(\neg a\to b)\land(\neg b\to a),
$$
where $a,b$ are <Boolean literals>. It expresses a two-<Boolean-literal> <Boolean clause> as two <logical implications>. Representing these <logical implications> as edges in a <directed graph> gives a route to the <polynomial-time algorithm>. In the example, $C_2$ says both $x\to z$ and $\neg z\to\neg x$: enabling the feature requires its component, and an absent component excludes the feature.

= Integer programming formulation of satisfiability
{parent=Boolean satisfiability problem}
{title2=$\sum_{\ell\in C_i}L_\ell(t)\geq1$}

Encode each truth value by $t_k\in\{0,1\}$. A positive <Boolean literal> has value $t_k$ and its negation has value $1-t_k$. The sum of literal values in a clause is at least one exactly when that clause is true. Thus the displayed inequalities, with objective zero, express <Boolean satisfiability> as a binary <integer programming> feasibility problem. For <maximum satisfiability>, introduce $q_i\in\{0,1\}$ with $q_i\leq\sum_{\ell\in C_i}L_\ell(t)$ and maximize $\sum_iq_i$. False clauses force zero indicators; true clauses permit indicators one, and maximization selects all of them. Hence the optimal objective equals the maximum number of true clauses.

= Maximum satisfiability
{parent=Boolean satisfiability problem}
{title2=$\max_t\#\{\text{clauses true under }t\}$}

= MAX-SAT
{c}
{synonym}

Maximum satisfiability asks for a truth assignment maximizing the number of true clauses of a <conjunctive normal form> formula. The <Boolean satisfiability problem> asks whether all its clauses can be made true. Binary clause indicators give an <integer programming> formulation, and the <literal-frequency greedy approximation for MAX-SAT> guarantees at least half the optimum. Counts of clauses, rather than multiplicities of repeated literals within one clause, are relevant to this objective.

= Literal-frequency greedy approximation for MAX-SAT
{parent=Maximum satisfiability}
{title2=$G\geq\operatorname{OPT}/2$}

In the residual unsatisfied formula, choose a <Boolean literal> contained in the largest number $a$ of clauses and make it true. Its opposite occurs in at most $a$ clauses, since it too was an eligible literal. The step permanently satisfies $a$ clauses; only clauses containing the opposite can become empty, so it loses at most $a$ clauses. Delete satisfied clauses and false literals and repeat. No satisfied clause or newly empty clause is counted twice. Summing gives total lost nonempty clauses at most total satisfied clauses $G$. All initially nonempty clauses are eventually in one of these classes, so $G\geq N_+/2\geq\operatorname{OPT}/2$. Initial empty clauses can never be satisfied and are excluded from $N_+$. This proves the <approximation algorithm> guarantee even with tautological clauses or repeated literals.

= 2UN-SAT
{c}
{parent=Boolean satisfiability problem}
{title2=$\text{at most two positive literals per clause}$}

Satisfiability of <conjunctive normal form> formulas whose <clauses> have at most two unnegated variables. It is <NP-complete>: binary AND/OR and unary NOT gate equivalences in a <Tseitin transformation> already satisfy that restriction. <Clauses> may contain arbitrarily many negative <literals>; the total <clause> width is not restricted to two.

= Maximum 2-satisfiability
{parent=Boolean satisfiability problem}

= MAX-2SAT
{c}
{synonym}

Maximum 2-satisfiability asks for an assignment satisfying as many <clause> occurrences as possible when every nonempty <clause> has at most two <literals>. Occurrences are counted even when a <clause> is repeated. Its decision problem is <NP-complete> by the <seven-clause gadget for MAX-2SAT>, while the <method of conditional probabilities> gives a polynomial-time half approximation.

= Golden ratio approximation for MAX-2SAT
{parent=Maximum 2-satisfiability}
{title2=$p=(\sqrt5-1)/2$}

When each variable appears in at most one normalized singleton <clause>, satisfy that favored <literal> with <probability> $p>1/2$ and choose independent variables. Every proper binary <clause> is then satisfied with <probability> at least $1-p^2$, and every singleton with <probability> $p$. Maximize the common lower bound by $p=1-p^2$, giving the reciprocal of the <golden ratio>. The <method of conditional probabilities> derandomizes the construction, obtaining <approximation ratio> $p$. Tautologies are harmless; the singleton restriction must be applied after removing repeated <literals> within <clauses>.

= Seven-clause gadget for MAX-2SAT
{parent=Maximum 2-satisfiability}

A three-<literal> disjunction can be represented by ten unit or two-<literal> <clause> occurrences with one fresh auxiliary variable. If the number $r$ of true input <literals> is zero, the best auxiliary choice satisfies six; for $r=1,2,3$, the best count is seven. Applying separate gadgets to all <clauses> of a <3-SAT> instance gives target seven times the original <clause> count, proving <NP-completeness> of the decision form of <MAX-2SAT>. The local counting argument is essential: no gadget may exceed seven and compensate for an unsatisfied input <clause>.

= Boolean formula
{c}
{parent=Boolean satisfiability problem}

A <Boolean formula> is a finite expression built from <Boolean variables> and <Boolean operations>, equivalently a <propositional formula> with two-valued semantics. A <Boolean valuation> determines its <truth value>. In $(x\lor y)\land\neg x$, <logical negation> acts only on $x$, and the outer <logical conjunction> combines $x\lor y$ with $\neg x$. Occurrences of the same <Boolean variable> share one <truth value>. The <Boolean satisfiability problem> asks whether some <Boolean valuation> makes the <Boolean formula> true.

A <Boolean formula> is in disjunctive normal form when it is a disjunction of conjunctions of <Boolean literals>. Width bounds the number of literals in each conjunction, not the number of conjunctions. A depth-$s$ <decision tree> gives such a formula of width at most $s$ by taking the disjunction of its accepting leaf conditions; rejecting leaves give the dual <conjunctive normal form>.

= Endpoint-false disjunctive normal form
{parent=Disjunctive normal form}

A <propositional formula> false on the all-true and all-false <Boolean valuations> has a <disjunctive normal form> in which every <minterm> contains a positive <literal> and a negative <literal>. Grouping the positive <propositional variables> into $C$ and the negated <propositional variables> into the <negation> of a <logical disjunction> $D$ writes each <minterm> as $\neg(C\to D)$. <De Morgan's laws> therefore give the <negation> of a <logical conjunction> of such <logical implications>. For a <contradiction> use $\neg(p\to p)$.

= Conjunctive normal form
{title2=$\bigwedge_i\bigvee_j\ell_{ij}$}
{parent=Boolean formula}

= CNF
{c}
{synonym}

A <Boolean formula> is in <conjunctive normal form> when it is a <logical conjunction> of <Boolean clauses>. It is true precisely when every <Boolean clause> is true under the same <Boolean valuation>; an empty <logical conjunction> is true. For example, $(x\lor\neg y)\land(z)$ has two <Boolean clauses> with widths two and one. Width counts <Boolean literal> occurrences within a <Boolean clause>, whereas the <Boolean clause> count counts the conjuncts. <2-SAT> bounds width by two, and <3-SAT> bounds width by three. A <Boolean formula> with an empty <Boolean clause> is an <unsatisfiable Boolean formula>.

= 3-CNF formula

A <Boolean formula> in <conjunctive normal form> with at most three <Boolean literals> per <Boolean clause>. A shorter nonempty <Boolean clause> can be padded by repeating a <Boolean literal>. The corresponding <Boolean satisfiability problem> is <3-SAT>.

= 2-CNF formula
{parent=Conjunctive normal form}
{title2=$\bigwedge_i(\ell_{i,1}\lor\ell_{i,2})$}

A <Boolean formula> in <conjunctive normal form> with at most two <Boolean literals> per <Boolean clause>. Shorter <Boolean clauses> are allowed. The <Boolean satisfiability problem> restricted to these <Boolean formulas> is <2-SAT>.

= Tseytin transformation
{parent=Conjunctive normal form}
{wiki}
{c}

= Tseitin transformation
{c}
{synonym}

Introduce a <Boolean variable> for each gate output and impose its equivalence to the gate's input function with a constant number of <clauses>. A final unit <clause> forces acceptance. For a bounded-fan-in <Boolean circuit>, the formula size is linear in the gate count and it is satisfiable exactly when some input makes the <Boolean circuit> output one. Auxiliary variables extend the satisfying assignments; this is equisatisfiability, not equality as functions of the enlarged variable set.

= Clause of a Boolean formula
{title2=$\ell_1\lor\cdots\lor\ell_k$}
{parent=Boolean formula}

= Clause
{synonym}

= Boolean clause
{c}
{synonym}

= Clauses of a Boolean formula
{synonym}

A <Boolean clause> is an expression $\ell_1\lor\cdots\lor\ell_k$ formed from <Boolean literals>, true when at least one <Boolean literal> is true. The empty <Boolean clause> is false. Repeating a <Boolean literal> does not change the <truth value>. A <CNF> <Boolean formula> is a <logical conjunction> of these <Boolean clauses>.

For $(\neg x\lor z)$, the only failing pair is $(x,z)=(1,0)$: its two <Boolean literals> then both have <truth value> zero. The one-<Boolean-literal> <Boolean clause> $(x)$ requires $x=1$. A <Boolean clause> containing both $x$ and $\neg x$ is a <tautology>, since one of those <Boolean literals> is true under every <Boolean valuation>. These observations separate <Boolean clause> satisfaction from the simultaneous satisfaction required by <SAT>.

= Boolean literal
{c}
{title2=$u\text{ or }\neg u$}
{parent=Boolean formula}

= Literal
{synonym}

A <Boolean literal> is a <Boolean variable> $u$ or its <logical negation> $\neg u$. The two <Boolean literals> have opposite <truth values>: a <Boolean valuation> $v$ gives $v(\neg u)=1-v(u)$ when false and true are encoded as zero and one. Thus $u=0$ makes the positive <Boolean literal> $u$ false and the negative <Boolean literal> $\neg u$ true. A <Boolean clause> combines <Boolean literals>, and a <Boolean-pair colouring gadget> represents a <Boolean variable> and its <logical negation> by two <vertices> with opposite Boolean colours.

= Boolean variable
{c}
{title2=$u\in\{0,1\}$}
{parent=Boolean formula}

A <Boolean variable> takes one of two <truth values>, false or true, encoded as zero or one. It is an input to a <Boolean formula>; a <Boolean literal> uses the <Boolean variable> either positively or with <logical negation>. A <Boolean valuation> assigns one <truth value> to each distinct <Boolean variable>, so three distinct <Boolean variables> give eight possible complete assignments regardless of how often each appears.

= 3-SAT
{c}
{parent=Boolean satisfiability problem}

3-SAT is the <Boolean satisfiability problem> restricted to <Boolean formulas> in <conjunctive normal form> with at most three <Boolean literals> per <Boolean clause>. It is <NP-complete>. A nonempty short <Boolean clause> can be padded to three positions by repeating a <Boolean literal>, without changing satisfiability.

The Horn-SAT forward-chaining algorithm starts with every variable false and repeatedly makes the conclusion of any enabled implication true. It reports failure if it enables a clause with no positive conclusion; otherwise the fixed point is the least satisfying assignment.

= NC1
{c}
{parent=Circuit complexity}
{title2=$\mathrm{NC}^1$}

Languages computable by polynomial-size <Boolean circuit> families of bounded fan-in and depth $O(\log n)$. One can specify the nonuniform or logspace-uniform convention explicitly. Balanced constant-size operations give examples such as the <MOD3 binary divisibility problem> without nonuniform advice.

= MOD3
{c}
{synonym}

For a binary numeral, its remainder is the sum of its bits weighted alternately by $+1$ and $-1$ from the least significant position. A <balanced finite-monoid reduction circuit> adds these residues modulo three in two-bit encodings. A final zero test gives a uniform linear-size logarithmic-depth <Boolean circuit>, proving membership in <NC1>.

= Balanced finite-monoid reduction circuit
{parent=NC1}
{title2=$\text{size }O(n),\quad\text{depth }O(\log n)$}

A fixed finite <monoid> operation has a constant-size Boolean truth-table <Boolean circuit> on its constant-bit encodings. Reduce $n$ elements in a balanced binary tree to get linear size and logarithmic depth. Associativity ensures that tree grouping does not change the product. <MOD3> uses addition in the three-element residue group, with input-position signs handled at the leaves.

= Combinational logic

A <Boolean circuit> whose current output depends only on its current input, with no stored state or feedback dependency. Its delay is bounded by the longest input-to-output path of <logic gates>. = Static-one logic hazard
{parent=Hazard (logic)}

A <logic hazard> in which an output intended to remain one briefly falls to zero. In a <sum of products>, cover every adjacent pair of one-cells in a <Karnaugh map> with a common product <implicant>. That term omits the changing input and remains one throughout the transition, holding the OR output high regardless of the other path delays. This argument assumes one input changes at a time and the circuit starts settled.

For a concrete circuit, let $x=\bar a\bar c$, $y=bc$, $z=\bar cd$, $w=y+z$ and $q=x+w$. Give every gate, including each inverter, <propagation delay> 10 ns. Starting from $a=b=c=d=1$, lower $c$ at time zero. Signal $y$ falls at 10 ns, while $z$ rises only at 20 ns. Their gap passes through the two OR gates, making $q$ fall during 30–40 ns even though its steady-state value remains one.

{title=A <static-one logic hazard> from unequal inversion and product paths}

Adding the two <consensus theorem> products $\bar ab$ and $bd$ preserves the <Boolean function> and holds the output high across every potentially hazardous single-input transition. The resulting five-term expression factors as $q=bc+(\bar a+d)(b+\bar c)$. When a change of $c$ could leave the output steadily one, $b=1$ and $\bar a+d=1$ keep the second product steadily one. In the zero-to-zero case with changing $c$, $b=0$ and $\bar a+d=0$ keep both output products zero. Changes of $a,b,d$ use only one polarity each and therefore have no opposite-polarity race. This factored implementation uses three OR gates, two AND gates and two NOT gates, with a 40 ns maximum input-to-output path at the stated delays.

= Propagation delay
{parent=Combinational logic}
{title2=$t_{\mathrm{pd}}$}

The elapsed time between a change at a <logic gate>'s input and the corresponding settled change at its output, under specified loading and transition conditions. Dependent gate delays add along a path. The <combinational critical path> gives the longest such input-to-output path; reconvergent paths of unequal delay can produce a <logic hazard> even when the final <Boolean function> value does not change.

= Combinational critical path
{parent=Combinational logic}

= Critical path
{synonym}

The <combinational critical path> is a longest propagation-delay path through a <combinational logic> circuit. Register-to-register clock timing also includes launch delay, setup time and clock uncertainty. Putting two functional units in series adds their dependent delays; operating them in parallel instead contributes the slower branch plus any subsequent selection delay.

= Barrel shifter
{parent=Combinational logic}

A <barrel shifter> moves a <machine word> by a variable number of <bit> positions through a bounded-depth <combinational logic> circuit. For a $2^k$-bit <machine word>, cascade $k$ banks of <multiplexers> selecting optional shifts of $1,2,\ldots,2^{k-1}$. The binary shift-amount <bits> select the stages; the chosen distances add. Logical shifts fill vacated positions with zero, whereas <bit rotations> reconnect the discarded positions. A 32-bit logical <barrel shifter> can use five banks of 32 two-input <multiplexers>.

= Count leading zeros
{parent=Combinational logic}
{title2=$\operatorname{clz}_n(x)$}

= Leading-zero count
{synonym}

The number of zero <bits> before the first one, reading a fixed-width <binary representation> from its <most significant bit>. The all-zero $n$-<bit> input has count $n$. Thus $\operatorname{clz}_8(00000101)=5$, and $\operatorname{clz}_8(00000000)=8$; the width is part of the definition.

= Byte-table leading-zero count
{parent=Count leading zeros}
{title2=$L(0)=8,\quad L(b)=7-\lfloor\log_2b\rfloor\ (b>0)$}

For <leading-zero count>, inspect a word's bytes from most significant to least significant. Every zero byte contributes eight; the first nonzero byte contributes its table value in the title. If all bytes are zero, a word of width $w$ contributes $w$. Defining the zero table entry explicitly makes the all-zero argument a regular case rather than an out-of-range logarithm.

= Hierarchical leading-zero counter
{parent=Count leading zeros}

For a block of $2^k$ <bits>, encode its <count leading zeros> result as a zero flag $z$ followed by $k$ low count <bits> $r$. An all-zero block has $(z,r)=(1,0)$; otherwise $z=0$. Two half-block encoders supply flags $z_H,z_L$ and low counts $h,\ell$. Combine them using $z=z_H\land z_L$, $r_{k-1}=z_H\land\neg z_L$, and $r_i=\operatorname{mux}(z_H,h_i,\ell_i)$ for $i<k-1$. A one-<bit> leaf has $z=\neg x$ and no low count <bits>. Checking whether the upper half is nonzero, only the lower half is nonzero, or both halves are zero proves the formula.

All count <bits> are selected in parallel, so $D(n)=D(n/2)+O(1)$ for <circuit depth>. The <circuit size> satisfies $S(n)=2S(n/2)+O(\log n)$; summing the work over levels gives $S(n)=O(n)$. Sharing the all-zero flags avoids a serial <adder> along the critical path.

= Adder
{parent=Combinational logic}

A <Boolean circuit> computing the <sum> of <binary representations>, possibly including input and output <carry> <bits>. Its delay depends on how carries are propagated; specifying an <adder> does not by itself imply constant <circuit depth> as the input width grows.

= Half adder
{parent=Adder}
{title2=$a+b=s+2c$}

A <combinational logic> circuit adding two input <bits> $a,b$ to a sum <bit> $s=a\oplus b$ and <carry> <bit> $c=a\land b$. An <exclusive or> gate and an <AND gate> implement it. The identity $a+b=(a\oplus b)+2(a\land b)$ follows by checking the four input pairs. A <half adder> has no input carry, so adding three equally weighted <bits> needs a different circuit or multiple stages.

= Multiplexer
{parent=Combinational logic}
{wiki}
{title2=$\operatorname{mux}(s,a,b)=(\neg s\land a)\lor(s\land b)$}

= Mux
{synonym}

A selector that routes one of several inputs to its output according to control <bits>. The displayed two-input version selects $a$ when $s=0$ and $b$ when $s=1$. A word selector applies the same control <bit> to parallel one-<bit> <multiplexers>; its <circuit size> grows with the word width while its added <circuit depth> remains constant.

= Digital comparator
{parent=Combinational logic}

= Binary comparator
{synonym}

A <combinational logic> device comparing two fixed-width <binary representations>. For unsigned inputs $a,b$, a two-output encoding is $L=1$ exactly when $a<b$ and $G=1$ exactly when $a>b$. Equality gives $(L,G)=(0,0)$; $(1,1)$ is unreachable. A one-<bit> implementation is $L=\neg a\land b$, $G=a\land\neg b$.

= Bit-serial comparator
{parent=Digital comparator}

A <digital comparator> processes one pair of <bits> per <clock cycle>, storing a comparison result in a <finite-state machine>. For least-significant-first unsigned input, a new unequal pair overrides the stored result, while equal <bits> preserve it: the newest unequal pair has the greatest place value seen so far.

= Comparator composition
{parent=Digital comparator}
{title2=$L=L_H\lor(E_H\land L_L),\quad G=G_H\lor(E_H\land G_L)$}

To combine more and less significant <digital comparators>, compute $E_H=\neg(L_H\lor G_H)$ and use the displayed formulas. Unequal upper blocks decide the order, because their difference outweighs every possible lower-block difference; equal upper blocks delegate the decision to the lower block. This is an <associative> operation on the three comparison outcomes. A <balanced binary tree> of these combinations has $O(n)$ <circuit size> and $O(\log n)$ <circuit depth> for $n$-<bit> inputs.

{wiki}

A physical or idealized component implementing a fixed <Boolean function> on one or more input <bits>. For example, an <AND gate> outputs one exactly when both input <bits> are one. A <Boolean circuit> connects <logic gates>; <circuit size> counts components and <circuit depth> measures the longest chain of dependencies.

= XNOR gate

{c}

{wiki}

A two-input <logic gate> whose output is one exactly when its two input <bits> agree. Its <Boolean function> is $(a\land b)\lor(\neg a\land\neg b)$, equivalently $(a\lor\neg b)\land(\neg a\lor b)$. This follows by considering the two cases in which inputs are equal. It implements <logical equivalence> of the input truth values.

The number of load inputs driven by one output of a <logic gate>. A large fan-out increases the capacitive load and can increase <propagation delay>; the allowable number also depends on the logic technology and input characteristics.

= NOR gate

A <logic gate> computing $\neg(a\lor b)=\neg a\land\neg b$. This is distinct from <exclusive or>.

= NAND gate

A <logic gate> computing the <logical negation> of the <logical conjunction> of its inputs. Thus $\operatorname{NAND}(x_1,\ldots,x_k)=\neg(x_1\land\cdots\land x_k)$. It implements a <logical disjunction> of complemented inputs by <De Morgan laws>.

= Circuit size
{parent=Boolean circuit}
{title2=$M$}

The size of a <Boolean circuit> counts its gates, or in another common convention its wires. The convention must be fixed when stating quantitative bounds. In switching arguments, new clauses created from a <decision tree> are not separate original gates to be charged in the failure union bound.

= Depth of a Boolean circuit

= Circuit depth
{synonym}

Circuit depth is the largest number of counted gates on any input-to-output path in the <Boolean circuit>. For an AND/OR circuit with negations on input literals, only the AND/OR gates are counted. This convention makes the restriction argument for the <Linial-Mansour-Nisan theorem> precise.

= Circuit value problem

= CIRCUIT VALUE
{c}
{synonym}

Given a finite acyclic <Boolean circuit> and its input assignment, determine the output bit. Topological gate evaluation places the problem in <P>; it is a standard <P-complete> problem under <logspace many-one reductions>. <Boolean circuit> evaluation is different from <circuit satisfiability problem>, which asks whether some assignment succeeds.

= AND-NOT circuit value problem
{c}

The <circuit value problem> restricted to AND and NOT gates remains <P-complete>. Replace each OR by $\neg(\neg x\wedge\neg y)$, using a constant-size gadget. Gate indices and gadget positions can be emitted in <logarithmic space>, and assignments are preserved. Constants, when needed, can be represented by fixed-valued input nodes.

= Threshold function

A threshold Boolean function outputs one exactly when a weighted sum of its input bits reaches a specified threshold. The unweighted threshold function $f_{n,r}$ tests whether at least $r$ of its $n$ inputs are one.

= Majority function
{parent=Threshold function}
{title2=$\operatorname{MAJ}$}
{wiki}

A majority <Boolean function> outputs one when more than half its input bits are one. An odd number of inputs avoids a tie convention. For three bits its unique <multilinear polynomial> is $x_1x_2+x_1x_3+x_2x_3-2x_1x_2x_3$, so the <polynomial method for quantum query lower bounds> requires at least two exact queries.

= Block conjunction of three-bit majorities
{parent=Majority function}
{title2=$\operatorname{MAJ}_n(x)=\bigwedge_{i=1}^n\operatorname{MAJ}(b_i)$}

Its $n$ disjoint triples give a product of degree-three <multilinear polynomials>, with all-variable coefficient $(-2)^n$. Hence its degree is $3n$ and its <exact quantum query complexity> is at least $\lceil3n/2\rceil$. At the input consisting of repeated $110$ triples, each of the $2n$ one bits is a disjoint sensitive singleton. Thus <block sensitivity> is at least $2n$, implying a bounded-error <quantum query complexity> lower bound $\Omega(\sqrt n)$.

= Dual Boolean function
{parent=Boolean circuit}

The dual of a Boolean function $f$ is $f^*(x)=\neg f(\neg x)$. Swapping AND with OR and zero with one in a monotone circuit for $f$ produces a circuit for $f^*$ by <De Morgan's laws>.

= Circuit family
{parent=Circuit complexity}

A circuit family $(C_n)$ contains one circuit for each input length $n$. The circuit for one length may be chosen independently of those for other lengths, so a family is a nonuniform model of computation.

= Circuit size class
{parent=Circuit family}
{title2=$\mathrm{SIZE}(T(n))$}

= SIZE
{c}
{synonym}

The languages whose length-$n$ <indicator functions> have <Boolean circuits> with at most $T(n)$ gates for sufficiently large $n$, over a fixed bounded-fan-in complete basis. The family need not be constructible by one algorithm. Polynomial-size bounds give <p-poly>; the <truth-table upper bound for circuit size> applies even to <undecidable> languages.

= Truth-table upper bound for circuit size
{parent=Circuit size class}
{title2=$L\in\mathrm{SIZE}(O(n2^n))$}

OR together one minterm for each accepted length-$n$ input. Each minterm is an AND of the appropriate <Boolean literals>. There are at most $2^n$ minterms, and their negated input wires can be shared, giving $O(n2^n)$ bounded-fan-in gates. This is a nonuniform existence statement, not an algorithm for determining an <undecidable> truth table.

= Polynomial-size circuit family
{parent=Circuit family}

A circuit family has polynomial size when $C_n$ has at most $n^{O(1)}$ gates.

= Undecidable unary languages with linear-size circuits
{parent=Polynomial-size circuit family}
{title2=$U_A=\{1^n:n\in A\}$}

For any set of lengths $A$, choose at length $n$ a constant-zero <Boolean circuit> when $n\notin A$, and an AND of all inputs when $n\in A$. This uses $O(n+1)$ gates. If $A$ is <undecidable>, so is $U_A$, yet it belongs to <p-poly>. Since all <NP> languages are decidable by certificate enumeration, this proves <p-poly> is not equal to <NP>; it does not resolve containment in the other direction.

= Constant-depth circuit complexity

Constant-depth circuit complexity studies circuit families whose depth is bounded independently of the input length.

= Håstad switching lemma
{parent=Constant-depth circuit complexity}
{c}
{wiki}

The Håstad switching lemma says that a small-width DNF or CNF becomes representable by a shallow <decision tree> with high probability under a sufficiently sparse random restriction. Iterating it is a central method for proving lower bounds against constant-depth circuits.

= Switching-lemma depth reduction
{parent=Håstad switching lemma}

Switching-lemma depth reduction applies the <Håstad switching lemma> to every bottom-layer gate, replaces each restricted gate by a shallow decision tree, and merges adjacent layers of the same gate type. Repetition reduces a constant-depth circuit to a bounded-depth decision tree while retaining many live variables.

= Monotone circuit complexity
{parent=Circuit complexity}

Monotone circuit complexity studies Boolean circuits built only from AND and OR gates, without negations. Such circuits compute <monotone Boolean function>[monotone Boolean functions], but some monotone functions require much larger monotone circuits than unrestricted circuits.

= Monotone circuit
{parent=Monotone circuit complexity}

A monotone <Boolean circuit> uses only AND and OR gates, variables, and optional constants. It computes a <monotone Boolean function>; negation gates are excluded.

= Superpolynomial monotone clique lower bound
{parent=Monotone circuit complexity}
{title2=$\operatorname{size}(\operatorname{CLIQUE}_{n,\lfloor n^{1/4}\rfloor})\geq\exp(c(\log n)^2)$}

In the <finite lattice approximation for monotone clique circuits>, set $m=r=\lfloor n^{1/4}\rfloor$ and $\ell=\lfloor\log_2n\rfloor$. A nonuniversal output accepts at most $\sum_{s=2}^\ell s!(r-1)^s(m/n)^s\leq2(\ell rm/n)^2$ of uniform positive <cliques>. Its missing positives require the circuit size times the <positive clique error of a truncated lattice meet> to be bounded below. A universal output accepts every negative colouring input; those errors require the circuit size times the <negative colouring error of a forced-set closure> to be at least one. Both alternatives imply the displayed superpolynomial bound by the <Razborov gate-by-gate approximation lemma>.

= Razborov approximation method
{parent=Monotone circuit complexity}
{c}

The Razborov approximation method replaces the AND and OR operations of a monotone circuit by tractable lattice operations. If each gate introduces only a controlled set of positive or negative errors, a small circuit cannot separate all positive inputs from all negative inputs.

= Finite lattice approximation for monotone clique circuits
{parent=Razborov approximation method}

Take upward-closed <set families> of subsets of $[n]$ of size at most $\ell$, closed under the forcing rule in <Razborov closure>. Normalize any family containing a set of size at most one to the full family, since its clique predicate is identically true. Intersection is the <meet in a lattice>; closure of the union is the <join in a lattice>. A family represents the <graphs> containing a <clique> on at least one of its members. The approximate meet can lose positive inputs and the approximate join can acquire negative inputs. The <Razborov gate-by-gate approximation lemma> charges output errors to those local errors.

= Negative colouring error of a forced-set closure
{parent=Finite lattice approximation for monotone clique circuits}
{title2=$\mathbb P(G_{\mathrm{colour}}\in\delta_\vee)\leq n^{\ell+1}2^{-r}$}

Independently colour each <vertex> with one of $m-1$ colours and join differently coloured <vertices>. This <complete multipartite graph> has no $m$-<clique>. If a forced set $W$ is rainbow but its $r$ witnesses are not, condition on the colours of $W$. The disjoint petals make those failure events <conditionally independent>. For each witness of size at most $\ell$, the probability of a colour collision is at most $\binom{\ell}{2}/(m-1)$. If this is at most $1/2$, one closure step causes an error with probability at most $2^{-r}$. There are at most $n^{\ell+1}$ possible steps; apply the <union bound>.

= Positive clique error of a truncated lattice meet
{parent=Finite lattice approximation for monotone clique circuits}
{title2=$\mathbb P(K_Z\in\delta_\wedge)\leq4q^{\ell/2},\quad q=\ell rm/n\leq1/2$}

Choose a uniform $m$-subset $Z$ and the <graph> consisting only of its <clique>. Acceptance by two approximating <set families> but rejection by their intersection requires two minimal witnesses whose union has size greater than $\ell$. At least one has size greater than $\ell/2$. The <sunflower bound for minimal members of a Razborov-closed family> and $\mathbb P(W\subseteq Z)\leq(m/n)^{|W|}$ give $2\sum_{s>\ell/2}s!(r-1)^s(m/n)^s\leq4q^{\ell/2}$.

= Razborov closure
{parent=Razborov approximation method}
{c}

Fix integers $r$ and $l$. The Razborov closure of a family of vertex sets of size at most $l$ repeatedly adjoins a set $W$ whenever there are $r$ existing sets $W_1,\ldots,W_r$ whose pairwise intersections are contained in $W$. A family equal to its closure is called $r$-closed.

= Sunflower bound for minimal members of a Razborov-closed family
{parent=Razborov closure}
{title2=$a_s\leq s!(r-1)^s$}

An inclusion-minimal $s$-set in an upward-closed family cannot belong to an $r$-member <delta-system> of such minimal sets: its proper core would be adjoined by <Razborov closure>, violating minimality. The <Erdős–Rado sunflower lemma> therefore bounds the number $a_s$ of minimal $s$-sets. This weaker factorial bound is sufficient for the <superpolynomial monotone clique lower bound>.

= Minimal-member bound for a Razborov-closed family
{parent=Razborov closure}

An $r$-closed family has at most $(r-1)^k$ inclusion-minimal members of cardinality $k$. This limits the number of cliques accepted by a proper closed approximation.

= Razborov gate-by-gate approximation lemma
{parent=Razborov approximation method}
{c}

The Razborov gate-by-gate approximation lemma compares a monotone circuit with the lattice computation obtained by replacing each gate by an approximate meet or join. Every disagreement at the output is charged to an error introduced by one of the circuit's gates.

= Polynomial hierarchy

The polynomial hierarchy consists of decision problems described by a constant number of alternating polynomially bounded existential and universal quantifiers with a polynomial-time predicate.

= Second level of the polynomial hierarchy

{parent=Polynomial hierarchy}

A language is in $\Sigma_2^{\mathbf P}$ when membership has the form $\exists u\,\forall v\,R(x,u,v)$ for a polynomial-time predicate $R$ and polynomially bounded strings. Reversing the quantifiers defines $\Pi_2^{\mathbf P}$.

= Two-block quantified Boolean formula
{parent=Second level of the polynomial hierarchy}
{title2=$\exists X\,\forall Y\,\psi(X,Y)$}

A <propositional formula> with two blocks of quantified <Boolean variables>. For completeness one may restrict the matrix $\psi$ to a disjunction of terms with at most three literals. = Miller-Rabin
{synonym}
{c}

For an odd candidate $n>3$, write $n-1=2^s d$ with $d$ odd. A base $a$ passes when $a^d\equiv1\pmod n$ or $a^{2^jd}\equiv-1\pmod n$ for some $0\le j<s$; a nontrivial common divisor of $a,n$ or failure of these conditions proves compositeness. A prime passes every base, while an odd composite passes at most one quarter of possible bases. Independent rounds give a false probable-prime probability at most $4^{-r}$. A passing composite is a <strong pseudoprime>, stronger than a <Fermat pseudoprime>.

= Fermat primality test
{parent=Primality testing}
{c}

The Fermat test looks for a coprime base $a$ with $a^{N-1}\not\equiv1\pmod N$. Such a witness proves compositeness by the <Fermat little theorem>, but <Carmichael numbers> pass for every coprime base.

= Pseudoprime base
{parent=Primality testing}
{title2=$b$}

A base $b$ coprime to the tested odd composite $N$ for which a specified probable-prime criterion passes. The sets of passing bases depend on the criterion and need not be subgroups.

= Agrawal–Biswas primality test
{parent=Primality testing}
{c}

The Agrawal–Biswas primality test checks the identity $(X+1)^n=X^n+1$ modulo $n$ and a random low-degree monic polynomial. Prime inputs always pass, while a composite input that is not a prime power fails with inverse-polynomial probability per trial.

= Abstract machine

An <abstract machine> specifies a computational state and rules for advancing that state without requiring one particular physical implementation. A <Turing machine> and a <stack machine> give different ways to organize the state and its transitions.

= State machine
{parent=Abstract machine}
{title2=$s_{t+1}=F(s_t)$}

A computational model with an internal state and transition rule, together with an initial state and optional observation and stopping functions. The state space need not be finite; a <finite-state machine> is the special case with finitely many states. A trace records observations along transitions. An interface providing only reset, update, stopping and observation operations does not by itself provide copying or rollback; a trace <iterator> can revisit saved observations without reversing machine effects.

Code whose operand-producing instructions precede the instruction that consumes those operands. A <stack machine> can translate a binary <program expression> by producing its left operand, producing its right operand, and then applying the operation to the two top values.

= Optimal stack evaluation of a binary expression tree
{parent=Stack machine}
{title2=$d(e\circ f)=\min\{\max(d(e),1+d(f)),\max(d(f),1+d(e))\}$}

Suppose each subtree of a <binary expression tree> is evaluated completely before its sibling, leaves one result on an operand <stack>, and is not spilled or interleaved. If the child depths are $p,q$, evaluating the first child needs $p$ slots and keeping its result while evaluating the second needs $1+q$. Reversing the order gives $\max(q,1+p)$. If either order preserves the expression's meaning, the minimum is $\max(p,q)$ when $p\ne q$ and $p+1$ when $p=q$. For example, if $p>q$, integrality gives $p\geq q+1$, so evaluating the deeper child first attains the lower bound $p$. If $p=q$, the second child needs its own $p$ slots plus one saved result regardless of order. Induction over the <binary expression tree> proves optimality in this evaluation model.

For a noncommutative operator, an instruction swapping the top two <stack> entries or a reverse-operand opcode permits the same ordering while preserving operand positions. Reordering still requires absence of order-sensitive <side effects>. Reassociation and interleaving are separate transformations and are not part of this optimality claim.
