Correct operations through an abstraction function (α(F(r,s))=f(α(r),α(s)))

For a deterministic binary operation on an abstract data type, let f be its specified operation on abstract values and F the implementation on concrete states. For every permitted valid input pair (r,s), require both
I(F(r,s))andα(F(r,s))=f(α(r),α(s)).
(3)
The first condition preserves the representation invariant. The second makes a commutative diagram: either execute F and then apply the abstraction function, or apply the abstraction function to both inputs and then execute the abstract operation f; both paths reach the same value. These conditions state functional correctness of a completed operation; termination is an additional obligation for algorithm correctness.[ref]
For addition in the unreduced rational representation, choose
f(x,y)=x+y,F((a,b),(c,d))=(ad+bc,bd).
(4)
For example, F((1,2),(1,3))=(5,6) represents 5/6, precisely the sum of 1/2 and 1/3. The short correctness argument uses nonzero denominators: b=0 and d=0 imply bd=0, preserving the representation invariant, and
α(F((a,b),(c,d)))=bdad+bc​=ba​+dc​=f(α(a,b),α(c,d)).
(5)
Now consider an incorrect implementation that uses addition on the numerators and multiplication on the denominators:
B((a,b),(c,d))=(a+c,bd).
(6)
It preserves the representation invariant for every valid input pair because its denominator is still bd=0. Yet B((1,2),(1,3))=(2,6) represents 1/3, not the specified sum 5/6. Even perfect checks of the representation invariant before and after this call would miss the error: the result is a legal representation of the wrong rational number.
The incorrect operation also exposes an accidental dependence on representation. Replace (1,2) by the equivalent state (2,4) while keeping (1,3). The correct operation gives (10,12), still representing 5/6; the incorrect operation gives (3,12), representing 1/4 instead of its previous 1/3. A correct addition must yield the same abstract result for equivalent inputs, although its concrete outputs may differ. This is why checks against the formal specification should compare abstract values, including unreduced representations and representations with a negative denominator, rather than demand identical stored pairs.
The calculation assumes exact integers. An implementation with bounded storage must additionally specify how it handles products and sums outside its supported range; the mathematical argument alone does not establish its functional correctness. The bounded queue with encapsulation illustrates the corresponding need to account for returned status values and failed operations, alongside the abstract state transition.
