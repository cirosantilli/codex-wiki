Counting sort (T(n,K)=O(n+K))

 Home Computer science Algorithm Sorting algorithm
OurBigBook.com Words: 1k Articles: 2
Counting sort uses integer sort keys in {0,…,K−1} directly as indices into an array of counts. Constant-cost counting and indexing give O(n+K) time complexity in Big O notation. To retain complete sorting records, cumulative counts locate their output ranges; filling each range from its end while scanning the input backwards gives stable sorting. Emitting bare sort keys from counts would discard associated data. The K term matters when the key range is large.[ref]
For an original worked example, take n=7 complete sorting records and K=4 possible integer sort keys:
A=((2,A),(0,B),(2,C),(1,D),(0,E),(3,F),(2,G)).
(33)
The letters label the associated data, and are never compared. Both input and output array indices start at zero, so their valid positions are 0,…,6; the count array has array indices 0,…,3. Stable sorting must produce
B=((0,B),(0,E),(1,D),(2,A),(2,C),(2,G),(3,F)).
(34)
The equal-sort key groups retain B,E and A,C,G in arrival order. Counting sort prefix ranges explain where those groups belong; stable record placement in counting sort explains how to fill them without losing that order or the complete sorting records.
