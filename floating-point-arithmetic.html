Floating-point arithmetic (±(d0​.d1​⋯dp−1​)β​βe)

 Home Mathematics Area of mathematics Analysis Numerical analysis
OurBigBook.com Words: 2k Articles: 9
Floating-point arithmetic represents a real number by a sign, a fixed number of significant digits, and a scale. It trades exactness for a compact representation spanning many orders of magnitude. The picture shows the essential compromise: with the same precision, large numbers have wider gaps between representable neighbors. Thus accuracy is naturally relative to magnitude, rather than a fixed distance along the number line.
In radix β, an integer at least two, a nonzero normalized value has the positional notation
y=±(d0​+βd1​​+⋯+βp−1dp−1​​)βe,1≤d0​<β,0≤dj​<β (j≥1),
(1)
where the digits and exponent e are integers. The parenthesized factor is the significand; p counts all its significant digits, including the leading digit. Normalization means d0​=0, so the same value has one such representation. The allowed exponents satisfy emin​≤e≤emax​. Finite precision restricts the available digits, while the exponent bounds restrict the range. Zero needs a separate representation. This scales a digit string in positional notation by a power of its base.[ref]
For positive normalized values in [βe,βe+1), increasing the last digit by one gives the constant neighbor spacing
Δe​=βe−p+1.
(2)
At the next scale, the spacing is multiplied by β. In the binary numeral system with p=4, the values in [1,2) are 1,1.125,1.25,…,1.875; those in [2,4) are 2,2.25,…,3.75; those in [4,8) are 4,4.5,…,7.5. The respective gaps are 1/8, 1/4, and 1/2. Although absolute resolution deteriorates with magnitude, Δe​/y stays between β−p and β1−p. This scale invariance is why floating-point arithmetic suits both microscopic and astronomical calculations.
The IEEE 754 binary64 format uses the binary numeral system with p=53, including an implicit leading one for normalized values, and normal exponents −1022≤e≤1023. Its 64 stored binary digits comprise one sign digit, 11 exponent digits and 52 trailing significand digits. Subnormal numbers extend the range toward zero with a different leading-digit rule. In rounding to nearest, an operation returns the representable value closest to its exact result; a tie goes to the value whose last significant binary digit is even. Machine epsilon describes the gap just above one, whereas unit roundoff bounds a single relative rounding error in the normal range. These format and rounding rules are presented in MIT's floating-point lecture.[ref]
Even an ordinary terminating decimal can require rounding in the binary numeral system. The rational number 0.1=1/10 has the repeating positional notation 0.0001100110011…2​. Every finite binary fraction has a reduced denominator that is a power of two, so the factor five in 10 prevents an exact finite binary representation. In binary64, the exact stored values of three decimal literals and their computed sum are
Python expression0.10.20.30.1+0.2​exact stored rational number3602879701896397/360287970189639683602879701896397/180143985094819845404319552844595/180143985094819841351079888211149/4503599627370496​​
(3)
The exact sum of the first two stored rational numbers is 10808639105689191/36028797018963968, halfway between two binary64 values. The even-last-digit tie rule rounds it upward. The printed result is 0.30000000000000004, one step 2−54 above stored 0.3, so 0.1 + 0.2 == 0.3 is false. Both conversion of the inputs and rounding of the addition matter here.
To reproduce the table on a Python installation using binary64, inspect exact fractions rather than only their printed decimal representations:
import sys
assert (sys.float_info.radix, sys.float_info.mant_dig) == (2, 53)
for value in (0.1, 0.2, 0.3, 0.1 + 0.2):
    print(repr(value), value.as_integer_ratio())
print(0.1 + 0.2 == 0.3)  # False
Python's as_integer_ratio() returns a pair of integers whose quotient equals the stored finite value exactly.[ref] Exact rational numbers are also useful for checking floating-point arithmetic: a short decimal printout can hide the approximation being made.
Historically, David Goldberg's March 1991 ACM Computing Surveys paper explained representation, rounding and catastrophic cancellation together with the IEEE standard's design choices. Oracle provides an authorized edited reprint. Its enduring lesson is practical: use the spacing to understand roundoff error, and inspect intermediate values when mathematically equivalent algorithms behave differently.[ref]

Floating-point underflow

Words: 48
Floating-point arithmetic OurBigBook.com
Floating-point underflow occurs when a nonzero numerical result is smaller in magnitude than the representable range or loses precision in the subnormal range. A long product of probabilities can become zero despite a mathematically positive result. Adding logarithms avoids forming the product; adding alternative path probabilities then requires log-sum-exp or controlled rescaling.

Compensated summation

Floating-point arithmetic OurBigBook.com
Compensated summation retains a correction for low-order information lost to roundoff error in successive floating-point arithmetic additions. Kahan summation is a common implementation; it can substantially reduce accumulated error when many terms are added.

Machine epsilon (ϵmach​=β1−p)

Words: 176
Floating-point arithmetic OurBigBook.com
Here machine epsilon means the gap from one to the next larger value in normalized floating-point arithmetic:
ϵmach​=next(1)−1=β1−p.
(4)
It is a relative resolution scale near one, not the smallest positive representable value and not a fixed absolute error for all magnitudes. In binary64, p=53 gives
ϵmach​=2−52≈2.220446049250313×10−16,u=2−53≈1.1102230246251565×10−16,
(5)
where u is unit roundoff for rounding to nearest. Some authors instead call u their machine epsilon; MIT 18.335J uses this half-gap convention. Always check which definition an error bound uses.[ref]
The gap below one is smaller: the preceding binary64 value is 1−2−53, whereas the next value above one is 1+2−52. Under nearest-even rounding, 1.0 + 2.0**-53 is exactly 1.0: the exact sum is a tie and one has the even final binary digit. By contrast, 1.0 + 2.0**-52 is the next value. Thus searching for the smallest increment that changes one by trial addition also depends on the rounding convention. At 253 the next larger binary64 value is 253+2, illustrating why a small absolute increment can disappear at large magnitude.

Unit roundoff (u=21​β1−p)

Words: 117
Floating-point arithmetic OurBigBook.com
For floating-point arithmetic with precision p in radix β and rounding to nearest, unit roundoff is the half-gap scale u=β1−p/2. If a nonzero exact real number z lies in the normal finite range, its nearest rounded value satisfies
fl(z)=z(1+δ),∣δ∣≤u.
(6)
Indeed, the absolute distance to the nearest value is at most Δe​/2, and ∣z∣≥βe gives the bound. For a correctly rounded addition, subtraction, multiplication or division, apply this estimate to the exact result of that one operation on the stored operands. The bound does not include earlier roundoff error or automatically bound a whole algorithm. Results outside the finite range and tiny subnormal numbers require separate treatment. Rounding in a directed mode also changes the bound.[ref]

Subnormal number (kβemin​−p+1,1≤k<βp−1)

Words: 150
Floating-point arithmetic OurBigBook.com
A subnormal number is a nonzero representable value smaller in magnitude than the least positive normalized value βemin​. Keep the exponent scale fixed at emin​ and allow a zero leading digit: the positive values are kβemin​−p+1 for integers 1≤k<βp−1. This fills the gap toward zero with constant absolute spacing, at the cost of fewer significant digits. Goldberg describes this gradual approach to zero and why it matters for differences of small numbers.[ref]
For binary64 the least positive normalized value is 2−1022, and subnormal numbers are spaced by 2−1074. With nearest rounding and gradual underflow enabled, an exact result z with ∣z∣<2−1022 has absolute rounding error at most 2−1075. A uniform relative bound by unit roundoff fails here: z=2−1075 rounds to zero under the even-last-digit tie rule, giving relative error one. Machine epsilon measures resolution near one; it does not measure the distance from zero to the first positive value.

Catastrophic cancellation (1+x​−1=1+x​+1x​)

Words: 384
Floating-point arithmetic OurBigBook.com
Catastrophic cancellation occurs when subtraction of nearly equal approximations removes their matching leading digits and exposes earlier roundoff error. The subtraction can itself be exact on the stored operands: the information may already have been lost while obtaining them. Goldberg distinguishes this from cancellation of accurately known quantities, which can be harmless.[ref]
For x>0, consider the single real-valued function
f(x)=1+x​−1=1+x​+1x​.
(7)
The rationalization of a square-root difference proves equality in exact arithmetic. The two evaluations use the same input x, but the direct version first forms a value near one and then subtracts one. The rearranged version keeps the small input in its numerator and divides by a denominator near two.
For binary64 x = 1e-16, the rounded sum 1.0 + x is one, so sqrt(1.0 + x) - 1.0 is zero. The rationalized evaluation returns approximately 5×10−17. A 100-digit Decimal calculation using the exact stored input gives relative errors of one and about 2.50×10−17 respectively. At x = 1e-12, the direct result is about 5.0004445029×10−13, with relative error 8.89×10−5; the rearranged result is about 4.99999999999875×10−13, with relative error 1.21×10−17.
The plot uses Decimal.from_float(x) to preserve the binary input exactly, computes x/(1+x​+1) at 100 decimal digits, and verifies the reference at 160 digits. Exact conversion of a stored binary value is documented by Python.[ref] Each error is ∣f​−f∣/∣f∣, with the computed result converted exactly to Decimal before comparison. Hence the curves measure evaluation error for one common input, rather than a mixture of input conversion error and evaluation error. The plotted interval 10−16≤x≤10−1 is far above the subnormal number range.
The original problem is well conditioned with respect to relative changes in x. Using the derivative f′(x)=1/(21+x​) and rationalization of a square-root difference, its relative condition number is
κf​(x)=​f(x)xf′(x)​​=21+x​1+x​+1​,21​<κf​(x)<1(x>0).
(8)
It tends to one as x tends to zero. The direct evaluation instead introduces the intermediate difference s−1 with s=1+x​; an error of order unit roundoff in s is large relative to f(x)≈x/2. This is a failure of the chosen algorithm's accuracy despite a small condition number for the same real-valued function. The rationalized evaluation avoids that intermediate catastrophic cancellation, retaining relative accuracy near the unit roundoff scale throughout the plotted interval. Recognizing this structure can improve a calculation far more than merely printing extra digits.
