Prefix maximum correctness example

 Home Computer science Algorithm Algorithm correctness
OurBigBook.com Words: 559
Given a nonempty finite sequence a=(a0​,…,an−1​) of integers, return its maximum value. Represent the sequence by an array whose contents remain unchanged during execution. The precondition requires an integer length n≥1 and exact, terminating integer comparisons and variable assignments. The postcondition for returned value r is
r∈{ai​:0≤i<n}andai​≤r for every 0≤i<n.
(12)
Thus the output belongs to the finite set of entries and is at least every entry. The contract permits ties and negative integers; it asks for a value, not the position of a particular occurrence. There is no maximum of an empty set of integers, so empty input is deliberately outside this precondition. A service accepting empty inputs needs a different formal specification, such as a separate absent result.
This Python implementation makes the variable assignments explicit. Its index arithmetic models exact integer arithmetic; fixed-width implementations additionally need enough index range for n:
def find_max(a):
    n = len(a)
    best = a[0]
    k = 1
    while k < n:
        if a[k] > best:
            best = a[k]
        k = k + 1
    return best
For the original input [3,1,4,4,2], initialization gives k=1 and best=3. Reading a1​=1 keeps 3; reading a2​=4 changes it to 4; reading a3​=4 and a4​=2 keeps 4. At successive condition checks, the pairs (k,best) are (1,3),(2,3),(3,4),(4,4),(5,4). The returned maximum is 4.
At each condition check, use the loop invariant
I:1≤k≤n,best=max{ai​:0≤i<k},
(13)
together with the fact that the input array is unchanged. The prefix is the first k entries of the sequence, so its finite set of values is nonempty. The maximum need not be unique as an occurrence: the invariant concerns its value.
Initialization establishes I: k=1 and best=a0​, the maximum of a one-element set. For preservation, suppose I and k<n hold. Then ak​ is a valid array entry. Either the comparison replaces best with the larger value ak​, or it keeps a value at least ak​. Before increasing k, the resulting value is
max(max{ai​:0≤i<k},ak​)=max{ai​:0≤i<k+1}.
(14)
The variable assignment k←k+1 restores the complete loop invariant. Between the two variable assignments, the old prefix formula may temporarily be false; the loop invariant is required at condition checks, not at every instruction.
At exit, k≥n, while I gives k≤n. Hence k=n, and I gives exactly the required postcondition. This establishes partial correctness. The preservation argument is mathematical induction on the number of completed iterations, covering every permitted integer sequence, rather than just the pictured input.
For algorithm termination, the loop variant V=n−k is a nonnegative integer whenever I holds. If k<n, then V≥1. Every body terminates under the precondition and changes V to V−1. Starting at n−1, it reaches zero after exactly n−1 iterations. For n=1, the initial value is already zero and the body is never entered. Together with partial correctness, this proves total correctness.
Starting best at zero instead of a0​ fails on the original negative input [−7,−3,−3,−8]: it returns zero, which is neither an entry nor the maximum −3. Keeping k=1 forever preserves the correct initial prefix claim but loops forever when n>1; a loop invariant alone does not ensure algorithm termination. Using >= instead of > still returns the same maximum value when entries tie, although a version returning a position would need an explicit tie rule.
