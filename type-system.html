Type system

 Home Computer science Programming language
OurBigBook.com Words: 2k Articles: 16
A type system assigns types to program expressions and supplies rules governing their use. A type constrains permitted operations: in our teaching programming language, int admits integer addition, bool supplies true and false for conditions, and a function type specifies an argument type and a result type. Storage as bits alone does not explain these distinctions; the type system determines whether an expression can serve as an argument, a condition or an operand.
A typing judgment Γ⊢e:τ says that expression e has type τ under the assumptions in the typing context Γ. For example,
Γ={x:int,y:int},Γ⊢x+y:int.
(1)
The assumptions give each operand type int; the addition rule then gives the sum type int. Changing y to type bool prevents this derivation. Our teaching programming language has distinct int and bool types and no implicit conversions between them.
The conditional rule requires a Boolean condition and the same type for both branches:
Γ⊢if c then e1​ else e2​:τΓ⊢c:boolΓ⊢e1​:τΓ⊢e2​:τ​.
(2)
Thus if true then 1 else 2 has type int, while if true then 1 else false is rejected: its branches would require τ=int and τ=bool simultaneously. Even a branch that will not execute is checked by this rule. This is a rule of this particular type system; a different programming language can choose different rules. [ref]
The useful feature is compositional reasoning: after checking the parts, a rule explains how to check the whole. The function type diagram shows this for a call. Type inference can discover the required types automatically, and type variables let one express relationships that recur across many concrete types. The result is both a practical early error detector and a small, readable derivation explaining why an expression fits its intended use.
The guarantee depends on the rules and execution model. Type safety can exclude specified failures such as adding a Boolean or calling an integer as a function. It does not by itself establish every desired runtime property or guarantee that execution terminates. A type system that permits unrestricted recursion can accept a computation that runs forever; exception handling also needs its own account of permitted outcomes.
