Linear search comparison count (C)

 Home Computer science Algorithm Linear search
OurBigBook.com Words: 417
Count just the equality tests between the target and an entry, excluding loop conditions and index updates. If the first match is at index j, linear search uses exactly C=j+1 equality tests. If the target is absent, it uses exactly C=n. Thus for n≥1 the best successful case costs one equality test, and the worst case costs n, attained by absence or a first match at the last index. For n=0, the sole outcome is absence with C=0.
An expected value needs a specified probability distribution. For n≥1, condition on success, assume the target occurs exactly once, and assume its position J has a uniform distribution on a finite set of indices 0,…,n−1. Then the expected value of the linear search comparison count is
E[C∣success]=n1​∑j=0n−1​(j+1)=2n+1​.
(22)
This is the average of the costs 1,2,…,n under those assumptions, with no assumption that the array is sorted. It is not a universal average for arbitrary queries. For example, with n=5, a unique successful target at index 0 with probability 3/4 and at index 4 with probability 1/4 has expected value (3/4)⋅1+(1/4)⋅5=2, rather than 3.
Duplicates also require care about what is sampled. Choose a position uniformly in [7,4,7,2,9], then search for its value. All queries succeed, but the five possible sampled positions give costs 1,2,1,4,5: both positions holding 7 cause an immediate match at index 0. The expected value is 13/5, not (5+1)/2. Uniformly choosing an occurrence does not uniformly locate the first match.
More generally, let the success probability be p>0 and let qj​ be the conditional probability that the first matching index is j, allowing duplicates. Since ∑j=0n−1​qj​=1, the expected value is
E[C]=p∑j=0n−1​(j+1)qj​+(1−p)n.
(23)
Under the unique, uniformly located successful-target assumptions this becomes p(n+1)/2+(1−p)n. If every query is absent, p=0 and C=n without needing conditional probabilities. When n=0, success is impossible and C=0; the successful-search conditional formula is undefined.
Converting the linear search comparison count to execution time needs a cost model. Under constant-cost equality tests, next-entry access, and loop bookkeeping, worst-case time complexity is O(n) in Big O notation for n≥1, with constant overhead even for the empty sequence. Variable-length entries can make an equality test expensive. On a linked list, advance along its links; repeatedly restarting at the head to obtain the next numeric index adds work that the comparison count does not capture. These are exact operation counts and conditional mathematical averages, not runtime measurements.
