Merge sort (T(n)=O(nlogn))

 Home Computer science Algorithm Sorting algorithm
OurBigBook.com Words: 626
Merge sort is a divide-and-conquer algorithm that sorts a finite array by splitting it into contiguous halves, sorting each half using recursion, and combining the two sorted arrays with the merge algorithm. An empty or one-entry array is returned immediately. For length n≥2, put the first ⌊n/2⌋ entries on the left and the remaining ⌈n/2⌉ on the right; the brackets are the floor function and ceiling function. Always choose the left head on equal keys to obtain stable sorting. This is the split, sort, combine structure taught in the MIT lecture notes.[ref]
Take the concrete input array
A=(7,2a​,5,2b​,9,1,4,3).
(45)
The tags identify the entries originally at indices 1 and 3, counting from zero. Both keys are 2; the tags are never compared. The first two halves are (7,2a​,5,2b​) and (9,1,4,3). Their pairs split into one-entry base cases. Applying the merge algorithm gives the following fully worked return levels; each number in the last column counts only comparisons between two available heads.
Returning levelResulting sorted arraysHead comparisons
Pairs(2a​,7), (2b​,5), (1,9), (3,4)1+1+1+1=4
Halves(2a​,2b​,5,7), (1,3,4,9)3+3=6
Whole array(1,2a​,2b​,3,4,5,7,9)7
In the left-half merge algorithm, the head pairs are (2a​,2b​), (7,2b​) and (7,5); it takes 2a​,2b​,5, then appends 7. In the final merge algorithm, the head pairs are (2a​,1), (2a​,3), (2b​,3), (5,3), (5,4), (5,9) and (7,9). It takes 1,2a​,2b​,3,4,5,7, then appends 9. Thus this precise version makes 4+6+7=17 head comparisons and, ignoring identity tags, returns (1,2,2,3,4,5,7,9).
The elegance of merge sort is that it creates exactly the structure its next step needs: two smaller sorted arrays make the larger ordering inexpensive. Once the whole array is sorted, equal keys are adjacent and binary search can serve repeated queries. Stable sorting also retains information that the keys alone do not express. If the left-half merge algorithm instead takes the right head on the 2a​=2b​ tie, it returns (2b​,2a​,5,7); the keys are sorted but stable sorting has failed.
For time complexity, assume each key comparison, entry access and entry copy has constant cost. The merge algorithm processes n entries in O(n) time. In Big O notation, the resulting recurrence relation is
T(0),T(1)=O(1),T(n)=T(⌊n/2⌋)+T(⌈n/2⌉)+O(n)(n≥2).
(46)
For n=2k, the balanced levels contain n entries each and there are k=log2​n returning levels. Each costs O(n), so the worst-case time complexity is O(nlogn). For arbitrary n, there are at most ⌈log2​n⌉ returning levels, each processing at most n entries, giving the same bound. The worst-case number of head comparisons is also O(nlogn). Here log2​ is the base-two logarithm. The MIT notes give this level-by-level analysis for merge sort.[ref]
The conventional array implementation uses a reusable buffer of n entries for the merge algorithm, together with O(logn) pending calls for recursion. Its auxiliary space complexity is therefore O(n), beyond the original array. This bound describes that implementation. A linked list permits a merge algorithm that reconnects existing nodes; its storage accounting differs from copying array entries into a buffer.
For a short algorithm correctness outline, the empty and one-entry base cases are sorted. Assuming recursion correctly sorts both shorter halves, the merge algorithm returns all their entries in order. Equal keys within a half keep their relative order by the same argument applied to the smaller call; across halves, every left entry originally preceded every right entry, so taking left first preserves stable sorting. Both half-lengths decrease for n≥2, establishing termination.
