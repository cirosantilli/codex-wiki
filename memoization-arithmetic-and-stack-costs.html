Memoization arithmetic and stack costs

 Home Computer science Algorithm Memoization
OurBigBook.com Words: 208
Under constant-cost lookup and integer addition, Memoized Fibonacci evaluation has time complexity O(n) in Big O notation, retaining O(n) values. A hash table needs its own lookup-cost assumptions; an array indexed by 0,…,n avoids hash collisions in this example. Memoization removes repeated bodies, but also pays for keys, lookups and retained answers. A workload without reuse can pay those costs without saving evaluations.
The call stack remains. Left-first recursion descends through arguments n,n−1,…,1 before returning, giving n simultaneously active frames for n≥2. Therefore the auxiliary space complexity includes O(n) frames as well as O(n) table entries in the constant-size-value model. An iterative bottom-up dynamic programming calculation removes these recursive frames; retaining only the two previous Fibonacci numbers suffices when only the final value is wanted, but discards the table useful for later requests.
Exact Fibonacci numbers do not remain constant-size values. For k≥2, the recurrence relation gives 2(k−2)/2≤Fk​≤2k−1, so the representation of Fk​ as a binary number has order k bits. With ordinary addition costing order k bit operations on such operands, the n−1 additions cost order n2 bit operations in total. Retaining all values also requires order n2 bits of value storage, before keys and frame overhead. The linear bound counts additions under its stated cost model; it is not a linear bound on exact integer arithmetic in bits.[ref]
