Insertion sort

 Home Computer science Algorithm Sorting algorithm
OurBigBook.com Words: 321
Insertion sort grows a sorted prefix of an array one entry at a time. In the adjacent-swap version, start with position i=1, compare its current sort key with the preceding sort key, and swap the complete sorting records only when the right sort key is strictly smaller. Continue leftward until no swap is needed or the entry reaches position zero; then process original position i+1. A tie stops the pass. This is the strict comparison and exchange rule in the authored implementation.[ref]
Take A=(2A​,1B​,2C​,1D​), where the subscript labels a complete sorting record and comparisons inspect only its sort key. Starting from index zero, the complete key-comparison trace is:
ComparisonRight sort key smaller than left?ActionArray after the action
1, insert position 11B​<2A​: yesSwap positions 0,1.(1B​,2A​,2C​,1D​)
2, insert position 22C​<2A​: noStop this pass on a tie.(1B​,2A​,2C​,1D​)
3, insert position 31D​<2C​: yesSwap positions 2,3.(1B​,2A​,1D​,2C​)
4, continue leftward1D​<2A​: yesSwap positions 1,2.(1B​,1D​,2A​,2C​)
5, continue leftward1D​<1B​: noStop this pass on a tie.(1B​,1D​,2A​,2C​)
The loop invariant is that, before pass i, positions 0,…,i−1 satisfy sortedness and contain precisely the entries originally in that prefix. Moving the next entry left through strictly larger sort keys extends that prefix, and every swap retains sorting permutation preservation. Equal-key entries never cross, giving stable sorting. Each leftward step decreases the position, and each completed pass increases the prefix length, so the algorithm terminates.
With constant-cost key comparisons and swaps, reverse-ordered distinct sort keys cause 1+2+⋯+(n−1)=n(n−1)/2 comparisons and swaps. Thus worst-case time complexity is O(n2) in Big O notation. An already sorted array needs only n−1 key comparisons for n≥1 and no swaps. The adjacent-swap version uses constant auxiliary space complexity. Small or nearly sorted arrays can therefore make insertion sort useful despite its quadratic worst case.
