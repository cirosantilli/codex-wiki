At equal sample count, rejection sampling eventually has smaller variance for fixed σ2>1; at equal expected proposal cost, importance sampling eventually wins. The distinction matters because a sample of the rejection sampling estimator means an accepted draw.
For the importance sampling estimator, all coordinates contribute to the importance weight although only one enters the integrand. The same normal distribution transform as in (c), now with linear coefficient −2 for coordinate one, gives
Eq​[(w(Z)e−Z1​)2]=Adexp(2s−12s​),A=2s−1​s​.
(10)
Both estimators are unbiased estimators of e​, and
Var(θnIS​)=nAde2s/(2s−1)−e​,Var(θnRS​)=ne2−e​.​
(11)
For fixed s>1, the first variance grows exponentially while the second stays constant. This is the benefit of returning exact target draws in rejection sampling. However, obtaining those draws costs sd/2 proposals each on average.
To compare computational work, multiply each variance by its expected proposal count. For importance sampling that count is n; for rejection sampling it is nsd/2. The ratio of the resulting cost-normalized variances is
sd/2(e2−e)Ade2s/(2s−1)−e​⟶0(d→∞),​
(12)
because A/s​=s/(2s−1)​<1. Thus importance sampling eventually gives better precision for the same expected number of proposals, assuming comparable work per proposal. This is an asymptotic cost comparison, not a guarantee that a fixed small computing budget produces any accepted draws. Both methods still deteriorate exponentially in this comparison. For s=1 they coincide and every proposal is accepted.
A practical improvement is to exploit the integrand's one-coordinate structure directly: average e−G1​ for standard normal distribution draws G1​, without generating unused coordinates. The optimal change of proposal distribution in (iii) improves further.

The following R function performs inverse transform sampling with vectorized numerical computation. It checks finite real scalar parameters, including a nonnegative integer sample count, and gives beta its requested default.
r_sample_f <- function(n, p, beta = 1) {
  scalar <- function(v) {
    is.numeric(v) && !is.complex(v) && length(v) == 1L &&
      is.finite(v)
  }
  if (!scalar(n) || n < 0 || n != floor(n))
    stop("n must be a nonnegative integer")
  if (!scalar(p) || p <= 0 || p >= 1)
    stop("p must lie strictly between 0 and 1")
  if (!scalar(beta) || beta <= 0)
    stop("beta must be positive")
  if (n == 0) return(numeric(0))
  v <- runif(n)
  (log1p(-p) - log(-expm1(v * log(p)))) / beta
}
Here V=1−U is again a uniform distribution draw, so the expression is the quantile function from (ii). The function expm1(t) evaluates et−1 accurately when t is small, avoiding cancellation in 1−pV; log1p(-p) evaluates log(1−p). For default bounds, runif excludes both endpoints, so this implementation does not deliberately generate the infinite endpoint of the quantile function. It returns a numeric vector of length n, including an empty vector when n = 0. [ref] [ref]

A numerical power series evaluation needs a stopping rule. For r=∣z∣<1 and integer a≥0, the absolute remainder after N terms satisfies the polylogarithm series remainder bound
​Lia​(z)−k=1∑N​kazk​​≤(N+1)a(1−r)rN+1​.​
(32)
Indeed k−a≤(N+1)−a for k>N, and the remaining powers sum as a geometric series. This also covers negative z. The code sums terms in vectors of at most 4096 entries, checking the bound after each block; there is no loop over individual terms.
polylog <- function(a, z, tol = 1e-10, max_terms = 1000000) {
  scalar <- function(v) {
    is.numeric(v) && !is.complex(v) && length(v) == 1L &&
      is.finite(v)
  }
  if (!scalar(a) || a < 0 || a != floor(a))
    stop("a must be a nonnegative integer")
  if (!scalar(z) || abs(z) >= 1)
    stop("z must be real with abs(z) < 1")
  if (!scalar(tol) || tol <= 0 || tol >= 1)
    stop("tol must lie strictly between 0 and 1")
  if (!scalar(max_terms) || max_terms < 1 ||
      max_terms != floor(max_terms))
    stop("max_terms must be a positive integer")
  if (z == 0) return(0)
  r <- abs(z)
  N <- 0
  ans <- 0
  repeat {
    if (N >= max_terms)
      stop("requested truncation tolerance not reached")
    B <- min(4096, max_terms - N)
    k <- seq.int(N + 1, N + B)
    ans <- ans + sum(z^k * exp(-a * log(k)))
    N <- N + B
    log_bound <- (N + 1) * log(r) - a * log(N + 1) - log1p(-r)
    if (log_bound <= log(tol)) return(ans)
  }
}
This accepts every positive integer order in the question, and also order zero if 0∈N is the convention adopted. The bound controls absolute truncation error; floating-point rounding is a separate source of error. Close to ∣z∣=1, convergence can be slow. If the resource limit is reached, the function reports failure instead of silently claiming the requested accuracy. Useful exact checks are Li1​(z)=−log(1−z) and Li0​(z)=z/(1−z).

Assume a,b,μ>0 and a current state with 0<p<1, β>0. The unnormalized posterior density is
π(p,β∣x) ∝ exp{ℓ(p,β;x)}pa−1(1−p)b−1μ−1e−β/μ.
(37)
Thus the log-posterior, up to an additive constant, is the log-likelihood plus the beta distribution and exponential distribution log prior densities. The exponential distribution rate is 1/μ, since μ is its mean. [ref] [ref]
Choose a symmetric joint random-walk Metropolis algorithm proposal: p′=p+0.1G1​ and β′=β+(μ/2)G2​, for independent standard normal distribution draws. Its scale depends only on fixed hyperparameters, so forward and reverse proposal probability density functions agree. Reject immediately outside (0,1)×(0,∞); otherwise accept with Metropolis–Hastings acceptance probability
α=min{1,exp[logπ(p′,β′∣x)−logπ(p,β∣x)]}.​
(38)
The following function makes exactly one proposal, with rejection retaining both old parameters:
MHstep <- function(x, p, beta, a, b, mu) {
  p_new <- rnorm(1, mean = p, sd = 0.1)
  beta_new <- rnorm(1, mean = beta, sd = mu / 2)
  if (p_new <= 0 || p_new >= 1 || beta_new <= 0)
    return(list(p = p, theta = beta))
  logpost <- function(pp, bb) {
    ll_f(pp, bb, x) + dbeta(pp, a, b, log = TRUE) +
      dexp(bb, rate = 1 / mu, log = TRUE)
  }
  logA <- logpost(p_new, beta_new) - logpost(p, beta)
  if (log(runif(1)) <= min(0, logA)) {
    p <- p_new
    beta <- beta_new
  }
  list(p = p, theta = beta)
}
The returned field theta contains the updated value of beta. The original PDF really asks for p and theta, although no parameter θ is defined in this question. This choice preserves its literal interface while making the intended second parameter explicit. A caller therefore advances with state <- MHstep(x, p, beta, a, b, mu), p <- state$p, and beta <- state$theta.
The proposal is an unrestricted symmetric normal distribution followed by rejection outside the support. Repeatedly drawing until a valid proposal appears would instead truncate and renormalize the proposal, requiring a proposal-density correction. The code uses immediate rejection and needs no such correction. The displayed scales are valid fixed choices; practical efficiency can be improved using a separate tuning phase.

  • Trace plots of each parameter and the log-posterior against iteration, including early iterations and later windows. Look for initial drift, long flat stretches, abrupt switches and sustained changes in spread. Several independent chains started at dispersed points should explore the same region after burn-in.
  • Plots of cumulative sample means and selected sample quantiles against iteration. Compare chains and successive long blocks; persistent movement indicates that the estimated posterior moments or tails have not stabilized.
  • Autocorrelation function plots for both parameters after tentative burn-in. Slow decay reveals strong serial dependence and a small effective sample size of a Markov chain, even when 106 iterations have been generated.
  • Overlaid histograms or kernel density estimation curves from successive retained blocks and from different chains. Their agreement provides evidence of stable marginal posterior distributions.
  • A scatter plot of retained (p,β) pairs, colored by time block if helpful. Strong dependence or separate clusters can expose slow joint exploration that marginal plots conceal.
A million iterations and stable-looking plots do not prove convergence. Agreement across dispersed chains, exploration of all visible modes and adequate effective sample size of a Markov chain provide stronger evidence. Estimate the Monte Carlo standard error using the chain's autocorrelation; the independent random variables formula from 3(b)(ii) does not apply directly to these dependent draws.
