Entropy rate and coding length

 Home Mathematics Area of mathematics Probability and statistics Information theory Entropy rate
OurBigBook.com Words: 246
Consider a binary Markov source with fair initial bit and flip probability q=1/8. Its exact n-symbol information entropy is Hn​=1+(n−1)h2​(1/8). At n=16,
H16​≃9.15346665 bits,H16​/16≃0.57209167 bits per symbol.
(122)
This includes the uncertainty of the initial bit; the entropy rate itself is h2​(1/8)≃0.54356444 bits per symbol. The finite-block difference is (1−h2​(1/8))/n.
For any finite block distribution, the entropy lower bound for prefix codes gives expected codeword length Ln​≥Hn​, while Shannon coding achieves Ln​<Hn​+1. These bounds apply to each block as one source symbol, without requiring consecutive blocks to be independent. Here Huffman coding on all 216 possible 16-symbol words gives the independently calculated value L16​≃9.19511361 bits per block, or 0.57469460 bits per symbol. The noninteger value is an expected value; each actual codeword has an integer length. As the block length grows, the prefix code bounds squeeze Ln​/n towards the entropy rate when an optimal code is used.
An entropy rate below one does not allow every word to fit into a shorter fixed binary word with zero error. For 0<q<1, all 2n binary words are possible, so an injective fixed-length code needs at least n bits. Compression instead exploits variable codeword lengths, or the vanishing-error convention in reliable source encoding at a rate. These are different guarantees.
