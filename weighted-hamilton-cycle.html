Weighted Hamilton cycle (L(C)=∑e∈E(C)​we​)

OurBigBook.com Words: 344
A weighted Hamilton cycle is a Hamilton cycle in a weighted graph, with cost equal to the sum of its traversed edge weights. Here weights represent symmetric nonnegative costs, rather than conductances. Asking whether a Hamilton cycle exists is a feasibility question; asking for the cheapest one is an instance of the travelling salesman problem. A complete graph supplies every possible connection between distinct vertices, making feasibility automatic for n≥3, while choosing the cheapest visiting order remains a separate mathematical optimization problem.
Assign the complete graph K4​ the symmetric edge costs wAB​=2, wBC​=3, wCD​=4, wAD​=5, wAC​=6 and wBD​=7, in arbitrary units. Fix the start at A and identify each Hamilton cycle with its reverse. The three possibilities are
A,B,C,D,AA,B,D,C,AA,C,B,D,A​:2+3+4+5=14,:2+7+4+6=19,:6+3+7+5=21.​
(37)
These exhaust the possibilities: the permutations of the other three vertices give 3!=6 orders, paired into three reversals. Hence the perimeter tour really is optimal for this toy instance. The diagram's geometric lengths are not costs, and no triangle inequality is assumed.
The usefulness of this model is to distinguish visiting required sites from covering required connections. If tasks are assigned to vertices and the route must return after one visit to each, a weighted Hamilton cycle captures the ordering requirement. If the job instead requires each edge once, the relevant object is an Euler circuit. The shortest path problem asks only for a cheapest route between specified endpoints. A 1954 primary research paper gave a concrete motivation for the travelling salesman problem: certify that a particular tour through 49 cities has minimum road-distance cost.[ref]
These are abstract route models. If a cost stands for a whole graph path through an underlying network, travelling between consecutive task vertices can pass through intermediate network vertices more than once. One visit per task therefore does not imply one visit per physical junction. One-way connections require a directed graph; changing costs or extra timing constraints require a richer model than the fixed symmetric toy instance.
