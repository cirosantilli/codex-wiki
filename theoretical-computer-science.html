L-system

A parallel string-rewriting system: at each generation, every symbol is replaced simultaneously by its assigned word. Symbols can also encode drawing commands such as moving forward or turning. Large recursively defined drawings can be queried without expanding the whole word by precomputing the length, displacement, and rotation of each expanded block.

A binary string is a finite word over the alphabet {0,1}. There are 2n strings of length n. Finite binary strings have an effective bijection with natural numbers, so computable enumerability and immunity apply to sets of strings.

Instantaneous description of a Turing machine (C)

Words: 69
Turing machine OurBigBook.com
An instantaneous description records the current control state, head position, and tape contents. For a tape blank outside a finite window, a word huqvh records the symbols u to the left of the head and v from the scanned cell rightward, with unrecorded cells blank. If v is empty, the head scans an implicit blank. Extra outer blanks can represent the same infinite tape. The instruction of a Turing machine determines its successor description.

Instruction of a Turing machine (δ(q,a)=(p,b,D))

Words: 72
Turing machine OurBigBook.com
For a deterministic single-tape Turing machine, an instruction reads a state q and scanned tape symbol a, writes b, changes state to p, and moves the head one cell left, one cell right, or not at all according to D. The state and tape alphabets are finite; an undefined transition halts. A dedicated terminal state can be introduced by directing undefined transitions to it without changing whether computation halts.

Two-stack encoding of a Turing tape (c=(q,L,R))

Words: 56
Turing machine OurBigBook.com
Encode the cells immediately left of the head in a reversed positional stack L, and the current and right cells in R. Quotient and remainder by the alphabet base read and remove cells; multiplication by that base pushes a cell. The resulting local tape transitions are primitive recursive, which makes them directly implementable on Church numerals.

Modular machine (M)

Words: 183 Articles: 2
Turing machine OurBigBook.com
A modular machine of modulus m>1 acts on pairs in N2. Each instruction (a,b,c,R) or (a,b,c,L) has 0≤a,b<m and 0≤c<m2, and at most one instruction is assigned to each residue pair (a,b). The two transition types are (mu+a,mv+b)↦(m2u+c,v) and (mu+a,mv+b)↦(u,m2v+c). These finite arithmetic operations can encode a Turing machine; a designated terminal configuration can have a nonrecursive halting set.

Group encoding of a modular machine

Words: 73
Modular machine OurBigBook.com
A modular machine can be encoded by HNN extensions of K=Z2∗⟨t⟩. The kernel of K→Z2 has a free basis of a group t(r,s)=x−ry−stxrys. Associated-subgroup maps send these basis elements according to the two arithmetic transition types. In the resulting group, membership of t(r,s) in the subgroup generated by t and the instruction stable letters is equivalent to (r,s)∈H0​(M). One more HNN extension centralizes that finitely generated subgroup, converting membership to equality and hence to the word problem for a group.

Boolean operation (f:{0,1}n→{0,1})

Words: 1k Articles: 6
Theoretical computer science OurBigBook.com
A Boolean operation is a Boolean function taking truth values encoded as bits: 0 means false and 1 means true. These operations supply the concrete two-valued interpretation of a Boolean algebra. A Boolean valuation fixes the inputs; a truth table lists every possible input. With two input bits there are four rows.
The basic logical connectives are logical conjunction (AND, P∧Q, both true), logical disjunction (OR, P∨Q, at least one true), exclusive or (XOR, P⊕Q, exactly one true), and logical negation (NOT, ¬P, the opposite value). OR is inclusive: it accepts the case where both inputs are true.[ref]
For an original program-condition example, let P mean “the backup is recent” and Q mean “the backup is verified”. A rule requiring a recent, verified backup uses logical conjunction; one accepting either qualification uses logical disjunction. A rule flagging a mismatch between the two qualifications uses exclusive or. A recent, verified backup gives (P,Q)=(1,1): AND and OR accept it, while XOR does not flag it. The last row of the truth table makes this difference explicit.
The same small Boolean operations build larger tests and Boolean circuits. In a programming language, the value of a condition and the procedure for evaluating it both matter. For Boolean operands, Python's and, or, and not implement these logical connectives. Evaluation proceeds from the left; and skips its right operand if the left is false, and or skips it if the left is true. More generally, and and or return an operand, whereas not returns a Boolean.[ref]
For example, the Python condition denominator != 0 and numerator / denominator > 2 avoids division by zero because the logical conjunction's second test is evaluated only when the first succeeds. Reversing the tests preserves the abstract truth table for defined operands but can raise a division-by-zero error handled through exception handling. A rewrite involving a side effect must also preserve the needed evaluation behavior.

Boolean operations on events

Words: 110
Boolean operation OurBigBook.com
Events turn Boolean operations into operations on sets. For a die with sample space U={1,2,3,4,5,6}, let A={2,4,6} be the event “even outcome” and B={4,5,6} the event “outcome at least four”. At outcome u, use the indicator functions P=1A​(u) and Q=1B​(u). Then
AND: A∩BXOR: A△B​={4,6},={2,5},​OR: A∪BNOT A: U∖A​={2,4,5,6},={1,3,5}.​
(1)
Thus logical conjunction becomes set intersection, logical disjunction becomes set union, exclusive or becomes symmetric difference, and logical negation becomes the complement of a set within U. Outcome four satisfies both events, so inclusive logical disjunction includes it and exclusive or excludes it. If the die is fair, these four events have probabilities 1/3, 2/3, 1/3, and 1/2, respectively. No assumption of independent events is needed for the set identities; indeed A and B here are not independent, since 1/3=(1/2)(1/2).

Exclusive or (XOR, P⊕Q)

Words: 291 Articles: 1
Boolean operation OurBigBook.com
Exclusive or returns one exactly when its two input bits differ. Its truth table gives 0⊕0=0, 0⊕1=1, 1⊕0=1, and 1⊕1=0. The identities
P⊕Q=(P∨Q)∧¬(P∧Q)=(P∧¬Q)∨(¬P∧Q)
(2)
express exclusive or using logical conjunction, logical disjunction, and logical negation. The first expression accepts at least one input and then excludes both; the second explicitly lists the two accepted input pairs.
For numerical bits, exclusive or is addition in modular arithmetic modulo two:
x⊕y=(x+y)mod2.
(3)
The binary operation is commutative and associative, because addition modulo two has those properties. It satisfies x⊕0=x, x⊕1=¬x, and x⊕x=0. These identities explain why a bit can be toggled and restored with the same operation.
On binary strings of equal length, bitwise exclusive or applies the one-bit rule separately at each position. For example,
1010⊕0110=1100,1100⊕0110=1010.
(4)
A bit mask of 0110 toggles exactly the middle two bits. Applying the mask twice restores the original binary string: each selected bit changes twice, and each unselected bit stays fixed. This positional operation is distinct from taking the exclusive or of the overall truth values of two integers.

Exclusive or toggles and parity

Words: 135
Exclusive or OurBigBook.com
For bits x1​,…,xn​, repeated exclusive or computes the parity of the number of ones:
x1​⊕⋯⊕xn​=(∑i=1n​xi​)mod2.
(5)
An induction proves this: the first bit gives its own parity, and appending a zero preserves it while appending a one changes it. The binary string 10110 has three ones, so its parity bit is one. Append that parity bit to obtain 101101, whose six bits have even parity. Flipping the second bit produces 111101 and changes the combined exclusive or to one, detecting an error. Flipping the third bit as well produces 110101, with four ones and combined exclusive or zero: an even number of flips can escape this check.
For three inputs, repeated exclusive or means an odd number of true inputs, rather than exactly one: 1⊕1⊕1=1. The “exactly one” description applies to the two-input exclusive or. This distinction matters when translating a requirement that exactly one option be selected into a program condition.

Negation (¬P)

Words: 102
Boolean operation OurBigBook.com
Logical negation exchanges zero and one: ¬0=1 and ¬1=0. For a numerical bit x, this is 1−x; applying logical negation twice restores x. It acts on the entire propositional formula in its scope. Parentheses therefore matter: ¬(P∨Q) says that neither condition holds, while (¬P)∨Q also accepts every case where Q holds. At (P,Q)=(1,1) their values are zero and one.
On a set, logical negation becomes taking a complement in a fixed universal set. In Boolean operations on events, “not even” selects {1,3,5}. “Not both even and at least four” selects {1,2,3,5}; it does not require both qualifications to fail. De Morgan's laws make the scope of these compound negations precise.

De Morgan's laws (¬(P∧Q)≡¬P∨¬Q)

Words: 443 Articles: 1
Boolean operation OurBigBook.com
De Morgan's laws exchange logical conjunction and logical disjunction when a logical negation moves across them:
¬(P∧Q)≡(¬P)∨(¬Q),¬(P∨Q)≡(¬P)∧(¬Q).
(6)
Here ≡ denotes logical equivalence: the two propositional formulas agree under every Boolean valuation.[ref]
A complete verification uses the four rows of a truth table. In input order (0,0),(0,1),(1,0),(1,1), both sides of the first logical equivalence have output sequence (1,1,1,0); both sides of the second have (1,0,0,0). A proof in words is equally short: failure of “both” means at least one failure, whereas failure of “at least one” means both fail. The differing middle rows explain why simply pushing logical negation inward without changing AND to OR is wrong.
For the events in Boolean operations on events, the corresponding set identities are
U∖(A∩B)=(U∖A)∪(U∖B)={1,2,3,5},
(7)
U∖(A∪B)=(U∖A)∩(U∖B)={1,3}.
(8)
One can prove these identities by checking an arbitrary set element u∈U: its two membership truth values obey De Morgan's laws. The same reasoning works for any two subsets of a common universal set.
For a nested program test, let R mean “backup recent”, V mean “backup verified”, and O mean “manual override authorized”. Rejecting when neither an acceptable backup nor an override is present gives
¬((R∧V)∨O)≡((¬R)∨(¬V))∧¬O.
(9)
The transformed condition reads “backup stale or unverified, and no override”. Apply the second of De Morgan's laws at the outside, then the first at the inner logical conjunction. For (R,V,O)=(1,0,0) it rejects; changing only O to one makes it accept. With Boolean operands in Python, not ((recent and verified) or override) and ((not recent) or (not verified)) and (not override) have the same result and inspect the operands in the same order, with the same skipped operands.

De Morgan dual of a Boolean function (f∗(x)=¬f(¬x))

Words: 141
De Morgan's laws OurBigBook.com
For a Boolean function f of n input bits, define its De Morgan dual by complementing every input, applying f, and complementing the output:
f∗(x1​,…,xn​)=1−f(1−x1​,…,1−xn​).
(10)
De Morgan's laws say that the De Morgan dual of logical conjunction is logical disjunction, and conversely. The constant zero Boolean function becomes constant one. This is different from merely negating the output: for AND, output logical negation gives one at (0,0), whereas the De Morgan dual gives zero there.
Taking the De Morgan dual twice restores the original Boolean function:
(f∗)∗(x)=1−(1−f(x))=f(x).
(11)
Here each input is complemented twice as well. For a Boolean formula built from AND, OR, NOT and constants, its De Morgan dual can therefore be obtained by exchanging AND with OR and zero with one throughout, leaving input names and NOT in place. A structural induction proves the rule: it holds for an input and each constant, De Morgan's laws handle the two binary logical connectives, and double logical negation handles NOT. This symmetry lets one translate a complex test systematically instead of guessing where its failures occur.

Communication complexity

Words: 76
Computational complexity theory OurBigBook.com
Communication complexity studies how much information distributed parties must exchange to compute a function of their separately held inputs. Local computation is free; the resource being counted is communicated bits or qubits, with the allowed shared randomness, quantum entanglement or other correlations specified separately. For a Boolean function f(x,y), a one-way exact protocol has the receiver output f correctly for every input after a single message. One-bit computation using Popescu–Rohrlich boxes shows that this resource measure changes drastically if ideal superquantum boxes are available.

Independent runs of a BQP algorithm with fresh ancilla qubits can be combined by a classical threshold rule. If completeness exceeds soundness by γ, a Hoeffding inequality bounds the error after r runs by e−rγ2/2. Polynomial repetition handles inverse-polynomial gaps. A quantum witness is a polynomial-size quantum state supplied to a verifier as evidence for a YES instance. The verifier fixes its own ancilla qubits independently. Pure quantum witnesses suffice when maximizing a linear acceptance functional on density operators. Quantum witnesses are not generally restricted to basis vectors or product states.

StoqMA (StoqMA(a,b),1/2≤b<a≤1)

Words: 71
Quantum complexity theory OurBigBook.com
StoqMA is a restricted quantum-verifier class using stoquastic circuits and polynomial-size quantum witnesses. A YES instance has a quantum witness accepted with probability at least a; on a NO instance every quantum witness has acceptance at most b, with an inverse-polynomial gap a−b. An optimal quantum witness can be chosen with nonnegative amplitudes, since the witness acceptance operator is entrywise nonnegative. The quantum witness is generally a superposition, rather than a computational basis vector. The stoquastic acceptance floor explains the lower limit b≥1/2 for a nontrivial soundness promise.

QMA

Words: 350 Articles: 5
Quantum complexity theory OurBigBook.com

Decision tree

Words: 1k Articles: 12
Decision tree model OurBigBook.com
A decision tree represents a deterministic computation of a known Boolean function f:{0,1}n→{0,1} by inspecting input bits. Each internal vertex of its binary tree names a coordinate i to query, its two outgoing edges carry answers 0 and 1, and each leaf carries the output 0 or 1. Starting at the root of a tree, read the named bit, follow its answer edge, and repeat until a leaf is reached. Correctness requires the leaf's label to equal f(x) for every input x.[ref]
The next coordinate, or the decision to stop, can depend on earlier answers: this is adaptive querying. The same input always follows the same graph path; adaptivity does not require randomness. A correct leaf must have the same output for every completion of the observed bits. Thus a decision tree can stop as soon as the observations form a query certificate. Querying an already known coordinate adds no information, so we use decision trees without repeated coordinates on a graph path; an efficient tree also removes queries made after the output is already forced.
The motivation is exact computation with shortcuts. If inspecting an input entry is expensive, the question is how much of the input must actually be read. The decision-tree query cost counts these inspections, while local calculations on known values are free in this model; this cost need not equal an implementation's time complexity. Here the Boolean function is specified in advance and must be computed exactly on every input. Decision tree learning instead fits a predictor from data, with a different objective.

Time complexity (T(n))

Words: 2k Articles: 16
Complexity class OurBigBook.com
The time complexity of an algorithm bounds its number of computation steps as a function of its input length.
Specify both the size parameter and the operations counted. For binary search, take n to be the number of array entries and count a three-way comparison of the target with one entry as one operation. Code using separate equality and less-than tests may perform two primitive tests per inspected entry; this changes a constant factor. The input size in bits is a different parameter when entries have variable-length representations.
Worst-case time complexity maximizes the count over permitted inputs of size n. An absent target forces n comparisons in linear search. For binary search, the worst-case count is ⌊log2​n⌋+1 for n≥1, attained by a target larger than every entry. Both have a best case of one comparison when the first inspected entry matches.
In Big O notation, the worst-case bounds are O(n) and O(logn) respectively. Here T(n)=O(g(n)) means that fixed constants C,n0​ exist with T(n)≤Cg(n) for all n≥n0​. It is an upper bound, so a logarithmic count is also O(n); the sharper bound communicates its scaling better. The base of the logarithm changes only a constant factor.
For n=1,000,000, linear search can require 1,000,000 comparisons, whereas binary search needs at most 20, since 219≤n<220. Doubling n adds just one to the worst-case binary search count. These are operation counts, not measured machine runtimes. Translating them into logarithmic execution time assumes constant-cost indexed access, comparison and index arithmetic. Long entries can make comparison expensive; a linked list does not provide constant-cost access to an arbitrary middle index. Building or sorting the array is additional work: merge sort can provide order for many subsequent searches, but its cost belongs in the analysis too.

Amortized analysis (ci​=ci​+Φi​−Φi−1​)
Words: 1k Articles: 5
Time complexity OurBigBook.com
Amortized analysis bounds the total cost of every permitted sequence of operations from a specified initial state. An amortized O(1) bound means that some constants a,b satisfy ∑i=1m​ci​≤am+b for every such sequence of length m. The cost model and allowed operations are part of the claim; Big O notation alone does not specify them.
  • A worst-case bound for one operation limits its cost in any reachable state. Summing these separate maxima can overestimate the cost of a whole sequence because expensive states may take many cheap operations to rebuild.
  • An amortized analysis limits the total over every allowed sequence, including an unfavourably chosen one. Dividing that bound by the number of operations is a deterministic guarantee about the sequence.
  • A probabilistic average-case analysis bounds an expected value under a stated probability distribution on inputs. For a randomized algorithm, an expected value can instead average over its random choices. Neither interpretation is required by a deterministic amortized analysis.
This distinction, and the credit and potential method viewpoints, are developed in R. Endre Tarjan's 1985 paper Amortized Computational Complexity, sections 1–2, pp. 306–308. The dynamic array doubling example below shows how an expensive operation can pay for itself through the cheap operations that precede it.
Dynamic array doubling (T(n)=n+Cn​−1)
Words: 479
Amortized analysis OurBigBook.com
Consider a dynamic array holding fixed-size entries. Its size n is the number of occupied slots and its capacity C is the number of allocated slots. Start with n=0, C=1. The only operation is append: if n=C, allocate a new array of capacity 2C, copy the C existing entries, and release the old array; then write the new entry and increase n by one. There is no reserve operation, deletion or shrinking in this model.
Count one unit for writing the new entry and one unit per existing entry copied during resizing. Thus the ith append has actual cost ci​=1 without resizing and ci​=C+1 when the old capacity C is full. Copying an entry, including its read and write, is one counted action. Allocation, deallocation, index arithmetic operations and the initial one-slot allocation are outside this exact count. If these add only a constant per ordinary append and a linear cost per resize, the Big O notation conclusions still hold, with different constants; costly entry copies require their own cost model.
The first ten costs are 1,2,3,1,5,1,1,1,9,1. For example, append 9 copies eight entries and writes one, so c9​=9. At that point the capacity becomes 16, but the total cost of all nine appends is only 24.
For n≥1, the final capacity is Cn​=2⌈log2​n⌉. Every earlier capacity 1,2,4,…,Cn​/2 was copied once. This geometric series sums to Cn​−1, including the empty sum when n=1. Therefore aggregate analysis gives the exact total
T(0)=0,T(n)=∑i=1n​ci​=n+Cn​−1,n≤Cn​<2n(n≥1).
(20)
Consequently T(n)<3n, so append has amortized O(1) cost in Big O notation for every prefix from this empty initial state. The values being appended do not affect the count. In contrast, an append to a full dynamic array with n entries costs n+1: its worst-case cost is O(n), and actually grows linearly along full-capacity states. A bound on total work does not promise a constant response time for each call.
The same policy controls computer memory: after each completed append, n≤Cn​<2n for n≥1, so fewer than n slots are unused. This is a bound on the retained backing array, with fixed-size slots. During a resize from full capacity k to 2k, a copying implementation can temporarily hold both arrays, totalling 3k allocated slots before releasing the old one. Thus the retained-capacity bound does not bound this temporary peak by twice the live size. Allocator metadata and separately allocated objects are additional computer memory costs.
The geometric series is the source of the efficiency. If capacity instead increases by one each time, the same count becomes n+1+2+⋯+(n−1)=n(n+1)/2, a quadratic total. Dynamic array doubling buys a linear total with bounded spare capacity, even when the final length is unknown.

The potential method assigns a number Φ(D) to each state D of a data structure. Let Di​ be the state after operation i, Φi​=Φ(Di​), and ci​ its actual cost. Its amortized cost is the actual cost plus the change in potential. Summing and cancelling adjacent potentials gives a telescoping sum:
ci​=ci​+Φi​−Φi−1​,∑i=1m​ci​=∑i=1m​ci​+Φ0​−Φm​.
(21)
If Φ0​=0 and every reachable Φi​≥0, the sum of amortized costs bounds the actual total for every prefix. A nonzero initial potential contributes the explicit additive term Φ0​. Potential is proof bookkeeping; the algorithm need not store it.[ref]
For dynamic array doubling, choose
Φ(n,C)=max(0,2n−C).
(22)
The potential method now starts at Φ(0,1)=0. After every nonempty reachable state, C<2n, so the maximum equals 2n−C. There are just three cases for append:
  • First append: (0,1) becomes (1,1), so c1​=1 and c1​=1+(1−0)=2.
  • Later append without resizing: C stays fixed and n increases by one, so ΔΦ=2 and ci​=1+2=3.
  • Append to a full capacity k: (k,k) becomes (k+1,2k), so the potential changes from k to 2. Hence ci​=(k+1)+(2−k)=3, including the resize from capacity one to two.
For every n≥1, the total charge is 2+3(n−1)=3n−1, and the telescoping sum proves
T(n)=3n−1−Φ(n,Cn​)≤3n−1.
(23)
This agrees exactly with T(n)=n+Cn​−1. The unmodified choice 2n−C has initial value −1, so calling it nonnegative at the empty state would be incorrect. It also works if that initial constant is retained in the identity; alternatively, 2n−C+1 starts at zero and is nonnegative on these reachable states. The maximum above keeps a literal nonnegative credit balance from the beginning. The proof covers append alone; allowing reserve or arbitrary deletion changes the reachable states and requires a new argument.

Boolean satisfiability problem
Words: 2k Articles: 23
NP-completeness OurBigBook.com
The Boolean satisfiability problem asks whether a Boolean formula has an assignment making it true. A complete assignment is a Boolean valuation: it gives every Boolean variable a truth value, consistently at all occurrences. A satisfying assignment, also called a model of a Boolean formula, makes the entire Boolean formula true. A solver's answer SAT asserts that at least one satisfying assignment exists; UNSAT asserts that the input is an unsatisfiable Boolean formula. These are statements about existence, rather than the truth value under one particular Boolean valuation.
For conjunctive normal form, or CNF, write
F=C1​∧⋯∧Cm​,Ci​=ℓi1​∨⋯∨ℓiki​​.
(24)
Each Boolean literal ℓ is a Boolean variable or its logical negation. Each Boolean clause uses inclusive logical disjunction: one true Boolean literal suffices. The outer logical conjunction requires every Boolean clause to succeed under the same Boolean valuation. Choosing a different Boolean valuation for each Boolean clause would answer a different question.
Consider the original three-Boolean variable example
F=(x∨y)∧(¬x∨z)∧(¬y∨¬z),C1​=x∨y,C2​=¬x∨z,C3​=¬y∨¬z.
(25)
At the Boolean valuation (x,y,z)=(0,1,0), the Boolean literals in C1​ have values (0,1), those in C2​ have values (1,0), and those in C3​ have values (0,1). Every Boolean clause therefore has truth value one, so F has truth value one: this is a satisfying assignment.
The complete truth table has 23=8 Boolean valuations. Exactly two are satisfying assignments: (0,1,0) and (1,0,1). In particular, (1,1,1) satisfies the first two Boolean clauses but falsifies the third, so satisfying most Boolean clauses does not suffice for SAT. That different objective belongs to maximum satisfiability.
A short proof of completeness avoids listing all eight rows. If x=0, the Boolean clause C1​ forces y=1, after which C3​ forces z=0; C2​ is already true. If x=1, C2​ forces z=1, after which C3​ forces y=0; C1​ is already true. These two cases exhaust the truth values of x and produce precisely the two satisfying assignments above.
Verifying a satisfying assignment and finding a satisfying assignment are different tasks. Given a candidate, evaluate the Boolean formula once; finding a candidate requires choosing compatible truth values across all its Boolean clauses. The Cook-Levin theorem says that general SAT is NP-complete, even though a proposed satisfying assignment is efficiently checkable. Its proof encodes a bounded nondeterministic computation as a Boolean formula whose satisfying assignments describe accepting computations. Stephen A. Cook's 1971 paper established this connection between computational complexity theory and propositional logic.[ref]
A concrete use is checking finite configuration rules. Let x mean that an optional feature is enabled, y that a fallback is selected, and z that the feature's required component is installed. Require a feature or fallback, require the component whenever the feature is enabled, and forbid using the fallback with that component. Logical implication rewrites the second rule x→z as ¬x∨z; De Morgan's laws rewrite the third rule ¬(y∧z) as ¬y∨¬z. Their logical conjunction is exactly F, so its two satisfying assignments give the two allowed configurations. The usefulness of SAT lies in expressing local rules uniformly while demanding one globally consistent Boolean valuation. The conclusion concerns exactly these encoded rules.
